# What's new, older releases

What each release before 1.46 added, newest first, each feature with where it is documented. The newer releases are in [What's new](whats-new.md); what a release breaks is in [Upgrading](upgrading.md).

## 1.45.0

- A `try` block that throws on the server takes back the `head` tags and island titles its components set, so a page never serves a title from an island it did not render ([Head](head.md)).
- A `kay/test` page whose renderer crashes, killed or out of memory, fails the call waiting on it and every later one at once, where they waited for the test's timeout ([Testing](testing.md)).
- `kay/eslint` passes the classes of a template, the shorthand `.flex.flex-col` and a static `class="..."`, to the Tailwind rules of `@kaynooo/eslint`, reporting at the class in the `.kay` file and fixing inside a static `class` of an element with no shorthand ([Checks](checks.md#lint-the-script-fences-and-template-expressions-with-eslint)).
- `kay/eslint` lints the expressions of a template, attribute values, `{...}` in text and the heads of `if`, `match`, `for`, `await`, `const` and `slot`, reporting at their `.kay` line and column and fixing them in the file ([Checks](checks.md#lint-the-script-fences-and-template-expressions-with-eslint)).
- `kay dev` bundles a worker (kay's own proof-of-work worker included) once per session and again only when a file it read changes, instead of starting a process for it on every island edit: an edit spends about 13% less CPU over 21 edits ([Dev server](dev-server.md)).
- `kay dev` starts the client builder beside the first types and server when an earlier run left a client build, instead of once the server asks for it, so the build no longer waits for the server to boot; it spends no more CPU or memory, and `ready` drops by about a quarter ([Dev server](dev-server.md)).
- Two `kay build` runs of the same sources give byte-identical prerendered pages, so a warm build compresses none of them again: the docs site's compress stage takes about 40 ms where it took 1 s ([Prerendering](prerendering.md#prerendering)).
- `kay dev` runs one server process for the whole session: an edit to a template, island, loader or API route imports what changed again and swaps the routes in place, spending about 40% less CPU than a new process per edit, and the spare process is gone ([Dev server](dev-server.md)).
- An island sets the page title with a `head` block holding a `title`, which follows the signals it reads in the browser and is wrapped in `seo.titleTemplate` as on the server, so a title from live state no longer needs `document.title` ([Head](head.md#follow-live-state-in-the-page-title)).
- A page that reads nothing from its request (no `ctx`, `query`, clock, random number, environment or package import) is prerendered by `kay build` and served from memory without `prerender`, and checked against a live render after a request that writes: the bench app's pages cost 650 and 80 us of CPU per request, about 50 and 38 now ([Prerendering](prerendering.md#prerendering)).
- `kay dev` keeps what was typed into a text field, checkbox, select or textarea through a template or server code edit that leaves the field as it was, where it used to show the page's rendered value ([Dev server](dev-server.md)).
- `kay check` and the editor type a linked or sibling extension's pages under the `tsconfig.json` of its own package when its options differ from the app's, with the app's catalogs, `ctx.locals` and matchers in scope, and its pages resolve the dependencies its package installs itself ([Components](components.md)).
- A build compresses a file and draws the favicons only when their content changed, keeping the copies and icons under `.kay/cache`, so a build with nothing new spends about a quarter less CPU ([Build](build-and-start.md)).
- A route of a module with a `cors` rule can no longer widen it: the `Access-Control-*` grant headers it sets itself, or a `Response` it passes on carries, are replaced by the module's, and a redirect or a `fetch()` result is answered with its `Vary: Origin` instead of a 500 ([CORS](api-routes.md#cors)).
- `kay check` reports a signal or memo handed to a parameter typed `unknown` or `any`, as in `String(count)` or `JSON.stringify(count)`, which rendered the function's source, as `uncalled-signal` ([Components](components.md)).
- A page rendered per request goes out as zstd to a browser taking it, at about a quarter of brotli's CPU, one taking no zstd gets gzip rather than brotli, a body up to 128 KB is compressed within its request, and a page rendering the same bytes again is compressed once: the server spends about half the CPU per compressed page it did ([Production](proxy-and-security.md#compress-responses)).
- `kay check` types the named exports of a library's `.kay` module, such as a prebuilt page's actions, as the file declares them, so a test imports one without a cast ([kayjs-auth](../packages/auth/llms.txt)).
- A `kay.config.ts` importing only `defineConfig` from `kay/server` loads without the server in the processes that only read the config (the client builder, the types process, `kay build`, `kay check`), about 230 ms and 13 MiB less each.
- `kay build --compile server --verify` starts the executable it wrote, waits for its health route and runs `--health`, failing the build with the server's own output when it crashes at startup ([Check the executable starts](production.md#check-the-executable-starts)).
- `testSite()` builds the islands for the browser and throws when one fails, such as an island reaching a Bun builtin, once per process, and `islands: false` skips it ([Testing](testing.md#test-site)).
- The executable `kay build --compile` makes leaves out the code only `kay dev` and `kay build` run, so it is about 2 MB smaller and holds up to 1 MiB less memory, and a further 4 MB smaller with the AVIF coders embedded compressed ([Production](production.md#reference)).
- `db/roles.sh` protects `_pgorm_migrations` in any schema, and finishes with a notice on a managed Postgres whose owner is not a superuser ([Upgrading](upgrading.md#the-app-presets-database-runs-the-app-as-a-role-that-cannot-change-the-schema)).
- `kay/test/dom` is a preload registering happy-dom's DOM with the popover API it lacks, for `mount()` in every test file, and `kay/test` exports `cookieJar()`, `solveWork()` and `scratchDir()` for a test of its own ([Testing](testing.md#helpers-for-a-test-of-its-own)).
- kayjs-auth: the prebuilt pages' actions import as `@kaynooo/kayjs-auth/pages/<page>.kay`, for a test to submit them ([kayjs-auth](../packages/auth/llms.txt)).
- The app's stylesheets leave out the rules of a library's stylesheets for the classes no file of the app or library component it reaches writes, so kayjs-ui's theme ships only the components the app renders ([Using a component library](component-libraries.md#using-a-component-library), a class put together at runtime in [1.45.0](upgrading.md#1450)).
- kayjs-auth: a request sending a bearer token reads the token and its user in one query with the built-in stores, and a custom store may add `bearerTokens.findByDigestWithUser` for the same ([kayjs-auth](../packages/auth/llms.txt)).
- `kay build` prints a table with one row per route (scripts and stylesheets it loads, whether it was prerendered), the time each stage took and what each cache under `.kay/cache` answered, each size beside its change since the last build and what the last build had that this one lacks; `--format json` carries them as `routes`, `stages` and `caches` ([Build](build-and-start.md)).
- The `app` preset connects the app as `app_rw`, a Postgres role that reads and writes rows but cannot change the schema, and runs the migrations as the owner; `db/roles.sh` creates it and sets default privileges, so a later migration needs no `GRANT`, pg-orm's migration history table staying read-only to it ([Commands](project.md#commands), adopting it in [1.45.0](upgrading.md)).
- kayjs-cms: `guard` takes `{ load }`, an async function returning the guard that runs on the first request, so `kay.config.ts` no longer imports the app's auth and database to build one; the built guard still works ([kayjs-cms](../packages/cms/llms.txt)).
- `kay mcp` serves the project to an agent as an MCP server over stdio, with tools for `check`, `routes`, `explain`, `render` and the dev server's errors, and the guides as resources: [Give an agent kay's tools](check-and-tools.md#give-an-agent-kays-tools).
- kayjs-ui: IconPicker's `Show more` asks `search(query, limit, offset)` for the next page and adds it, where it asked again for every icon shown ([kayjs-ui](../packages/ui/llms.txt), in [1.45.0](upgrading.md#1450)).
- The dev tool's Request tab also shows the response headers (CSP and cache-control first), whether `kay build` prerenders the page, the guards that ran and their outcome, the redirects the request went through before the page and what made them, and the server's time to answer ([Dev server](dev-server.md)).
- Every error a compile, build, content load or static export raises carries a stable code, which `kay explain <code>` documents with the section that covers the fix, and `--format json` carries as `code` ([Errors](errors.md#errors)); `kay build --static --format json` reports each page it cannot export as its own problem.
- The dev tool has a Head tab: the page's search result, title and description with their lengths and limit, canonical, alternates, robots and sitemap membership, og and twitter tags with the social card, JSON-LD parsed or failing, and what `kay check` would flag in the head, read again after each page swap ([Dev server](dev-server.md)).
- The dev tool has an Env tab: the variables `publicEnv` sends the browser with their values, a name or value that looks like a secret flagged, and a note when the app sends none ([Dev server](dev-server.md)).
- The dev tool has an Images tab: each image of the page with its variant and format, the size served against the size drawn, the largest contentful paint, and images without dimensions or lazy-loaded in view, outlined on hover ([Dev server](dev-server.md)).
- The dev tool has a Performance tab: LCP, CLS and INP as the page is used, each against its good limit, and the page's HTML, CSS and JS gzipped with the island chunks split out, as dev sizes, beside what the last `kay build` measured for the page's route, its age and `~` for an estimate ([Dev server](dev-server.md)).
- kayjs-ui: `LineChart` reads chartist once it is on the page, so an island showing one runs before chartist loads, and a `Table` reads each row's sort value once per sort ([kayjs-ui](../packages/ui/llms.txt)).
- A loader takes optional `count`, `body` and `get`, so a CMS lists its collection or opens one entry without running `load` for every entry, `collections({ counts: false })` skips the counting, and reads at the same moment share one run ([Content](content-cms.md#loaded-collections)). kayjs-cms reads an entry screen's collection and entry together, saves without counting, and deletes the unused uploads it selects in one scan ([kayjs-cms](../packages/cms/llms.txt)).
- kayjs-mail loads nodemailer with the first SMTP send, or the first `.eml` download of the dev preview, where it loaded with the module; it reads the dev pages with the first request to one and builds its dark style once per settings ([kayjs-mail](../packages/mail/llms.txt)).
- kayjs-auth: an app with no passkey and no OAuth provider no longer loads `@simplewebauthn/server` or `jose` (read on the first ceremony or ID token), a sign-in answers without waiting on its security-notice mail whatever `mailer` does (a mailer silent for 30 seconds is given up on, and with 200 mails waiting a new notice is dropped), and the hourly prune and `audit.forget` read through indexes that `db.sync()` creates ([kayjs-auth](../packages/auth/llms.txt)).
- The dev tool's Routes tab has a "Served by kay" section: the sitemap, robots.txt, feeds, manifest, favicons, service worker, health check and a library's dev pages such as `/_kay/mail`, each GET path linked, and with `seo` set but no origin it says why there is no sitemap or robots.txt ([Dev server](dev-server.md)).
- `localPath` also refuses a path that leaves the site once decoded, `/%2F/evil.example` or `/%09/evil.example` at any depth of encoding, a backslash or a control character; kayjs-auth's `safeRedirect` is now `localPath` ([Routing](routing.md)).
- kayjs-cms refuses a body with every tag and attribute kay's sanitizer drops, `<bgsound>`, `<keygen>` and `formaction` included, and a script URL in `ping`, `cite`, `longdesc` or `background` ([kayjs-cms](../packages/cms/llms.txt)).
- An idle `queue` looks at its store from one worker and backs off, 1 second after a job up to `idlePoll`, 10 seconds by default, a job enqueued in the same process still running at once; `sqliteRooms` beats and polls only while a connection is joined, and the sessions, rooms and failed jobs are cleaned through indexes and one `DELETE` ([Production](production.md#background-jobs), [Rooms](api-from-islands.md#rooms)).
- `kay dev` on a terminal rewrites an identical restart or stylesheet line with a count, `(x3)`, instead of repeating it ([Dev server](dev-server.md)).
- `shortcut('mod+s', save)` from `kay` binds a keyboard shortcut for as long as an island lives, Cmd on macOS and Ctrl elsewhere, on the page or one element with `on`, firing in a text field only with a modifier ([Islands](navigation.md#bind-a-keyboard-shortcut)).
- kayjs-ui: a `Table` takes `selectable`: a checkbox per row, a tri-state select-all with `N selected`, keys of rows that left `rows` dropped, and a `@bulk(keys, clear)` block for the bulk actions beside the count, in stacked cards too ([kayjs-ui](../packages/ui/llms.txt)).
- kayjs-ui: `SaveForm` is a form calling a page's action with a sticky bar of unsaved changes, the save under way, Discard and Save, its dirty state read from the form's own controls, leaving with unsaved changes asking and Ctrl+S saving ([kayjs-ui](../packages/ui/llms.txt)).
- kayjs-ui: Checkbox, Toggle, ChipGroup, Segmented, Select, MultiSelect, IconPicker, TextInput, Textarea, MarkdownEditor and RangeInput follow a `form.reset()`, so `SaveForm`'s Discard and a `<button type="reset">` put them back, saved values included, and their `onChange` hears of it ([kayjs-ui](../packages/ui/llms.txt)).
- kayjs-ui: a `ref` on a TextInput, Textarea, MarkdownEditor, Select, MultiSelect, IconPicker, ChipGroup or Segmented gets its element once, as on a plain element ([kayjs-ui](../packages/ui/llms.txt)).
- kayjs-ui: a Segmented started with none picked tells `onChange` `null` when a reset clears it, and `onChange` is typed `(value: Value | null)` only when `value` is typed nullable ([kayjs-ui](../packages/ui/llms.txt)).
- kayjs-ui: `infiniteList` and `LoadMore` own an infinite-scroll list's rows, offset or cursor paging, the end of the list, a retry after a failed page and the "Loading more" row, dropping a row already shown when the list shifts ([kayjs-ui](../packages/ui/llms.txt)).
- A `for` over plain objects with no `id`, edited immutably, keeps each row's nodes, fields and focus through an edit, a removal or an insertion, with no id of your own ([Templates](templates.md)).
- A layout declares a `query` of its own, read through `ctx.query` typed and validated with the page's, so the pages under it no longer repeat the schema, and an island's `queryParam` reads it too ([`ctx.query`](routing.md#the-server-fence)).
- A static export writes its endpoint files, sitemap and feeds sixteen at a time, so an endpoint's `GET` no longer runs alone ([Endpoint files](routing.md#endpoint-files)).
- `markInvalid(element, by, invalid)` from `kay` marks a field `aria-invalid` for one source among several, so an island's refused field stays invalid while a kayjs-ui `FormField` still shows a message for it ([Islands](navigation.md#forms-posting-in-place)).

## 1.44.0

- kayjs-ui: a `Button` whose `onClick` returns a promise is busy and disabled until it settles, alone among the buttons on one action, and a submit `Button` is busy while its form's async `onSubmit` runs, which marks the form `aria-busy`.
- kayjs-ui: a `FormField` `group` with a message marks its fields `aria-invalid` and described by it, so `focusInvalid` reveals the group's tab and focuses its first field.
- kayjs-auth: an hourly `prune` deletes expired links, codes, invitations and sessions, a session ended by sign-out everywhere or a password change included, and its stores batch reads and deletes into fewer round trips; a custom store implements `prune`, in [1.44.0](upgrading-archive.md#1440).
- kayjs-auth: a data export asks for a sign-in or proof under ten minutes old, an email change on a two-factor account its code, ID tokens need an asymmetric signature and an issuer `https:` in production, and a plain Elysia app refuses cross-site session writes, breaking changes in [1.44.0](upgrading-archive.md#1440).
- kayjs-ui: `Select` and `MultiSelect` take the type of their options' values, a number option handing back a number, a breaking change in [1.44.0](upgrading-archive.md#1440).
- kayjs-ui: `ConfirmDelete` takes `success`, toasted once through, and `tone="neutral"` for a confirm that is not a deletion.
- kayjs-ui: `FileDrop` takes `compact`, a slim row to sit inline in a form.
- kayjs-ui: `TabNav` takes `current={ctx.url}` and `keep`, carrying the named query params onto each tab.
- kayjs-ui: `PageHeader` takes a `@meta` block beside its title and a `description` under it.
- kayjs-ui: `EmptyState` takes `level` to make its title a heading, `level={1}` for an error page.
- kayjs-ui: `Segmented` takes `value={null}` to show no option picked.
- kayjs-ui: a number `TextInput` hands back a number, or `null` once emptied, a breaking change in [1.44.0](upgrading-archive.md#1440).
- AVIF variants encode twice as fast, on kay's own SIMD build of libavif and libaom: [Responsive images](images.md#responsive-images).
- `images.card.logo` draws a square image, an SVG or a raster, at the top left of every share card, `kay check` reporting one the boot would refuse: [Draw a share card for a page](images.md#draw-a-share-card-for-a-page).
- kay's default favicon is a kingfisher on a navy tile, for a site that names none: [Set a favicon and make the site installable](sitemap-search-fonts.md#set-a-favicon-and-make-the-site-installable).
- `kay render <url>` prints what the server answers for one URL, as `kay dev` serves it, without starting it on a port: [Check what a page renders](check-and-tools.md#check-what-a-page-renders).
- `--format json` on `kay build`, `kay routes`, `kay explain`, `kay fmt` and `kay migrate` prints one JSON document on stdout, as `kay check` does; `kay routes --format json` lists each route with its file, layouts and guards: [Commands](project.md#commands).
- `kay build` in a terminal redraws one line with its step, the step's time and a bar over the routes prerendered and images encoded; piped, it prints the lines it printed before: [Build](build-and-start.md).
- `--quiet` on `kay build`, `kay check`, `kay fmt`, `kay migrate` and `kay new` prints the problems and one summary line, and on `kay dev` the ready line and errors alone: [Commands](project.md#commands).
- `kay dev` lists the errors its servers meet in `.kay/dev/errors.json`, for a reader without a browser, and `kay dev --format json` prints its events as JSON lines: [Dev server](dev-server.md).
- `kay dev` in a terminal reads `o` (open), `r` (restart), `c` (clear) and `q` (quit), and under `--host` names its address on the network: [Dev server](dev-server.md).
- `watch` and `debounced` from `kay`: `watch` runs on a change only, handed the value before, and `debounced` gives a value once it stops changing: [React to a change, or to typing once it pauses](components.md#react-to-a-change-or-to-typing-once-it-pauses).
- Assigning a signal a component holds in a `const`, an import or a `Signal<T>` prop writes it wherever it was made, `kay check` refusing an assignment to a name holding no signal: [Signals](components.md#signals).
- `workChallenge` and `verifyWork` from `kay/server` put a proof of work in a form field the app's own code checks; kayjs-auth makes it its default CAPTCHA, a breaking change in [1.44.0](upgrading-archive.md#1440): [Proof of work checked in code](action-protection.md#proof-of-work-checked-in-code).
