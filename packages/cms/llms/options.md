# Options of cms()

The options `cms()` takes, from `kay.config.ts`.

`cms({ prefix, logo, guard, files, uploads, pageSize, collections, rawHtml, author })`: `prefix` is where the screens live (`/admin`; `/` is the root, where the screens mount under a `(admin)` group, so an app root layout and guard neither wrap them nor are wrapped by theirs), `logo` an image (`/logo.svg` or an https URL) before the name in the admin's header, `pageSize` how many entries a collection's list shows on a page (50), a positive whole number, `collections` how the screens arrange a collection by name, `{ form: { fields, hide }, list: { columns, actions } }` (see [Arranging and replacing the screens](screens.md)), `guard` who may use them and the API, as `{ load }` returning the guard, which runs on the first request so `kay.config.ts` imports nothing of the app's auth or database, or the built guard itself, which does import it, `files` where a folder entry's file goes, `workingTree()` by default, which a production server refuses to boot with unless named, as the next deploy would drop its saves. `uploads` lists the types a file field takes, exact or `image/*`, PNG, JPEG, WebP, GIF, AVIF and PDF by default, the type read off the file name's extension, in any case, as kay's storage serves it; another is answered 415. The bytes must be that type too, whatever the name or the declared type says: PNG, JPEG, GIF, WebP and AVIF are read by their signatures, a PDF by its header, an SVG by its `<svg` root, and a file that is not what it is named (HTML named `x.png`, a JPEG named `x.png`, a PNG cut short of its header) is answered 415 with `cms.upload.notReal`; a type with no signature (`text/csv`, video) is taken as named, and storage serves anything but a PNG, JPEG, WebP, GIF, AVIF, video, audio, PDF or plain-text type as a sandboxed download, an SVG included, so it never runs as the site; the SVG check is only for a `<svg` root in the first 4 KB. `uploads: { types, maxSize }` also sets the most an upload may weigh, bytes or `'50mb'` as kay's `budget` takes them, 20 MB by default; the upload route reads that much whatever the app's `bodyLimit`, so nothing else is raised, and a `maxSize` that is zero, negative, fractional in bytes or over 128 MB less 64 KB throws as `kay.config.ts` loads, as Bun refuses a request body over 128 MB before the route sees it and buffers an upload in memory. A save whose body renders HTML that would run as the site or cover it, every tag and attribute kay's sanitizer drops (a `<script>`, an `<svg>`, a `<form>` or an input, an `on*`, `style` or `formaction` attribute), a `javascript:` URL in any URL attribute, or a tag left open or wrapped around a component, read off the HTML kay renders as a browser tokenizes it, is refused with an issue on the body, unless `rawHtml` lists its collection; the collection's own components, HTML in code and Markdown's task lists pass, and publishing keeps the stored body unchecked. `author` names who a save is committed as, and who the entry screen lists as also open in its entry (kay's `presence()`, the names of the other editors, else how many), from the guard's context, so only with a `guard`; without it the forge commits as the account behind its token and no editor's name or email reaches git, and git history cannot be erased (RGPD art. 17), so prefer a pseudonym such as `{ name: \`Editor ${user.id}\`, email: \`${user.id}@users.noreply.example.com\` }` unless the editors agreed to stay in the history for good; a real identity is written like this: `author: async ({ locals }) => { const user = await locals.auth.user(); return user && { name: user.name, email: user.email } }`.
