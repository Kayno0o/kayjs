# Deprecated lints

## Common tasks

- Move an app off every old form at once: `kay upgrade`, or `kay check --fix --since 1.74` for one minor alone; see [Apply the quick fixes](lints.md#apply-the-quick-fixes).

## Reference

### Deprecated lints

The lints of the `deprecated` group, each the old form a minor replaced, reported for three minors with a safe fix unless its row says otherwise.

| Lint | Default | Group | Reports |
| --- | --- | --- | --- |
| `deprecated-local-state` | warn | deprecated | `pending()` and `status()` of a `local()` collection, since 1.92: `unsynced()` and `syncStatus()`, as every other source reads `pending()` as a boolean and `status()` as `idle|loading|ready|failed`. The old names work until 2.0, which gives them that meaning, so this lint stays past the three minors of the others and a template rendering `{todos.pending()}` would read `true` then. `kay upgrade` renames the method, and a `status()` compared with a string reads `'unsynced'` for `'pending'`, on a name bound once to `local(` from `kay` in the file, its template included; a `status()` read in any other way is reported with no fix. |
| `deprecated-workflow-start-id` | warn | deprecated | `id` in the options of a workflow's `start()`, since 1.98: `key`, as `enqueue()` names it. The old form still works. Found on `name.start(input, { id })` where `name` is bound to a `workflow()` call imported from `kay/server` or `kay`, anywhere in the project. The fix renames the key, and writes `key: id` for a shorthand; an object holding a `key` already is reported with no fix. |
| `deprecated-config-keys` | warn | deprecated | A `kay.config.ts` key under its name before 1.98, which still works: `serve.apiPath` is `serve.apiPrefix`, `subset` and `weight` of a Fontsource font are `subsets` and `weights`, `live.perMinute` and `images.perMinute` are `live.rateLimit` and `images.rateLimit`, and a number `mcp.rateLimit` is `{ max, window }`, as every rate limit option is. Found in the config object of `kay.config.ts`, through a `const` it names. The fix renames the key, writes a lone name or weight in a list, and writes `perMinute: 60` (or `mcp: { rateLimit: 60 }`) as `rateLimit: { max: 60, window: '1m' }`; a value that is not a literal, or an object holding the new key already, is reported with no fix. |
| `deprecated-event-names` | warn | deprecated | An event under its name before 1.99. Every public DOM event is `<lib>:<verb>` on the `document` with an object `detail`: `kay:renew`, `kay:install`, `kay:dev-built`, `kay:dev-types`, `kai:chat-open`, `kai:chat-send` and `kai:chat-draft` (`detail: { text }`), where `kay-renew`, `kay-dev-built`, `kay-dev-types` and the chat's `kai-chat-*` were dashed, on the window, with no detail or a bare string. The old names still fire, on their old target with their old detail, until 1.103. Found in the TypeScript files and `.kay` scripts of the project, on a literal name and the window (or no object); a handler written in a template is not read, nor an event on another element, as `kai-chat-send` on a `.kai-chat` element or `kui-hold-defaults` on a form. The fix moves a listener for `kay-renew` or `kay:install` to the document, and a dispatch of `kai-chat-open`, or of `kai-chat-send` or `kai-chat-draft` with a text `detail` written as `{ detail: text }`; a listener of `kay-dev-built` or `kay-dev-types`, whose `detail` changed, and a dispatch written otherwise are reported with no fix. |
| `deprecated-schedule-tz` | warn | deprecated | `tz` in the options of `schedule()`, since 1.98: `timeZone`, the name of the `timeZone` in `kay.config.ts` it falls back to. The old form still works. Found on a call of `schedule` imported from `kay/server` or `kay`, in the options written in the call. The fix renames the key, and writes `timeZone: tz` for a shorthand; an object holding a `timeZone` already is reported with no fix. |
| `deprecated-analytics-options` | warn | deprecated | An `analytics()` option under its name before 1.98: `host` is `url`, `policyUrl` is `privacy`, and `domain` of Plausible and `hostname` of Simple Analytics are `site`, the other providers keeping their own id word. The old names still work. Found in the options written in a call of `analytics` imported from `kay/analytics`; `domain` and `hostname` need a literal `provider`. The fix renames the key, and writes `url: host` for a shorthand; a key whose new name is written too is reported with no fix. |
| `deprecated-redirect-permanent` | warn | deprecated | `permanent` of a redirect in `kay.config.ts`, since 1.96: `status` is the one spelling for 301, 302, 307, 308 and 410 (a path that is gone, with no `to`), where `permanent` named two of them and could contradict it. The old form still works. Found in the `redirects` object of `kay.config.ts`, through a `const` it names. `kay upgrade` writes `status: 307` for `permanent: false`, and drops `permanent: true`, which is the 308 default, and `permanent` beside a `status` that agrees; any other form is reported with no fix. A static export lists a `status` as written in `_redirects`, where `permanent: false` was listed as 302, so it lists 307 after the fix. |
| `deprecated-ui-hotkey` | warn | deprecated | `hotkey` of a kayjs-ui Toaster or CommandPalette, since 1.97: `shortcut` takes the full chord, as SaveForm's does (`alt+t` for the Toaster, `mod+k` for the CommandPalette by default), and `false` or `null` turns it off on all three. `hotkey` still works. `kay upgrade` writes `shortcut` with the Alt (Toaster) or Ctrl or Cmd (CommandPalette) chord for a literal key, and `shortcut={null}` for `hotkey={null}`; any other value is reported with no fix. |
| `deprecated-ui-props` | warn | deprecated | A kayjs-ui or kayjs-ai prop under its name before 1.98. `heading` on a Dialog, SidePanel or FormDialog is `title`, which takes a string or a `@title` block as a Card's does, and the string that named the dialog for screen readers is `label`. `variant` on a Stat, Chat or ChatLauncher is `layout`, `variant` naming only the frame of a control. The old names work until 2.0. The fix renames the prop or the block, and the `title` string beside a `heading` to `label`; it offers none where the new name is already written. |
| `deprecated-await-consent` | warn | deprecated | `consent` in the options of `analytics()` and `vitals()`, since 1.99: `awaitConsent`, the app's choice to wait for the visitor's yes, where `consent` is the visitor's answer (the signal of `kay/analytics`, the checkbox of a form). The old name works until 1.103, `awaitConsent` winning when both are given. The fix renames the key, and writes `awaitConsent: consent` for a shorthand; it offers none where `awaitConsent` is already written. |
| `deprecated-ai-options` | warn | deprecated | `reasoning` and `confirm` in the options of kayjs-ai's `ask()`, since 1.99: `effort` (how much a model thinks) and `approval` (the visitor's yes to a tool call, as Chat's `approvalLabel` has it). The old names work until 1.103, the new ones winning when both are given. The fix renames the key, and writes `effort: reasoning` for a shorthand; it offers none where the new name is already written. |
| `deprecated-ui-items` | warn | deprecated | An item key of a kayjs-ui list under its name before 1.99, so every item is `{ key, label, description?, href?, icon?, tone?, disabled? }`, with `value` only where it is a form value. A Timeline entry's `text` is `label`; an Accordion item's `value` and `title` are `key` and `label`; a MediaGallery item's `title` is `label`; an AppSwitcher app's `id` is `key`; an AudioPlayer chapter's `title` and `url` are `label` and `href`. The old names work until 1.103, the new ones winning when both are given. Found in a literal array given as `entries`, `items`, `apps` or `chapters`, written there or bound to a `const` of the file's script. The fix renames the key, and writes `label: text` for a shorthand; an item holding the new key already is reported with no fix. |
| `deprecated-filter-options` | warn | deprecated | `hide` in the form layout of a kayjs-cms collection (`cms({ collections: { posts: { form: { hide } } } })`), since 1.99: `exclude`, the word every list of what to leave out takes (`include` for what to keep). The old name works until 1.103, `exclude` winning when both are given. The fix renames the key, and writes `exclude: hide` for a shorthand; it offers none where `exclude` is already written. |
| `deprecated-ai-props` | warn | deprecated | A kayjs-ai Chat or ChatLauncher prop under its name before 1.99. `reasoning` is `showReasoning`, and `thinkingLabel` is `waitingLabel`, what the chat says while it waits for the first words (`reasoningLabel` names the thinking it folds). The old names work until 1.103, the new ones winning when both are given. The fix renames the prop and writes a shorthand out; it offers none where the new name is already written. |
