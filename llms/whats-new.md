# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- `a(href="/docs" section)` is marked `aria-current="true"` on the pages below `/docs`, and `page` on it, so a header lights a section with no path passed down; the attribute is never written out and `section-not-a-link` flags it on anything but a link ([Navigation](navigation.md)).
- kayjs-mail's `contactForm` takes `honeypot: 'nectar'` to rename its honeypot field, which frees `website` as a field of yours, and `consent: true` for a required consent checkbox, refused when unticked in the page's language and left out of the mail; kayjs-ui's `ContactForm` draws it from the action and links `privacy="/privacy"` ([A contact form](../packages/mail/llms/contact-form-and-testing.md)).
- A post in place keeps the focus inside a held deferred server island, which goes to the same field (by `id`, else `name`) once the island's fetch lands, and an island of its own still waiting to hydrate no longer logs a missing client chunk ([Prerendering](prerendering.md#prerendering)).
- `page.click` in kay/test reaches an element covered at the middle of the view, such as one under a fixed bar or the dev tool's open panel: it scrolls it to the other alignments and aims at a point of its box nothing covers, and one covered everywhere fails naming what covers it ([Testing in a browser](testing-browser.md)).
- `persisted('theme', 'light', { values: ['light', 'dark'] })` reads a cookie or localStorage value outside `values` as the default, on the server and in the browser, so an app no longer re-checks the signal behind a helper ([Shared and persisted state](islands.md#shared-and-persisted-state)).
- A loaded collection's `save({ data })` is typed from the collection's `schema` (defaults filled in, dates as text) instead of `unknown`, so a loader no longer casts it in every `save` ([Loaded collections](content-cms.md#loaded-collections)).
- An action's `messages.serverError` may be a function, sync or async, given the error and the action's `ctx`, so the failure text can read a collection entry, a setting or `ctx.locale` without a `try`/`catch` in the handler; one that throws leaves kay's message, both errors logged ([Refused posts](actions.md#refused-posts)).
- A schema says how kayjs-cms enters a field: `fieldInput(schema, { placeholder, prefix, suffix, rows, type, labels, lines, titleField, when })` from `kay/content`, and a collection takes a `description`; the schema's own `format`, `maxLength`, `minimum`, `maximum` and `integer` already shape the input, and a toggle keeps its hint and issue ([Field kinds and entering a field](../packages/cms/llms/fields.md)).
- `kay migrate content` rewrites the entry files of the folder collections that declare `migrations`, keeping each file's format and body; a refused folder entry with no `migrations` points at them, and `unique()` reads a field of an `Intersect` ([Loaded collections](content-cms.md#loaded-collections)).
- `kay build` and `kay check` word a refused entry field in the site's default locale from its catalogs (`kay.entry.*`), the English where it gives none, instead of always in English ([Locales](locales.md#texts-from-kay-and-its-libraries)).
- A stored image shows its mean colour until it loads, as an imported one does: `files.put` reads it once on upload and keeps it in the key (`photos/<id>.1600x1200-c86432.jpg`), so no store changes and no request reads it; keys stored before have none, and a key with a colour is 7 characters longer ([Stored files](files.md)).
- `kay build`'s page footprint counts the `html`, `head`, `body` and `tbody` elements a browser makes up, so a page's DOM count and EcoIndex score can move a little (a `budget.grade` near a boundary may change); `(600px <= width)` media ranges are read ([Lints](lints.md)).
- A `Save-Data` page keeps the chunk preloads of its `hydrate="load"` and `hydrate="client"` islands, which hydrate at once, and injects no preload of the code waiting for the viewport when none of its islands wait ([Islands](islands.md)).
- A collection declared `single: true` is one entry: kayjs-cms's content list links to its form, titled with the collection's `title`, with no list row, slug, New entry or Delete; `seed` fills the form until the first save, and `home.one()` reads the entry typed, with a fallback ([A collection of one entry](content.md), [kayjs-cms](../packages/cms/llms.txt)).
- A GIF that Bun.Image cannot decode but a browser draws, such as some 1x1 uploads, is answered as it is by `/_kay/image` instead of a `415`, so its preview no longer breaks; an imported one gets no variants instead of failing the build ([Responsive images](images.md#responsive-images)).
- kayjs-cms file and image fields are easier to use: a Clear button, a slim drop zone saying what it takes, a progress bar with Cancel, failures told under the field, Save held while an upload runs, a picker of stored uploads and a preview saying when it cannot load; `imageField({ accept, maxSize, minWidth, minHeight, alt, width, height })` and `fileField({ accept, maxSize })` set the limits per field and pair an image with its alt text and size ([Uploads and image fields](../packages/cms/llms/uploads.md)).
- kayjs-cms gives an "Edit this page" link to any signed-in editor on every page they read, with no app code and no page losing its static copy: a readable `kay_editor` cookie marks the browser and the guard is asked on each page; `cms({ pageLink: false })` leaves it out and an `a(data-cms-edit-page)` of the app's own takes its place ([Edit this page link](../packages/cms/llms/page-links.md)).
- An entry of a collection a page lists in its `sitemap`, or that a page without params reads by its slug (a section on `/`), now has its page, so the cms shows Edit on page for it; an entry no page shows has none ([content CMS](content-cms.md)).
- kayjs-cms's form helps fix a refused save: focus goes to the first refused field, a summary of links lists them, an edit clears only its own issue, schema limits are checked as typed, unparsed JSON blocks Save, a taken slug marks its field ([Fixing a refused save](../packages/cms/llms/screens.md#fixing-a-refused-save)).
- kayjs-cms's admin sets `layouts: false` on its layout, which a library layout can do to start its own chain: it draws its own chrome (skip link, nav with Missing pages and Uploads, a link back to the site, `Content admin` in every title, `noindex`, kayjs-ui's theme in light or dark) instead of rendering inside the site's header and footer ([Libraries](component-libraries.md), [kayjs-cms](../packages/cms/llms/screens.md)).
- A page swap keeps a fetched deferred server island on screen while its next copy is fetched, so a post back to the same page no longer swaps the form for its inert copy and back, which jumped the scroll ([Prerendering](prerendering.md#prerendering)).
- kayjs-cms ships the French of every `cms.*` text, read on a French page after the app's own catalog with no setup; another language is a `cms` block in the app's `src/messages/<locale>.ts`, and `tests/words.test.ts` fails for a new key without its French ([Texts and languages](../packages/cms/llms/words.md)).
- `ctx.redirect()` to a page puts on its `trailingSlash` spelling and, on a site with `i18n`, the page's locale, as `llms/routing.md` said it did (`/login` from an English page now goes to `/en/login`), so a post, a page swap or an island call lands on the page in one response ([Pages and routing](routing.md)).
- A content entry the schema refuses reads as a sentence naming the field by its label (`Date de parution is not a valid date-time`) instead of the validator's `Property 'x' should be uri`, in the CMS editor, `kay build` and `kay check`, each keyword worded under `kay.entry.*` in the site's locale; a nested field is reported on its own (`networks.youtube`) rather than its top-level field ([Locales](locales.md#texts-from-kay-and-its-libraries)).
- kayjs-cms list fields are easier to scan and fill: a list of strings shows one label and compact rows, items of a group fold under their own title, the count and `minItems`/`maxItems` show and hold, an item can be duplicated, a new item starts from its schema's `default` (a select stays unpicked), a removal can be undone with focus kept, rows wrap at 375px, and reordering by keyboard is Alt+Shift with an arrow, no longer Alt alone ([kayjs-cms](../packages/cms/llms.txt)).
- The kayjs-cms on-page editor keeps previewing when one entry fails its schema: `showDraft` renders the page again without it, that entry showing its saved text, and resolves where it fails; the editor says `Updating the page…` while it renders, names the entries whose edits the page does not show, shows unsaved edits again after in-app navigation, and keeps saying for five minutes that a forge save is still rebuilding ([content CMS](content-cms.md#edit-mode), [kayjs-cms](../packages/cms/llms.txt)).
- A stored entry the schema refuses (a database row from before a schema change) is left out of its loaded collection and logged instead of failing every page that reads it, and the CMS still lists and opens it; the error names the whole path of a nested problem and no longer repeats a type, and defaults fill nested objects and list items ([Loaded collections](content-cms.md#loaded-collections)).
- `migrations` on a collection carries stored entries over after a schema change, with `renameField`, `setField` and `convertField` for the common steps, a loader's migrated entry written back through its `save` once; `unique()` refuses a save repeating another entry's value ([Loaded collections](content-cms.md#loaded-collections)).

## 1.61.0

- Edit mode in kayjs-cms pairs fields of the same text with the field rendered, not one read only in a condition, and a literal text between two numbers of a child keeps the second's mark: [Edit mode](content-cms.md#edit-mode).
- The kayjs-cms on-page editor keeps clear of the dev tool's bar, which publishes the room it takes as `--kay-dev-bar-top` and `-bottom`, starts under a header fixed across the top of the page so it stays visible, scrolls a clicked element clear of such a header, and a collapsed editor no longer flashes open while the page loads ([content CMS](content-cms.md)).
- The kayjs-cms on-page editor and the dev tool's bar and floating drawer keep out of one another: the open editor publishes `--kay-panel-right` and `-bottom` for the dev tool to sit outside it, and the bar publishes its room as `--kay-dev-bar-top` and `-bottom`. The editor also starts under a header fixed across the top of the page so it stays visible, scrolls a clicked element clear of such a header, and a collapsed editor no longer flashes open while the page loads ([content CMS](content-cms.md)).
- `kay dev` follows a `.env` edit for a value that expands another (`A=$HOME/x`, `B=${A}`), which kept its first value, and the process loading `kay.config.ts` for the editor types reads the new `.env` values as the server does ([Dev server](dev-server.md)).
- A post behind a proxy that ends TLS swaps its page in place: the redirect back is a path, so the browser no longer reads `http:` against its own `https:` and loads the page in full ([Actions](actions.md#forms)).
- Edit mode in kayjs-cms marks every field a page renders from an entry, also one a component reads from data its page handed down (`Crew({...data})`), and each part of a mixed child like `{age} ans`: [Edit mode](content-cms.md#edit-mode).
- The on-page editor lists the entries a page read in the order the page shows their first marked field, so the forms follow the page and no longer swap places after a draft render ([content CMS](content-cms.md)).
- A page holding a server island, with no `prerender` of its own, whose layout reads `ctx.locals`, `ctx.cookies` or `ctx.query` is rendered per request instead of failing `kay build`, and a `prerender: true` page or a static export that meets such a read fails naming the file and line of it ([Prerendering](prerendering.md#prerendering)).
- kayjs-cms save and publish no longer surprise the editor: Ctrl or Cmd+S saves, Save is disabled with nothing to save (and shown in the editor on the page), the fields are locked while saving, a line keeps `Saving…`, `Unsaved changes` or `Saved at` on screen (with `Not live yet` and a link after a commit), Unpublish, Publish now and Clear schedule exist, Publish refuses over unsaved edits and never leaves the form showing published after a refused save, and Delete names the entry; `cms.entry.deleteMessage` takes `{title}` and `cms.entry.deletePage` is new ([kayjs-cms](../packages/cms/llms/screens.md)).
- The kayjs-cms on-page editor no longer covers the page or the dev tool: it docks to the right from 64rem and to the bottom below it, the page keeps its width and a fixed header stays in view, it sits beside a docked dev tool, can be resized by drag or arrow keys, docked to either edge, and hidden, remembering all three, and it scrolls a clicked element above the bottom sheet ([kayjs-cms](../packages/cms/llms.txt)).
- `ask(messages, { schema })` in kayjs-ai answers an object instead of text: `await` is the value an `s.Object` describes, typed and checked with no cast, `for await` and a streaming action give the object so far with strings growing, and an answer the schema refuses fails with an `AiError` of kind `schema` naming the fields. Anthropic is asked through `output_config.format`, OpenAI-compatible servers (Ollama included) through `response_format` or a forced tool call, and `fakeAi.reply({ data })` scripts the object ([kayjs-ai](../packages/ai/llms/asking.md#an-object-instead-of-text)).
- `reply.deltas({ onRestart })` of a kayjs-ai `ask` with a `schema` tells a reader when a tool step drops the text it wrote, so what it kept can be cleared ([kayjs-ai](../packages/ai/llms/asking.md#an-object-instead-of-text)).
- A visitor asking for less data (`Save-Data: on`, `prefers-reduced-data`) gets a lighter site by itself: the next image width down, no font preloads, speculation rules or prefetch, fonts only when cached; `saveData: false` turns it off ([Navigation](navigation.md#full-loads-and-prefetching)).
- kayjs-mail's outbox is kept in `.kay` under `kay dev`, the last 500, so the Mail tab keeps its mails through a page refresh and a server restart, and the tab has a Clear button; it stays in memory under `bun test` ([kayjs-mail](../packages/mail/llms/contact-form-and-testing.md#development)).
- A visitor asking for less data also gets islands that wait: one with no `hydrate` hydrates once it scrolls near, a deferred server island is fetched only then, and the page preloads no island chunk; `hydrate="load"` opts an island out ([Islands](islands.md#hydration)).
- kayjs-mail's Mail tab has a Send for real switch that delivers every mail sent under `kay dev` to one typed address over the environment's SMTP, never to its own recipients, kept in `.kay` across restarts and shown on the tab's badge, and lists the app's mail templates, each opening its preview ([kayjs-mail](../packages/mail/llms/contact-form-and-testing.md#development)).
- The dev tool's Routes tab lists kay's own endpoints the app serves (`/_kay/live`, the actions, `/_kay/image`, `/_kay/files/`, `/_kay/csp`, the analytics and search routes and the rest), each with its purpose and a docs link, filterable with the rest ([The dev tool](dev-tool.md)).
- `kay build` prints what each route's page weighs whole, in requests, DOM elements, EcoIndex grade and grams of CO2e per view, `budget` takes `weight` and `grade`, and the dev tool's Performance tab shows the same for the open page ([Build](build-and-start.md#build-and-start-commands), [Eco-design](eco-design.md#fail-the-build-when-a-page-gets-heavy)).
- `kay dev` leaves the browser build of the last run as it is when nothing it read has changed, so a second start builds nothing, an edit to the scripts or version of `package.json` restarts nothing, a `kay.config.ts` edit starts the new server at once, the server imports its extension servers and lists its API modules while the browser build runs, and the icons it draws from the favicon are kept across reloads and restarts ([The dev server](dev-server.md), [Favicon](sitemap-search-fonts.md#favicon-and-web-manifest)).
- An image shows its average color until it loads, as a `style` attribute of about 35 bytes with no script and no setting: an imported image, `image()`, a Markdown body's relative image, and an image of `images.dirs` or `images.remote` once the route has read it; one with transparency, an SVG and an animated GIF get none, and `no-placeholder` on an `img`, `image(src, { placeholder: false })` or `images: { placeholder: false }` turns it off ([Responsive images](images.md#responsive-images)).
- `kay build` reads a site's prerendered pages against one another: `long-title`, `duplicate-description`, `orphan-page`, `broken-canonical`, `one-way-hreflang` and `redirect-chain` join the `seo` lints, each set with `lints` and named with a fix, and `kay check` reads `redirect-chain` over `redirects` and measures `long-title` in `seo.titleTemplate` ([Lints](lints.md#seo-lints)).
- The dev tool has a Screen reader tab: the page's landmarks, headings, links, controls and form fields in reading order with the names a screen reader speaks, flagging a skipped heading level, a page without exactly one `main`, a missing name and links of one name going to different places, an element outlined and its `.kay` file named on hover ([The dev tool](dev-tool.md)).
- A collection's `publishAt: 'publishAt'` names an `s.Date()` field and holds an entry back until that time, as `draft` does, then shows it by itself in `all()`, `get()`, the sitemap and the feed and rebuilds the prerendered pages that read it, with no cron, job or webhook; kayjs-cms shows the date in the entry form and marks a scheduled entry in the list, a date and time field shown and typed in the editor's own time zone and stored as an instant, and a scheduled badge, in the entry screen and in the list, that names the editor's zone and goes when the date passes ([Drafts](content.md#drafts), [kayjs-cms](../packages/cms/llms.txt)).
- `vitals()` from `kay/analytics` reports the LCP, CLS and INP of real visits from the app's own origin, in a deferred script of about 700 bytes gzip that sends one beacon per page view when the tab is hidden, keeps a 75th percentile per route over seven days in `store.vitals` (which `sqliteData(path)` holds, so replicas add up), and shows them rated against their good limits on a screen behind a guard; it follows `analytics({ consent })` and keeps no identifier ([Privacy](privacy.md#measure-how-fast-pages-load-for-real-visitors)).
- The dev tool draws the page's tab order: a drawer head button numbers each element Tab reaches with lines between them, and flags a jump up the page, an element whose focus shows nothing and a possible focus trap as accessibility problems ([The dev tool](dev-tool.md)).
- `presence(room, member)` from `kay` in an island lists who else has a room open with no route, socket or store line, `presence()` the tabs on the page: `others()` and `count()` follow joins and leaves on the page's live connection, the room and member covered by the page's signed proof, and `sqliteData(path)` now holds `rooms`, so replicas sharing it share presence ([Presence](api-from-islands.md#presence)).
- kayjs-cms's entry screen lists who else has the entry open, by the names `cms({ author })` gives, else how many ([kayjs-cms](../packages/cms/llms/screens.md)).
- A `kay/test` page intercepts requests with `route(match, handler)` (fulfil, abort, continue, or `fetch()` the server's answer and pass it on changed), goes `offline()` and back `online()`, runs `initScript(fn)` before each document's scripts, lists the `responses` it received with their status and the request and response headers as sent, `waitForResponse(match)`, `hover(selector)` and `click(selector, { modifiers })`; a click scrolls its element into place again while it waits ([Testing in a browser](testing-browser.md)).
- A `snippet feature(title: string, text: string)` line and the lines under it name a block for the file that declares it: `{feature('Fast', 'Built on Bun')}` renders it as many times as needed, it reads the signals and loop variables around it, calls itself for a tree, and `List(row={feature})` passes it to a component as a function prop, with no component file and no new helper in an island's JavaScript ([Templates](templates.md#snippets)).
- A `kay/test` page opens with `javaScript: false` to see what the server rendered and `reducedMotion: 'reduce'`, answers dialogs with `onDialog(handler)`, puts files in an input with `upload(selector, files)`, lists its console `warnings`, and a route sees what the browser kept in its cache ([Testing in a browser](testing-browser.md)).
- A `kay.config.ts` reading a file beside it as it loads, `readdirSync(join(import.meta.dir, '../llms'))`, no longer fails with ENOENT on `/$bunfs` when a `--compile` executable boots: the config's `import.meta.dir` names the project's folder as the build saw it ([Build and start](build-and-start.md#build-one-executable)).
- A French page rendered per request costs less CPU: a not-found page whose markup repeats is spaced once instead of read tag by tag each time, tags are read faster, and a page in pieces is no longer counted byte by byte to judge its size, which takes back most of what the 404 page of a French app cost more since 1.56 ([French typography](locales.md#french-typography)).
- A stacked star variant, `*:*:p-2`, and one followed by brackets, `*:[&.x]:p-2`, are left out of a page's head when it does not use them, as the other star variants are ([Styles and assets](styles-and-assets.md#link-or-inline-the-stylesheets)).
- A button takes `commandfor` and `command` in a template, typed by `kay check` (`show-modal`, `close`, `request-close`, `show-popover`, `hide-popover`, `toggle-popover` or a `--custom` name), so a popover or a dialog opens with no handler and the component stays static ([Islands](islands.md#islands)).
- kayjs-ui's `SiteNav` and `AppHeader` ship no JavaScript: the menu is a popover its toggle opens, the browser closing it on Escape or a press outside and giving the focus back, and a page with no other island loads no script for it ([kayjs-ui](../packages/ui/llms/tables-navigation-and-layout.md)); see [Upgrading](upgrading.md).
- `kay check` type-checks with Bun's own `bun check` instead of tsgo: a cold check of the docs site takes 1.3 s and 4.4 s of CPU instead of 2.0 s and 7.2 s, at 310 MB instead of 760 MB, with the same diagnostics at the same `.kay` lines; a warm check of a project nothing changed in still skips the type check ([Checks](checks.md)).
- A keyed row that moves, and an island kept by `persist` across a page swap, keep their loaded iframe, playing video and focus in a browser with `Element.moveBefore` (Chrome 133, Firefox 144). An island kept across a page swap keeps the scroll of its scrolled panels in every browser ([Templates](templates.md), [Navigation](navigation.md)).
- A server build sends each page after the first as its difference from the build's 404 page to a browser holding it (Compression Dictionary Transport, `Content-Encoding: dcz`): no setup, off in development and in a static export, and a browser without the feature gets what it did before; on kay's docs a 41 KB page goes in 4.4 KB instead of 9.2 KB with brotli ([Production](proxy-and-security.md#compression)).
- `kay check` no longer asks an app's locale for the `ui.*` or `mail.*` keys of kayjs-ui or kayjs-mail when the library ships no catalog for it, `de` for one: the locale reads the default locale's texts ([Locales](locales.md)).
- kayjs-cms keeps the on-page editor's unsaved edits in the browser and brings them back after a reload, a crash or in a second tab (a draft older than the saved entry is left out with a note), asks before a reload, a link or Stop editing drops them, and a save conflict names the fields both sides changed and offers Take their version beside Keep my edits ([kayjs-cms](../packages/cms/llms.txt))
- kayjs-cms lists who edits an entry on the entry list (`Being edited`) and above the on-page editor's form, a returning entry shows its current copy and version unless it holds edits, and a loaded entry's version leaves out the fields its schema does not declare, so a loader adding or changing computed fields no longer causes false conflicts ([kayjs-cms](../packages/cms/llms/screens.md))
