# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## 1.66.0

- `previewUrl(path, { entry })` from `kay/server` gives a signed link showing one entry's draft on its page alone, with no cookie nor preview mode for the visitor ([Preview mode](content-cms.md)); kayjs-cms's entry screen has a Share preview button for it ([screens](../packages/cms/llms/screens.md)).
- kayjs-cms has an activity log at `<prefix>/activity`: who created, saved, published, deleted, restored or renamed which entry and when, across the collections that keep a history ([The activity log](../packages/cms/llms/history.md)).
- kayjs-cms: `cms({ collections: { notes: { history: false } } })` keeps no revisions nor trash for one collection ([History and the trash](../packages/cms/llms/history.md)).
- kayjs-cms's entry editor has a Rename button for a slug: a folder file is moved (one commit on Forgejo), a loaded entry keeps its history, the entries referring to it follow the new slug, and the old page redirects to the new one by itself ([renaming](../packages/cms/llms/rename.md)).
- kayjs-cms's editor outlines the field under the pointer and, with a toggle (on by default on a phone), every marked field, attributes and comment pairs included; it asks which field when an element holds several, names each tab stop, and has a Browse toggle that lets links and menus work with the editor open ([Screens](../packages/cms/llms/screens.md)).
- kayjs-cms moves the uploads an older release kept per collection into its shared `cms-media` folder when the server starts, pointing the entries at the copies, and its media library pages 48 uploads at a time with a search ([kayjs-cms](../packages/cms/llms/uploads.md)).
- kayjs-cms's editor adds, removes and reorders a list's items, blocks included, on the page: a toolbar on the item under the pointer or the focus, an Add on an empty list, Alt+Shift with the arrows, Delete or Enter on the keyboard, and Undo for a removal ([Screens](../packages/cms/llms/screens.md)).

## 1.65.0

- kayjs-cms keeps the last 50 saves of every entry of a SQLite or Postgres collection and its deleted entries for 30 days, by default, to list, compare and restore from an entry's History button and the list's Trash; `cms({ history: false })` turns it off ([History and the trash](../packages/cms/llms/history.md)).
- kayjs-ui's TabNav keeps the window scrolled where it was when a tab is followed, so a bar needs no `data-keep-scroll` ([TabNav](../packages/ui/llms/tables-navigation-and-layout.md)).
- kayjs-cms keeps every upload in one folder, named by the hash of its file so a file sent twice is stored once, and has a media library at `<prefix>/media` listing them with a preview, size and the entries using each, to rename or delete; `files.put(file, { id })` names a key ([kayjs-cms](../packages/cms/llms/uploads.md), [Files](files.md)).
- `blocks({ hero: s.Object({ ... }), text: s.Object({ ... }) })` from `kay/content` declares a list of items of several types, stored with a `type` key and read as a union discriminated on it, and kayjs-cms adds, reorders and removes them by type and marks their fields in edit mode ([kayjs-cms](../packages/cms/llms/fields.md#blocks)).
- `kay i18n translate` translates the texts inside `blocks()` lists, each item by its type ([kayjs-ai](../packages/ai/llms/translating.md)).
- kayjs-ui's MarkdownEditor loads its toolbar apart, so `toolbar={false}` ships none of it, and the toolbar is one Tab stop; kayjs-cms's Preview highlights code with `markdown.highlight`, shows an entry's relative images and takes `form.previewClass` such as `prose` ([MarkdownEditor](../packages/ui/llms/forms.md#markdowneditor), [Arranging and replacing the screens](../packages/cms/llms/screens.md#arrange-a-collection)).
- kayjs-cms edit mode types a one-line text in place on the page, as plain text, with the form following each keystroke ([kayjs-cms](../packages/cms/llms/screens.md)).

## 1.64.0

- kayjs-cms's entries list shows Last modified and Author columns that sort, the content list shows a collection's last edit and its `icon`, and a new entry has Cancel and Create and add another ([kayjs-cms](../packages/cms/llms/screens.md)).
- `site.runJobs()` waits for a `queue.enqueue()` or a kayjs-mail `send`/`enqueue` an action left unawaited, with nothing declared ([Testing](testing.md)).
- A text field replaced by a query `navigate()`, such as a live search box whose island gets the new value, keeps its caret, selection and the keys typed while the page was fetched instead of restarting at 0 ([Navigation](navigation.md)).
- kayjs-ui's MarkdownEditor has a toolbar (bold, italic, heading, lists, link, image; `toolbar` turns it down) and, given a `preview` function, a Preview button showing the server-rendered text beside the field or in its place on a narrow one ([MarkdownEditor](../packages/ui/llms/forms.md#markdowneditor)).
- kayjs-cms's Markdown boxes carry kayjs-ui's toolbar and a Preview rendered by the site's own Markdown pipeline, and `cms({ collections: { posts: { form: { body: { label, hint }, toolbar } } } })` words the body and cuts the toolbar down per collection ([Arranging and replacing the screens](../packages/cms/llms/screens.md#arrange-a-collection)).

## 1.63.0

- A schedule's `boot: true` runs again on a restart minutes after the previous boot, replicas starting within the same minute still running it once ([Production](production.md)).
- kayjs-auth's `auth.signInAs(site, { email, username })` signs a test site in as a member, making them (with the app's user `data`) when none exists and refusing one whose fields differ, with no form round trip, and `auth.signOut(site)` signs it out; a second call switches member ([Hardening and testing](../packages/auth/llms/hardening-and-testing.md)).
- A test waits for a queued mail with one call, `outbox.waitFor(address, { site, find })`, which runs the site's queues until it is delivered and fails naming the mails the outbox holds, and reads a link's token with `outbox.token(mail, path)` or the link itself with `outbox.link(mail, path)`, no polling and no regex ([kayjs-mail](../packages/mail/llms/contact-form-and-testing.md#testing), [Testing](testing.md)).
- A test database for each test file needs no declaration: `kay/test/preload` copies the database a `pg-orm.config.ts` describes, seeded by the default export of `tests/seed.ts` when there is one, so an app deletes its `tests/database.ts` and its `bunfig.toml` line; and `sqliteStore` keeps its sessions in memory under `bun test`, so the `NODE_ENV === 'test'` switch in `src/session.ts` goes ([Test databases and setup](testing-setup.md#databases-and-setup)).
- A test site made with `testSite()` is closed once the tests ran, its pages, sockets, streams and server with it, so a test file no longer ends with `afterAll(async () => site.close())` ([Testing](testing.md#requests-jobs-sockets-and-sessions)).
- An entry whose `unpublishAt` passed answers 410 Gone from a page that calls `ctx.notFound()`, a redirect from its path winning, which an editor can add from the missing pages screen, also for a 410 your own code answers ([Drafts](content.md#drafts)).
- Site search finds the singular of a plural query (`links` finds a heading about a link), and a palette no longer keeps the hits of the last query when the next search fails ([Search](sitemap-search-fonts.md#site-search)).
- Site search finds the singular of a plural query (`links` finds a heading about a link, `entries` one about an entry), ranks an option named in a reference table's first column above the text mentioning it, and a palette lists an entry matching by characters in order after the site's hits, and no longer keeps the hits of the last query when the next search fails ([Search](sitemap-search-fonts.md#site-search)).
- kayjs-cms's database loaders follow a save made by another process and an edit made outside the CMS (`watch`), `cms({ onSave })` runs after each save, and the sitemap is built afresh after any invalidation instead of up to an hour later ([loaders](../packages/cms/llms/loaders.md#other-processes-and-edits-made-outside-the-cms)).
- kayjs-cms's database loaders follow a save made by another process and an edit made outside the CMS (`watch`), `cms({ onSave })` runs after each save, and the sitemap is built afresh after a change to what it read instead of up to an hour later, served with an `ETag` and `must-revalidate` so a CDN never holds it past a save ([loaders](../packages/cms/llms/loaders.md#other-processes-and-edits-made-outside-the-cms)).
- kayjs-cms sends a visitor without access to a sign-in screen and back to the same page, ships `passwordGuard` for simple sites, shows who is signed in with Sign out, limits roles with `cms({ roles })` to publish, delete, upload and redirects (disabling those buttons for a role that may not, and `cms({ member })` giving a custom guard its roles), ends a signed-out cookie's copies, and tells an editor whose session ended mid-edit ([Options](../packages/cms/llms/options.md#signing-in-and-roles)).
- kayjs-auth brings a visitor back to the page they asked for after registering with a mailed verification, resetting a password, a failed OAuth sign-in, a second factor and from a localized page, and `auth.guard()` and `requireUser()` redirect to `signInPage` without `pages` ([Setup](../packages/auth/llms/setup.md)).
- A link leaving the site opens in a new tab by itself, in templates, islands, Markdown, `markdownHtml` and entries' bodies, unless it writes its own `target`; `links: { outside: 'same-tab' }` turns it off ([Navigation](navigation.md#navigation)).
- kayjs-cms asks which entries refer to the one being deleted when the delete confirmation opens, from a small API route, and kayjs-ui's `ConfirmDelete` takes an `onOpen` ([Screens](../packages/cms/llms/screens.md)).
- kayjs-cms ships `sqliteLoader` and `postgresLoader`, a seeded table of JSON entries editors can save to on a live site, with a loader's new `saveMany` making a reorder all-or-nothing ([loaders](../packages/cms/llms/loaders.md)).
- kayjs-cms's list sorts, searches (accents ignored) and filters by status across every page from the URL, ticks rows for bulk publish, unpublish and delete, duplicates an entry, and the content list groups, orders and counts drafts; a `reference()` field is a picker and a save refuses a dangling one ([Screens](../packages/cms/llms/screens.md#the-list)).
- kayjs-cms lists get Add at the top, a jump menu from eight items and an issue count on a folded item, and Reset asks before dropping edits ([fields](../packages/cms/llms/fields.md)).
- kayjs-cms pairs a text field called `alt` with the image beside it with no hint, and asks before the page is left over a running upload ([uploads](../packages/cms/llms/uploads.md)).
- The CMS tab of the dev tool speaks the page's language, from new `cms.dev.*` words (French shipped; see [the words](../packages/cms/llms/words.md)).
- kayjs-cms shows the missing translations of a localized collection: the locales an entry lacks in the list, a locale switcher with a draft copy to translate over and a compare view on the entry, untranslated texts said under their field, and a Translations screen at `<prefix>/translations` (see [kayjs-cms](../packages/cms/llms.txt)).
- `translations(name)` from `kay/content` gives a localized collection's translation index without reading every entry, which the CMS list and entry screens use ([content for a CMS](content-cms.md)).
- kayjs-cms has ready-made field kinds `colorField()`, `moneyField({ currency })`, `tagsField()`, `linkField()`, `geoField()` and `iconField(set)`, a search box on a long select and Today, Now and Clear on date fields, and a form layout names a field of a group by its dotted path, `address.street` ([Ready-made kinds](../packages/cms/llms/fields.md#ready-made-kinds)).
- The dev tool's bar publishes its measured room as `--kay-dev-bar-bottom-left` or `-right` for a bottom corner (see [the dev tool](dev-tool.md)), and kayjs-cms's collapsed editor button is a panel the bar keeps off.
- A page showing one content entry (`prerender` or `sitemap` of a collection on a one-param route) takes the entry's `title`, `description` and date for its head, with `og:type` `article`; its own `head` tags win ([A page per entry](head.md#site-defaults-and-social-cards)).
- `testSite()` keeps a test's content saves out of the project's `src/content` (a folder collection is copied under `.kay/scratch` when a save reaches it), and `site.content.reset()`, `seed()` and `write()` start a test from fixtures, loaded collections included ([Reset or seed content](testing.md#reset-or-seed-content)).
- A collection's `unpublishAt: 'endsAt'` takes an entry down at a set time, beside `publishAt`: it leaves `all()`, `get()`, the sitemap and the feed, the pages that read it render again and the URL answers what the page's code chose; kayjs-cms shows `Ends` or `Ended` on the entry screen and clears the date ([Drafts](content.md#drafts)).
- `section={isDocs}` on a link takes a boolean expression in place of a bare `section`, read on the server and never written out ([Navigation](navigation.md)).
- The kayjs-cms on-page editor names, above an entry's form, the fields the page cannot let it click (a transformed value, an island's props, a frozen object), from the new `unclickable` of `EditorProps` ([Edit mode](content-edit.md#the-editor)).
- kayjs-cms's admin takes `cms({ logo })`, shows crumbs on entry screens and keeps its chrome and guard at `prefix: '/'` under an app root layout; a new folder entry's slug is written from its title, cleaned as typed and checked against the collection, and its missing pages screen dismisses and clears paths, names the linking pages, edits and bulk-removes redirects, answers 410 and lists the config's ([Screens](../packages/cms/llms/screens.md)).
- kayjs-cms's list has an `unpublish` row action, a save shown only after a rebuild turns to `Live now` once the public page serves it, and a delete confirmation lists the entries that reference the one deleted ([Screens](../packages/cms/llms/screens.md)).
- kayjs-cms's list Status column shows `Ends` and `Ended` for an `unpublishAt` date, also for a collection with that date alone ([Screens](../packages/cms/llms/screens.md)).

Releases before 1.63 are in [What's new, older releases](whats-new-archive.md).
