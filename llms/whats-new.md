# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## 1.87.0

- The config's keys are grouped by concern: `dirs` (`routes`, `api`, `public`), `limits` (`body`, `byPath`), `serve` (`apiPath`, `compress`, `compressionDictionary`, `shutdownTimeout`), `observe` (`log`, `serverTiming`, `requestIdHeader`, `tracer`, `onError`) and `client` (`navigation`, `inlineStyles`, `lateStyles`, `typography`, `hydration`, `prefetch`, `saveData`), so a key is found by what it does; the flat keys work until 1.91 and `kay upgrade` moves them (`deprecated-config-groups`): [the config](project.md), [upgrading](upgrading.md#the-config-keys-are-grouped-by-concern).
- A production site with `site` set answers 421 to a `Host` that is not its own by default, so `ctx.url.origin` cannot be poisoned; `security: { hosts: false }` opts out and `hosts: ['www.example.com']` adds names: [proxy and security](proxy-and-security.md).
- Every store has the same two optional methods, `StoreBase`'s `ping()` and `close()`: `health` pings each store and answers 503 when one rejects, a stop closes each once, and `pgData(db)` has both. Files are a store too, `store: { files }` (the `fileStore` key is `deprecated-file-store`, `kay upgrade` moves it) and `AppStore` carries them when the app writes it: [Stores](stores.md).
- `navigate(path)` puts the current locale's prefix on a path as a link's `href` does, so `navigate('/second')` on `/fr/...` goes to `/fr/second`: [navigating from code](navigation-from-code.md).
- kayjs-ui overlays are one family: Dialog gains a close button in its head line (`closeLabel`, `@actions`, `@header`, `@close`), `closeHref` (open by URL, server-rendered) and `modal={false}`, SidePanel gains `dirty`, `level`, `@header`, `@close` and the `size` names, CommandPalette and FormDialog take the same `size`: [Dialog](../packages/ui/llms/basics.md#dialog-confirmdelete).
- kayjs-ui callbacks follow one rule: state a prop can hold reports through `on<Prop>Change` (`onSelectedChange` on Table, TreeView and Timeline, beside `selected`), a press of an item is `onSelect`; `kay check` flags the old Table, TreeView and Timeline `onSelect` with the safe-fixable `deprecated-ui-callbacks` lint: [deprecated lints](deprecated-lints.md).
- `kay` classifies each of its values as browser or shared in one table, so a component using only `ActionError`, `ActionRedirectError`, `ApiError`, `apiUrl`, `publicEnv` or `defineUi` is static, with the other values that compute the same on both sides: [islands](islands.md#islands).
- `resource`, `stream`, `socket`, `track()` and `call.track` share `status()`, `pending()`, `error()` (an `ApiError`) and `retry()`, so one block shows any of them; a socket the server closes with a code from 4000 to 4999 fails with that status minus 4000 instead of reconnecting forever. `LoadStatus`, `ConnectionStatus` and `Source` type them, see [API from islands](api-from-islands.md).
- kayjs-mail needs no `src/mail.ts`: `mail({ from, locale, ...mailer options })` in `kay.config.ts` builds the mailer, `send` and `enqueue` from `@kaynooo/kayjs-mail` use it, `kayjs-auth` sends through it, and `kay add mail` writes that one line: [setup](../packages/mail/llms/writing-and-sending.md#setup).

- kayjs-auth can require two-factor: `twoFactor: { require: ['admin'] }` sends those users to the security page from guards, gates and the admin pages, `auth.admin` answers `two-factor-required`, `guard({ twoFactor })` overrides it per guard, and production warns when `admin` has no requirement: [two-factor](../packages/auth/llms/oauth-passkeys-two-factor.md).
- kayjs-mail needs no `src/mail.ts`: `mail({ from, locale, ...mailer options })` in `kay.config.ts` builds the mailer, `send` and `enqueue` from `@kaynooo/kayjs-mail` use it, `kayjs-auth` sends through it, and `kay add mail` writes that one line: [setup](../packages/mail/llms/writing-and-sending.md#setup).
- kayjs-auth can require two-factor: `twoFactor: { require: ['admin'] }` sends those users to the security page from guards and the admin pages (gates answer 403), `auth.admin` answers `two-factor-required`, a passkey sign-in counts as two factors, and production warns when `admin` has no requirement: [two-factor](../packages/auth/llms/oauth-passkeys-two-factor.md).
- Commands a library adds to `kay` (`kay ui eject`, `kay ui diff`, `kay i18n translate`, `kay auth create-user`, `kay push keys`) take `--quiet`, `--format json` and `--dry-run` as kay's own do, or list why not in `refuses`, and report a failure through `fail(message)`, so `--format json` gets the failure document: [Component libraries](component-libraries.md#extensions).

- A queue's workers, a room's heartbeat, a mail list's sweeper and the other timers a request starts run outside that request, so the first request's server scope, locale and reads no longer reach every later job; an `AsyncLocalStorage` or OpenTelemetry span an app entered around `listen()` no longer reaches workers: [queues](queues.md).
- A public prerendered page with a `ttl` (the page setting `revalidate` is now called) answers `cache-control: public, max-age=0, s-maxage=T, stale-while-revalidate=T` so a CDN keeps it, `cacheControl` in `page` sends other text or `false` the old default, and `kay build --static` writes the same into `_headers`; a guarded page or one rendered for a visitor stays private: [what is cached](rendering.md#what-is-cached-and-for-how-long).
- `invalidate()` takes a key, a function over keys, a `cache()` function, a `cacheTag()`, a collection or `{ page }`, `sitemap: { ttl }` and `images: { ttl }` keep their age in the config, and one table says what is cached for how long: [caching](rendering.md#what-is-cached-and-for-how-long).
- A response that sets a cookie never leaves with a `public` cache-control, whichever plugin or route set it (`keepCookiesPrivate` from `kay/library`): [a CDN in front](cdn-caching.md).
- A lifetime is `ttl` or ends in `Ttl` everywhere: `notify`'s `ttl`, a queue's `failedTtl`, a Chat's `history`, flagged by the safe-fixable `deprecated-lifetimes` lint: [deprecated lints](deprecated-lints.md).
- A new project's `fmt:check` script (`kay fmt --check`) runs in its server and site workflows, and the server workflow builds too: [kay new and kay add](project-new-and-add.md).
- A `--- server` fence in a component is a `fence-invalid` error, as the docs always said: [components](components.md#file-layout).
- `navigation` from `kay` tells an island where an in-place navigation stands (`status()`, `pending()`, `to()` and `error()`, an `ApiError`), `onBeforeNavigate(({ url, from }) => ...)` may cancel one and `onNavigate(({ url }) => ...)` follows each shown page, and `kay:navigate-start` and `kay:navigate-error` join `kay:navigate`: [navigation state and hooks](navigation-from-code.md#navigation-state-and-hooks).
- A page whose pattern is a collection's `route` prerenders and lists its entries in the sitemap with no `page` export, a feed needs no `item` or `title` (the fields of the entry and the collection's `title` stand in), and the collection's `modified` field gives each URL its `lastmod`, the entry's head `article:modified_time` and the feed its update times; `url` as a function and a feed item's `path` next to a `route` are the `deprecated-collection-links` lint: [content](content.md#show-one-entry-per-page).
- A feed item carries `content` (`content: true` renders each entry's body), `categories`, `image` and `updated`, `format` takes `'json'` or a list serving several formats, and the head of every page showing an entry of a collection with a feed links it, `page = { feed: posts }` adding the link to another page and `feed: false` leaving it out: [feeds](content-markdown-to-caching.md#feeds).
- Every kayjs-ui field control takes `size` (`sm`, `md`, `lg`) and `invalid` (the danger line and `aria-invalid`), and the field look is one constant: [forms](../packages/ui/llms/forms.md).
- Every kayjs-ui component with a `tone` (Button, IconButton, BareIconButton, RecordButton, CopyButton, Badge, Stat, Notice, Toast, Timeline, Sparkline, StatusStrip, ConfirmDelete, Menu and its entries) takes the one exported `Tone` and styles all six: [basics](../packages/ui/llms/basics.md).
- `toast.warning(...)` pushes a warning toast, `ToastOptions.tone` takes any `Tone`, and `kay check` flags the old `muted` tone with the safe-fixable `deprecated-ui-tone` lint: [deprecated lints](deprecated-lints.md).
- kayjs-auth groups its account, provider and audit methods (`auth.account.delete(proof)`, `auth.oauth.link(...)`, `auth.audit.list()`, `auth.admin.createUser(input)`), and the `deprecated-auth-account-methods` lint renames the flat names: [grouped methods](../packages/auth/llms/grouped-methods.md).
- kayjs-auth checks new passwords against Have I Been Pwned by default in production (`breachedPasswords: false` opts out), and warns at boot in production when password sign-up is open with no `email`: [hardening and testing](../packages/auth/llms/hardening-and-testing.md).
- Every command takes `--quiet`, `--format json` and `--dry-run` or refuses it for a listed reason (`tests/command-options.test.ts`); `kay render --format json` prints `{ status, headers, body, ms }` and `kay upgrade --format json` `{ steps, changed }`: [project commands](project.md#reference), [check and tools](check-and-tools.md).
- `kay mcp` serves `fmt`, `generate` and `add` (dry run), `test`, `env`, `i18n_missing` and `a11y` as tools, and the llms.txt and guides of each installed kayjs-* library as resources: [MCP](editor-and-agent-commands.md).
- One hook convention for kay and its libraries: `onX` observes after X, `beforeX` alone changes or refuses (returning fields, `false`, or throwing `refuse()` from `kay`), runs use `onStart`/`onSuccess`/`onError`; `kay/library` gets `HookContext`, `hookContext()`, `notify()` and `decide()`, and `onError` in `kay.config.ts` receives the `source` of a hook that threw: [hooks](hooks.md).
- Queues and workflows take `onStart`, `onSuccess`, `onRetry` and `onError` (`onFailed` is `onError`, renamed by `deprecated-hook-names`), schedules take `onStart`, `onSuccess` and `onError`, and queue and workflow runs feed `kay_queue_runs_total{queue,result}`: [queues](queues.md), [hooks](hooks.md).
- `refuse(message, { status, errors, data })` from `kay` stops an action with a message, field errors and data, answered as `ctx.fail` is (the `Symbol.for('kay.refused')` contract gains `errors` and `data`); `kay/library` gets `HookContext`, `hookContext()`, `notify()` and `decide()` for libraries' hooks, and `onError` in `kay.config.ts` receives the `source` of a hook that threw: [hooks](hooks.md).
