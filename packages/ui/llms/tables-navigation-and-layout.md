# kayjs-ui: Tabs, navigation and pagination

## Common tasks

### Segmented, ChipGroup, TabNav, Breadcrumb, SiteNav, AppHeader, Tabs, Toggle, Checkbox

```kay
Tabs(tabs={[{ value: 'details', label: 'Details' }, { value: 'reviews', label: 'Reviews' }]} value="details" label="Product")
  @panel(tab)
    if tab === 'details'
      ProductDetails(product={product})
    else
      Reviews(product={product})
```

- `Segmented(options={[{ value: 'day', label: 'Day' }, { value: 'week', label: 'Week' }]} value="day" label="Period" name="period" onChange={period.set})`: real radios, so arrow keys move between options (`orientation="vertical"` stacks them in a column) and the group posts as `name` inside a form. An option may carry an `icon` and be `disabled`, or `disabled` on the group disables every option, as ChipGroup's does (Tabs has a per-tab `disabled` only). A parent passing another `value` moves the choice, and `null` picks none, for a state matching no option, such as a zoomed range beside a period picker; a reset to none tells `onChange` `null`, typed only when `value` is typed nullable. When it is, an option may carry `value: null` for a "none" choice: it is checked while the held value is `null` and tells `onChange` `null` when picked, and posts an empty string in a form. `kay check` fails a null option on a `value` that cannot be `null`, and one beside an option of `""` (same posted value), by the options' type: literal or union values, not `string`, and a wrapper generic in its option value casts `options`. Without `name`, the group draws one unique on the page. `param="period"` (with `paramDefault="7d"`) holds a query param of the page with no island of the app's: a pick runs `navigate({ query: { period } })`, keeping the other params and leaving the param out for `paramDefault`, the group busy until the page shows it, an `onChange` of yours running first and refusing by answering `false`. The group shows the option the address names, else `paramDefault`; the radios take `param` as their name, so a GET form around the group works without JavaScript, and the group alone needs it. A pick made while a change is busy takes nothing, and a refused change is put back: the check goes back and keyboard focus moves to the checked radio with it. Option values may be numbers: `Segmented(options={[{ value: 10, label: '10' }, { value: 25, label: '25' }]} value={size()} label="Round size" onChange={size.set})` hears `10`, not `'10'`, and `0` is a value like any other. `label` names the group for screen readers only; `showLabel` also writes it above the group in a Slider's label type and names the radiogroup by it (`aria-labelledby`), for a row of controls mixing a Segmented with a Slider. The label and the group then sit in a `field` part, the label being `heading`, and `class` still reaches the group.
  - `onChange` may return a promise, as Toggle's may: the group is `aria-busy` and takes no other pick until it settles, and goes back to the previous option when it resolves to `false`, rejects or throws (logged), unless the parent set `value` meanwhile.
- `TabNav(links={[{ href: '/settings', label: 'Profile' }, { href: '/settings/keys', label: 'Keys' }]} current={pathname} label="Settings")`: tabs as links, one page each. The current tab is marked `aria-current="page"`, and a bar too narrow for every tab scrolls to centre it, without moving the page. Following a tab keeps the window where it was, as `data-keep-scroll` does, except a link to a `#section`, which scrolls to it; going back restores the saved position. `links` may carry `prefix: true` (current on every page under the link's path, `/traffic` on `/traffic/requests/12`) or `also: ['/logs/archive']` (current on the pages under those paths), for a URL `current`, the exact page winning. `TabNav(tabs={[{ value: 'findings', label: 'Findings' }, { value: 'hosts', label: 'Hosts' }]} param="tab" label="Host")` builds the links of one query param instead, with `withQuery` (so every other param is kept, and `base`, `trailingSlash` and the locale hold) and needs no `current`: the tab the address names is current, the first when the param is left out or names none, or the one `paramDefault` gives, whose link then leaves the param out. It reads the request, so it needs a page rendered per request. `current={url}` with `keep={['period', 'site']}` carries those params of the page's URL onto each link that does not set them itself, for tabs sharing filters; a URL `current` marks the link whose path matches and whose own params the URL holds. `pathname` and `url` come from `ctx.url`. The address is compared with each `href` as the site renders it, in the page's locale and with a trailing slash ignored, so SiteNav, TabNav and TreeView mark the link on `/fr/settings` for an `href` of `/settings`.
- `SiteNav(links={[{ href: '/', label: 'Home' }, { href: '/rooms', label: 'Rooms' }]} current={pathname} label="Main" menuLabel="Menu")`: a site's main links, in a row from the `lg` breakpoint and folded behind a menu toggle below it, a popover the browser opens and closes (Escape, a press outside, the focus handed back), so it ships no JavaScript. With no `links` it draws nothing, no toggle and no empty landmark; so do AppHeader's nav, TabNav, and SideNav (whose lists are empty once loaded).
  - The page on screen is marked `aria-current="page"`, and a link to a section holding it `aria-current="true"`, as `/rooms` for `/rooms/blue`; `/` only marks itself.
  - The toggle is a `popovertarget` button and the list a `popover`: the browser opens it, closes it on Escape or a press outside, gives the focus back, and exposes `aria-expanded` itself, and a page swap closes one left open. A link to a `#section` of the page leaves the menu open until a press outside or Escape.
  - It needs the Popover API (Chrome and Edge 114, Firefox 125, Safari 17); in an older browser the links show as a plain list and the toggle is hidden. The list sits under the toggle through CSS anchor positioning, as for `Popover`.
  - It is a static component, so a layout holds it and a page of it ships no island. It takes data alone, with the logo and any call to action beside it in the app's own header: `AppHeader` is that header.
  - A link (`NavLink`, `{ href, label, icon?, badge?, disabled?, children? }`, a `NavItem` as TabNav's links are) may carry an `icon` (a slot name or an imported icon), drawn before its label as decoration, the label naming the link, and a `badge` after it. A `disabled` link is a text with `aria-disabled`, no link. Type links holding an `icon` `as const`, so a name stays a slot name.
- `SideNav(groups={[{ label: 'Admin', links }]} links={links} current={pathname} label="Main")`: a vertical navigation, an island. `links` is a run with no heading (before the `groups`), each group `{ label?, links }` (`SideNavGroup`) a titled list; links are SiteNav's `NavLink`, current matching included. `@link(link)` replaces a link's text, `@heading(group)` a heading, `@header` sits above the lists and `@footer` under them. `links` and `groups` may also be a function or a promise of the list, loaded once the island runs (a loading row, then a failure row with a retry); a page that has the list at hand passes the array, drawn from the first paint. `collapsed`/`onCollapsedChange` and `open`/`onOpenChange` control the rail and the narrow-screen panel.
  - The toggle at the bottom collapses it to a rail of icons (a link with no icon shows its first letter, the text stays for screen readers and a tooltip): `collapsed` controls it, else the component holds it, `collapsedKey="side"` keeps it in a `persisted` cookie the server reads (first paint right), `onCollapsedChange(collapsed)` reports each toggle, `collapsible={false}` drops the toggle, `collapseLabel` and `expandLabel` name it.
  - Below `lg` the nav gives way to a menu button (`menuLabel`) opening the same lists in a `SidePanel` (`open`, `onOpenChange`; following a link closes it); `panel={false}` keeps the nav in place at every width. Parts are listed in [restyle](restyle.md).
- `AppHeader(links={links} current={pathname} label="Main")` with `@brand` and `@actions` blocks: the bar across the top of an app, the brand at the start, a `SiteNav` of the `links` (same props, `menuLabel` too) and the `@actions` at the far end, such as a user menu or a theme toggle. `sticky` is on, so it stays at the top while the page scrolls; `sticky={false}` lets it scroll away.
  - A block left out draws no wrapper. Below `lg` the links fold behind the menu button, which follows the brand, `@actions` keeping the far end; a long brand or actions wrap. A sticky header covers what an anchor scrolls to: give the page `scroll-padding-top` the header's height.
  - It is a `header` (`.kui-app-header`) with `brand`, `nav` and `end` parts, painted by the theme's colours, so a skin restyles it with no CSS of the app's own.
- `AppSwitcher(apps={[{ id: 'atlas', href: 'https://atlas.example.com', label: 'Atlas', icon: 'globe' }]} current="atlas")`: an IconButton (a grid of dots, the `apps` slot) opening a Popover of tiles, each an icon above its name, to switch between sibling apps, `@trigger(attributes)` replacing the button as a Menu's does, `open` and `onOpenChange(open)` as Popover's, other attributes (`data-*`, `aria-*`, `style`) on the default button; it sits in `AppHeader`'s `@actions` or in a header of your own.
  - A tile is a link, the current app's marked `aria-current="true"` and drawn bold with a bar under it. Tiles open in the same tab, as the apps are one place to the visitor, even to another origin; `newTab` opens them all in a new one (`target="_blank"`, `rel="noopener"`), and an app's own `newTab` and `rel` win.
  - An app is `{ id, href, label, icon?, description?, newTab?, rel? }` (`SwitcherApp`): `icon` is a slot or an imported icon, the first letter of the label standing in when it has none, and `description` is the tile's tooltip. `@tile(app)` replaces the text under the icon.
  - `label` names the trigger and the panel (the `ui.appSwitcher.label` message, `Apps`), `icon` replaces the dots and `placement` is `bottom-end`. Opening focuses the current tile; the arrow keys move between tiles (three to a row), Home and End jump, and Escape closes it and gives the focus back to the trigger.
  - Parts: `root` (the trigger), `menu` (the popover), `grid`, `tile`, `icon`, `initial` and `name`. It is an island, like Menu, and takes no attributes besides `id`.
- `Breadcrumb(items={[{ label: 'Home', href: '/' }, { label: 'Moons', href: '/moons' }, { label: 'Phobos' }]} label="Breadcrumb")`: a `nav` holding an ordered list of the trail, top first and the page on screen last. The last item is marked `aria-current="page"` and is never a link; an earlier item without an `href` is plain text. Separators are drawn by the style and hidden from screen readers. From four items on, a phone shows the first and the last two with a menu button (`more` icon, named `moreLabel`, `ui.breadcrumb.more`) in place of the middle, which lists those crumbs as links, a crumb with no `href` a disabled entry. `structured` also writes the trail as a `BreadcrumbList` JSON-LD script in the head, each `href` made absolute by `site` in kay.config.ts (which it then needs). Use it on one Breadcrumb per page.
- `Tabs`: panels that switch in place, without navigating, each tab `{ value, label, icon?, disabled? }`, the arrow keys going past a disabled one, for settings or a product's details; use TabNav when each tab is a page of its own.
  - A `tablist` of buttons, each paired with its `tabpanel` through ids drawn with `uid()`. `@panel(tab)` draws each tab's panel once, hidden while another tab shows, so what a panel holds survives a switch.
  - A click, or the arrows (wrapping), Home and End, show a tab and focus it; only the shown tab is in the page's tab order. `onChange(value)` runs on each switch, and a parent passing another `value` shows that tab. A `value` naming no enabled tab (an unknown one read from a URL, or a disabled tab) shows the first enabled tab, as TabNav's `param` does, so a tab is always in the tab order, and tells `onChange` nothing for the fallback.
  - `tabs` is an `OptionsSource`, as the options of RadioGroup are: a list, a promise or a function returning one (`Tabs(tabs={() => loadSections()} value="details" label="Product")`). It is asked in the browser, the root is `aria-busy` with a `status` row saying `loadingLabel` (`ui.tabs.loading`) until it answers, or an alert row saying `failureLabel` with a `retryLabel` button (a function source only) when it rejects; `onLoad(tabs, query)` and `onError({ error, query })` follow the answer. Until then no tab is drawn, and a `value` naming no loaded tab shows the first enabled one. New parts `status` and `retry`.
  - `Tabs(tabs={...} param="tab" paramDefault="details" label="Product")` holds the shown tab in a query param of the page instead of `value`, with no island of the app's: the server draws that tab from the first paint, and a pick rewrites the address without a navigation (every panel is already drawn), keeping the other params, replacing the current history entry as `queryParam` does (so Back leaves the page, not the last tab) and leaving the param out for `paramDefault`. Without `paramDefault` the first enabled tab shows while the param is left out, and picking it sets the param. `onChange` still runs on each pick. It reads the request, so it needs a page rendered per request.
  - A panel not shown is `hidden="until-found"`, so the browser's find in page or a link to an id inside it shows its tab, and so does kay's `focusInvalid`: after a refused save, `focusInvalid(form)` shows the tab holding the first field marked `aria-invalid` and focuses it, with no work out of which tab that is.
  - It renders inside an island, since its panels come from a block.
- `Toggle(label="Public" checked={post.public} name="public" onChange={setPublic})`: a checkbox drawn as a switch, with `role="switch"`, that posts like a checkbox. Without `label`, give it `aria-label`. `hint`, `name`, `issue`, `invalid`: as on Checkbox.
  - `onChange` may return a promise: the switch is `aria-busy` and flips no further until it settles, and goes back where it was when it resolves to `false`, rejects or throws (logged), unless the parent set `checked` meanwhile. A void answer leaves it as clicked. The jump back is all the user sees, so toast the failure too; `attempt` resolves to `undefined` on failure, so turn that into `false`: `onChange={async checked => (await attempt(() => setPublic({ id, public: checked }), 'Could not publish')) ?? false}`.
- `Checkbox(label="I agree" checked={agreed()} name="terms" onChange={agreed.set})`: a native checkbox and its label, posting like one. `hint` adds a quieter note after the label. `name` and `issue` show a field message under it (not when a FormField of that `name` wraps it) and mark it invalid, `invalid` marks it with none; with either declared the root is a wrapper, styled by `class.field`. `indeterminate` draws it as neither ticked nor not, for a box over a partly ticked list; a click toggles it from `checked`. Without `label`, give it `aria-label`. `onChange` may return a promise, as Toggle's may. Use Toggle for a setting that applies as it is flipped.
- `ChipGroup(options={[{ value: 'films', label: 'Films' }, { value: 'games', label: 'Games', icon: 'star' }]} value={decks()} label="Decks" name="decks" onChange={decks.set})`: chips to pick several options from, real checkboxes posting each picked option under `name` (one unique on the page without it). `onChange` gets every picked option in the order of `options`, and may return a promise, as Segmented's may. An option may be `disabled`, or `disabled` on the group disables every chip. Option values may be numbers, such as `Date.getDay()` weekdays: `onChange` hears numbers, not their text. A parent passing another `value` moves the picks. `showLabel` writes `label` above the chips, as on Segmented.

### Pagination, QrCode

- `Pagination(page={page} pages={pages} url={url})`: links to the pages of a list through the URL's query, so it renders on the server with no island and each page has a URL of its own.
  - Each link keeps `url`'s path and query, `param`, `page` by default, set to its page and left out for the first one. Read the page in a server fence: `const page = Number(ctx.url.searchParams.get('page') ?? 1)`. A page past the ends, or no whole number, such as `?page=abc`, shows as the nearest that exists, so clamp it the same way where the page's own query reads it.
  - It shows the first and last pages and `siblings` on each side of the current one, 1 by default, an ellipsis for those left out, or the page itself when only one would be. The current page is marked `aria-current="page"`; Previous and Next are links with `rel="prev"` and `rel="next"`, and plain text at the ends. With one page or none it draws nothing, except the summary of a `total`.
  - `label` (`Pagination`), `previousLabel` and `nextLabel` replace its words.
- `Pagination(page={page} total={134} pageSize={20} url={ctx.url})` makes the pages from the rows and adds a summary beside the links, `21–40 of 134` (`rangeLabel` replaces it: a string filling `{from}`, `{to}` and `{total}`, or a function of `{ from, to, total }`; the word is `ui.pagination.range`). `sizes={[10, 25, 50]}` adds a link per page size under a group named `sizeLabel` (`Rows per page`, `ui.pagination.size`), each setting `limitParam` (`limit` by default) and dropping the page, the one equal to `pageSize` marked `aria-current="true"`; read the size from that parameter in the page and pass it as `pageSize`. The sizes stay while the rows outgrow the smallest, even on one page, so a size picked past the rows can be undone; with no size smaller than the rows, and one page, the summary stands alone.
- `onPage` and `onSize` make the same links answer a click in an island: see [open state](open-state-and-sources.md#pagination).
- A list whose length is unknown, which fetches one row past the page to know whether another follows, passes `more` in place of `pages`, and gets Previous and Next alone, Next a link while `more` is true: `Pagination(page={page} more={next !== null} url={ctx.url})`, or by offset, `Pagination(offset={offset} limit={20} more={next !== null} url={ctx.url})`, which steps `?offset=` by `limit`, `param` then being `offset` by default. With no step to link, it draws nothing.
- `Pagination(of={list})`: the same links for a page kay's `paginate()` from `kay/content` gave, `const list = await blog.page(ctx.params.page) ?? ctx.notFound()` in a `blog/[[page=integer]].kay` route, each page at its own path, `/blog`, `/blog/2`, rather than through the query. `of` takes any `{ page, pages, href(n) }`.
- `QrCode(value={shareUrl} label="Scan to open the list" pixels={160})`: the value as a QR code, an SVG image drawn where the page renders. `label` is its `alt`; leave it out for a decorative code, hidden from assistive technology. `pixels` is its width and height, else CSS sets the width.
  - `inline` draws the SVG in the page instead of an image, so the colours in `options` may be CSS ones and follow the page: `QrCode(value={url} inline options={{ foreground: 'currentColor', eyeColor: 'var(--color-accent)', background: null }})`. A `label` then makes it `role="img"`; `size` sets the box's width and height.
  - It keeps dark modules on a light ground with a quiet zone, which every scanner reads, whatever the theme. `options` takes what `qrCodeSvg` from @kaynooo/utils does, `ecc`, `moduleShape`, `eyeColor`, `foreground`, `background`, `margin` and the rest, colours written out unless `inline`, as the image cannot read the page's CSS.

## Reference

- Any parent, a layout and a page included, passes an island children and slots without parameters, which the server renders as static markup. A component or a page without a `--- server` fence passing one a function, a block with parameters or a class instance (such as Tabs' `@panel`, a Table's `@cell` or a function `rowKey`) is the `island-prop` error, fixed with `--- island` on it; a layout, or a page with a `--- server` fence, cannot be one, and moves that markup into a component of its own.
