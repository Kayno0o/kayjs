# MCP endpoint

The reference for `mcp` in `kay.config.ts`; the first steps are in [API routes](api-routes.md#let-an-agent-call-the-app).

- `mcp: true` serves Streamable HTTP at `/mcp`, or at `mcp: { path: '/tools' }` under the same rules as the OpenAPI paths, its sign-in metadata then at `/.well-known/oauth-protected-resource/tools`: one JSON-RPC message per `POST`, answered with JSON, `initialize`, `ping`, `tools/list` and `tools/call` only, no resources or prompts. `GET` and `DELETE` answer 405, a notification 202.
- `mcp: { rateLimit: 60 }` caps the requests one client may send the endpoint a minute, 120 by default, `false` for none, counted in `store.rates` where the app has one so replicas share it; one past it answers 429 with `Retry-After` and `Too many requests; try again in N s`, as an API module does. A call also meets the limits of the action or route it runs.
- `mcp: { instructions: 'Read French text through temtem_resolve first.' }` is sent as `instructions` of `initialize`, the MCP spec's field for guidance spanning tools that a client shows its model before any tool description; a non-empty string, else the boot fails. Absent, `initialize` carries none.
- `mcp: { key }` requires `Authorization: Bearer <key>` on every request to the endpoint, for a local agent holding a static key where no OAuth server signs it in: `key: true` reads `KAY_MCP_KEY`, else the trimmed file `KAY_MCP_KEY_FILE` names (a container secret); a string is the key itself; `{ file: 'data/mcp-key' }` reads the environment, else that file, made on first use with a random key (folder `0700`, file `0600`); a relative path is resolved against the project root, and against the working directory in a compiled server (`kay build --compile`), so it lands next to where the executable runs like a relative `sqlite://` path does, and an absolute one is used as given. A key is at least 16 characters, read once at boot, so a rotation is a restart. The check runs after the cross-site check and the rate limit (which refused guesses count against) and before the body is read: `initialize`, `ping`, `tools/list`, calls, notifications and unreadable bodies alike answer 401 with `WWW-Authenticate: Bearer realm="mcp"` and one JSON-RPC error, the same for a missing, malformed or wrong key. The scheme is matched in any case; the key is compared in constant time (both sides hashed first, so its length shows nothing). `GET` and `DELETE` stay 405. A tool call is dispatched by the endpoint after the check, so it needs nothing more, and the bearer is not passed on to the route or action it runs. A production server with `key: true` and no key does not boot; elsewhere, with none given, every request is refused and a warning names the variables. Checked under `kay dev` and `kay/test` too.
- An endpoint with `mcp.key` takes the static key alone: a kayjs-auth OAuth token is refused there, and the bearer is not passed on. With `proxy.key`, a `POST` to it is open to that check by itself (this path only; the rate limit counts the address `proxy` reads, so spoofing needs `hops` or `header` trusted from a caller that can reach the port, and a key of 32 random characters or more, as `{ file }` makes, makes guessing pointless), as its bearer is its credential: no `proxy.open: ['/mcp']` and no app guard. [Proxy and security](proxy-and-security.md).
- A message that is no JSON-RPC request answers 400, a body over `maxSize` 413, a request from another site (`Origin`, `Sec-Fetch-Site`) 403.
- A tool per action that sets `tool` and per API route whose `detail` sets `tool`, even with `openapi` off; a route that does not is in the OpenAPI document and no tool: absent from `tools/list`, and a `tools/call` naming it is refused as any unknown name is. Before 1.51 every route not hidden was a tool.
- A route's `detail.tool` is `true`, a description, or `{ name, description }`, as an action's. Its tool is named by `tool.name` else its `operationId` (a route setting only `tool.name` takes it as its `operationId`), made a safe name (`users.list` is `users_list`, a clash `_2`), described by `tool`'s description else its `summary` and `description`, its input one JSON Schema of the path params, query and JSON body, merged by name.
- Left out: `detail: { hide: true }` routes, `tool` or not (`hidden-tool` in `kay check`), websockets, a route whose body is files, text or bytes, an action holding a file, an action in a file whose pages have route params (a post from no page cannot name one), and `in: header` parameters. `tools/list` is served behind the API directory's `_guard.ts` as the document is, and with `requireGuards` it is refused (403) unless the guards cover every module; `initialize` and `ping` stay open, and a call runs the guards of its own route.
- A route answering every method, `.all()`, that sets `tool` is a tool per method; a `tool.name` takes the method as a suffix, `echo_get`.
- An action is a tool only when its third argument sets `tool`: `true`, a description, or `{ name, description }`; its name is the export in snake case, `addNote` is `add_note`, a clash `add_note_2`, and its input schema is the action's as JSON: `s.Integer()` and `s.Numeric()` read as a number, not also as the text a form sends (which a call still takes), and a top-level body or query field with a `default` is left out of `required`, as a call omitting it gets the default.
- A name is made of letters, digits and `_`, at most 64 characters.
- A call is dispatched through the whole app as a fetch to the route's or action's URL would be, so its guards, `rateLimit`, body limit, schema validation and `ctx.locals` are the web path's; `ctx.params` and `ctx.url` of an action are read as for a script's post from no page.
- It carries the caller's `Authorization` (not the endpoint's own `mcp.key` bearer), `Cookie`, `Accept-Language` and `User-Agent`, and rate limits count the caller's address as `proxy` reads it, not the server's.
- `toolCall(request)` from `kay/server` answers `{ tool, client }` for a request the endpoint dispatched, `tool` being the tool's name and `client` the address of the agent's client, and `undefined` for any other. It reads a hook registered before `pages()` (`.onRequest`), a guard's `request` and a handler's alike, and a client sending the marker headers itself is no tool call: the marker is a per-process secret. A front guard lets a bearer key reach the tools alone: `if (key && url.pathname !== '/mcp' && !toolCall(request)) deny(403, 'The key opens tools only')`; `/mcp` is let through because `tools/list` runs the API directory's guards as a request to `/mcp`, with no tool call.
- An `onRequest` hook that throws, the app's own Elysia one, a param matcher, `rewrite` or an extension's, is answered like a handler that throws: logged, handed to `onError`, and a 500 with `Internal Server Error` in production, the message in development, instead of Elysia's 200; a GET asking for HTML gets the routes directory's `_error.kay` (or kay's error page) in the default locale, any other request plain text. A `Response` the hook throws is answered as given, and an `onError` registered before `pages()` answers first. An `_error.kay` drawn for it reads in `ctx.locals` what a `derive` added before it threw.
- `honeypot`, `minTime` and `proofOfWork` are skipped, as only a form a person filled in can pass them; a marker only the endpoint sets, a per-process secret no request can send, says so, and `rateLimit` still counts.
- A path param is one segment: it is percent-encoded and an empty one, `.` or `..` is refused, so no value reaches another route.
- A refused call is a result with `isError`: the schema's field errors, the `ctx.fail` data and status as `{ status, errors, data }` JSON, a route's own refusal text, a redirect naming where it leads. The agent corrects and calls again.
- A guard answering 401 makes the endpoint answer 401 with `WWW-Authenticate: Bearer resource_metadata="<site>/.well-known/oauth-protected-resource"`, how a client learns to sign in (kay serves that document when kayjs-auth's OAuth server is on: see its "OAuth server for MCP clients"); any other refusal, 403 included, is a result. Only a guard's 401 does: a route answering 401 itself is a result too. A refused `tools/list` answers the same way (a redirect counting as a 401), as a JSON-RPC error. It keeps the guard's response headers, `Retry-After` of a 429 among them. A `tools/call` of a name no tool has is refused the same way, so names cannot be probed; a call to a tool runs its own guards.
- A result is JSON as text, and `structuredContent` when an object; any other type read as its size. A route's object `response` is the tool's `outputSchema`, with no `detail.tool.output` ([action protection](action-protection.md#offering-an-action-to-agents)).
- `/mcp` is claimed like a route: a page, endpoint or file serving it stops the boot, and `kay check` reports it.
- `unguarded-tool` warns, with `mcp`, of a tool action with a `honeypot`, `minTime` or `proofOfWork` that no guard covers: an agent calls it without the form those protections ask of a person. A `...spread` in the options counts as one of them, so it warns; options that are not an object literal, `action(schema, run, options)`, are not read, so the action is not taken for a tool.
- `site.mcp.initialize()` resolves with `{ serverInfo, instructions }` of the `initialize` answer, `instructions` being `mcp: { instructions }` or undefined.
- `site.mcp.tools()` lists the tools of an app with `mcp: true`, each `{ name, description, inputSchema }`, and `site.mcp.call('add_note', { title: 'Milk' })` calls one as an agent does, through the cookies of the site so far and the `headers` given, `{ headers: { authorization: 'Bearer token' } }`: it resolves with `{ isError, text, data, status }`, `isError` set when the app refused the call, `data` the answer when it is an object, `status` 401 when a guard asks for a sign-in; a protocol error, such as an unknown tool, throws. With `mcp: { key }`, `testSite({ mcpKey })` sets the key and `site.mcp` sends it as the bearer unless the call or the site's `headers` give an `authorization`; a config with `mcp.key` and no `mcpKey` gets a generated one.
