# What's new, older releases

What each release before 1.91 added, and the end of a newest release that was cut short (`(continued)`), newest first, each feature with where it is documented. The newer releases are in [What's new](whats-new.md); what a release breaks is in [Upgrading](upgrading.md).

## Unreleased (continued)

- An endpoint file exports `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE` and `OPTIONS` handlers (a method it lacks answers 405 with `Allow`), takes `export const page = { query, rateLimit, cors, maxSize }` as an API route does, and answers 404 with the routes directory's `_404.kay` for a request asking HTML, so a webhook outside `/api` needs no Elysia plugin; `kay check` warns (`endpoint-export`) of an export that is no method: [endpoint files](routing-endpoints-and-base.md#endpoint-files).
- kayjs-ui Menu takes checkbox entries (`checked`, `onCheckedChange`), radio entries (`radioGroup`, `value`), submenus (`{ label, items }`, ArrowRight and ArrowLeft), `{ heading }` titles, `shortcut` hints (CommandPalette entries too), `closeOnSelect: false` and first-letter typeahead; the `@item` snippet is handed any `MenuItem` ([pickers](../packages/ui/llms/pickers.md)).
- A library's boot error names its library and option, `configError('cms', 'pageSize', message)`, and its message ends on `(kayjs-cms option `pageSize`: kayjs-cms/llms.txt)`; the older `configError(option, value, takes)` and `configError(message)` keep working, and `kay explain` documents the library codes in its `library` group ([library conventions](component-library-conventions.md), [errors](errors.md)).
- A handler that calls `event.preventDefault()` on a link click now keeps kay's router from following that link, whether it is an island's `onClick` on an `a` or kayjs-ui's `Button(href onClick)`; the router listens after the document's handlers ([Navigation](navigation.md), [kayjs-ui](../packages/ui/llms/basics.md)). Toaster's link action uses its own `onClick` to close its toast.
- Results discriminate on `ok`: `step.waitFor` with a `timeout` resolves `{ ok: true, data }` or `{ ok: false, error }`, `installPrompt.install()` and `webPush.enable()` resolve `{ ok }` where `show()` and `subscribe()` answer a bare string, a tracked call's refusal carries its `error`, kayjs-cms saves and deletes answer `{ ok: true, saved: true }` or `{ ok: false, error, issues }`, and `showDraft`, `saveEntry`, `saveEntries` and `removeEntry` resolve `{ ok: true }` or `{ ok: false, error, issues }`; the old fields stay beside them, though a result built by hand (a test fake) needs `ok` and `error` now, and kayjs-auth's results carry `error` as the same `ErrorShape` with the kind as `error.code` (`result.error === 'limited'` is `result.error.code === 'limited'`, which `kay upgrade` rewrites): [queues](queues.md), [notifications](notifications.md), [errors](errors.md).
- `kay new` writes `CLAUDE.md` (`@AGENTS.md`) and `.mcp.json` (registers `bunx kay mcp`) beside `AGENTS.md`, which names the MCP tools; `--agents none` leaves the three out ([project-new-and-add](project-new-and-add.md)).
- `kay doctor` refuses a config whose `i18n` the server would refuse, and gains `tsconfig`, `browser` (a warning when no Chrome or Chromium is found) and `database` (`DATABASE_URL` answers) checks: [check and tools](check-and-tools.md).
- `site.runSchedule(which?)` from `kay/test` fires a `schedule()` job once, and `site.advance('1h')` moves the server's clock with `setSystemTime`, runs each schedule at every instant it falls due and then the queue jobs now due: [testing](testing-requests-jobs-sockets.md).
- kayjs-ui's Table columns take `width`, `minWidth`, `sticky`, `hidden`, `class` and `footer`, the table takes `@header(column)`, `@footer(column)`, `label` (a caption for screen readers), `columnToggle` and `hiddenColumns`, and a table that scrolls becomes a focusable named region ([Table](../packages/ui/llms/table.md)).

- `// kay-allow <lint>[, <lint>] -- <reason>` and `// kay-allow-file` keep the reason after `--` on the comment's line, commas and issue links included, as ESLint's `eslint-disable` does, and the editor's lint completion stops at the `--`: [lints](lints.md).
- kayjs-mail sends through Resend, Postmark, SendGrid, Mailgun and Amazon SES from `MAIL_URL` alone (`resend://KEY`, `mailgun://KEY@mg.example.com`...), with `fetch` and no dependency, the provider's id kept as the delivery's `messageId`; `resend()`, `postmark()`, `sendgrid()`, `mailgun()` and `ses()` are the same transports for `transport` ([Mail](../packages/mail/llms/contact-form-and-testing.md)).
- Reserved names follow one rule, written once with every reserved file, folder and `/_kay/` route in a table ([project](project.md#reserved-paths)): jobs live in `src/plugins/jobs.ts` alone (`unmounted-jobs` warns of a `src/jobs.ts` no plugin imports), and the image resizer is `/_kay/images` beside its variants, the old `/_kay/image` answering until 1.95.
- kayjs-mail's `MAIL_TO` drops empty items, so `a@example.com,` is one recipient rather than two, and a value of only separators is no recipient ([Mail](../packages/mail/llms.txt)).
- `cache()` takes `max`, the number of loaded values it keeps (the oldest goes first), its function has `reload(...args)`, and with `store: false` holds values that cannot serialize; kayjs-mail's SNS certificates use it in place of their own map: [rendering](rendering.md).
- `notify` names only the inbox of `kay/server`: the hook helper of `kay/library` is `dispatch`, and `deprecated-hook-dispatch` renames it ([upgrading](upgrading.md), [hooks](hooks.md)).
- `randomId(bytes)` from `kay` gives random hex that works on an insecure page, where `crypto.randomUUID` is missing; kay's idempotency keys, presence tabs and uploads, and kayjs-ai's chat replies use it ([Islands](islands.md)).
- An app whose `store` is `pgData` keeps the 404 log and the redirects added while the site runs in its Postgres (`kay_missing`, `kay_missing_referrers`, `kay_redirects`, made with the other `kay_*` tables or by `createDataTables` from `kay/server`, listed in `dataTableNames`) instead of `data/not-found.sqlite`, an existing `data/not-found.sqlite` moved into them at the next start, and production no longer warns of it; `unansweredPaths`, `dismissMissing`, `clearMissing`, `runtimeRedirects`, `addRuntimeRedirect`, `removeRuntimeRedirect` and `redirectMovedPage` from `kay/library` return promises: [routing](routing-endpoints-and-base.md#redirects), [stores](queues.md).
- kayjs-ai asks again, by default (2 requests per model, opt out with `retry: false`), after a failure before the first word of a reply (`unavailable`, `rate-limited` honouring `Retry-After`, `timeout`, `network`) and `ai({ retry, fallback })` or the same on an `ask` names the attempts, the backoff and the models to fall back on; `reply.steps` lists every request with its `provider`, `model`, `attempt` and `failed`: [when a provider fails](../packages/ai/llms/asking.md#when-a-provider-fails).
- kayjs-ui's `toast` takes a `description`, markup as its `message`, `onDismiss(reason)` and a link `action`, adds `toast.update(id, patch)` and `toast.promise(source, { loading, success, error })`, and `Toaster` takes `position`, `limit` and a `@toast(item, dismiss)` block: [toast and Toaster](../packages/ui/llms/toasts.md).
- The `slug` matcher accepts what the cms `slugify` gives, lowercase words of any script with `_`, joined by single dashes (and slashes in a rest param), where it took ASCII only ([Routing](routing.md)).
- `call()` types a route's `null` answer as `null`, as it already arrives, rather than `''`; an empty answer (`undefined`, a 204) stays `''` ([API from islands](api-from-islands.md)).
- `src/context.ts` (picked up by `kay dev` when added or removed, with a new process), default-exporting `defineContext(...)`, gives templates `ctx.<key>` with no extension, typed in `kay check`; two sources giving one key stop the page naming both: [Request values](request-values.md).
- kayjs-ui's `ThemeToggle` switches light, dark and system, keeps the choice in a cookie and puts it on `<html>` as `data-theme`, and `scheme()` writes it from the first render so the page never flashes the other scheme: [ThemeToggle](../packages/ui/llms/setup.md).
- The 1.88 deprecations are gone: the flat config keys (`routesDir`, `compress`, `navigation` and the rest, now `dirs`, `serve`, `observe`, `client` and `limits`), the AsyncRoomStore, AsyncRooms and StoreRooms types, and a number of seconds for `lifetime` and `durationWords`; the root of kayjs-mail and kayjs-ai no longer exports the store names that moved in 1.88: [Upgrading](upgrading.md).

- kayjs-ui's `ui()` Toaster and TooltipHost give way to the ones an app renders itself whichever hydrates first, so a Toaster with a `limit` never shows more toasts than it, `fallback` marking the extension's own ([kayjs-ui setup](../packages/ui/llms/setup.md)).
- A `reference('authors')` field is checked: `kay check` and `kay build` fail on a slug the collection has no entry for, naming the file and line, and `saveEntry` and `showDraft` refuse it at the field's path; `resolve(slug, collection)` from `kay/content` reads the referenced entry, or the entries of a list of slugs ([content](content.md#point-at-another-collections-entry)).

## 1.90.0

- kayjs-ui fields share one `onInput` (live) and `onChange` (committed) convention: MarkdownEditor gains `onChange`, DateInput, TimeInput and ColorInput gain `onInput`, and Select, RadioGroup, Segmented, IconPicker pass the picked option as a second argument, ChipGroup and MultiSelect the picked options: [Forms](../packages/ui/llms/forms.md).
- Every rate limit option is one `RateLimit` (`{ max, window, store?, key? }`, from `kay`, `kay/server` and `kay/library`) alone or in a list: kayjs-ai's `rateLimit` takes a list, kayjs-auth's buckets take a list and a `store` each: [rate limits](rate-limits.md#in-the-libraries).
- kayjs-ui Select, RadioGroup, Slider, ColorInput, Rating, Segmented and ChipGroup take no `value` like the text fields: they keep what is picked, post it under `name` with no JavaScript and a form reset goes back to what they first showed: [forms](../packages/ui/llms/forms.md).
- A FormField (or Checkbox, Toggle) with a `name` inside any `form(action={add})` shows `add.error('name')` with and without JavaScript, so ContactForm and SubscribeForm and your own forms need no `issue` per field; `formErrors()` from `kay` is what a component of yours reads, and kayjs-ui's `Form(action={add})` is the plain page form calling the action as SaveForm does: [forms](../packages/ui/llms/forms-and-steps.md), [actions](actions.md).
- kayjs-ui names the controls a component holds beside its content `@actions` everywhere (Card, FormField, AppHeader, TreeView, MarkdownEditor join the rest; ConfirmDelete's `trigger` string is `triggerLook`), and kayjs-ai's Chat and ChatLauncher take every icon as one `icons` prop; the old names work until 1.93: [blocks and links](../packages/ui/llms/slots-and-links.md#one-name-for-one-role), [Chat blocks](../packages/ai/llms/chat-blocks.md#change-the-icons).
- kayjs-ui entries with an address take `newTab: true | false | 'auto'` (Menu, BellInbox, AudioPlayer chapters, CommandPalette, SiteNav, AppHeader, Breadcrumb, TabNav, Timeline, TreeView, BarList, Carousel, AppSwitcher), an address leaving the site opening in a new tab by default; `isExternal(href)` is exported, and `LineChart` takes `href(mark)`: [links](../packages/ui/llms/slots-and-links.md).
- `format: 'email'` is one strict check, `isEmail` from `kay` (and `normalizeAddress` from `kay/library`), shared by the schema, the browser check, kayjs-auth sign-up and kayjs-mail, so an address that signs up is never refused as a recipient: [actions](actions.md), [upgrading](upgrading-archive.md).
- `kay check` reads a `--- style` fence: `unused-selector` warns of a rule no element of the template can match, `unreachable-selector` is an error for a rule ending on `:root`, `html` or `body` (fixed to `:global(...)`), and a `@keyframes` name is scoped to its component with its `animation` uses, `@keyframes :global(spin)` keeping it global: [components](components.md#file-layout), [upgrading](upgrading.md).
- `sitemap: false` in kay.config.ts serves no `/sitemap.xml` and leaves the `Sitemap:` line out of `robots.txt`, as `robots: false` and `favicon: false` switch theirs off: [sitemap and robots.txt](sitemap-search-fonts.md#sitemap-and-robotstxt)
- kayjs-auth answers `'off'` for every feature the app switched off (`signUp: false` was `'closed'`) and `'not-enabled'` where `twoFactor.regenerateRecoveryCodes` said `'disabled'`; a default-on feature (`password`, `magicLink`, `twoFactor`, `signUp`) is switched off with `false`, `true` working until 1.93 with `deprecated-auth-options` dropping it: [upgrading](upgrading.md)
- A size limit is `maxSize` (bytes or `'5mb'`) and a map by path `maxSizeByPath`: kayjs-ai's `ask` and `Chat` take `maxSize` (was `maxAttachmentBytes`, `maxFileSize`) and an extension's path map is `maxSizeByPath`, the old names working until 1.93 with `deprecated-size-limits` renaming them: [upgrading](upgrading.md)
- kayjs-ui FileDrop is a form control: `name` keeps the files on its input so a plain form posts them, `maxSize` and `maxFiles` refuse the rest with `onReject(files, reason)` (one call per `type`, `size` or `count`), `list` shows the kept files with a remove button, `onChange` hears them, `issue` shows a message under it, and `onFiles` and `@content` are optional (a default button opens the picker); `onReject` is called once per reason and `onChange` is the kept-files callback, see [upgrading](upgrading-archive.md): [FileDrop](../packages/ui/llms/pickers.md#rangeinput-slider-multiselect-combobox-filedrop-menu-iconpicker).
- kayjs-ui words empty states one way: Table, LineChart, ContributionGraph, Sparkline, StatusStrip, Timeline, DescriptionList, TreeView, Carousel and VirtualList take `emptyLabel` and now draw its default text where they drew nothing (`emptyLabel=""` hides it), every data component (BarChart, BarList, ScatterChart, MediaGallery, Combobox, MultiSelect, IconPicker, CommandPalette too) takes an `@empty` block beside it, and EmptyState takes `icon` and `tone`: [slots and links](../packages/ui/llms/slots-and-links.md).
- kayjs-ui names a failure the same everywhere: `failureLabel` is the message of CopyButton, ConfirmDelete, FormDialog, RecordButton, SaveForm, AudioPlayer, IconPicker and ImageCropper, CopyButton's `onError` replaces `onFail`, and every component's `onError` receives one object (`{ error }`, `{ event }` for the DOM's), as [the components guide](../packages/ui/llms/open-state-and-sources.md) says; the old names work until 1.93 ([upgrading](upgrading.md))
- `kay check` types the HTML attributes limited to keywords (`loading`, `type`, `scope`, `dir`, `target`) and the SVG attributes, with a nearest-name hint for `viewbox` or `strokeWidth`, and the `invalid-aria-value` lint holds a written ARIA state to its values: [upgrading](upgrading.md)
- kayjs-ui reports every show and hide through `onOpenChange`: Table and TreeView take it for `onToggle` (renamed by `deprecated-open-change`), SplitLayout has `onDetailOpenChange` with a back button above the detail below `md`, and CollapsibleSection and Accordion share the defaults `open` and `boxed` false: [open state](../packages/ui/llms/open-state-and-sources.md), [upgrading](upgrading.md).
- `kay check` warns with `once-read-prop` for a destructured prop read into a top-level `const` or `let` that a function or the template reads later in a browser script, which keeps its first value: [lints](lints.md). kayjs-ui Table follows a `countLabel` and a `selectedLabel` the parent changes.
- Each exported name means one thing: kayjs-mail's `cssColours` is `cssColors`, and kay's `schedule()` option type, job table names and data table names are `ScheduleEveryOptions`, `jobTableNames` and `dataTableNames`, and each library prefixes the type or function another package also exports (`MailReply`, `AiReply`, `CmsAction`, `AuthMember`, `authGuard`, `rowEditing`); `kay upgrade` renames the old ones ([upgrading](upgrading.md)).
- A function an `effect` or `onMount` callback returns runs as its cleanup; `effect`, `watch`, `every`, `listen` and `onCleanup` called with no owner warn once in development, and the `unowned-effect` lint flags them in a handler, a timer or after an `await`: [components](components.md), [lints](lints.md).
- A name has one home: kayjs-auth's credential rules are exported by `@kaynooo/kayjs-auth/rules` alone and kayjs-cms's `EntryForm` and `FormScope` by `@kaynooo/kayjs-cms/form` (`deprecated-import-path` moves the imports), `mount` is exported from `kay` as well as `kay/mount`, and `sqliteCache` from `kay/server` as well as `kay/cache`: [project](project.md).
- `createContext(default)` replaces `context(default)` from `kay`, so it does not read as `ctx` or `defineContext`; `TemplateContext` is the public type of `ctx`, and `deprecated-context-name` renames the old import: [components](islands-state-to-ids.md#context), [request values](request-values.md).
- The 404 log and the redirects added while the site runs live in the SQLite file of the app's `store` (`sqliteData`) instead of `data/not-found.sqlite`, an existing `data/not-found.sqlite` still read; workers fill what the `store` leaves out in the database it names (SQLite or Postgres) instead of `data/workers.sqlite`; production warns once at boot when either stays in a local file: [routing](routing-endpoints-and-base.md), [workers](workers.md).
- The 404 log and the redirects added while the site runs live in the SQLite file of the app's `store` (`sqliteData`) instead of `data/not-found.sqlite`, an existing `data/not-found.sqlite` moved into it at the next start; workers fill what the `store` leaves out in the database it names (SQLite or Postgres) instead of `data/workers.sqlite`; production warns once at boot when either stays in a local file: [routing](routing-endpoints-and-base.md), [workers](workers.md).
- kayjs-ui: a Select or Segmented with a `param` and no `value` shows the option the address names, else `paramDefault`, on the server and in the browser, following each navigation and Back or Forward step, so the param is no longer passed as `value` too: [forms](../packages/ui/llms/forms.md).
