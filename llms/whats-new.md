# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## 1.89.0

- A page's load on a freshly started browser (until one page has loaded) waits 20 s instead of 5 s when you gave no `timeout`, so a CI host busy with other work does not fail it: [browser tests](testing-browser.md).

## 1.89.0

- The upkeep of kay's stores and libraries (expired sessions and notifications on Postgres, kayjs-auth's prune, kayjs-mail's list sweep, kayjs-cms's history sweep) runs once per pass across the processes sharing a database, counts in `kay_job_runs_total` as `maintenance:<name>`, shows under Maintenance in the dev tool's Jobs tab and stops with the server: [production](production.md#run-a-job-on-a-schedule).
- kayjs-ai: a Chat message sent while the conversation is still being read (right after New conversation, or on a slow page) waits for the read and goes, where it used to be dropped with the text left in the field.
- kayjs-auth: a passkey ES256 signature whose r or s carries a leading zero DER does not write is refused, as a second encoding of the same signature: [passkeys](../packages/auth/llms/oauth-passkeys-two-factor.md).
- The hook of `kay/test` that drops a file's test database waits 90 s instead of 20, as Postgres can take that long to drop a database on a busy host: [testing setup](testing-setup.md).
- kayjs-ui: Carousel (`autoplay`), VirtualList (`estimate`, `overscan`), FormField (`group`) and ContactForm (`consent`, `action`) follow a prop the parent changes after render, as [components](components.md#props) says of a read at the top of the script.
- `kay check` warns of `invalid-nesting`, markup the HTML parser rewrites so the server and an island disagree (`p > div`, `form > form`, `table > tr`, an `li` outside a list); a parent holding a component or a slot is left alone: [lints](lints.md).
- `kay check` warns of `invalid-nesting`, markup HTML forbids or the parser rewrites so the server and an island may disagree (`p > div`, `form > form`, `table > tr`, an `li` outside a list, an `option` outside a `select`); a parent holding a component or a slot is left alone, and kayjs-mail's Layout, Button, Code, Divider, Fields and Quote now emit `<tbody>`: [lints](lints.md).

- `limiter({ max, window, store })` from `kay/server` has `hit`, `peek`, `reset` and `enforce` over any `RateStore`, kay working out the `peek` and `reset` a store lacks (a hit of weight 0, and a hit of minus the count, which needs a store that adds a negative weight), so actions, guards, kayjs-auth, kayjs-ai and kayjs-cms no longer warn, throw or count in memory for a store with only `hit`; a derived `peek` writes an empty window on a hit-only store, which the next hit joins, and kayjs-auth and kayjs-cms count under keys of their own, so their open windows start over once: [rate-limits](rate-limits.md).
- kayjs-ui BellInbox, Bell, ContactForm, FormDialog, FormField, LoadMore, RecordButton, SaveForm, SubscribeForm, TooltipHost and WhenVisible spread the attributes they do not name, so they take `id`, `data-*` and `aria-*`: [basics](../packages/ui/llms/basics.md).
- kayjs-ui Widget names its empty state `empty` (the boolean) and `@emptyState` (the block), `isEmpty` and `@empty` working until 1.92 with `deprecated-ui-props` renaming them: [upgrading](upgrading.md)
- `kay check` warns with `once-read-prop` for a destructured prop read at the top of an island's script, outside a function or `memo`, which keeps its first value: [lints](lints.md).
- `kay check` warns with `once-read-prop` for a destructured prop read into a top-level `const` or `let` that a function or the template reads later in a browser script, which keeps its first value: [lints](lints.md). kayjs-ui Table follows a `countLabel` and a `selectedLabel` the parent changes.
- Each exported name means one thing: kayjs-mail's `cssColours` is `cssColors`; `kay upgrade` renames the old one ([upgrading](upgrading.md)).

## 1.88.0

- kayjs-ui `createLabel`, `resultsLabel`, `selectedLabel`, `removeLabel` and `loadedLabel` take a string as well as a function, Steps draws a step's markup with an `@step` block, and BellInbox and SubscribeForm word their texts under `ui.bellInbox.*` and `ui.subscribeForm.label`, the old keys still read: [words](../packages/ui/llms/words.md)
- kayjs-ui DateInput and DateRangeInput name their per-day predicate `disabledDay`, `disabled` staying the boolean for the whole input; `isDisabled` works until 1.92 and `deprecated-ui-props` renames it: [upgrading](upgrading.md)
- kayjs-ui PageHeader, CollapsibleSection and Accordion take `level` for their title's heading, the defaults of every titled component listed in one place: [slots and links](../packages/ui/llms/slots-and-links.md)
- kayjs-mail, kayjs-ai and kayjs-cms keep their data in the database of the app's `store`, old local files still read; `pgConversations` and `/pg`, `/sqlite` entries are new: [upgrading](upgrading.md).
- A call of an action takes `queue` (`'parallel'`, `'serial'`, `'latest'`, also `add.track({ queue })`), `timeout`, `retry`, the hooks `onStart`, `onSuccess`, `onError` and `onSettled`, and `refresh` a `resource()` or a list of them; optimistic changes of calls in flight roll back to where they began whichever fails first, a call that retries sends one `Idempotency-Key` header on every try, `optimistic(change)` gives `{ undo, keep }`, and a form posting in place fires `kay:action-start`, `kay:action-success` and `kay:action-error` (with `status` and `errors`): [calling actions from islands](actions-from-islands.md).
- `ctx.fail(status, data, errors)` puts a message on a named field of the action's schema (or on the form under `''`), so `error <field>`, `aria-invalid`, `add.error('field')`, the value re-fill, `ActionError.errors` and kayjs-ui `FormField` follow it with and without JavaScript: [actions](actions.md#refused-posts).
- `for` takes any iterable: [templates](templates.md#render-a-list).
- A client-only island shows an `@fallback` until it renders: [browser-only](browser-only.md#fallback-while-the-browser-renders).
- `ctx.cookies.delete` takes the `secure`, `sameSite` and `partitioned` a cookie was set with: [server](server.md#sessions).
- The cookies of an `api()` route get the `security.cookies` defaults too, with no wiring and a cookie's own option winning: [server](server.md#sessions).
- A `method="get"` form swaps in place: [navigation](navigation-from-code.md#full-loads-and-prefetching).
- `security: { cookies: {} }` hardens `ctx.cookies.set`: [sessions](server.md#sessions).
- `serve: { timeout: '15s' }` holds a page, action, API route and endpoint to a time: past it the request answers 504 (a page through `_error.kay`), is reported to `onError`, and `ctx.signal`, new on every request context, aborts; a page, `api({ timeout })` and an action set their own: [production](production.md#request-timeouts). `signal` is a new required member of `RequestContext`, `ActionContext`, `PageContext` and `ErrorPageContext`, so a context built by hand in a test needs one.

- A deferred server island that fails or times out is retried with a backoff and, if lost, keeps its inert copy with `data-kay-failed` and a `kay:server-island-error` event carrying the `ApiError` and `retry()`; `kay:server-island` follows a success, and leaving the page aborts the request: [server islands](server-islands.md#server-islands).

- A request's `traceparent` puts its server span under the caller's trace (`observe.extract` reads other formats, `false` ignores it), the response sends `traceresponse` and JSON log lines carry `trace`: [tracing](tracing.md#join-the-callers-trace).

Releases before 1.88 are in [What's new, older releases](whats-new-archive.md).
