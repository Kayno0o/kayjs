# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- Browser tests prefer a `chrome-headless-shell` (on the `PATH` or in Playwright's cache) over full Chrome when no `path` or `BUN_CHROME_PATH` is given: same Blink and V8, far less memory, and a start failure names the executable; the shell also leaves no lock file, which kay's browser cleanup now follows through `/proc`. See [the browser itself](testing-browser.md).
- kay parses scripts, fences and templates with oxc-parser in place of `@babel/parser` and `@babel/traverse`: compiling a `.kay` file takes about 40% less CPU and a dev or LSP start compiles its first file faster, an install carries oxc's native binding in place of `@babel/*`, and a syntax error in a script reads in oxc's words. A compiled executable still carries no compiler.
- `links: { schemes: ['webcal', 'geo'] }` lets a bound `href`, `src` or `action` keep a scheme the app trusts instead of going out as `unsafe:`, on the server and in islands (`javascript`, `vbscript` and `data` are refused), and `kay dev` logs once per URL each bound URL it rewrote: [security](proxy-and-security.md).
- An action, an API route and a websocket upgrade refuse a request whose `Origin` is `http:` on the site's own host once the site is served over https (the request itself, `X-Forwarded-Proto`, or an https `site` in production), where only the host was compared; `kay dev` and a server tried on `localhost` over http keep working: [action protection](action-protection.md).
- An island reading the clock, `Math.random()` or a locale-less `Intl` is the `hydration-mismatch` lint of the `islands` group, so `// kay-allow hydration-mismatch`, `kay-allow-file` and `lints` reach it (so `lints: { islands: 'allow' }` now covers it too): [Browser globals on the server](browser-only.md#browser-globals-on-the-server).
- `kay check` points at the attribute and says what to write for a handler written as a call (`onClick={bump()}`), a mistyped `bind:value`, `elif` for `else if`, `className` and `htmlFor`, and reports a bare attribute value (`Card(title=3)`) once, with `title={3}`: [Checks](checks.md#what-kay-check-verifies).
- kayjs-ui: `Tabs` takes `param` (and `paramDefault`) to hold the shown tab in a query param of the page with no island of the app's, drawn from the first paint and written on a pick without a navigation, and a `value` naming no enabled tab shows the first enabled one instead of leaving no tab reachable by keyboard: [Tabs](../packages/ui/llms/tables-navigation-and-layout.md#segmented-chipgroup-tabnav-breadcrumb-sitenav-appheader-tabs-toggle-checkbox).
- kayjs-ai: a conversation kept on the server leaves out a reply stopped before it said anything instead of replaying words the model never wrote, and keeps at most 200,000 characters of tool results, the oldest turns' becoming `(left out)`: [Conversations](../packages/ai/llms/chat-conversations.md).
- kayjs-ai: `kay build --no-cache` keeps the `imageAlt` drafts, `ai({ imageAlt: { reviewed } })` makes `kay check` stop listing reviewed drafts, and a served-page hook that throws is logged once: [Images and PDFs](../packages/ai/llms/attachments.md#draft-the-alt-of-imported-images).
- kayjs-ai: an API root (`AI_BASE_URL`, `AI_AUDIO_URL`, `AI_EMBED_URL`, `baseUrl`) that is not an http(s) URL throws naming the variable when the provider is built, a key goes over plain http only to a loopback host unless `AI_INSECURE=true`, and `AI_PROVIDER=openai` without `OPENAI_API_KEY` throws unless `AI_BASE_URL` names a compatible server: [Asking](../packages/ai/llms/asking.md).
- A string field of an action with no `maxLength` takes a default bound of 10,000 characters, refused with the error of a declared one and carried to the form's `maxlength` and the tool's schema. `unbounded-string` is now a warning, and only for a field named like a short value (`name`, `email`, `title`...): [actions](actions.md).
- An island handed an action by a page needs no `Action` import to type the prop, `(input: { name: string }) => Promise<string>` does: the code reviving the action loads in the browser only for a page that passes one, and the `island-action` lint and its render error are gone: [actions from islands](actions-from-islands.md).
- kayjs-auth: `safeRedirect` is kay's `localPath`, which the library's own redirects use; the old name works until 1.87 and `kay upgrade` rewrites it: [Redirects](../packages/auth/llms/oauth-passkeys-two-factor.md).
- `session.settings` holds its lifetimes as durations (`'2592000s'`), like every other duration in the API: [Sessions](server.md#sessions).
- The session stores are `memorySessions()` and `sqliteSessions(path)`, named for what they hold like `memoryJobs` and `sqliteRates`; `memoryStore` and `sqliteStore` work until 1.87, and `kay upgrade` renames them: [Sessions](server.md#sessions).
- Config keys are named by what they hold: `routes`, `api`, `content`, `storage`, `maxSizes` and `settings` are `routesDir`, `apiDir`, `contentConfig`, `fileStore`, `maxSizeByPath` and `librarySettings`, the old names working until 1.87 with `kay upgrade` renaming them: [Project](project.md), [Upgrading](upgrading.md).
- Tailwind needs no line in `kay.config.ts`: a project with `bun-plugin-tailwind` in its `package.json` gets the plugin (once, if the config lists it too), `kay new` stops writing the import and the `plugins` line, and `kay/test` keeps loading its native addon lazily: [Use Tailwind](styles-and-assets.md#use-tailwind).
- `kay start --host <address>` sets `HOST` over the shell's, as `--port` sets `PORT` and `kay dev --host` binds its server: [Build and start](build-and-start.md).
- `base` reads `SITE_BASE` where the config sets none, as `site` reads `SITE_URL`, so a deployment under a path (Pages) needs no line in `kay.config.ts`; `kay new` no longer writes a `process.env.SITE_BASE` line and its import when no base is chosen: [Base path](routing-endpoints-and-base.md).
- A key kay does not know in `kay.config.ts`, `trailingslash` say, is a type error in `defineConfig` and stops `kay check` and the server with the nearest known name, in the config's top level and its `security`, `i18n`, `seo`, `offline`, `health` and `proxy` bags: [Project](project.md).
- kayjs-cms: `github({ repo, token })` commits a file entry to GitHub (or GitHub Enterprise Server with `baseUrl`) through the Git Data API, a rename with the entries that named it as one commit, and `CMS_HOST=github` makes a production server without `files` build it from `CMS_REPO` and `CMS_TOKEN`: [Setup and saving files](../packages/cms/llms/setup.md#commit-saves-to-github).
- kayjs-ai: a conversation a Chat keeps on the server (`keepOnServer`) keeps each reply's tool calls and results too, and the next ask replays them to the model, which no longer invents follow-up answers a tool already gave: [Conversations](../packages/ai/llms/chat-conversations.md).
- kayjs-ai: `mocked(action, run)` makes a tool of an app's action with its own name, description and input schema and a `run` of yours, so a script benches a prompt against the real model with nothing restated: [Actions as tools](../packages/ai/llms/tools.md#benching-a-prompt-against-the-real-model).
- kayjs-ai: `ai({ imageAlt: true })` drafts the `alt` of each imported image a server-rendered page shows with none, once per image content and kept in `.kay/cache`, `kay check` lists the drafts for review and no longer reports `missing-alt` for those images, and `describeImage()` asks the model for one: [Images and PDFs](../packages/ai/llms/attachments.md#draft-the-alt-of-imported-images).
- An extension can carry `transformServedPage`, the page hook for a page rendered per request, and declare `satisfies: ['missing-alt']`, which makes `kay check` skip an `img` of a server-rendered page whose `src` is an imported image, and `kay/library` exports `libraryCacheSlot`, `readCacheEntry` and `writeCacheEntry` for a library's own entries under `.kay/cache`: [Component libraries](component-libraries.md).

## 1.83.0

- kayjs-ai: `ground(found, read)` turns the rows pg-orm 8's `nearest()` found into the `system` and `sources` of an `ask`, so a chat answers from the app's own documents and cites them, and the fake answers it all under `bun test`: [Speech and embeddings](../packages/ai/llms/speech-and-embeddings.md).
- kay and its libraries accept `@kaynooo/pg-orm` 7 or 8 as their peer, and `kay new` and `kay add` scaffold an app on 8, where a call that matched every row (an empty WHERE on an update or delete, an object as a key) throws `ValidationError`: [pg-orm 8's guide](https://git.kaynooo.fr/kaynooo/pg-orm/src/branch/main/MIGRATION_v8.0.0.md). kayjs-ai's embeddings example uses 8's `embedding()` trait and `repo.read.nearest()`.
- Re-clicking or re-hovering a link whose page is still loading no longer fetches it again: a repeated click joins the load under way and a prefetch is skipped, so a slow page costs one request.
- `kay build` warns of an `await` block with a pending branch on a prerendered page outside an island, which the build resolves so its pending content never shows, and names a page that waited 1 s or more on one: [prerendering](prerendering.md#prerendering).
- Going back or forward to a page already being fetched takes that fetch instead of starting a second one, and two refreshes of a page leave one request running.
- kayjs-ai: `transcribe(audio)`, `speak(text)` and `embed(texts)` call an OpenAI-compatible server's audio and embeddings API (a local Whisper or Kokoro server, Ollama, OpenAI) from `AI_AUDIO_URL`, `AI_EMBED_URL` or the server `ask` uses, and the fake answers them under `bun test`, embeddings as stable vectors from the words: [Speech and embeddings](../packages/ai/llms/speech-and-embeddings.md).
- `kay check` reports an island whose imports reach a builtin a browser build refuses, `async_hooks` through a database library or `bun:sqlite` say, as `browser-builtin-import` at the island's import with the chain the build prints, where only `kay build` refused it: [Browser-only code](browser-only.md).
- `kay check` reports a refused builtin behind a `sideEffects: false` package or a child `.kay` component an island renders as `browser-builtin-import` too, keeps the other islands' reports when one import fails to bundle, and reports one chain once per island: [Browser-only code](browser-only.md).
- `kay build` writes the navigation-only entry and its chunks only when a component renders a form posting to an action, so an app with none deploys no `nav-*` file: [building](build-and-start.md).
- A content collection with a `load` function keeps its compiled Markdown bodies in `.kay/cache/content` as a folder collection does, so a build compiles only the bodies that changed: [Content](content-markdown-to-caching.md).
- kayjs-auth: `organizations.update(id, {})` and an empty update of a user answer the row as it is on the pg store, where it threw and the organization update reported `slug-taken`; `slug-taken` now means a slug another organization holds.

## 1.82.0

- An extension's API module may default-export a function of the `ExtensionApp`, called with the `appFiles` modules as a `server` function is, so a library serves the app's data file, `api({ cors })` included, and the app writes no module only forwarding it; an island hands such a module to `call()`, `socket()`, `stream()` or `resource()`, typed off the routes it builds: [Component libraries](component-libraries.md).
- An action's stream is read to its end with `await answer.ended()`, resolving with its last value and rejecting when it failed or was closed, with no polling of `status()`: [streaming actions](actions-from-islands.md).
- A production page that posts forms and holds no island loads the navigation-only entry alone, which `kay build`'s route sizes and size report weigh it with, and an island page loads the forms' listener only once it shows a form: [building](build-and-start.md#build-and-start-commands).
- A form posted before the forms' listener loaded is held only when the swap would take it and posted once, a post the swap leaves out going to the browser untouched, and a form holding a control named `enctype`, `elements`, `style`, `noValidate`, `requestSubmit` or `reportValidity` is checked, posted and refused as one without it, a multipart one posting multipart again.
- `site.open()` serves a `testSite()` with a `base` under it, so a browser test needs no front of its own, and `kay screenshot` and `kay a11y` pipe a page's websockets under a base too; `testSite()` rebuilds its islands when any file the build read changes (`kay.config.ts`, `public/`, content, libraries) and keeps them when one it did not read changes, a file the root `.gitignore` leaves out included: [Testing in a browser](testing-browser.md), [testing](testing-setup.md).
- A page reading `window['scrollTo']`, or a parameter or import named like `Date` or `fetch`, is now kept, and one reading an exported constant is no longer refused because a string, a comment, an object key or a template's tag shares its name: [prerendering](prerendering.md).
- A rate limit whose store throws, rejects or hangs counts in memory instead, logged once, for an action's limits, API routes, `rateLimit()` and proof of work as for kay's own routes, and the MCP endpoint's 429 says how long to wait: [Rate limits](rate-limits.md#reference).
- kayjs-ui: `RecordButton` records the microphone into a File, owning permissions, busy state and device release, and kayjs-ai's `Chat(transcribe={transcribe})` adds a microphone beside the field that sends what the action writes down: [RecordButton](../packages/ui/llms/basics.md#recordbutton), [Chat](../packages/ai/llms/chat.md#speaking-a-message).
- kayjs-ui: a `SaveForm`, `FormDialog` or submitting `Select` whose form holds a control named `elements`, `requestSubmit` or `reset` saves, submits and discards instead of throwing.
- kayjs-auth: the methods of a feature are grouped under it, `auth.admin.listUsers()`, `auth.password.signIn(input)`, so an editor lists one feature's methods at a time; the flat names work until 1.85, and `kay upgrade` renames the calls: [Grouped methods](../packages/auth/llms/grouped-methods.md).
- kayjs-auth: attempts count in memory, logged once, while the store's `rates` throws, rejects or takes over 8 s, so a sign-in still answers and still locks out: [Limits](../packages/auth/llms/hardening-and-testing.md#limits).
- kayjs-ai: `Chat`'s `keepOnServer` has the server keep the conversation through the action's own `ask`, a reload or Back showing it again under `?conversation=`, `conversations` lists the visitor's with rename and delete, a reply of an `outlive` ask is picked back up after a reload, and a tab whose reply lost its write to another tab is refused with 409: [Conversations kept on the server](../packages/ai/llms/chat-conversations.md).
- kayjs-ai: `ChatLauncher` takes `keepOnServer` and `conversations`, the panel's conversation named by this browser through `Chat`'s new `conversationIn="browser"`, so a reload, another page or a new tab shows it again: [A chat on every page](../packages/ai/llms/chat-conversations.md#a-chat-on-every-page).
- kayjs-ai: an approval ticket whose store fails or takes over 5 s runs no call, where a hanging store held the reply: [Actions as tools](../packages/ai/llms/tools.md).

Releases before 1.82 are in [What's new, older releases](whats-new-archive.md).
