# kayjs-ui: MarkdownEditor

## Common tasks

### MarkdownEditor

- `MarkdownEditor(value={body()} onInput={body.set} onImage={upload} name="body")`: a markdown `textarea` that writes like an editor, in an island.
  - Ctrl or Cmd with B, I or K wraps the selection in bold, italics or a link; Enter continues a list, and Tab indents a list item, leaving Tab alone elsewhere and after Escape, so the keyboard can always leave the field; `keysHint` tells screen readers so, as the field's description. These go through the browser's own editing, so Ctrl+Z undoes them like typing.
  - A page pasted as HTML turns into markdown.
  - A toolbar over the field offers bold, italic, a heading, bulleted and numbered lists, a link and an image, each as the shortcuts do, undone with Ctrl+Z. `toolbar={false}` hides it and `toolbar={['bold', 'italic', 'link']}` keeps those, in that order; the names are `bold`, `italic`, `heading`, `bulletList`, `numberedList`, `link` and `image`. `image` opens the file picker when `onImage` is given, else writes `![](url)` with the url selected. The toolbar is one Tab stop, the arrows, Home and End moving between its buttons. Its buttons and icons load in a chunk of their own after the editor, so `toolbar={false}` with no `preview` ships neither.
  - `@actions(tools)` adds your own buttons after the built-in ones (also with `toolbar={false}`; each a Tab stop): `tools.wrap(open, closing)`, `tools.edit({ text, start?, end? })` and `tools.selection()` change the field through the built-in buttons' undoable path. `previewing` and `onPreviewChange(previewing)` drive the preview; `onImageError(file, error)` hears a failed upload besides the toast.
  - `preview={markdown => renderOnServer(markdown)}` (a promise of HTML) adds a Preview button: the rendered text shows beside the field where the editor is wide and replaces it, with the formatting buttons, where it is narrow (under 36rem of its own width, so a side panel counts). It renders after a short pause in typing, the last answer winning, and says so in the pane if the call throws. The HTML goes through `sanitizeHtml` (images and tables kept), so a script, handler or `javascript:` link in the text never runs, whatever the renderer gets. `previewTrusted` inserts the HTML as it comes, for a renderer that has run `sanitizeHtml` itself; no parser ships with the editor. `previewHtml` (a `SafeHtml`, such as `markdownHtml(body)` computed on the server) is the preview of the starting `value`: the pane shows it in the server render and keeps it until the text is edited, when `preview` answers in its place, so a page opened with `previewing` loads rendered and nothing shifts. The pane's code loads the first time the preview is shown, and the HTML takes `kui-prose`, `previewClass="prose"` adding the classes your pages style rendered Markdown with. kayjs-cms wires it to the site's own Markdown pipeline.
  - `kui-prose` is the class for running text you did not template, such as `markdownHtml`, `renderMarkdown` or `sanitizeHtml` output set through `innerHTML`, which Tailwind's preflight leaves unstyled: `div.kui-prose(innerHTML={markdownHtml(text())})`. It styles headings, paragraphs, lists, definition lists, links, quotes, inline code, code blocks, tables and images from the theme tokens, so each skin restyles it, and a wide table or code block scrolls inside it. Its rules weigh one class, so a rule of yours wins. The MarkdownEditor preview and Chat replies carry it already.

## Reference

- MarkdownEditor details:
  - `class` and the other attributes land on the `textarea`, which sits in a wrapper that holds the toolbar and the preview. Inside a FormField the field is named by the label's text alone, and Tab goes from the field to the toolbar, as one stop.
  - With `onImage(file)`, a pasted or dropped image is embedded behind an `![Uploading …]()` placeholder at once, swapped for `![](url)` once `onImage` resolves with its url, or removed, line break included, with `uploadFailure` toasted if it throws (or a refusal of the whole call such as a limit, as `attempt` does). Writing goes on meanwhile, and a finished upload never takes focus back; the field is `aria-busy` while one is under way.
  - It shows about 12 lines and grows with its text up to 70% of the screen, where the browser sizes a field by its content (Chromium); it can be resized by hand.
  - `onInput(value)` reports the text after every change, typed or applied. A parent passing other text replaces it; passing back what it was given leaves the caret alone.
