This page lists what each release adds, newest first, with a link to where each feature is documented. kay and its libraries share one version number, so one section covers them all. What a release breaks, and what to change in your app, is in [Upgrading](/guides/upgrading).

## Unreleased

- **Linked libraries are checked**: `kay check` now type-checks the pages of an extension the app reaches through a workspace link, as it does an installed one, so an app linking a library may see new diagnostics. kayjs-mail's `authWords` throws for a mail kind kayjs-auth does not send.
- **Word count and reading time**: a Markdown entry has `words` and `readingTime`, counted from its rendered text. [Content](/guides/content)
- **One rule for writing a signal**: assign a signal held in a `const`, an import or a prop, and use `.set` for one held in a property ([Components](/essentials/components)).
- **Shorter config**: `proxy: true` is one proxy in front and `proxy: 2` two, `mailExtension('./src/mail')` names the module exporting the mailer, and an extension names its server plugin with `serverModule: { path, export }`. A Fontsource font entry takes `preload`. [Deployment](/guides/deployment#behind-a-proxy), [kayjs-mail](/libraries/kayjs-mail).
- **Typed locals and passkeys in libraries**: `guard<Own>(...)` types the locals a library's guard reads beyond the app's, and `kay check` type-checks the pages of an extension reached through a workspace link. kayjs-auth gains `@kaynooo/kayjs-auth/browser` for passkeys in an island and the `passkeyAssertion` and `passkeyAttestation` schemas for actions, with no cast and no `@simplewebauthn/browser`. [Guards](/structure/guard)
- **kayjs-auth with no wiring**: one line in `kay.config.ts`, `authPages({ auth: () => import('./src/auth') })`, declares it. `requireUser()` gives a page or an action its user, or sends the visitor to sign in and back, or refuses a post with a 401, `signInUrl()` builds that link, sign-out is a post to `/auth/sign-out` with no action of yours, and `pages.profile` adds your own fields to the account page. The account layout's `signOut` action is gone. [kayjs-auth](/libraries/kayjs-auth#the-signed-in-user)
- **Typed locals and passkeys in libraries**: `guard<Own>(...)` types the locals a library's guard reads beyond the app's, and `kay check` type-checks the pages of an extension reached through a workspace link. kayjs-auth gains `@kaynooo/kayjs-auth/browser` for passkeys in an island and the `passkeyAssertion` and `passkeyAttestation` schemas for actions, with no cast and no `@simplewebauthn/browser`. [Guards](/structure/guard), [Passkeys in an island](/libraries/kayjs-auth#passkeys-in-an-island)
- **Jobs in one call, and no server entry**: `schedule` takes a list of jobs or a table of schedules, and `boot: true` runs them once at start. `kay build --compile` serves the pages of a project with no `src/server.ts`. [Background jobs](/guides/background-jobs)
- **Actions shared by pages and components**: an `_actions.kay` in a routes directory holds actions with no page around them, imported by path from pages and islands, and served behind the guards of its directory. [Forms and actions](/essentials/forms-and-actions#actions-shared-by-pages-and-components)
- **Fixed fields without hidden inputs**: `form(action={move.with({ id, to: 2 })})` posts the values with or without JavaScript. [Forms and actions](/essentials/forms-and-actions#fixed-fields)
- **One call's own pending state and outcome**: `add.track()` gives a component a handle on an action whose `pending()` reads only its own calls, and a call through it resolves with `{ ok, data }` or the refusal's status, field errors and data, with no `try`. [Forms and actions](/essentials/forms-and-actions#reading-one-calls-outcome)
- **One call to refresh**: `invalidate('posts')` and `news.invalidate()` also mark the prerendered pages that read them stale, so a webhook is one line. `invalidatePage` stays for a page no data explains. [Caching and streaming](/guides/caching-and-streaming)
- **CI for GitHub**: `kay new --host github` writes a GitHub Actions workflow instead of a Forgejo one, and picks it alone when the `origin` remote is on github.com. [kay new](/reference/cli#kay-new)
- **Line chart scroll**: a `LineChart` with many labels no longer makes the page scroll past its content. Its data table for screen readers now sits in a visually hidden block, which a bare table box ignored.
- **One request context**: a page, a layout, a guard, an endpoint and an action all get `request`, `url`, `locale`, `params`, `cookies`, `locals`, `headers`, `redirect`, `notFound` and `deny`. An endpoint gets the ones it lacked, an action gets `url`, `notFound` and `deny`, a guard gets `notFound`, and a redirect is a statement everywhere. See [Endpoint files](/essentials/routing#endpoint-files) and [Guards](/structure/guard).
- **One request context**: a page, a layout, a guard, an endpoint and an action all get `request`, `url`, `locale`, `params`, `cookies`, `locals`, `headers`, `redirect`, `notFound` and `deny`. An endpoint gets the ones it lacked, an action gets `url`, `notFound` and `deny`, a guard gets `notFound`. See [Endpoint files](/essentials/routing#endpoint-files) and [Guards](/structure/guard).
- **`kay build` says why a page is not kept**: each route is listed as prerendered, kept or on request, with the file and line that stopped a page from being kept. Writing `export const page = { keep: true }` makes the build warn when the page is not kept. [Prerendering](/essentials/routing#prerendering)
- **One rule for imports**: what a component is written with needs no import, and everything else comes from `kay`, `kay/server` or the entry of its topic. `invalidatePage` moved to `kay/cache`, beside `invalidate`. See [Modules](/reference/modules).
- **A signing secret without sessions**: `secret` in `kay.config.ts`, or `KAY_SECRET`, signs form stamps, links to private files and the flash cookie, so an app without `session()` sets one in one place. The warning about the key of the process names it, and tests no longer print it. [Config](/reference/config)
- **Mail relay checked at boot**: a mailer configured from the environment warns as the server starts when its relay does not offer STARTTLS, and the warning names `SMTP_INSECURE=true`. It was refused only at the first send. [kayjs-mail](/libraries/kayjs-mail)
- **Short pages paint sooner**: a page writes its stylesheets into its head when together they compress under about 14 KB, and links them above that. `inlineStyles: true` and `false` still force one way. [Styling and assets](/essentials/styling-and-assets#linked-or-inlined-styles), [Upgrading](/guides/upgrading)
- **Lint with no check first**: `kay lint` writes the types ESLint reads for `.kay` files, then runs `keslint`. A new project's `lint` script is `kay lint --cache`, its `check` script no longer fails on warnings, and it writes the `.vscode/settings.json` the ESLint extension needs for `.kay` files. [ESLint](/reference/checks#eslint)
- **One command to move to a newer kay**: `kay upgrade` moves `kay` and the kay libraries in `package.json` to their latest version, installs, applies the fixes of each minor it crosses and prints what is left for you to change. The old forms a minor replaced are the `deprecated` lints, each with a `--fix`. [CLI reference](/reference/cli#kay-upgrade), [Checks reference](/reference/checks#deprecations)
- **`kay build` says why a component is an island**: each island is listed with what made it one, such as `onClick, line 4`, and a static component that may become one with the prop it passes. `--format json` adds them, and the islands of each route. [Islands](/essentials/islands#see-which-components-are-islands)
- **Actions with no input need no schema**: `action(async (ctx) => ...)` takes nothing, as with an empty schema, and an island or a test calls it with no argument. [Forms and actions](/essentials/forms-and-actions#an-action-with-no-input)
- **Page hooks know the locale**: a `transformPage` hook gets the `locale` of the page it rewrites, with its `path`, so a footer needs no scraping of `<html lang>`. [Page hooks](/llms/components#extensions)
- **Tests can read what an element holds**: `page.find()` returns each element's `html`, the markup inside it, so a test asserts a link holds an `svg` with no regex over the whole page. [Testing](/guides/testing)

## 1.45.0

- **A failed `try` leaves no head behind**: a `try` block that throws on the server takes back the `head` tags and island titles its components set, so a page never serves a title from an island it did not render. [Head and SEO](/essentials/head-and-seo)
- **A crashed test page fails at once**: a `kay/test` page whose renderer was killed or ran out of memory fails its next call saying so, instead of waiting for the test to time out. [Testing guide](/guides/testing#in-a-browser)
- **Tailwind rules reach template classes**: with `tailwind` on in `@kaynooo/eslint`, `kay/eslint` reports the shorthand classes and static `class` values of a template at their place in the `.kay` file, and fixes those in a `class="..."` of an element with no shorthand. [Checks reference](/reference/checks#eslint)
- **ESLint reaches template expressions**: `kay/eslint` lints attribute values, `{...}` in text and the heads of `if`, `match`, `for`, `await`, `const` and `slot`, reporting at their `.kay` line and column and fixing them in the file. [Checks reference](/reference/checks#eslint)
- **Workers bundled once per `kay dev` session**: a worker (kay's own proof-of-work worker included) is bundled again only when a file it read changes, instead of by a process of its own on every island edit, so an edit spends about 13% less CPU. [CLI reference](/reference/cli)
- **The client builder starts with the first server**: when an earlier run left a client build, `kay dev` builds the client beside the first types and server instead of once the server asks, so `ready` no longer waits for the builder to start, at the same CPU and memory. [CLI reference](/reference/cli)
- **Builds give the same pages**: two `kay build` runs of the same sources write byte-identical prerendered pages, so a warm build compresses none of them again, and the docs site's compress stage takes about 40 ms instead of 1 s (see [Prerendering](/essentials/routing#prerendering)).
- **One server for the whole `kay dev` session**: an edit to a template, island, loader or API route imports what changed again in the running process and swaps the routes in place, spending about 40% less CPU than a new process per edit. The config, the entry and modules they import still start a new process. [CLI reference](/reference/cli)
- **Live page titles**: an island can have a `head` block holding a `title`, which follows the signals it reads and is wrapped in `seo.titleTemplate` as on the server. [Head and SEO](/essentials/head-and-seo)
- **Pages that read nothing are built once**: a page that reads nothing from its request (no `ctx`, `query`, clock, random number, environment or package import) is prerendered by `kay build` and served from memory without `prerender` (the first visit after a request that writes checks it against a live render), so the bench app's pages cost about 50 and 38 us of CPU per request instead of 650 and 80 (see [Prerendering](/essentials/routing#prerendering)).
- **Typed values survive edits**: `kay dev` keeps what you typed into a field through a template or server code edit that leaves the field as it was ([kay dev](../reference/cli.md#kay-dev)).
- **An extension's own options**: `kay check` and the editor type the pages of a linked or sibling extension under the `tsconfig.json` of its package when its options differ from the app's, with the app's catalogs, `ctx.locals` and matchers in scope, and its pages resolve the dependencies its package installs itself.
- **Warmer builds**: a build compresses a file and draws the favicons only when their content changed, keeping the results under `.kay/cache`, so a build with nothing new spends about a quarter less CPU. [CLI reference](/reference/cli)
- A route of a module with a `cors` rule can no longer widen it: the `Access-Control-*` grant headers it sets itself, or a `Response` it passes on carries, are replaced by the module's, and a redirect or a `fetch()` result is answered with its `Vary: Origin` instead of a 500 ([CORS](api-routes.md#cors)).
- **A signal handed to a parameter that takes anything**: `kay check` reports `String(count)` or `JSON.stringify(count)`, which rendered the function's source, as `uncalled-signal`, and leaves a parameter typed `Signal<T>`, `Memo<T>`, a function type or a generic `T` alone.
- **Cheaper compression**: a page rendered per request goes out as zstd to a browser that takes it, at about a quarter of brotli's CPU, a browser without zstd gets gzip, a body up to 128 KB is compressed within its own request, and a page rendering the same bytes again is compressed only once. The server spends about half the CPU per compressed page it did. [Deployment](/guides/deployment)
- **Library actions in tests**: `kay check` types the named exports of a library page, such as kayjs-auth's actions, as the file declares them, so a test imports one without a cast.
- **A lighter config load**: a `kay.config.ts` importing only `defineConfig` from `kay/server` loads without the server in the processes that only read the config (the client builder, the types process, `kay build`, `kay check`), about 230 ms and 13 MiB less each.
- **Prove the executable starts**: `kay build --compile server --verify` starts it, waits for its health route and runs `--health`, failing the build with the server's own output when it crashes at startup. [Deployment](/guides/deployment#prove-the-executable-starts)
- **Tests catch islands the browser cannot build**: `testSite()` builds them and throws the error, once per process, `islands: false` skips it. [Testing](/guides/testing#islands-that-fail-the-browser-build)
- **A smaller compiled server**: the executable `kay build --compile` makes leaves out the code only `kay dev` and `kay build` run, so it is about 2 MB smaller and holds up to 1 MiB less memory, and a further 4 MB smaller with the AVIF coders embedded compressed. [Deployment](/guides/deployment)
- **Roles script on a managed Postgres**: `db/roles.sh` protects `_pgorm_migrations` in any schema, and finishes with a notice when the owner is not a superuser. [Upgrading](/guides/upgrading)
- **A DOM preload and smaller test helpers**: `kay/test/dom` registers happy-dom's DOM, popover API included, for `mount()` in every test file, and `kay/test` exports `cookieJar()`, `solveWork()` and `scratchDir()`. [Testing](/guides/testing#one-component)
- **Test the prebuilt auth pages**: their actions import as `@kaynooo/kayjs-auth/pages/<page>.kay`, for a test to submit them ([kayjs-auth](/llms/kayjs-auth)).
- **Library stylesheets ship only the classes the app uses**: kayjs-ui's theme keeps the rules of the components the app renders and drops the rest. [app.css](/structure/app-css), [Upgrading](/guides/upgrading)
- **kayjs-auth reads a bearer token and its user together**: one query instead of two with the built-in stores; a custom store may add `bearerTokens.findByDigestWithUser`. [kayjs-auth](/libraries/kayjs-auth)
- **Build report per route**: `kay build` prints one row per route with the scripts and stylesheets it loads and whether it was prerendered, the time each stage took and what each cache under `.kay/cache` answered, each size beside its change since the last build, and what the last build had that this one lacks. [kay build](/reference/cli#kay-build)
- **The app preset runs the app as a role that cannot change the schema**: `app_rw` reads and writes rows, the migrations run as the owner, and default privileges cover the tables a later migration creates, pg-orm's migration history table staying read-only to it. [Database roles](/guides/deployment#database-roles), [Upgrading](/guides/upgrading)
- **kayjs-cms loads its guard lazily**: `guard` takes `{ load }`, an async function returning the guard that runs on the first request, so `kay.config.ts` no longer imports the app's auth and database to build one; the built guard still works. [kayjs-cms](/libraries/kayjs-cms)
- **`kay mcp`**: serves the project to an agent as an MCP server over stdio, with tools for `check`, `routes`, `explain`, `render` and the dev server's errors, and the guides as resources. [kay mcp](/reference/cli#kay-mcp)
- **IconPicker pages its search**: "Show more" asks `search(query, limit, offset)` for the next page and adds it, where it asked again for every icon shown. [Upgrading](/guides/upgrading)
- **Request tab shows how the page was answered**: the response headers with the CSP and cache-control first, whether `kay build` prerenders the page, the guards that ran and their outcome, the redirects the request went through before the page and what made them, and the server's time to answer. [kay dev](/reference/cli#kay-dev)
- **Error codes**: a compile, build, content or export error carries a stable code, which `kay explain <code>` documents with the section that covers the fix, and `kay check`, `kay build` and `kay explain` carry as `code` in their `--format json` ([Checks](/reference/checks#errors)); `kay build --static --format json` reports each page it cannot export as its own problem.
- **Head tab in the dev tool**: the page's search result, title and description with their lengths and limit, canonical, alternates, robots and sitemap membership, og and twitter tags with the social card, JSON-LD parsed or failing, and what `kay check` would flag in the head, read again after each page swap. [kay dev](/reference/cli#kay-dev)
- **Env tab in the dev tool**: the variables `publicEnv` sends the browser with their values, a name or value that looks like a secret flagged, and a note when the app sends none. [kay dev](/reference/cli#kay-dev)
- **Images tab in the dev tool**: each image of the page with its variant and format, the size served against the size drawn, the largest contentful paint, and images without dimensions or lazy-loaded in view, outlined on hover. [kay dev](/reference/cli#kay-dev)
- **Performance tab in the dev tool**: LCP, CLS and INP as the page is used, each against its good limit, and the page's HTML, CSS and JS gzipped with the island chunks split out, as dev sizes, beside what the last `kay build` measured for the page's route with its age. [kay dev](/reference/cli#kay-dev)
- **kayjs-ui loads and sorts less**: `LineChart` reads chartist once it is on the page, so an island showing one runs before chartist loads, and a `Table` reads each row's sort value once per sort.
- **Loaders count and get**: a loader takes optional `count`, `body` and `get`, so a CMS lists its collection or opens one entry without running `load` for every entry, `collections({ counts: false })` skips the counting, and reads at the same moment share one run. kayjs-cms reads an entry screen's collection and entry together, and deletes the unused uploads it selects in one scan. [Content](/guides/content)
- **kayjs-mail loads nodemailer later**: with the first SMTP send, or the first `.eml` download of the dev preview, where it loaded with the module, and the dev pages with the first request to one.
- **kayjs-auth loads and waits less**: an app with no passkey and no OAuth provider no longer loads `@simplewebauthn/server` or `jose`, a sign-in answers without waiting on its security-notice mail whatever the `mailer` does (a mailer silent for 30 seconds is given up on, and with 200 mails waiting a new notice is dropped), and the hourly prune and `audit.forget` read through indexes that `db.sync()` creates.
- **Routes tab shows what kay serves**: a "Served by kay" section lists the sitemap, robots.txt, feeds, manifest, favicons, service worker, health check and a library's dev pages such as `/_kay/mail`, each GET path linked, and says why there is no sitemap when `seo` is set without an origin. [kay dev](/reference/cli#kay-dev)
- **`localPath` is stricter**: it also refuses a path that leaves the site once decoded, such as `/%2F/evil.example`, and kayjs-auth's `safeRedirect` now calls it. [Data loading](/essentials/data-loading)
- **kayjs-cms refuses more unsafe bodies**: every tag and attribute kay's sanitizer drops, such as `<bgsound>` or `formaction`, and a script URL in `ping` or `cite`. [kayjs-cms](/libraries/kayjs-cms)
- **Idle queues and rooms ask the database less**: a `queue` looks at its store from one worker and backs off up to `idlePoll`, 10 seconds by default, a job enqueued in the same process still running at once; `sqliteRooms` beats and polls only while a connection is joined, and expired sessions, rooms and failed jobs are cleaned through indexes and one `DELETE`. [Background jobs](/guides/background-jobs), [Rooms](/guides/api-routes)
- **`kay dev` counts repeated lines**: on a terminal, a restart or stylesheet line the same as the one before is rewritten with a count, `(x3)`, instead of repeated. [kay dev](/reference/cli#kay-dev)
- **`shortcut`** binds a keyboard shortcut such as `mod+s` for as long as an island lives, on the page or one element, Cmd on macOS and Ctrl elsewhere. [Islands](/essentials/islands#keyboard-shortcuts)
- **kayjs-ui `Table` `selectable`** adds a checkbox per row, a tri-state select-all with `N selected`, keys of rows that left `rows` dropped, and a `@bulk(keys, clear)` block for bulk actions beside the count, in stacked cards too. [Table](/ui/table)
- **kayjs-ui `SaveForm`** is a form calling a page's action with a sticky bar of unsaved changes, the save under way, Discard and Save, its dirty state read from the form's own controls, leaving with unsaved changes asking and Ctrl+S saving. [SaveForm](/ui/save-form)

- **A reset tells a Segmented's `onChange` `null`**: a Segmented started with none picked tells the app when a reset clears it, and `onChange` is typed `(value: Value | null)` only when `value` is typed nullable. [Segmented](/ui/segmented#none-picked)
- **kayjs-ui `infiniteList` and `LoadMore`** own an infinite-scroll list's rows, offset or cursor paging, the end of the list, a retry after a failed page and the "Loading more" row, dropping a row already shown when the list shifts. [LoadMore](/ui/load-more)
- **Rows without an id keep their fields** when a `for` over plain objects is edited immutably: an edit, a removal or an insertion keeps every other row's nodes and focus. [Templates](/essentials/templates)

- **`markInvalid`** marks a field invalid for one source among several. A refused field in an island stays invalid while a `FormField` still shows a message for it. [Modules](/reference/modules)

## 1.44.0

- **`Button`** is busy and disabled until the promise its `onClick` returned settles, alone among the buttons on one action, and a submit button is busy while its form's async `onSubmit` runs. [Button](/ui/button#busy)
- **`FormField`** `group` with a message marks its fields invalid and described by it, so `focusInvalid` shows the group's tab and focuses its first field. [FormField](/ui/form-field)
- **kayjs-auth cleans up after itself**: once an hour it deletes expired links, codes, invitations and sessions, including sessions ended by a sign-out everywhere or a password change. Its stores also batch reads and deletes into fewer database round trips. A custom store implements `prune`, as [Upgrading](/guides/upgrading#kayjs-auth-stores) covers.
- **kayjs-auth guards sensitive actions harder**. A data export needs a recent sign-in. An email change on a two-factor account needs its code. OpenID Connect providers are checked harder, and a plain Elysia app refuses cross-site session writes. [Upgrading](/guides/upgrading#1440) lists what to change.
- **`Select` and `MultiSelect`** take the type of their options' values, so a union needs no cast and a number option hands back a number. [Select](/ui/select#typed-values)
- **`ConfirmDelete`** toasts a `success` message once through, and `tone="neutral"` words it for a confirm that deletes nothing. [ConfirmDelete](/ui/confirm-delete#a-confirm-that-is-not-a-deletion)
- **`FileDrop`** takes `compact`, a slim row that sits inline in a form. [FileDrop](/ui/file-drop#compact)
- **`TabNav`** carries the query params named in `keep` from tab to tab, such as a period the tabs share. [TabNav](/ui/tab-nav#params-the-tabs-share)
- **`PageHeader`** takes a `@meta` block beside its title and a `description` under it. [PageHeader](/ui/page-header#meta-and-description)
- **`EmptyState`** takes `level` to make its title a heading, the page's `h1` on an error page. [EmptyState](/ui/empty-state#as-the-whole-page)
- **`Segmented`** shows no option picked while its `value` is `null`. [Segmented](/ui/segmented#none-picked)
- **A number `TextInput`** hands back a number, or `null` once emptied, rather than a string. [TextInput](/ui/text-input)
- **AVIF images encode twice as fast**, on kay's own build of the AVIF encoder. [Responsive images](/essentials/styling-and-assets#responsive-images)
- **`images.card.logo`** puts the site's logo at the top left of every share card, an SVG or an image. `kay check` reports a logo the server would refuse. [Social card](/essentials/head-and-seo#social-card)
- **A kingfisher is kay's default favicon**, shown by a site that names none of its own. [Favicon](/essentials/head-and-seo#favicon)
- **`kay render <url>`** prints the HTML a page renders without starting a server, so a script or a coding agent can check a page in one command. [kay render](/reference/cli#kay-render)
- **`--format json`** on `kay build`, `kay routes`, `kay explain`, `kay fmt` and `kay migrate` prints one JSON document, as `kay check` already did. `kay routes --format json` gives a tool every route with its layouts and guards. [Output for tools](/reference/cli#output-for-tools)
- **`kay build` shows its progress** in a terminal: one line redrawn in place, with the step, its time and a bar over the routes it prerenders and the images it encodes. Piped or in CI, it prints the same lines as before. [kay build](/reference/cli#kay-build)
- **`--quiet`** on `kay build`, `kay check`, `kay fmt`, `kay migrate` and `kay new` prints only the problems and one summary line. On `kay dev`, it prints the ready line and errors, no line per restart. [Quiet and plain output](/reference/cli#quiet-and-plain-output)
- **`kay dev` lists its errors in `.kay/dev/errors.json`**, so a coding agent running it in the background reads what broke without a browser, and `kay dev --format json` prints each event as JSON. [Errors without a browser](/reference/cli#errors-without-a-browser)
- **`kay dev` reads keys in a terminal**: `o` opens the browser, `r` restarts, `c` clears the screen, `q` quits. Under `--host` it also prints the address other devices reach it at. [kay dev](/reference/cli#kay-dev)
- **`watch` and `debounced`** from `kay`: `watch` runs on a change only, handed the value before, and `debounced` gives a value once it stops changing. [Islands](/essentials/islands#browser-only-code)
- **Assigning a signal writes it** wherever it was made, `cart = []` on a signal held in a `const`, an import or a prop, and `kay check` reports an assignment to a name holding no signal. [Signals, memos and effects](/essentials/islands#signals-memos-and-effects)
- **Proof of work in a form field**: `workChallenge` and `verifyWork` from `kay/server` make a post cost the sender CPU, with no third-party script. kayjs-auth now uses it as its default CAPTCHA, which [Upgrading](/guides/upgrading#1440) covers. [Forms and actions](/essentials/forms-and-actions)
