This page lists what each release adds, newest first, with a link to where each feature is documented. kay and its libraries share one version number, so one section covers them all. What a release breaks, and what to change in your app, is in [Upgrading](/guides/upgrading).

## Unreleased

- **Test the prebuilt auth pages**: their actions import as `@kaynooo/kayjs-auth/pages/<page>.kay`, for a test to submit them ([kayjs-auth](/llms/kayjs-auth)).
- **kayjs-auth reads a bearer token and its user together**: one query instead of two with the built-in stores; a custom store may add `bearerTokens.findByDigestWithUser`. [kayjs-auth](/libraries/kayjs-auth)
- **Build report per route**: `kay build` prints one row per route with the scripts and stylesheets it loads and whether it was prerendered, the time each stage took and what each cache under `.kay/cache` answered, each size beside its change since the last build, and what the last build had that this one lacks. [kay build](/reference/cli#kay-build)
- **The app preset runs the app as a role that cannot change the schema**: `app_rw` reads and writes rows, the migrations run as the owner, and default privileges cover the tables a later migration creates. [Database roles](/guides/deployment#database-roles), [Upgrading](/guides/upgrading)
- **Build report per route**: `kay build` prints one row per route with the scripts and stylesheets it loads and whether it was prerendered, the time each stage took and what each cache under `.kay/cache` answered, each size beside its change since the last build. [kay build](/reference/cli#kay-build)
- **The app preset runs the app as a role that cannot change the schema**: `app_rw` reads and writes rows, the migrations run as the owner, and default privileges cover the tables a later migration creates, pg-orm's migration history table staying read-only to it. [Database roles](/guides/deployment#database-roles), [Upgrading](/guides/upgrading)
- **kayjs-cms loads its guard lazily**: `guard` takes `{ load }`, an async function returning the guard that runs on the first request, so `kay.config.ts` no longer imports the app's auth and database to build one; the built guard still works. [kayjs-cms](/libraries/kayjs-cms)
- **`kay mcp`**: serves the project to an agent as an MCP server over stdio, with tools for `check`, `routes`, `explain`, `render` and the dev server's errors, and the guides as resources. [kay mcp](/reference/cli#kay-mcp)
- **IconPicker pages its search**: "Show more" asks `search(query, limit, offset)` for the next page and adds it, where it asked again for every icon shown. [Upgrading](/guides/upgrading)
- **Request tab shows how the page was answered**: the response headers with the CSP and cache-control first, whether `kay build` prerenders the page, the guards that ran and their outcome, the redirects the request went through before the page and what made them, and the server's time to answer. [kay dev](/reference/cli#kay-dev)
- **Error codes**: a compile, build, content or export error carries a stable code, which `kay explain <code>` documents with the section that covers the fix, and `kay check`, `kay build` and `kay explain` carry as `code` in their `--format json` ([Checks](/reference/checks#errors)); `kay build --static --format json` reports each page it cannot export as its own problem.
- **Head tab in the dev tool**: the page's search result, title and description with their lengths and limit, canonical, alternates, robots and sitemap membership, og and twitter tags with the social card, JSON-LD parsed or failing, and what `kay check` would flag in the head, read again after each page swap. [kay dev](/reference/cli#kay-dev)
- **Env tab in the dev tool**: the variables `publicEnv` sends the browser with their values, a name or value that looks like a secret flagged, and a note when the app sends none. [kay dev](/reference/cli#kay-dev)
- **Images tab in the dev tool**: each image of the page with its variant and format, the size served against the size drawn, the largest contentful paint, and images without dimensions or lazy-loaded in view, outlined on hover. [kay dev](/reference/cli#kay-dev)
- **Performance tab in the dev tool**: LCP, CLS and INP as the page is used, each against its good limit, and the page's HTML, CSS and JS gzipped with the island chunks split out, as dev sizes, beside what the last `kay build` measured for the page's route with its age. [kay dev](/reference/cli#kay-dev)
- **kayjs-ui loads and sorts less**: `LineChart` reads chartist once it is on the page, so an island showing one runs before chartist loads, and a `Table` reads each row's sort value once per sort.
- **Loaders count and get**: a loader takes optional `count`, `body` and `get`, so a CMS lists its collection or opens one entry without running `load` for every entry, `collections({ counts: false })` skips the counting, and reads at the same moment share one run. kayjs-cms reads an entry screen's collection and entry together, and deletes the unused uploads it selects in one scan. [Content](/guides/content)
- **kayjs-mail loads nodemailer later**: with the first SMTP send, or the first `.eml` download of the dev preview, where it loaded with the module, and the dev pages with the first request to one.
- **kayjs-auth loads and waits less**: an app with no passkey and no OAuth provider no longer loads `@simplewebauthn/server` or `jose`, a sign-in answers without waiting on its security-notice mail whatever the `mailer` does (a mailer silent for 30 seconds is given up on, and with 200 mails waiting a new notice is dropped), and the hourly prune and `audit.forget` read through indexes that `db.sync()` creates.
- **Routes tab shows what kay serves**: a "Served by kay" section lists the sitemap, robots.txt, feeds, manifest, favicons, service worker, health check and a library's dev pages such as `/_kay/mail`, each GET path linked, and says why there is no sitemap when `seo` is set without an origin. [kay dev](/reference/cli#kay-dev)
- **`localPath` is stricter**: it also refuses a path that leaves the site once decoded, such as `/%2F/evil.example`, and kayjs-auth's `safeRedirect` now calls it. [Data loading](/essentials/data-loading)
- **kayjs-cms refuses more unsafe bodies**: every tag and attribute kay's sanitizer drops, such as `<bgsound>` or `formaction`, and a script URL in `ping` or `cite`. [kayjs-cms](/libraries/kayjs-cms)
- **Idle queues and rooms ask the database less**: a `queue` looks at its store from one worker and backs off up to `idlePoll`, 10 seconds by default, a job enqueued in the same process still running at once; `sqliteRooms` beats and polls only while a connection is joined, and expired sessions, rooms and failed jobs are cleaned through indexes and one `DELETE`. [Background jobs](/guides/background-jobs)
- **`kay dev` counts repeated lines**: on a terminal, a restart or stylesheet line the same as the one before is rewritten with a count, `(x3)`, instead of repeated. [kay dev](/reference/cli#kay-dev)
- **`shortcut`** binds a keyboard shortcut such as `mod+s` for as long as an island lives, on the page or one element, Cmd on macOS and Ctrl elsewhere. [Islands](/essentials/islands#keyboard-shortcuts)
- **kayjs-ui `Table` `selectable`** adds a checkbox per row, a tri-state select-all with `N selected`, keys of rows that left `rows` dropped, and a `@bulk(keys, clear)` block for bulk actions beside the count, in stacked cards too. [Table](/ui/table)
- **kayjs-ui `SaveForm`** is a form calling a page's action with a sticky bar of unsaved changes, the save under way, Discard and Save, its dirty state read from the form's own controls, leaving with unsaved changes asking and Ctrl+S saving. [SaveForm](/ui/save-form)
- **kayjs-ui form controls follow a reset**: Checkbox, Toggle, ChipGroup, Segmented, Select, MultiSelect, IconPicker, TextInput, Textarea, MarkdownEditor and RangeInput go back to their defaults on a `form.reset()`, `SaveForm`'s Discard and a reset button included, saved values too, and their `onChange` hears of it. [SaveForm](/ui/save-form)
- **kayjs-ui controls hand the app's `ref` their element**: TextInput, Textarea, MarkdownEditor, Select, MultiSelect, IconPicker, ChipGroup and Segmented call a `ref` put on them once, as a plain element does. [SaveForm](/ui/save-form)
- **kayjs-ui `infiniteList` and `LoadMore`** own an infinite-scroll list's rows, offset or cursor paging, the end of the list, a retry after a failed page and the "Loading more" row, dropping a row already shown when the list shifts. [LoadMore](/ui/load-more)
- **Rows without an id keep their fields** when a `for` over plain objects is edited immutably: an edit, a removal or an insertion keeps every other row's nodes and focus. [Templates](/essentials/templates)
- **Layout `query`** declares the params every page under a layout shares. They are read through `ctx.query` typed and validated with the page's own, and an island's `queryParam` reads them too. [Data loading](/essentials/data-loading)
- **Concurrent static export** writes endpoint files, the sitemap and feeds sixteen at a time, so an endpoint's `GET` no longer runs alone. [Routing](/essentials/routing#endpoint-files)
- **`markInvalid`** marks a field invalid for one source among several. A refused field in an island stays invalid while a `FormField` still shows a message for it. [Modules](/reference/modules)

## 1.44.0

- **`Button`** is busy and disabled until the promise its `onClick` returned settles, alone among the buttons on one action, and a submit button is busy while its form's async `onSubmit` runs. [Button](/ui/button#busy)
- **`FormField`** `group` with a message marks its fields invalid and described by it, so `focusInvalid` shows the group's tab and focuses its first field. [FormField](/ui/form-field)
- **kayjs-auth cleans up after itself**: once an hour it deletes expired links, codes, invitations and sessions, including sessions ended by a sign-out everywhere or a password change. Its stores also batch reads and deletes into fewer database round trips. A custom store implements `prune`, as [Upgrading](/guides/upgrading#kayjs-auth-stores) covers.
- **kayjs-auth guards sensitive actions harder**. A data export needs a recent sign-in. An email change on a two-factor account needs its code. OpenID Connect providers are checked harder, and a plain Elysia app refuses cross-site session writes. [Upgrading](/guides/upgrading#1440) lists what to change.
- **`Select` and `MultiSelect`** take the type of their options' values, so a union needs no cast and a number option hands back a number. [Select](/ui/select#typed-values)
- **`ConfirmDelete`** toasts a `success` message once through, and `tone="neutral"` words it for a confirm that deletes nothing. [ConfirmDelete](/ui/confirm-delete#a-confirm-that-is-not-a-deletion)
- **`FileDrop`** takes `compact`, a slim row that sits inline in a form. [FileDrop](/ui/file-drop#compact)
- **`TabNav`** carries the query params named in `keep` from tab to tab, such as a period the tabs share. [TabNav](/ui/tab-nav#params-the-tabs-share)
- **`PageHeader`** takes a `@meta` block beside its title and a `description` under it. [PageHeader](/ui/page-header#meta-and-description)
- **`EmptyState`** takes `level` to make its title a heading, the page's `h1` on an error page. [EmptyState](/ui/empty-state#as-the-whole-page)
- **`Segmented`** shows no option picked while its `value` is `null`. [Segmented](/ui/segmented#none-picked)
- **A number `TextInput`** hands back a number, or `null` once emptied, rather than a string. [TextInput](/ui/text-input)
- **AVIF images encode twice as fast**, on kay's own build of the AVIF encoder. [Responsive images](/essentials/styling-and-assets#responsive-images)
- **`images.card.logo`** puts the site's logo at the top left of every share card, an SVG or an image. `kay check` reports a logo the server would refuse. [Social card](/essentials/head-and-seo#social-card)
- **A kingfisher is kay's default favicon**, shown by a site that names none of its own. [Favicon](/essentials/head-and-seo#favicon)
- **`kay render <url>`** prints the HTML a page renders without starting a server, so a script or a coding agent can check a page in one command. [kay render](/reference/cli#kay-render)
- **`--format json`** on `kay build`, `kay routes`, `kay explain`, `kay fmt` and `kay migrate` prints one JSON document, as `kay check` already did. `kay routes --format json` gives a tool every route with its layouts and guards. [Output for tools](/reference/cli#output-for-tools)
- **`kay build` shows its progress** in a terminal: one line redrawn in place, with the step, its time and a bar over the routes it prerenders and the images it encodes. Piped or in CI, it prints the same lines as before. [kay build](/reference/cli#kay-build)
- **`--quiet`** on `kay build`, `kay check`, `kay fmt`, `kay migrate` and `kay new` prints only the problems and one summary line. On `kay dev`, it prints the ready line and errors, no line per restart. [Quiet and plain output](/reference/cli#quiet-and-plain-output)
- **`kay dev` lists its errors in `.kay/dev/errors.json`**, so a coding agent running it in the background reads what broke without a browser, and `kay dev --format json` prints each event as JSON. [Errors without a browser](/reference/cli#errors-without-a-browser)
- **`kay dev` reads keys in a terminal**: `o` opens the browser, `r` restarts, `c` clears the screen, `q` quits. Under `--host` it also prints the address other devices reach it at. [kay dev](/reference/cli#kay-dev)
- **`watch` and `debounced`** from `kay`: `watch` runs on a change only, handed the value before, and `debounced` gives a value once it stops changing. [Islands](/essentials/islands#browser-only-code)
- **Assigning a signal writes it** wherever it was made, `cart = []` on a signal held in a `const`, an import or a prop, and `kay check` reports an assignment to a name holding no signal. [Signals, memos and effects](/essentials/islands#signals-memos-and-effects)
- **Proof of work in a form field**: `workChallenge` and `verifyWork` from `kay/server` make a post cost the sender CPU, with no third-party script. kayjs-auth now uses it as its default CAPTCHA, which [Upgrading](/guides/upgrading#1440) covers. [Forms and actions](/essentials/forms-and-actions)
