# What's new, older releases

What each release before 1.105 added, and the end of a newest release that was cut short (`(continued)`), newest first, each feature with where it is documented. The newer releases are in [What's new](whats-new.md); what a release breaks is in [Upgrading](upgrading.md).

## 1.105.0 (continued)

- A page's `page` takes `seo: { title, description, image, canonical, noindex, sitemap, lastmod, search, feed }` and `cache: '1h' | { browser, shared, swr } | 'private' | false`, `head(title=... description=... image=... canonical=... noindex)` takes the same shorthand in a template, and `seo.noindex` in kay.config.ts keeps a whole site out of search engines: see [Head and site metadata](head.md) and [A CDN in front of prerendered pages](cdn-caching.md); `ttl`, `cacheControl` and the top-level `noindex`, `sitemap`, `lastmod`, `search` and `feed` are deprecated (`deprecated-page-seo`, `deprecated-page-cache`).
- `form(action={save} values={todo})` fills every field from a record, text, numbers, dates, checkboxes, radios and selects, a date by its field's type, and a refused post's values still win in the form that posted ([forms](actions.md#fill-a-form-from-a-record)).

- `bind:` works on any prop that has an `on<Prop>Change` callback beside it, so kayjs-ui's controls bind like a `Bindable` prop does: `Dialog(bind:open={open})` is `Dialog(open={open()} onOpenChange={v => open = v})`, an `onOpenChange` written beside it is called after the write, and `kay check` types the bind by the callback ([components](components.md#bind-a-prop-to-the-parents-signal)).
- A `selection` is written like a signal, `selected = id`; `selected.set(id)` is reported as `signal-set-call` and fixed by `kay check --fix` ([components](components.md#signals)).
- Jobs take one handler shape and need no plugin file: every handler is `(input, ctx)` with `ctx.signal`, `ctx.job`, `ctx.log`, `ctx.locale` and a workflow's `ctx.step`; every queue, workflow, schedule and `background` job a file of `src/jobs/` exports is mounted with no default export and no `.use`; `schedule({ every | cron, timeZone, lock, timeout, enabled, boot }, job)` is one shape; `enabled` is on every kind and `timeout` on queues, workflows and schedules ([Queues](queues.md), [Running in production](production.md#background-jobs)).
- Libraries name their stores one way: `ai({ store })`, `mailer({ store })`, `auth({ store })`, `pg<Lib>(db)` and `sqlite<Lib>(path)` on each `/pg` and `/sqlite` entry and `<lib>Tables` for an app's own `ignoreTables`; without a `store`, kay and the libraries share one SQLite file, `data/app.sqlite`, and still read the file of the old name where it exists ([stores](stores.md), [upgrading](upgrading.md)). The old names work until 1.108 and `kay check` fixes them as `deprecated-store-names`.
- `formatDuration('125m')` takes a `Duration` and `formatBytes('1.5kb')` a `ByteSize`, as every other length and size of kay is written; a number of milliseconds for `formatDuration` is deprecated (`deprecated-format-duration`): see [Locales](locales.md).
- An `img` takes `aspect`, `quality`, `sizes` and `placeholder={false}` as attributes, `img(src={hero} aspect="1/1")`, where it spread `image()`: see [Images](images.md); `no-placeholder` and the spread are deprecated (`deprecated-image-options`).

- Test helpers share one shape: each library's `/test` entry has `test(site)` with `reset()`, `site.signInAs({ email })` and `site.signOut()` sign in for every library that joined, `site.expectRefused` and `site.socket.refused` name the refusal helpers, `site.fetchStub({ 'https://api.x/*': json })` answers the app's outgoing `fetch` (an unstubbed call to another host fails the test), `site.freezeTime(at)` stops the clock, and `page.matchScreenshot(name)` compares a page with a baseline beside the test ([Fake the outside world](testing-requests-jobs-sockets.md), [browser tests](testing-browser.md)).
- `kay check` reports `server-import-in-island`: a page that hydrates reads in its template a function only its `--- server` fence imports, which the browser lacks; the offered fix imports it in the script fence too ([Components](components.md#file-layout)).
- A page without a `--- server` fence should not be an island: a handler, a `bind:`, a `ref`, a signal or a live or persisted import in one is the warning `deprecated-page-island` in `kay check`, which still works through 1.107 and which 1.108 refuses ([Islands](islands.md#islands), [upgrading](upgrading.md)).
- kayjs-mail sends through the site that answers the request: `ctx.locals.mail` in a page, an action or a guard, and `contactForm(options)` needs no mailer. Every `MAIL_*` setting is also an option (`url`, `smtp.insecure`, `smtp.rateLimit`, `smtp.dkim`), the forms are kayjs-ui's alone, and `deprecated-mail-send` and `deprecated-mail-form` find the old imports ([kayjs-mail](../packages/mail/llms/writing-and-sending.md#setup)).
- kayjs-ai: `ask`, `describeImage`, `transcribe`, `speak` and `embed` share one `CallOptions` (`provider`, `model`, `signal`, `timeout`, `retry`, `fallback` and the hooks), so a retry (one by default after a transient failure, `retry: false` for none), a fallback or a hook works on every call; `timeout` takes one duration for the whole call ([Asking](../packages/ai/llms/asking.md#options-every-call-takes)).
- kayjs-ai: `locale` takes a BCP 47 tag (`pt-BR`) in `transcribe()` and `describeImage()`, normalised for the provider; `language` is deprecated ([Speech and embeddings](../packages/ai/llms/speech-and-embeddings.md)).
- kayjs-ai: `Chat`, `ChatLauncher` and `ChatPanel` take `labels={{ send, stop, ... }}`, typed as `ChatLabels`, in place of one `<key>Label` prop each ([Chat](../packages/ai/llms/chat.md)).
- One API for each of query params, persisted state, navigation and effects ([state](islands-state-to-ids.md#shared-and-persisted-state), [navigating](navigation-from-code.md), [effects](effects.md)): `queryParam(name, { default, values, history })` is the one signal of a query param, `persisted.cookie()` names the cookie `persisted()` kept, `navigate.query(changes)` changes the query and `navigate(href)` goes to a page, `navigation.onNavigate()` and `navigation.onBeforeNavigate()` are the hooks of the `navigation` source, `listen` takes a function returning its target, `effect`, `onMount`, `debounced` and `throttled` take `{ signal }` as the other helpers do, and `mount`, `s`, `RateLimit` and `sqliteCache` each have one entry. The old forms work until 1.108 and `kay upgrade` rewrites them (`deprecated-persisted-call`, `deprecated-persisted-query`, `deprecated-navigate-query`, `deprecated-navigation-hooks`, `deprecated-listen-target`, `deprecated-import-path`).
- `cms({ access })` is the one option for who may edit: a kayjs-auth role or list of them, `{ password }`, or a function returning the person, inferred from kayjs-auth and `roles` when left out; `roles` and `can` stand alone. See [the cms options](../packages/cms/llms/options.md).
- `CMS_URL` names the forge a production server commits to, `forgejo://TOKEN@git.example.com/owner/repo`, `github://TOKEN@owner/repo` or `gitlab://TOKEN@group/project`, as `MAIL_URL` does for mail. See [setup](../packages/cms/llms/setup.md).
- A cms collection sets its own `uploads`, `fourEyes` and hooks beside the global ones, `history: { revisions: false }` turns the revisions off alone, and `pageLink: { button: false }` keeps the Edit this page hint with no button. See [options](../packages/cms/llms/options.md).
- Enter that confirms an input-method (IME) candidate no longer picks, runs or adds: kayjs-ui's combobox, command palette and markdown editor, kayjs-cms's tag field and kayjs-ai's chat edit, rename and message fields ignore it, as does the `.enter` event modifier (Safari's closing Enter included), and `composing(event)` from `kay` is that check for a handler of your own ([keyboard shortcuts](navigation.md)).

- A form names a field once: `FormField(field="title")` names the bare `input` in it and gives it the schema's constraints, `label(field="name")` writes the label's `for` and the control's `id`, and `button(action={x})` outside a form posts by itself, on a static page and in an island ([forms](actions.md#name-a-field-once)).
- The page flags `keep`, `reload`, `layouts` and `guards` are plain booleans in `page`, an endpoint and an `api()` module (`guards: true` says what the default does), where each took one literal before ([Routing](routing.md#page-settings)).
- An island declares its settings in one place: `island({ render, hydrate, persist, interactive })` first in its script, as it declares its props, replaces the `--- island`, `--- client` and `--- static` fence lines and `export const island`; a use writes `render="client"` for `hydrate="client"` and `server defer` for `server="defer"`. `kay upgrade` rewrites the old forms, which work until 1.108 ([Islands](islands.md#islands)).
- kayjs-ai's `ChatLauncher` is built on kayjs-ui's `SidePanel` and takes `Chat`'s props by type, `Chat` and `ChatLauncher` take `newTab` (`true`, `false` or `'auto'`, as kayjs-ui's links do; `'auto'` by default on the launcher) in place of `links`, and its attachment limits are FileDrop's (`maxFiles`, `maxSize`, one rule for both). A `modal={false}` `SidePanel` takes a `launcher` floating or docked, shaped by `launcherButton` and kept on screen as a toggle by an `openIcon`, and `keep` leaves its content mounted while it is closed ([Chat](../packages/ai/llms/chat.md), [Floating chat](../packages/ai/llms/chat-launcher.md)).
- An explicit `newTab={false}` keeps a link in this tab even where the app's `links.outside` would open it in a new one, for the links of kayjs-ui's components (`tabOf`) and for the reply links of `Chat` and `ChatLauncher`; `links.outside` stays the default where a component says nothing ([Links](../packages/ui/llms/slots-and-links.md), [Chat](../packages/ai/llms/chat.md)).
- A file pasted into a `Chat` now goes through `accept` like a picked or dropped one: a type it refuses is turned back with the `attachRefused` text, where a paste used to skip the type filter ([Chat](../packages/ai/llms/chat.md)).

- Every island source reads and reports the same way: `data()`, `status()`, `pending()`, `error()` and `retry()`, with `onData({ value })` and `onError`, on a `resource`, a `stream`, a `socket`, a `local()` collection and a `track()` handle (`data()` and `status()` on an action too), one `LoadStatus` for reads and one `ConnectionStatus` for connections ([island sources](island-sources.md)). A collection's sync moves under `sync` (`sync.status()`, `sync.queued()`, `sync()`), and `pending()` and `status()` mean what they do everywhere ([local collections](local-collections.md)). `value()`, `last()`, `rows()`, `succeeded()`, `onSuccess` and `onSync` work until 1.108, and `deprecated-source-readers` rewrites them.
- Live values and presence write alike: `live(initial, { key: true })` declares a value per key with a plain starting value, `set(next, { key })` and `set(next, { user })` write one key's or one user's, `presence({ room, member })` takes one object, and every live value tells `onData({ value })` and `onError({ error })` in a browser; `deprecated-live-api` rewrites the old forms ([live values](live-values.md), [island sources](island-sources.md)).
- One `Action` type crosses into components: bare `Action` takes any action, and a `.with()` action crosses into an island with its fields (`Action<never, unknown>` is rewritten by `deprecated-action-type`) ([actions from islands](actions-from-islands.md#pass-an-action-to-a-component)).
- Every component callback takes one event object and one naming rule: `onOpenChange({ open })`, `onChange({ value, option })`, `onSelectedChange({ keys, rows })`; state a prop can hold reports through `on<Prop>Change`, a press through `on<Verb>`, and `tests/callbacks.test.ts` holds the rule. `onChange` of Accordion, Tabs and ThemeToggle is `onValueChange`, ZoomPane's `onPlateChange`, Table's `onSortChange` and a chart's `onActiveChange`, the old names working until 1.108 with a `deprecated-ui-callbacks` fix ([conventions](component-library-conventions.md), [upgrading](upgrading.md)).
- Every guard option is named `guards` and takes a guard, a list, `{ load }` or `false`: `vitals({ guards })`, `jobs: { guards }`, `images: { guards }`, beside a page's and an API module's. A feature that lists or changes private data (`jobs`, `images.resolve`) answers 403 with none, and `requireGuards` is `guards: { default: 'closed' | 'open' }` ([Guards](guards.md#path-and-guard-options)); `kay check --fix` rewrites the old forms.
- Rate limits are one `RateLimit` and one check: `rateLimit(name, limit).check(ctx)` refuses a guard's request with a 429 (`enforce` is deprecated for it) and `.count(request)` gives `{ count, resetAt, wait }`; kayjs-auth's `rateLimit` is grouped by feature (`signIn: { ip, account, accountAll }`, `oauth: { token }`); `deprecated-rate-enforce` and `deprecated-auth-rate-limits` rewrite the old forms, and each kind of route's counting phase is written down ([Rate limits](rate-limits.md#when-a-request-is-counted)).
- `images.rateLimit`, `mcp.rateLimit`, `live.rateLimit` and `basicAuth({ rateLimit })` take a whole `RateLimit` minus `key`: a `store` to count in and an `onLimit` told of each refused request, as an action's does ([Rate limits](rate-limits.md#in-the-libraries)).

- A call to an action no longer reloads the page when its handler invalidated a `cached(..., { live: true })` key the page or a `resource()` follows: the live connection shows exactly the elements that read it, and `refresh: true` still reloads the page. ([actions from islands](actions-from-islands.md), [API from islands](api-from-islands.md)).
- `kay check` holds the context an endpoint file declares, `EndpointContext<{ slug: string }, { org: Org }>`, to its params and the `_guard.ts` files above it, and an `api({ guards: [needsKey] })` module reads what its own guards return as `ctx.guard` with no generic ([Guards](guards.md)). With no generic written, `ctx: EndpointContext` reads its `params`, its `guard` and its `page.query` typed from the file tree and `api()` reads the guards above its module, in `kay check`, which type-checks a shadow of those files.
- A page with `liveRefresh: true` in its settings is left to its live connection after a call whose handler invalidated only cached keys it follows, a streaming action's included (its end event names them), instead of loading again; `resource()` refetches when a tag its route's cached value names is invalidated, even once memory dropped that value, `resource(..., { tags: ['posts'] })` when a call of the page invalidated `posts` for a route reading no cached value, `revalidate: 'focus'` with `stale: '30s'` leaves an answer be for its window, and without `revalidate` a resource asks again only for `refresh()`, an invalidation or a changed option ([actions from islands](actions-from-islands.md), [API from islands](api-from-islands.md)).
- Every feature key of `kay.config.ts` takes `false`, `true` or its options (`robots`, `sitemap`, `favicon`, `security`, `health`, `preview`, `images.avif` and the rest), and `defineConfig` refuses an unknown key in every option bag at any depth, derived from `KayConfig` itself; `proxy: 2` is `proxy: { hops: 2 }`, which `deprecated-config-switch` rewrites ([Project](project.md)).
- The server hooks of kayjs-auth, -mail, -cms and -ai that observe are `after<Verb>`, as `before<Verb>` is the one that may refuse or change: `afterSignUp`, `afterSend`, `afterSuppress`, a list's `afterSubscribe`, `afterConfirm`, `afterUnsubscribe` and `afterBroadcast`, `afterSave` and `afterUpload`, `afterStep`, `afterToolCall` and `afterRequest`. The old `on<Verb>` names work until 1.108 and `deprecated-hook-names` renames them; see [Hooks](hooks.md) and [Upgrading](upgrading.md).
- The config's hooks are flat keys named by the moment they run, `onListen`, `onStop` and `onError` (which left `observe`), every hook event carries one `context` (an action hook's holds the action's own context too), `observe.log` is `{ format, requests, sink }`, and `pages()` and `testSite()` take their config as `{ config }` beside `root`; `deprecated-app-hooks`, `deprecated-hook-context` and `deprecated-pages-options` rewrite the old forms ([Hooks](hooks.md), [Production](production.md), [Project](project.md)).
- `images` is grouped as `remote: { hosts, maxSize, timeout }`, `formats: { quality, webp, avif }` and `limits: { variants, queue }`, and the lists a CMS or a database may hold take a function returning them (or a promise): `cors.origins`, `security.hosts`, `images.remote` hosts, `proxy.trusted`, `redirects`, `robots.disallow` and `allow`, `i18n.paths`, called once as the config loads; `ttl` is how long `signed.sign()`, `files.url()`, `workChallenge()`, kayjs-auth's `proofOfWork()` and an action's `minTime` and `proofOfWork` keep what they made, `maxAge` staying for HTTP and cookies, a store takes every length as a `Duration` (`durations: true`, [Stores](stores.md); a store written before keeps getting milliseconds until 1.108), and `deprecated-images-keys`, `deprecated-ttl-names` and `deprecated-store-ms` rewrite the old names ([Project](project.md), [Images](images.md)).

- `session.start(data, { maxAge })` signs a visitor in at once (new id, data, lifetime) and the session cookie follows `security.cookies`; rooms leave on close by themselves and take `member`, `beforeJoin`, `onJoin` and `onLeave` ([Rooms](rooms.md)); `files.response(key, request, { download })` names a download and `fileAnswer(file, request, { attachment })` from `kay/server` answers any file with `Range` and a download name ([Files](files.md)); `defineContext` comes from `kay/server` and the config's `env` is `envFiles` ([Server](server.md#sessions), [Environment](environment.md)).
- An island hears kay's DOM events through function hooks: `navigation.onStart`, `onError` and `onStall` beside `onNavigate`, and `add.onStart`, `onData` and `onError` on an action for the forms posting it in place, one table mapping each event to its hook ([events](events.md), [navigation](navigation-from-code.md#navigation-state-and-hooks), [actions](actions-from-islands.md)). The events stay for a plain script, `guardLeave` is documented as the preset of `navigation.onBeforeNavigate`, and `deprecated-island-events` reports an island's `listen` of an event and rewrites the swap's.
- `kay check` names the unknown id of a lone `T('nope')` (`T` has no message `nope`) instead of asking for the values of a message that does not exist ([Texts](locales.md#messages-holding-markup)).
- `T('intro', { name, about: text => ... })` renders a message with tags from a script or an expression, `kay check` holding its placeholders and blocks to the message as it does the `T(key="intro")` form ([Texts](locales.md#messages-holding-markup)).
- `guards` on a page, a layout, an endpoint and an `api()` module takes a guard, a list or `{ load }` as well as `false`: `false` skips the guards above, a list runs after them, and a route with guards of its own is covered ([Guards](guards.md)).
- `links`, `offline` and `search` of kay.config.ts are keys of `client`, with the rest of what the browser is given; `deprecated-client-keys` rewrites the old place ([Project](project.md)).
- The config's keys are grouped by concern: `assets` holds `images`, `fonts`, `favicon`, `manifest` and `publicCache`, `ops` holds `observe`, `health`, `metrics` and `jobs`, and `i18n` is `{ locales, default, mode }` with `mode` one of `'prefix'`, `'always'` or `{ domains }`, so a config can no longer give `domains` with `prefixDefault`; `deprecated-config-groups` and `deprecated-i18n-keys` rewrite the old places ([Project](project.md), [Locales](locales.md)).

- A secret of kay.config.ts is one shape, a string, `{ env: 'NAME' }` or `{ file: 'path' }`: `proxy: { key: { header, secret } }`, `mcp: { token }` (was `key`) and the new `ops: { metrics: { token } }`, each `true` or a secret where the environment is the default; `testSite({ config })` takes them as literals, and `deprecated-secret-keys` rewrites the old forms ([Proxies](proxy-and-security.md), [MCP](mcp.md), [Metrics](metrics.md), [Testing](testing.md)).
- An `error` or `pending` line in a snippet or a child component follows the form it is rendered in while it renders, so a field row can hold its own message and busy state; they stay as the markup form of `add.form.error('title')` and `add.pending()` ([Actions](actions.md#show-that-a-form-is-posting), [snippets](templates-elements-slots-snippets.md#snippets)).

Releases before 1.104.3 are in the notes of their releases, at https://git.kaynooo.fr/kaynooo/kayjs/releases.

- A `.ws()` route of an `api()` module speaks one JSON protocol, rooms included: every frame is JSON both ways, so a string, number, boolean or `null` reads back typed; a frame is measured before it is parsed and the upgrade is no longer wrapped; a message that is no JSON or fails `body` is answered `{ error: { key, fields } }`, never the schema, which `socket().onRefused` reads; `rooms({ reply })` checks what a room sends, for a route whose `response` is a status map too and against the models of the app each room's route belongs to; an `api()` route's refused upgrade frees its connection place at once ([API routes](api-routes.md#api-routes), [Rooms](rooms.md)).
- A refusal is one call, `ctx.deny(status, { message, errors, data })` in a guard, a page, an action and an endpoint, and `refuse(status, { ... })` throws it from anywhere; in an action it fails the post as `ctx.fail` did, which is now its deprecated spelling, as are `deny(status, 'text')` and `refuse('text', { ... })`. Helpers refuse a bad argument with a `KayError` coded `argument-invalid` ([Actions](actions.md#refused-posts), [Errors](errors-runtime.md))
- Eight lints that flagged a page shipped broken are errors now, not warnings: `unreturned-fail`, `brace-in-attribute`, `signal-set-call`, `constant-signal`, `literal-tag`, `positional-key`, `unkeyed-rows` and `once-read-prop` ([Lints](lints.md), [upgrading](upgrading.md)).
