# Renaming an entry's slug

## Savers

A `FileSaver` may have `move(move)`, which renames a folder entry's file: `move.from` and `move.to` each hold `repoPath` and `absolute`, `move.text` is the text the file has at `to`, `move.base` the version of `from` (as `change.base` for a save), and `move.message` and `move.author` as in a save. It writes `to` then removes `from` (in one commit on Forgejo) and throws `SaveConflict` when `from` is at another version or gone (`current` is its version, `null` once gone), or when `to` exists (`new SaveConflict(undefined, true)`). `forgejo()` commits the move as one commit (a delete and a create, which git reads as a rename) and `workingTree()` does it in place. A saver without `move` cannot rename entries.

## Renaming

The entry editor's Rename button (off for a collection of one entry and while the form has unsaved edits) asks for a new slug, cleaned as it is typed (Rename is off, with the reason beside the field, for a taken slug or a referrer; a new folder is announced; a refusal shows in the dialog), and opens the entry under it. It calls `POST /api/cms/entries/:collection/:slug/rename` with `{ slug }`, `?locale=` and the `?version=` the editor showed, which the server requires, and the store's `renameEntry(ref, slug, { author, version, required })`: a folder entry's file is moved through the saver, keeping its format and body, and a loaded entry is saved under the new slug and removed from the old, never going to the trash, its history moving with it. A `slug` field in the entry's data is set to the new slug. It is refused, writing nothing, for a new slug that is taken or names another place (`..`, a slash or a hidden part), a collection of one entry, a saver without `move`, an entry another entry refers to by its slug in a `reference` field (the issue names the first three: change them first), and a `version` that is not the entry's. `onSave` gets the verb `rename`, `slug` the new one and `from` the old. `unique` fields do not count the entry's own values as taken by its old slug.

## The old URL

The page the entry had, per locale (`url` as `entries()` gives it), redirects to the page it has now, by itself and with nothing in `kay.config.ts`: the redirect joins the set an editor adds on the Not found screen (307, which an editor can make permanent there), kept in `data/not-found.sqlite`, so it survives a restart, and it answers only where the old path finds nothing. The base and `trailingSlash` are the site's, as for any redirect. Another rename moves every redirect that led to the old page to the new one, so a chain is one hop, and a rename back to an earlier slug removes the redirect from the page that exists again, so there is no loop. An entry with no page of its own, or a page on another locale's domain, gets none. A redirect the set refuses (a path of `kay.config.ts`'s redirects, say) is logged and the rename stays. Translations of a localized entry pair by `translationKey` or, without one, by the slug: set `translationKey` before renaming one locale's slug.
