# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## 1.104.3

- `kay new` writes no `.npmrc`: kay and every package a preset installs (`@kaynooo/eslint`, `@kaynooo/pg-orm`, `@kaynooo/utils`) are on npm, and kay depends on `@kaynooo/cli-kit` 0.46.1, a version npm carries, so a project installs with Bun's defaults and the install pages have no registry step; the generated `Dockerfile` copies `package.json` and the lockfile alone, and an existing project's `.npmrc` stays harmless ([project setup](project-new-and-add.md)).
- A compiled component is smaller: a prop whose default is a literal (a string, number, boolean, `null`, a template with no expression) is written where the prop is read, with no holder, and a branch holding one component compiles to one call; an object, array or function default keeps its holder, so its identity holds across reads ([props](components.md)).
- kayjs-ui: `starfield` works without the space skin and in light mode: `@import '@kayjs/ui/starfield.css'` after the theme, `class="starfield"` on `body`; the dots (eleven, three tints, scattered where `random()` works) read `--color-star`, `--color-star-cool` and `--color-star-warm`, white by night and ink by day, and `kay new`'s starter uses it ([Setup](../packages/ui/llms/setup.md)).
- kayjs-ui: the space skin's sky is now orbit's, denser and in three tints, and `starfield` works without the skin and in light mode: `@import '@kayjs/ui/starfield.css'` after the theme, `class="starfield"` on `body`; the dots (eleven, three tints, scattered where `random()` works) read `--color-star`, `--color-star-cool` and `--color-star-warm`, white by night and ink by day, and `kay new`'s starter uses it ([Setup](../packages/ui/llms/setup.md)).
- `kay upgrade` adds to `devDependencies` the optional peers the app had installed without declaring them (`typescript7`, `axe-core`, `@happy-dom/global-registrator`, `@kaynooo/pg-orm`), at the new kay's range, in text, under `--dry-run` and as `changed` under `--format json` ([kay upgrade](check-and-tools.md)).
- `kay upgrade` warns when it raises a dependency the app shares with kay across a major (a 0.x minor counts), naming the versions and the package's migration file or repository, in text and as `warnings` under `--format json` ([kay upgrade](check-and-tools.md)).
- kayjs-ui: a Meter and a Progress draw their track `surface-strong`, so the unfilled part reads inside a Card or any `bg-surface` box; Toggle's frame, Slider's and AudioPlayer's range track already read at 3:1, and a test holds every track on the background, surface and popover in both schemes and each skin ([Setup](../packages/ui/llms/setup.md)).
- `kay new` starts from orbit's look: kayjs-ui's space skin (the `ui` feature, now in every preset, with `AppHeader`, Space Grotesk and JetBrains Mono through `fonts`), a near-black palette named as kayjs-ui names it (`background`, `foreground`, `border`, `muted`), a starfield behind the page, a hairline on every box, and an accent picker of twelve accents; the palette no longer defines `--color-base`, which made `text-base` paint text the page background ([kay new](project-new-and-add.md)).
- kayjs-ui's `AppHeader` and `SiteNav` are islands only in a use that sets `open`, `onOpenChange` or `link`, so a header with none of them is markup and its menu the browser's popover, with no script of its own ([kayjs-ui](../packages/ui/llms/tables-navigation-and-layout.md)).
- The `text-size-colour` lint reports `text-base` (or another size) in an app whose CSS defines a colour of the same name, such as `--color-base`, where the utility is the font size and the text colour at once ([code lints](code-lints.md)).
- `kay lint --fix` leaves no semicolon in a `.kay` fence: a fix that rewrites code up to the next token (`style/semi` after the `import type` split of `import/consistent-type-specifier-style`) is cut down to what it changes, so it applies instead of being dropped.
- A component reading a `persisted` value (`local`, `session`, `cookie` or `query`) imported from a `.ts` module is an island, as one reading a `live` value is, also when the module re-exports it (`export { x } from`, `export *`) or imports it and exposes it; `kay explain island` says so: [Islands](islands.md).
- A component reading a `persisted` value (`local`, `session`, `cookie` or `query`) imported from a `.ts` module is an island, as one reading a `live` value is, also when the module re-exports it (`export { x } from`, `export *`) or imports it and exposes it (a `live` value or a `signal` reached that way is now found too); `kay explain island` says so: [Islands](islands.md).
- `waitFor(selector, { text })` in a browser test matches a French page's text typed with plain spaces, where kay wrote non-breaking ones (U+00A0, U+202F), and a timeout says when an element holds the text up to its whitespace: [Browser tests](testing-browser.md).
- kayjs-ui: `Meter(segments={[{ value: 5, tone: 'success', label: 'known' }, ...]} max={22})` draws parts of one total end to end, each a `fill` part, and screen readers hear each one ([Meter](../packages/ui/llms/basics.md)).
- A utility a recipe lifts has one rule, in `utilities.recipe`: Tailwind no longer also writes it in `utilities` unless a file, a word of the build or an `@source inline` names it too ([styles](styles-and-assets.md)).

## 1.104.0

- The 1.100 deprecations are gone: the `id` of a kayjs-ui TreeNode and the `id`, `title` and `url` of a Bell item (now `key`, `label` and `href`, with `nodeKey()` removed), `pageSize` of `infiniteList` (`limit`), `cmsSignInAs`, `cmsSignInWith` and `cmsSignOut` (`cmsTest(site)`), and `count` of `CollectionInfo` (`total`): [Upgrading](upgrading.md).
- kay and its libraries are published under the `@kayjs` npm org: `@kayjs/kay`, `@kayjs/ui`, `@kayjs/auth`, `@kayjs/mail`, `@kayjs/cms` and `@kayjs/ai`, on npm and on the Forgejo registry, so no registry setup is needed for them; `kay upgrade` moves an app from `@kaynooo/kayjs*` and `deprecated-package-names` rewrites its imports, see [Upgrading](upgrading.md) and [Project setup](project.md#project-setup).
- The dev tool reads better in a narrow drawer: response headers stack the name over the value, an island's signal types no longer wrap per letter, the Request tab's files sit in one column, and the Not found, Data and Jobs tabs leave the list on an app with no log, database or queue; a library's tab does the same with `offer(false)` ([the dev tool](dev-tool.md#a-tab-for-a-library)).
- kayjs-ui: a Table drawn by a page sorts with no script: its sortable headers become links carrying the sort in the URL (`sortParam` names it, `sort` by default) and the server sorts the rows, so a plain Table ships no island and no JS unless a feature such as `selectable` or `pageSize` is written ([the Table](../packages/ui/llms/table.md#what-a-page-ships)).

## 1.103.0

- The island entry carries no class table when no module an island bundles merges classes at runtime (a class expression, a spread, a part or a recipe): hubble's heartbeat page loads 16.9 KB gzip less JS with the recipe lift, kay's docs home HTML is 21% smaller ([styles](styles-and-assets.md#override-a-class-a-component-sets)).
- `Schema` from `kay` is the type of what `s` builds, taken wherever a schema is (`action`, `defineEnv`, `collection`, an API route's `query`, kayjs-ai's `ask` and `tool`, kayjs-mail's `contactForm`) in place of Elysia's `TSchema`, with `s.typebox` as the documented, unstable way to the TypeBox builder; `TSchema` from `kay/library` works until 1.106 and `kay upgrade` renames it ([schemas](schemas.md)).
- `pages()`, `api()`, `session()`, `schedule()`, `background()`, `queue()`, `workflow()` and a library's mailer return a `KayPlugin` from `kay/server`, kay's own name for the Elysia instance they are in 1.x, with `plugin.elysia` as the documented, unstable way to reach it; `KayExtension`, `shutdown` and a test site's `use` take a `PluginInput`, so an Elysia instance keeps working ([Locals](server.md#mount-a-server-plugin)).
- kayjs-ui: a Table drawn by a page with `sortable={false}` and no feature (`selectable`, `pageSize`, `filter` and the rest) ships no island and no script, through the new `interactive` list of an `export const island`, [documented with islands](./islands.md) and in [the Table](../packages/ui/llms/table.md#what-a-page-ships).
- kayjs-ui: a Table in an island ships only the features the project's call sites write (`selectable`, `expandable`, `exportable`, `columnToggle`, `virtual`, `filter`, `pageSize` and the rest), one variant shared by every island, with nothing to declare; a spread or a Table read as a value keeps them all ([Table](../packages/ui/llms/table.md#what-a-page-ships)).
- kayjs-ui: a BarChart, LineChart or ScatterChart in an island ships only the features the project's call sites write (`marks`, `onMark`, `href`, `onSelect`, `tooltip`), 4 to 8 KB less when none is written ([what a page ships](../packages/ui/llms/table.md#what-a-page-ships)).
- A recipe's utility classes reach the browser as one short class per string, its rule in the `utilities.recipe` layer: smaller HTML, and no recipe classes in the island JS (kayjs-ui list page: 3.4 KB gzip less). An app `class` still wins ([styles](styles-and-assets.md)).

## 1.102.1

- `kay upgrade` raises a dependency the app shares with kay, `elysia` first, to the version kay's range starts at when the app's range or installed copy is below it, so the app and kay install one copy (an app already on the latest kay too, `--dry-run` listing it) and `kay check` no longer fails on Elysia's types ([kay upgrade](check-and-tools.md)).
- `kay upgrade` no longer stops on a stepping stone the registry has pruned: it installs the closest older minor that still holds the lints the stone is there for and says which, and when none installs it names the forms left unfixed and the `llms/upgrading.md` sections to read, then goes on ([kay upgrade](check-and-tools.md)).
- kayjs-ui: the blocks and callbacks of TreeView (`@actions`, `onSelectedChange`, `onOpenChange`), AppSwitcher (`@tile`), AudioPlayer (`@actions`) and BellInbox (`@item`) hand a node, app, chapter or note whose `key` (or `label`) is always set, filled from `id` (`title`) for an item still under the old name, so no `!` or `nodeKey()` is needed (for an item still under the old name the argument is a copy, so `node === mine` is false there). Timeline's `onSelectedChange` hands the same.
- `kay check` reports `innerHTML` bound to a name typed as a string literal, a `for` item over an `as const` array or a `const` string, as the runtime already dropped it: pass `sanitizeHtml(value)` or `trustHtml(value)`, or write the markup out ([templates](templates-elements-slots-snippets.md)).
- The code that posts an action call loads apart from the island: an island holding an action loads it once the browser is idle, so a call made as the page goes away (`keepalive`) finds it in, and the first call fetches it otherwise, trying again after 1 s and 3 s when the fetch fails ([islands](islands.md)).

## 1.102.0

- Content: a `draft` function reads the entry's `excerpt`, `body` and `html` (it saw them empty in production and the CMS), an `s.Date()` that names no day or cannot be decoded is a content problem at its field instead of rolling into the next day or crashing `kay check`, and heading ids keep non-ASCII letters, are never empty and are unique in the entry ([Markdown files](content-markdown-to-caching.md), [upgrade line](upgrading.md)).
- `persisted.query` keeps a cleared field in the URL: an empty string or list is written as `?q=` or `?tags=` when the default is not empty, so a reload reads it as empty, on the server and in the browser alike, and `values` of numbers or booleans match with no `query` schema ([state](islands-state-to-ids.md)).
- kayjs-ui: every control with a `label` takes `showLabel`: RadioGroup, Rating, RangeInput, DateRangeInput, RowsField and Combobox write it above the control on request (a `field` part, the label as `heading`, `title` on RowsField), and Slider, ColorInput, Checkbox and Toggle can drop their text with `showLabel={false}` while `label` still names the control for screen readers. Defaults are unchanged; see [forms](../packages/ui/llms/forms.md).
- `kay new`'s presets no longer include the `accents` picker: `--with accents` or `kay add accents` adds it, and a project made without `ci` or `docker` is told to run `kay add ci` and `kay add docker` ([Scaffold with kay new and kay add](project-new-and-add.md)).
- `--- script` opening a file is written `---`: `kay upgrade` rewrites it (`deprecated-script-fence`), and the one place the word stays is a script after a `--- server`, `--- module` or `--- style` fence, in the [fence table](components.md#file-layout).
- `if user then u` names the value an `if` or `else if` tests, as `await x then v` does, so `as` is only a cast and no longer an alias by the casing of what follows; `if user as u` works until 1.105 and `kay upgrade` rewrites it ([templates](templates.md)).

Releases before 1.102 are in [What's new, older releases](whats-new-archive.md).
