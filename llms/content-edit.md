# Edit mode and the CMS editor

## Edit mode

- Edit mode is preview mode for a CMS editing content on the page: `enterPreview(ctx, { edit: true })` from the CMS's guarded route or `previewUrl(path, { edit: true })` enter it, signed apart so no preview link or cookie becomes one, and `exitPreview` leaves both.
- Everything preview mode does holds, and `editing()` from `kay` is true while the server renders for such a visitor; `editRequested(request)` from `kay/server` tells the same of any request, for the CMS's own API modules and guards. `editedEntry(request, collection, slug)` from `kay/server` tells whether a page rendered in edit mode for the request's cookie read that entry, its collection named as the content config exports it, so a CMS's API serves an edit cookie, tied to no user, only those entries and not a customer or order collection. It is kept in memory per server until the cookie expires, so it is false on another server or after a restart until the page is loaded again.
- In edit mode the page marks what each entry's fields render, with nothing to declare: an element a field's text or number fills whole takes `data-kay-field="<collection>:<slug>[@locale]:<path>"`, the collection named as the content config exports it and the path dotted with indexes (`tags.0`); an attribute a field gives takes `data-kay-field-<name>`; text mixed with other text sits between `<!--kay-field ...-->` and `<!--/kay-field-->`; the element a `for` over a field's array fills takes `data-kay-list`; the element `Content` fills takes `data-kay-body="<collection>:<slug>[@locale]"`, else `<!--kay-body ...-->` comments.
- Islands, the static slots passed to them and the deferred parts of a streamed page stay unmarked, and outside edit mode the markup is unchanged.
- A field is marked wherever the data is read, in the page's fence or in a component, a loop or a snippet the entry's data was handed down to, whole (`Crew({...data})`) or by field (`Echo(text={entry.data.title})`), whatever the fence itself read; a frozen object's fields stay unmarked.
- A field is told apart by its value: a text is marked when it equals one a field gave and that is not rendered yet, the first read when several fields give the same text read together, else the latest one, and the earlier reads of that text are forgotten (a field read up front and rendered after a render and a later read of an equal text goes unmarked), so a field read only in a condition marks no later equal text; a number when it equals one read since a render no field gave, a literal text after a number in the same child (`{from} to {to}`) not counting, so a number is marked though a sibling field is read after it; each part of a mixed child (`{age} ans`) is marked on its own.
- A transformed value (`toUpperCase()`, a formatted date, a joined list) goes unmarked and a blank text is never marked; the editor is told which fields the page read and left unclickable, the transformed ones, those in an island, its props or slots, in the head or in a frozen object, as `unclickable` (see The editor); a string or number read only for logic, a condition or a class say, is listed too, as nothing shows it.
- A text read but never rendered, such as `status` in `if status === 'draft'`, marks a literal `"draft"` rendered right after it, with no field read between, as that field; a number computed equal to one just read is marked as it.
- A collection the content config does not export is named by its folder or loader name.

## The editor

- A CMS's extension gives its editor as `editor: `${import.meta.dir}/editor.kay``, absolute or relative to the project root: an island every page renders at the end of its body in edit mode alone, kept alive across navigations and drafts (`persist`), and given `{ entries, unclickable }`, typed `EditorProps` from `kay/edit`: `entries`, each entry the page read, `{ collection, slug, locale? }`, its head and attributes included, those of the next page once the swap shows it, and `unclickable`, `{ collection, slug, locale?, path, frozen? }` for each field the page read that no marker on its body reaches (a field a marker or a marked list around it covers is left out), `frozen` for one in a frozen object, kayjs-cms naming them in the entry's form. They come in the order the page shows each one's first marked field, not the order the reads resolved in, so a draft render keeps every form in place; an entry showing no marked field, one whose field a draft emptied say, comes after the others, by name.
- An entry read only in a deferred part of a streamed page is missing.
- The pages that extension's own `routes` serve render no editor: its screens and the `_error` or `_404` page one fails with or a guard refuses with, its own or the app's.
- An app page replacing one of its screens renders it, as another extension's pages do; a URL no page serves, `/nope` or `/admin/nope` under its prefix alike, renders none, as kay answers it outside preview mode, its `_404` showing no draft either.
- The editor needs a script the browser runs, and one extension at most gives one.
- The app's `kay check` reports the editor's errors, and those of what it imports, as its own when the extension is linked rather than installed, as a library's fixture app lists it.
- `showDraft(entries)` from `kay/edit`, called from the editor's island, shows the page with entries the editor has not saved in place of theirs, through the page swap, keeping scroll, focus and every island whose props did not change. An entry failing its collection's schema is left out of the render (the page shows its saved text, the other drafts in place) and `showDraft` resolves `{ issues }` for it; the server alone answers 422 `{ issues }` to `/_kay/draft` when any posted entry fails.
- Each entry is `{ collection, slug, locale?, data, body? }`, `collection` the config's export name and `body` Markdown.
- It resolves `{}` once shown, or `{ issues: [{ collection, slug, locale?, path, message }] }` with the entry left out of the render (the others still show) when its data fails the schema, `path` dotted (`tags.0`), `''` with `body: true` for a body that does not compile or uses a component the collection does not name, `''` with `key: 'locale'` for a locale missing from an entry of a localized collection, given to another's or not served by the site, `key: 'slug'` for a slug naming another folder, and a plain `''` for the data as a whole.
- A newer call cancels an older one, and going to another page cancels it too; either resolves `{}`.
- It throws outside edit mode (403), on a body over `bodyLimit` (413) and when the page fails to render (500).
