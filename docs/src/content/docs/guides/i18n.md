Declare the locales in `kay.config.ts`. Every page is then served in each of them. The default locale is unprefixed and the others sit under their prefix: `/about` and `/en/about`.

```ts
export default defineConfig({
  i18n: { locales: ['fr', 'en'], defaultLocale: 'fr' },
})
```

<Callout type="warning">

Do not create `src/routes/en/`: kay already serves every page under each prefix. Give the site an `index.kay`, or a root `[slug].kay` would take `/en` as a slug.

</Callout>

## Messages

Write one file per locale in `src/messages/`, exporting its messages through `defineMessages`. The default locale's file is the reference. `kay check` holds the others to it, and a key a locale lacks falls back to its text.

```ts
// src/messages/fr.ts
import { defineMessages } from 'kay/i18n'

export default defineMessages({
  nav: { home: 'Accueil' },
  greeting: 'Bonjour {name}',
  items: {
    zero: 'Aucun article',
    one: '{count} article',
    other: '{count} articles',
  },
})
```

### A link inside a message

A message can hold tags, `intro: 'Read <about>our story</about>, {name}.'`. `T` renders it, and a block named after each tag draws that part.

```kay
--- server
import { T } from 'kay/i18n'
---
T(key="intro" name="Ada")
  @about(text)
    a(href="/about") {text}
```

The block gets the text inside its tag. The text is escaped, so a value holding `<b>` shows as text.

`kay check` types the key and the placeholders as props. It reports a tag with no block, a block with no tag, and a locale whose message has other tags than the default's.

### Messages from a library

A library listed in `extensions`, such as kayjs-auth's pages, can bring its own catalogs. Its messages sit under the app's, so a key the app's file gives wins.

`auth: { title: 'Connexion' }` in `src/messages/fr.ts` changes that one text and keeps the library's others.

A locale the library does not translate is the app's to fill, and `kay check` says which keys it lacks. For a locale the library translates, the app needs no file.

A site without `i18n` still renders a library's texts, in its `lang`, `en` without one. A `src/messages/<lang>.ts` overrides them key by key the same way.

### Texts kay writes

Some texts a visitor reads are not yours: a form refused for a field too short, a post sent too fast, a server error. kay looks them up in your messages under `kay.*` keys (the sizes in a refusal and the page offline included), and reads its English when you give none. kayjs-ui, kayjs-cms, kayjs-auth, kayjs-mail and kayjs-ai do the same under `ui.*`, `cms.*`, `auth.*`, `mail.*` and `ai.*`.

kayjs-ui and kayjs-mail ship their French, so a French site needs nothing for them, and a key you word yourself wins.

```ts
// src/messages/fr.ts
export default defineMessages({
  kay: {
    invalid: { required: 'Champ requis', tooShort: 'Au moins {min} caractères', tooLong: 'Au plus {max} caractères' },
    protection: { rateLimit: 'Trop d\'essais, réessayez dans {seconds} s' },
    action: { serverError: 'Une erreur est survenue de notre côté' },
  },
})
```

One block words every action, and the form check the browser runs before a post says the same words: a page with a checked form sends the `kay.invalid.*` messages of its locale, so a visitor reads the same text before and after the post. A schema's `error`, an action's `messages` and a component's label still win for the one place that needs its own words. `kayjs-ui` does the same under `ui.*`, and `kay check` accepts these keys in a locale without the default locale having them.

## Using them

`t()` works anywhere a request is served from: pages, components, islands, actions, guards and API handlers. Keys and placeholders are typed from the default locale's file, and an object of plural forms is picked by `count`.

```kay
--- server
import { t, formatDate } from 'kay/i18n'
---
h1 {t('greeting', { name: 'Ada' })}
p {t('items', { count: 3 })}
p {formatDate(new Date(), { dateStyle: 'medium' })}
```

`formatNumber(value, options)`, `formatRelativeTime(date)` (`3 days ago`), `formatList(items)` (`Ada and Grace`) and `locale()` work the same way.

`ctx.locale` gives the locale in pages, guards, endpoints and actions. It is the site's `lang` when `i18n` is off. An island only receives the messages it uses.

### Relative times that keep ticking

`relativeTime` gives a relative time that keeps itself up to date. Read it by calling it, `{ago()}`.

```kay
---
import { relativeTime } from 'kay/i18n'

const ago = relativeTime(() => post.date)
---
p {ago()}
```

The server and the hydrating browser render it from the same moment. It then ticks every second, minute or hour, as far as the date is.

## French typography

French sets a non-breaking space before `:`, `;`, `!` and `?` and inside `« »`, so a mark never lands alone at the start of a line. kay does it for you. On a page whose `lang` is `fr` or starts with `fr-`, write the text as you would anywhere:

```kay
p Voulez-vous continuer ? Oui : non.
p Il dit « bonjour ».
```

The page comes out with a non-breaking space (U+00A0) in each of those places. This holds wherever the text comes from: the template, a prop, a constant in a `.ts` file, a Markdown file of a collection. On a site with `i18n`, only the pages in a French locale are changed. A page in any other language is not touched, and costs nothing.

It changes the text of the page and the `alt`, `title` and `aria-label` of its elements, and the content of its description and title meta tags (not an image `alt`). It leaves alone:

- the text inside `code`, `pre`, `kbd`, `samp`, `script`, `style` and `textarea`
- every other attribute, such as `href` or `value`
- times like `12:30`, URLs, and a colon right after a tag
- a non-breaking space (U+00A0) or a narrow one (U+202F) you typed yourself

It runs on the HTML the server writes, so it covers the streamed parts of a page, the pages `kay build` writes, the static export and the error pages. A streamed part or a server island is read alone, so one placed inside a `pre` or `code` is rewritten, and an `option` without a `value` submits its text, so give it one.

An island's text gets the same spaces in the browser, so a counter reading `Total : 3` keeps its non-breaking space when it updates. The `alt`, `title` and `aria-label` an island sets are left as they are.

The code for it is only built into a site whose `lang` is French or whose `i18n` has a French locale. It adds about 0.2 KB gzipped to the page's script, and a site in another language ships none of it.

To turn it off, set `typography` in `kay.config.ts`:

```ts
export default defineConfig({
  lang: 'fr',
  typography: false,
})
```

## Links and a language switcher

`localize('/about')` is a path in the current locale. `alternate('en')` is the current page in another locale.

```kay
--- server
import { localize, alternate } from 'kay/i18n'
---
a(href={localize('/about')}) About
a(href={alternate('en')}) English
```

A switcher does not need to name its languages. `locales()` lists the locales of your config. `localeName(code)` writes each in its own language, `Français` or `English`.

```kay
--- server
import { alternate, localeName, locales } from 'kay/i18n'
---
nav
  for code of locales()
    a(href={alternate(code)} hreflang={code}) {localeName(code)}
```

Add a locale to `i18n` and the switcher shows it. `alternate(code)` takes `code` as it is, with no `as const`.

### A path per locale

A page can go by another path in a locale. Its untranslated path redirects there unless something else serves it, and `localize` and `alternate` follow.

```ts
export default defineConfig({
  i18n: {
    locales: ['fr', 'en'],
    defaultLocale: 'fr',
    paths: {
      '/about': { fr: '/a-propos' },
      '/blog/:slug': { en: '/articles/:slug' },
    },
  },
})
```

With `site` set, every page also links its copies with `hreflang`, and the sitemap lists them.

A page in a locale written right to left, such as Arabic or Hebrew, gets `<html dir="rtl">`. `direction()` says which way the locale runs.

## Redirecting to the visitor's locale

With `prefixDefault: true`, every locale has a prefix. A path without one redirects to the visitor's locale: the last one they chose, then their browser's `Accept-Language`, then the default.

```ts
export default defineConfig({
  i18n: { locales: ['fr', 'en'], defaultLocale: 'fr', prefixDefault: true },
})
```

To serve each locale on its own host instead, use `domains: { fr: 'example.fr', en: 'example.com' }`. It does not combine with `prefixDefault`.
