# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- kayjs-auth bearer tokens start with `kat_`, expire after 90 days unless `expiresIn: null` asks for none, and an adopted `token` needs 32 characters of 10 kinds, see [Bearer tokens](../packages/auth/llms/oauth-server-and-tokens.md).
- kayjs-auth closes gaps in email codes, OAuth and CAPTCHA: five misses on one session's code no longer delete the code another session was mailed, a reset link is counted before the breached-password service is asked, a repeated sign-in link keeps the flow in flight and never replaces a provider link, an https site refuses plain-http provider endpoints in any environment, a second-factor lockout mails the holder, and the Turnstile and hCaptcha presets check the hostname (and Turnstile the action) ([kayjs-auth](../packages/auth/llms.txt)).
- kayjs-auth keeps personal data no longer than it needs: guests and, with `requireVerified`, accounts never verified are deleted after 30 days (`guests.maxAge`, `email.unverifiedMaxAge`), the audit log keeps each address cut to its /24 or /48 (`audit: { ip: 'full' }` keeps it whole), a provider's tokens are stored only with `keepTokens: true` and revoked at the provider on unlinking and on deleting the account, an erase fails when the audit log cannot be stripped, `exportData()` adds `grants`, `ban` and `invitations`, and the docs say what Turnstile and hCaptcha receive ([kayjs-auth](../packages/auth/llms/oauth-passkeys-two-factor.md)).
- A queue handler takes an `AbortSignal` as its second argument, aborted at `lostAfter` and at shutdown, so a slow job stops instead of running beside its retry, and a job a shutdown stopped is released, its attempt not counted, with an optional `release(id)` on `JobStore` ([Background jobs](production.md#background-jobs)).
- A production `schedule` locks itself by default, named after its schedule and its job's source, so two instances no longer run a digest twice (`lock: false` opts out), and a run past `timeout`, 10 minutes by default, is logged as failed and left so a hung job no longer blocks the schedule or a stop; the job receives an `AbortSignal`, and the job store should be writable there as the lock lives in it ([Background jobs](production.md#background-jobs)).
- A hung AVIF encode or decode no longer blocks image requests for good: a worker task with no answer after two minutes is stopped and fails its request, freeing its slot, see [Images](images.md).
- A hung AVIF encode or decode no longer blocks image requests for good: a worker that answers nothing for two minutes is stopped and fails its tasks, freeing its slot, see [Images](images.md).
- A production build removes a source map it could not keep, and the server never serves `.js.map` files outside development, so the app's island sources cannot go public, see [Islands](islands.md).
- The server render writes no attribute for a function prop, as the browser does, in elements, spreads and `<head>` tags, and treats as markup only what a component, element or island rendered: a JSON value with a `t` string rendered as a child is escaped text instead of raw HTML ([Templates](templates.md)).
- The server render writes no attribute for a function prop, as the browser does, in elements, spreads and `<head>` tags, and treats as markup only what a component, element or island rendered: a JSON value with a `t` string rendered as a child renders nothing instead of raw HTML ([Templates](templates.md)).
- A sitemap past 50,000 URLs or 50 MB becomes an index with the URLs in `/sitemap-1.xml`, `/sitemap-2.xml` and so on, and a `lastmod` that throws or is no date drops that URL's `lastmod`, logged and handed to `onError`, instead of answering 500 for the whole sitemap ([Sitemap](sitemap-search-fonts.md#sitemap-and-robotstxt)).
- An API response failing its route's `response` schema answers 500 instead of 422 and is logged and handed to `onError`, as a throw is; refused input stays 422 ([API routes](api-routes.md)).
- An analytics provider answering 4xx or 5xx to a visit logs one warning per provider and status a minute, and its body is cancelled, so a wrong site id no longer loses stats unnoticed ([Privacy](privacy.md)).
- kayjs-cms checks an upload's bytes against the type its name gives, in any case, so HTML named `x.png`, a JPEG named `x.png` or a file cut before its header is answered 415 (`cms.upload.notReal`) instead of getting a public URL; PNG, JPEG, GIF, WebP, AVIF, PDF and SVG are recognised, any other type is taken as named ([kayjs-cms](../packages/cms/llms.txt)).
- kayjs-auth reports a failed sign-in and the `sign-in-locked` notice after the response, and checks a hash for an account without a password in `verifyEmail` too, so the time taken no longer tells whether an email has an account ([kayjs-auth](../packages/auth/llms/passwords-and-mails.md)).
- kayjs-auth keeps the last owner of an organization, the last admin and a user's last way in when requests race: two owners leaving, demoted or removed at once leave one, two admins revoking each other's role keep one (`revokeRole` answers `last-admin`), and two unlinks or a passkey removal and an unlink at once keep one way in; the write that would leave none is undone, so no store needs a new verb ([kayjs-auth](../packages/auth/llms/admin-and-organizations.md)).
- kayjs-auth keeps the last owner of an organization, the last admin and a user's last way in when requests race: owners leaving, demoted or removed at once leave at least one, two admins revoking each other's role keep at least one (`revokeRole` answers `last-admin`), and two unlinks or a passkey removal and an unlink at once keep a way in; a write that would leave none is undone, so no store needs a new verb ([kayjs-auth](../packages/auth/llms/admin-and-organizations.md)).
- `images.remote` downloads only from public addresses: each hop resolves its host once and connects to the address it checked, refusing loopback, private, link-local and metadata addresses (IPv6 and mapped forms included), and a wildcard on a public suffix such as `*.co.uk` or `*.vercel.app` is refused; a host on a private network is listed by its address or as `localhost` ([Images](images.md#resize-images-from-another-host)).
- Private files are no longer readable by other users of the machine: `diskFiles` writes them at 0600 in 0700 folders, and the image cache holding their copies is a folder only the server's user enters, per app and per user for a compiled executable, never one a link or another user planted ([Files](files.md#private-files)).
- `sqliteRates` keys are never a plain hash of an address or email: with no secret set, each is an HMAC under a random key kept in `<path>.key` beside the store instead of a salt inside it, shared by every process opening it; counts in windows open at the upgrade start over ([Privacy](privacy.md)).
- Every answer behind a guard, a page, an endpoint or an API route, a refusal included, and an API answer that read the session go out `Cache-Control: private, no-cache` with `Vary: cookie`, so a CDN never keeps what a guard read from an `Authorization` header; a route setting its own `cache-control` keeps it ([Routing](routing.md)).
- kayjs-cms refuses a save or a delete of a loaded entry made over a change of it since the editor opened it, by another editor or by the app, with the conflict answer and Keep my edits a folder entry has; the version is a hash of what the loader gave, so a loader needs to give none ([kayjs-cms](../packages/cms/llms.txt)).
- A production site whose `site` is https sends `Strict-Transport-Security: max-age=31536000` on every response, with no `includeSubDomains` or `preload`; `'strict-transport-security': false` in `security.headers` turns it off, and a value replaces it, and the static scaffold's `nginx.conf` sends it too ([Proxy and security](proxy-and-security.md)).
- A font in `public/` is kept 30 days and an image a day without a `publicCache` entry, so a page view no longer costs a 304 per logo or font; `robots.txt`, manifests and scripts still revalidate, and a new static site's `nginx.conf` sets the same times ([Styles and assets](styles-and-assets.md#public-files)).
- The analytics notice and information line name the provider and link `policyUrl`, `kay_analytics` lasts 180 days (`consent.maxAge` up to 13 months) for a refusal as for a yes, `exclude` leaves pages out and the title is sent only with `titles: true`; the notice survives a page swap and takes focus when a click opens it ([Privacy](privacy.md)).
- kayjs-auth refuses a bearer or OAuth token for `deleteOrganization`, `setMemberRoles`, `removeMember`, `leaveOrganization`, `tokens()`, `revokeToken` and `enableTwoFactor`: they need a session, so a leaked API key cannot delete an organization, change roles or manage tokens ([kayjs-auth](../packages/auth/llms/admin-and-organizations.md)).
- kayjs-auth refuses a bearer or OAuth token for `deleteOrganization`, `setMemberRoles`, `removeMember`, `leaveOrganization`, `tokens()`, `revokeToken` and `enableTwoFactor` and every call that asks for a proof (two-factor setup, recovery codes, passkeys, password, address, account deletion): they need a session, so a leaked API key cannot delete an organization, change roles or manage tokens ([kayjs-auth](../packages/auth/llms/admin-and-organizations.md)).
- kayjs-cms documents what its `author` option leaves in git history for good: without it no editor's name or email is committed, and a pseudonym is the safe identity to give ([kayjs-cms](../packages/cms/llms.txt)).
- kayjs-auth titles each account page after its tab ("Security - Your account") instead of the same "Your account" on all seven, so a page swap announces where the user landed ([kayjs-auth](../packages/auth/llms.txt)).
- kayjs-auth's OAuth server gives a client asking for no scope the app's `oauthServer: { defaultScopes }`, else none, not every scope; its issuer never comes from the Host header in production, registrations are limited per address with no shared daily budget, and `impersonate` needs a sign-in or proof from the last ten minutes: [Letting an AI agent sign in](/libraries/kayjs-auth#letting-an-ai-agent-sign-in).
- kayjs-cms: an edit link or cookie reads only the entries the pages it rendered in edit mode read, not every collection (loaded ones included), and a server outside `kay dev` without `cms({ guard })` refuses every save, publish, delete and upload from one and warns at boot; `editedEntry(request, collection, slug)` from `kay/server` gives an API that scope ([kayjs-cms](../packages/cms/llms.txt), [Content](content-cms.md#edit-mode)).
- kayjs-ai's `Chat` and `ChatLauncher` tell the visitor they talk to an AI and that their messages go to a provider, in a line under the conversation (the `ai.chat.disclosure` message, the `disclosure` prop, `disclosure=""` to hide it), and a personal data section says what the provider receives and what to put in the privacy notice ([Personal data](../packages/ai/llms/personal-data.md)).
- kayjs-ai's `ChatLauncher` no longer keeps the conversation in the tab's session storage unless you pass `remember`, so the next visitor to use a tab does not reopen the previous one's; a reload now starts a new conversation ([Chat island](../packages/ai/llms/chat.md#floating-chat)).
- kayjs-ai no longer leaves a public chat unlimited: in production a visitor gets 20 asks per 10 minutes and 100,000 tokens a day unless `ai({ limit, budget })` says otherwise (`false` lifts one), messages past `maxInputChars` (50,000 characters) fail with `too-long` and a 413, and `ask({ tools, confirm })` asks the app before each tool call runs ([Limits](../packages/ai/llms/limits.md), [Confirming a call](../packages/ai/llms/tools.md#confirming-a-call)).
- kayjs-ui `Sortable` and `Board` say a move by arrow key to screen readers (`Moved to 2 of 3`, from `ui.dnd.moved`) through one shared polite live region, `Sortable` gives a bare handle a role and a name, and kayjs-cms list items moved with their buttons or Alt and an arrow are announced the same way; `announce(message)` from `@kaynooo/kayjs-ui/announce` is that region for an app's own moves ([kayjs-ui](../packages/ui/llms/charts-drag-and-media.md)).
- `describeField(ids, { required })` also writes `aria-required="true"` on the first field the component renders, or each field with `'all'`, unless the field writes its own ([Islands](islands.md)). kayjs-ui `FormField` with `required` gives its control, and each field of a `group`, `aria-required="true"`, on a static page and in an island, so a screen reader no longer announces a required field as optional ([kayjs-ui](../packages/ui/llms/forms.md)).
- kayjs-ui `Select` with `submit` no longer posts on every arrow key: a mouse pick submits at once, a keyboard pick waits for Enter or blur ([kayjs-ui](../packages/ui/llms/forms.md)).
- kayjs-auth no longer leaves an organization without an owner when its sole owner deletes their account or an admin deletes it: `deleteAccount` and `deleteUser` answer `last-owner` while the organization has other members, an organization the owner is alone in is deleted with them, and `deletionImpact()` and the account page tell the user which before they confirm ([kayjs-auth](../packages/auth/llms/admin-and-organizations.md)).
- kayjs-auth always asks for user verification when adding a passkey, whatever `passkeys.userVerification` says (it now only sets how hard a second factor answered with a passkey asks), so a passkey that sign-in would refuse no longer counts as a way in ([kayjs-auth](../packages/auth/llms/oauth-passkeys-two-factor.md)).
- `kay/test/preload` gives every test and hook of an app a 20 second timeout, so an `afterAll` that drops a database or stops a server no longer fails at Bun's 5 second hook default on a busy machine; a `[test] timeout` in bunfig.toml stays as the app set it ([Testing](testing.md)).
- `kay/test/preload` gives every test and hook of an app a 20 second timeout, so an `afterAll` that drops a database or stops a server no longer fails at Bun's 5 second hook default on a busy machine; a `[test] timeout` in bunfig.toml sets that time instead, hooks included ([Testing](testing.md)).
- `analytics()` of `ga4`, `fathom`, `cloudflare` and `custom` asks for the visitor's yes unless the app writes `consent: false`, and `plausible`, `umami`, `simpleanalytics` and `matomo` show an information line with an opt-out; the privacy guide gives the CNIL exemption's conditions and each provider's role, agreement and transfer ([Privacy](privacy.md)).
- A page no longer fetches a separate chunk when idle for the stale-build reload: that code is part of the entry, so a page loads one file and about 450 gzip bytes less, and still reloads on the next chunk a deploy dropped ([Production](production.md)).
- `ctx.redirect` refuses a path a browser would read as another host (`//evil.example`, `/\evil.example`, `\\evil.example`, `/%2F/evil.example`), so `redirect(ctx.query.next)` is no longer an open redirect to a protocol-relative URL; `kay check` flags a literal one ([Routing](routing.md)).
- `s3Files` stores each object with the type and `Content-Disposition` its key's extension gives, never the uploader's declared type, so an uploaded HTML page or SVG is a download from the bucket's `publicUrl` instead of running there; files stored by an earlier release must be put again ([Files](files.md)).
- kayjs-auth counts wrong passwords against an account per client (6) and in total (60), so a stranger can no longer keep a holder locked out by guessing at their email from another address; the total mails the holder once, as the new `sign-in-locked` event, and a right password costs nothing ([kayjs-auth](../packages/auth/llms.txt)).
- kayjs-auth counts wrong passwords against an account per client (`signInAccount`, 6, now per client rather than account-wide) and in total (`signInAccountAll`, 60), so a stranger can no longer keep a holder locked out by guessing at their email from another address; the total mails the holder once, as the new `sign-in-locked` event, and a right password costs nothing ([kayjs-auth](../packages/auth/llms.txt)).
- An `onRequest` hook, param matcher, `rewrite` or extension hook that throws is answered with a logged 500 and handed to `onError`, instead of a 200 whose body is the error message ([API routes](api-routes.md)).

## 1.54.1

- The `kay dev` class check no longer reports a class whose only rules mention it inside `:is()`, `:where()` or a variant (`.prose { & :is(.stats) }`, `group-open:`): it judges a class by the rules that need it, as the build does ([Styles and assets](styles-and-assets.md)).
- A constant exported inside a default-exported object or array (`export default { CONTACT }`), or exported later from a `--- server` fence, is judged like one exported where it is declared, so a write through the default import keeps its pages per request ([Prerendering](prerendering.md#prerendering)).
- The build warns of fewer classes it can read: a value read back from the element's own class, `cn`/`clsx`/`twMerge` of names the source writes, a member of a `const` record of literals (`GLASS[tone]`, also one imported from a relative module), a call to a function whose every return is a literal, a ternary or a template of literals, a `let` or `const` read by all its values, and a static export are no longer warned about, and a head's route stylesheet copy no longer outlives the page that replaced it, and a warning names the pages reaching the file ([Styles and assets](styles-and-assets.md)).

## 1.54.0

- `kay dev` restarts once for a save written in place: a second file event for a file whose content it already took in triggers nothing ([kay dev](dev-server.md)).
- `kay dev` serves its first page about 40% sooner, on a third less CPU up to that page: the first server starts once `kay.config.ts` is read instead of after the `.kay/types` tree is written, which now follows when the server listens ([The dev server](dev-server.md)).
- A page ships only its own rules: one whose rules fit the inline limit no longer loads the whole stylesheet after the paint (a `media="print"` link and a `noscript` copy), so a site's first page weighs what it uses. The classes its islands set after load are counted, a production build warns with the island and the line of a class set from a value it cannot read, and Tailwind 4.1's `@source inline("...")` in the app's CSS keeps its classes on every page; `kay dev` logs a `[kay]` error when an element gets a class its page has no rule for ([Styles](styles-and-assets.md#link-or-inline-the-stylesheets)). A page rendered at build time keeps the rules of the classes it shows, and `lateStyles: true` in `kay.config.ts` loads the whole stylesheet after the paint as before.
- An island's script no longer carries the icons of a module it imports without using them, and an island calling `signal()` alone no longer loads the value encoder `persisted()` and action calls share: a site of a few islands and a dozen icons loses about 1.8 KB of brotli ([Images](images.md)).
- kayjs-ai's chat looks finished: `Chat` takes `greeting`, `suggestions` (questions an empty chat sends on a click), `toolLabels` (a reply's tool calls fold into one muted line such as `Searched the docs x2`) and `sendIcon`/`stopIcon`; `ChatLauncher` has a New conversation button and an Enlarge button in its panel header, a filled launcher button that turns into a close icon, a 36rem panel of a fixed height (`--kai-chat-height`, `--kai-chat-height-large`), and `--kai-chat-*` custom properties to theme it ([Chat island](../packages/ai/llms/chat.md#floating-chat)).
- A stream an action call returns to a handler inside a block that the call itself removes, such as a chat suggestion that sends and leaves, is no longer closed with that block: it lasts with the nearest owner still alive ([Streams from islands](api-from-islands.md)).
- kayjs-ai's chat highlights the code of an answer once a block is finished, on the server with the app's own `markdown.highlight` from `kay.config.ts`, and ships no highlighter to the browser; an action returning `.progress()` streams it, an app without a highlighter shows plain code as before ([Chat island](../packages/ai/llms/chat.md)).

## 1.53.3

- kayjs-ai's `ChatLauncher` puts the chat behind a button at the bottom right of every page, opening it in a panel whose JavaScript loads on the first open, keeping the conversation across page swaps and reloads of the tab; `Chat` takes `remember` and `links="here"` for it ([Chat island](../packages/ai/llms/chat.md#floating-chat)). The docs' chat moved from `/ask` to that button. Escape anywhere in a `Chat` stops a reply under way and prevents the event's default, so a dialog or panel around it stays open.
- The `Chat` island opens the links of a reply in a new tab, so following a source no longer swaps the page and drops the conversation ([Chat island](../packages/ai/llms/chat.md)).
- A page is prerendered when the module it imports holds an exported container the build cannot vouch for, as long as the page takes none of it: only the pages importing that export, or something built from it, stay per request. A list of objects such as `export const NAV = [{ id, label, icon }]` (imported icons allowed) read by `for item of NAV`, `NAV.map(item => item.id)` and the like, a constant read by a computed key, and a test that writes to a constant or uses `import * as` on an unrelated module no longer make a module state, and a constant exported by `export { X }`, `export { X as Y }` or `export default X` is judged like one exported where it is declared ([Prerendering](prerendering.md#prerendering)).

## 1.53.2

- A command refused for an option or argument it does not take prints its own usage line alone, `kay build: unknown option --no-chek, did you mean --no-check?` without `parseArgs`'s hint, and `kay build --no-cache` builds without reading what earlier builds left in `.kay/cache` ([Build and start](build-and-start.md)).
- A page importing `image`, `shareImage` or `shareCard` from `kay/image`, or whose layouts, components or modules do, is prerendered like one importing an image, instead of being rendered per request ([Prerendering](prerendering.md#prerendering)).
- A page importing an exported object or array literal of strings, numbers and booleans, such as `export const CONTACT = { email: '...' }`, is prerendered when no file of the project writes to it or hands it on, instead of treating it as module state ([Prerendering](prerendering.md#prerendering)).

Releases before 1.53.2 are in [What's new, older releases](whats-new-archive.md).
