# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- `keslint --cache` lints every `.kay` file again after a kay upgrade, so findings a new kay adds show at once, and a lint message on a prop names it as the file writes it, not `__props.name` ([Checks](checks.md#linting)).
- kayjs-auth's OAuth server ends a refresh token family 90 days after its first token whatever its rotations (a token unused for 30 days is still refused), shows an approved app's last use as its last API call, and asks the user again when an app starts declaring `scopes` after approving a client while it declared none ([kayjs-auth](../packages/auth/llms.txt)).

## 1.50.0

- An MCP client (Claude Code, MCP Inspector) signs in to an app with kayjs-auth and `mcp` through OAuth with no code of the app's: the app serves the authorization server and resource metadata, registration (client ID metadata documents and dynamic), PKCE S256, a consent page, rotating refresh tokens that end their family when reused, and an account page listing approved apps with a revoke button; the tokens are kayjs-auth's bearer tokens, so `user()`, `via()` and `requireUser({ scope })` work unchanged. A Postgres or SQLite app runs `db.sync()` for the four `auth_oauth_*` tables and the two `auth_bearer_token` columns, and a custom store may add the optional `oauth` member ([kayjs-auth](../packages/auth/llms.txt), [API routes](api-routes.md#mcp)).
- A page whose stylesheets pass the 14 KB inline limit now inlines the rules its own components use, Tailwind's utilities included, and links the full stylesheet for the rest without holding the first paint back: a class built at runtime or added by an island still has its rule, nothing to configure, `inlineStyles` still forces one way ([Styles and assets](styles-and-assets.md#link-or-inline-the-stylesheets)).
- `testSite` serves a site under its `base` (or `testSite({ base })`): `visit`, `submit`, `fetch` and `call`'s `from` take paths with or without it, a redirect to a base-prefixed URL is followed with the cookies, and the jar sends a cookie only to the paths its `Path` covers ([Testing](testing.md#test-site)).
- A page carrying inlined stylesheets rendered alike a second time is no longer compressed again: its gzip is kept like any other page's, keyed on what lies around the stylesheets, which serves a short inlined page at about twice the requests per second.
- A live value an island imports is followed on every page rendering the island, so one read behind a click or in a `--- client` island follows the server too; a keyed value read only after the render still does not ([API routes](api-from-islands.md#keep-a-value-current-on-every-open-page)).
- A live connection's lifetime follows the newest proof of the keys it watches, a response nobody reads holds no connection slot, a live value's error names its constant, and a page that no longer holds a live value asks again only every five minutes after a refusal ([API routes](api-from-islands.md#keep-a-value-current-on-every-open-page)).

## 1.49.0

- `requiredInProduction: true` on a `defineEnv` field makes a variable required under `NODE_ENV=production` only, refused at boot there and optional in development and tests; `kay env [--format json]` lists every variable the app, `publicEnv`, its extensions (kayjs-mail's SMTP ones) and kay declare, with whether each is required and its default, for a deploy script ([Server](server.md#environment), [Commands](check-and-tools.md)).
- The `font` shorthand's metric-matched fallback is listed when its size is `var()` or `calc()` too, `font: var(--size) "Inter", sans-serif` included ([Head](sitemap-search-fonts.md#self-host-a-font)).
- kayjs-mail's `send` throws an `Error` with the original value as its `cause` when a transport throws something that is not an `Error` ([kayjs-mail](../packages/mail/llms.txt)).
- `budget: { js: '20kb', css: '10kb' }` in kay.config.ts limits what one page loads, compressed: `kay build` warns with `over-budget` for each page over it, naming the modules weighing most in its scripts, and `kay build --deny-warnings` fails on it ([Build](build-and-start.md)).
- A kay server and `kay build` read the site's URL from `ORIGIN` when `SITE_URL` is unset, `SITE_URL` winning when both are set, so a host or bench starting the server with SvelteKit's `ORIGIN` needs no wiring and its cross-site check accepts that origin ([Head](head.md#site-defaults-and-social-cards)).
- `/mcp` serves `tools/list` behind the API directory's `_guard.ts` as the OpenAPI document is, refused under `requireGuards` unless the guards cover every module; a route answering 401 itself no longer makes it ask for a sign-in, only a guard's 401 does. A `detail.operationId` stays as written in the OpenAPI document (`users.list` was `users_list`) and is kept on an `.all()` route, with the method as a suffix; `unguarded-tool` warns of an options spread. A refused `tools/list` keeps the guard's headers, `Retry-After` of a 429 among them, and a call to a name no tool has is refused as `tools/list` is, so names cannot be probed; a generated id or tool name no longer takes the one a chosen `operationId` is given as a tool ([API routes](api-routes.md#mcp)).
- `live()` makes a value the server changes follow on every open page, read in a template or an island as a signal and written with `set` on the server, with no API module, route or stream; one connection per page carries every live value it reads, and a page reading none opens none ([API routes](api-from-islands.md#keep-a-value-current-on-every-open-page)); its proofs last an hour and renew, a page keeps following across a restart, and a client holds at most 20 connections.

## 1.48.0

- A collection with a `highlight` recompiles its entries when a module the content config imports changes, so a helper the highlighter calls never leaves entries highlighted by its old code ([Content](content.md#caching)).
- A refused cross-site post or request answers 403 in plain text naming the `Origin` it got, the origin or origins kay takes for the site and the `site` setting that fixes a proxy changing the host ([Actions](action-protection.md#cross-site-posts)).
- A server from `kay new`, kay's own server and `./server --health` read `HOST` beside `PORT`, listening on every address when it is unset; `kay dev` keeps its own address ([Project](build-and-start.md#build-one-executable)).
- `kay build` keeps a page, layout or component that reads only `ctx.url.pathname` and `ctx.params`, so a layout marking the current nav link no longer stops every page; `ctx.url.search`, `ctx.url` whole, `ctx.request`, cookies and the rest still do. A kept copy reading the pathname is served at the path it was rendered at and rendered per request at any other spelling of it ([Prerendering](prerendering.md#prerendering)).
- `kay build` keeps a page importing `s`, `withBase`, `sanitizeHtml` or the other exports of `kay` that read nothing from a request, and one using a `persisted` signal kept in `localStorage`; a signal kept in a cookie or the query still reads the request ([Prerendering](prerendering.md#prerendering)).
- The metric-matched font fallback is listed in the `font` shorthand's family list too, and covers a WOFF2 whose `hmtx` table is transformed; `kay dev` reads a swapped font file's metrics again X.
- A site serving its own `/manifest.webmanifest` keeps it in every locale: kay no longer serves or links the per-locale manifests beside it, and changing one locale's `seo.name` no longer renames every share card ([Head](sitemap-search-fonts.md#favicon-and-web-manifest)).
- An `await` block streams any promise it is given, `await data.comments`, a prop or one a component makes, with no `defer()`, and a rejection before it renders crashes no server: `kay check` no longer asks for `defer()` ([Caching and streaming](rendering.md#stream-a-slow-value-into-the-page)).
- `mcp: true` in kay.config.ts serves an MCP endpoint at `/mcp` for agents: a tool per API route of the OpenAPI document and per action that sets `tool`, called through the app's own guards, rate limits and `ctx.locals`; the OpenAPI document gains an `operationId` per operation and the tool actions, `kay check` reports `unguarded-tool`, and `kay/test` has `site.mcp` ([API routes](api-routes.md#let-an-agent-call-the-app)).
- `kay build` keeps a page reading a `collection` over a folder (the call names the folder as a string), in the page or in a module it imports; a collection over a loader still stops it, as its `load` may read a database ([Prerendering](prerendering.md#prerendering), [Content](content.md)).
- A library adds a tab to the dev tool with `devTool: { module }` on its extension, loaded after the tool on dev pages and given the `DevTool` (`kay/dev-tool`) with nothing declared in the app: kayjs-auth shows the session's user with a sign-out, kayjs-mail the outbox with each mail previewed, kayjs-cms the edit mode with a toggle, and kay adds an i18n tab with the page's locale, a link to it in each other locale and the missing message keys ([A tab for a library](component-libraries.md#a-tab-for-a-library)).
- `kay/test/dom` works with `@happy-dom/global-registrator` 20.14.6 or 21.0.3 and later, so an app on either needs no change ([Testing](testing.md#helpers-for-a-test-of-its-own)).
- A `query` or `defineEnv` schema field's `error` may be a function, as an action's field is, and `kay dev` words a form's rules again after a messages file changes ([Actions](actions.md)).

## 1.47.0

- A site with a `seo.name` or `seo.description` per locale links the web manifest and draws the share card name of the page's locale (`/manifest.fr.webmanifest` beside the default locale's), and titles its one OpenAPI document with the default locale's name ([Head](head.md#site-defaults-and-social-cards)).
- `resource(load)` and `stream(source)` read any async function or async iterable in an island, not only an api route, with `loading`, `error`, the latest value, `refresh()` and a slower answer never replacing a newer one ([API routes](api-from-islands.md#read-a-routes-answer-in-an-island)).
- `invalidate` on a `sqliteCache` reads the keys each stored value was built from in a table of their own, not every row, so it stays fast on a large cache; a custom `CacheStore` may offer `dependencies()` for the same ([Caching](rendering.md#keep-a-cached-value-across-restarts)).
- A kayjs-auth profile field's `label` may be an object by locale, `{ en: 'Bio', fr: 'Biographie' }`, `auth.profile(locale)` resolves it, and `requireUser({ redirect: '' })` and `guard({ redirect: '' })` mean no redirect ([kayjs-auth](../packages/auth/llms.txt)).
- The cms editor's Markdown body takes a pasted or dropped image: it uploads to the collection's folder like a file field's and is embedded at the cursor, and a failed `MarkdownEditor` upload now leaves the text exactly as it was ([kayjs-cms](../packages/cms/llms.txt)).
- The dev tool's tabs sit in a vertical rail instead of a row that scrolled sideways, its dock, size and close controls are icon buttons, a button fills the window and the size is remembered, and a Content-Security-Policy header reads one directive to a line ([Dev server](dev-server.md)).
- The editor's ESLint on a fresh app works with no command before it: it runs the new `kay types`, which writes `.kay/types` without checking, the first time it meets a component with no types ([Linting](checks.md#linting)).
- `kay add <features> [dir]` gives an existing project a `kay new` feature (or `mail`, `cms`, the libraries' own), writing the same files and edits and installing what it needs, and stops with the edit to make by hand when a file is not what `kay new` wrote ([Project](project.md#commands)).
- A fresh `app` runs `bun run dev` with Bun alone: its members live in a SQLite file through pg-orm, `bun run dev` migrates it, and its tests and workflow need no Postgres; `kay new --template app --with postgres` keeps the Postgres stack ([Project](project.md#commands)).
- Self-hosted fonts get a metric-matched fallback: a `"Family Fallback"` face (Arial, Times New Roman or Courier New resized to the font) is declared and listed after the family in built stylesheets, so the swap shifts the layout less X.
- `seo.name`, `titleTemplate`, `description`, `image`, `imageAlt` and `locale` take a record of one text per locale, so a multilingual site writes its descriptions in `kay.config.ts` rather than a `meta` tag per page; the head lints check each ([Head](head.md#site-defaults-and-social-cards)).
- A schema field's `error` may be a function, `error: () => t('key')`, which kay calls in the request's locale for the server's refusal and the rules rendered into the page; kayjs-mail's `contactForm` field errors and kayjs-ui's `ContactForm` labels follow the page's language this way, in English and French ([Actions](actions.md)).
- kayjs-mail's `contactForm(mail, options)` and kayjs-ui's `ContactForm` make a contact form of one line, `export const contact = action(...contactForm(mail))` and `ContactForm(action={contact})`: the schema, the link cap, `rateLimit`, `honeypot` and `minTime`, the mail with the visitor in `replyTo`, and worded 503 and 502 refusals come with them, in English and French ([kayjs-mail](../packages/mail/llms.txt), [kayjs-ui](../packages/ui/llms.txt)).
- `kay build` reports a page saying both `keep: true` and `prerender: false` as `unkept-page`, and the route table lists the reason of a route stopped past its 25 rows ([Routing](routing.md)).
- `kay check` reports the head lints of prerendered pages (`untitled-page`, `undescribed-page`, `duplicate-title`, `long-description`, `unsized-share-image`, `noindex-in-sitemap`) at the page's file, without rendering the site ([Checks](checks.md)).
- `server-only-import` also follows a `.ts` module an island imports and a static component the build promotes to an island, and reports a name destructured off a namespace import of `kay/cache` by assignment or a parameter default ([Caching](rendering.md#keep-a-cached-value-across-restarts)).
- `kay check` reports a `match` with no `else` over a finite union whose `when` lines leave members out, naming them (`incomplete-match`; [Checks](checks.md)).

## 1.46.0

- `kay check` now type-checks the pages of an extension the app reaches through a workspace link, as it does an installed one, so an app linking a library may see new diagnostics; kayjs-mail's `authWords` throws for a mail kind kayjs-auth does not send ([Components](component-libraries.md#add-pages-to-the-app-from-a-library)).
- `locales()` and `localeName(code)` from `kay/i18n` list the configured locales and name each in its own language, so a language switcher hard-codes neither ([Locales](locales.md#switch-language)).
- A Markdown entry has `words`, counted from its rendered text, and `readingTime`, the minutes at 230 words a minute ([Content](content.md#reading-entries)).
- `kay check` reports `invalidatePage` or `sqliteCache` imported from `kay/cache` by an island's script or a `--- client` fence, where the browser's entry has `cached` and `invalidate` alone ([Caching](rendering.md#keep-a-cached-value-across-restarts)).
- `kay dev` reloads an edit to a content entry, to a component a collection renders or to a module the content config imports in the running process, in tens of milliseconds, where each started a new process; the terminal and the dev tool's bar say `reloaded in N ms` for such a change and `restarted` only for a new process, and a `restart` event under `--format json` carries `reloaded: true` ([Dev server](dev-server.md)).
- Writing a signal is one rule: assigning works wherever the compiler sees a signal made, and a property or a `let` set from a function is written with `.set`, which `kay check` reports when assigned ([Components](components.md#signals)).
- `proxy: true` is one proxy in front and `proxy: 2` two; `mailExtension('./src/mail')` names the module exporting the mailer, and any extension names its server plugin with `serverModule: { path, export }`, which kay imports as the server starts and `kay build --compile` bakes in; a Fontsource font entry takes `preload` ([Production](proxy-and-security.md#behind-a-proxy), [Components](component-libraries.md#extensions), [Head](head.md)).
- kayjs-auth is declared in one line, `authPages({ auth: () => import('./src/auth') })` (or `authExtension(...)` without its pages), and `auth.requireUser()` gives a page or an action its user, sending an anonymous visitor to sign in and back or refusing a post with a 401; `auth.signInUrl(back?)` builds that URL, sign-out is a post to `/auth/sign-out` with no action of the app, and `createAuth({ pages: { profile } })` adds the app's own fields to the account page's profile form. The account layout's `signOut` action is gone ([kayjs-auth](../packages/auth/llms.txt)).
- `guard<Own>(...)` types the locals a library's guard reads beyond the app's, and `kay check` now type-checks the pages of an extension the app reaches through a workspace link. kayjs-auth ships `@kaynooo/kayjs-auth/browser` (`askPasskey`, `makePasskey`, `canAskPasskey`, `canMakePasskey`, `passkeyFailure`) and the `passkeyAssertion` and `passkeyAttestation` schemas for actions, so passkey code needs no cast or `@simplewebauthn/browser`; its pages and kayjs-mail's words key messages by the catalog's own keys ([kayjs-auth](../packages/auth/llms.txt), [Server](server.md)).
- `schedule` takes a list of jobs, or a table of schedules to jobs, in one plugin, and `boot: true` runs them once as the server starts; `kay build --compile` compiles a project with no `src/server.ts` into kay's own server of its pages, so an app with nothing custom writes no server entry ([Production](production.md#background-jobs), [Build](build-and-start.md)).
- Actions several pages and components share live in an `_actions.kay` of a routes directory, imported by path, no route file needed, and served behind its directory's guards ([Actions](actions.md#declaring-an-action)).
- `form(action={move.with({ id, to: 2 })})` posts fixed fields with no hidden inputs, with or without JavaScript ([Actions](actions.md#forms)).
- `add.track()` gives an island a handle on an action for one component, row or button: its `pending()` reads only its own calls, and a call resolves with `{ ok, data }` or the refusal's `{ ok: false, status, errors, data }` instead of throwing ([Actions](actions.md#calling-from-an-island)).
- Invalidating a `cached` value or a collection refreshes the prerendered pages that read it: `invalidate('posts')` and `news.invalidate()` mark them stale, so a webhook is one line and `invalidatePage` is left for a page no data explains ([Routing](prerendering.md#invalidating), [Content](content.md)).
- `kay new --host github` writes a GitHub Actions workflow in `.github/workflows`, annotating each `kay check` problem on the diff and publishing a static site with GitHub Pages; the host is read from the `origin` remote when the flag is absent, Forgejo by default ([Project](project.md)).
- `LineChart` no longer makes the page scroll past its content when it has many labels: its data table for screen readers sits in a visually hidden block, as a table box ignored the hiding ([kayjs-ui](../packages/ui/llms.txt)).
- Pages, layouts, guards, endpoints and actions share one request context, `RequestContext`: `request`, `url`, `locale`, `params`, `cookies`, `locals`, `headers`, `redirect`, `notFound` and `deny` read and stop the same way in each, an endpoint gets `cookies`, `headers`, `locale`, `redirect`, `notFound` and `deny` it lacked, an action `url`, `notFound` and `deny`, a guard `notFound`, and `redirect` is written as a statement everywhere ([Routing](routing.md#the-request-context)).
- `kay build` shows each route as prerendered, kept or on request with the file and line that stopped a page from being kept, and `page = { keep: true }` has it warn with `unkept-page` when a page it expects kept is not ([Prerendering](prerendering.md#prerendering)).
- Which names need an import follows one rule: what a component is written with (`props`, `signal`, `memo`, `effect`, `onMount`, `onCleanup`, `t`, a server fence's `action`) needs none, and the rest comes from `kay` for browser code, `kay/server` for the server, or its topic's entry. `invalidatePage` moved to `kay/cache` beside `invalidate`, and the docs no longer import `action` in a server fence ([Components](components.md#imports-kay-adds)).
- `secret` in kay.config.ts, or `KAY_SECRET`, signs form stamps, links to private files and the flash cookie, so an app without sessions no longer needs `session()` for one, and the warning about a key of the process names it and never prints under `kay/test` ([Actions](actions.md), [Files](files.md)).
- kayjs-mail: a mailer configured from the environment checks its relay as the server starts and warns, naming `SMTP_INSECURE=true`, when it does not offer STARTTLS, where it was refused only at the first send ([kayjs-mail](../packages/mail/llms.txt)).
- A page writes its stylesheets into its head when together they compress under about 14 KB and links them above, so a short page paints without waiting for a stylesheet request; `inlineStyles: true` and `false` still force one way ([Styles](styles-and-assets.md#link-or-inline-the-stylesheets), [Upgrading](upgrading.md)).
- `kay lint` writes the types ESLint reads for `.kay` files, then runs the project's `keslint`, so linting needs no `kay check` first; a new project's `lint` script is `kay lint --cache`, its `check` script is `kay check` so a warning shows without failing CI, and `eslint` writes the `.vscode/settings.json` that lets the ESLint extension lint `.kay` files ([Checks](checks.md#linting), [Commands](check-and-tools.md)).
- `kay upgrade [dir]` moves `kay` and the kay libraries in `package.json` to their latest version, installs, applies the fixes of each minor it crosses and prints what is left to do by hand; the old forms a minor replaced are the `deprecated` lints, each with a `--fix` ([Commands](check-and-tools.md), [Checks](lints.md#apply-the-quick-fixes)).
- `kay build` lists each island with what makes it one, `onClick, line 4`, and a static component that may render as one with the prop it passes, and `--format json` gives them with the islands of each route ([Islands](islands.md#islands)).
- An action with no input is declared with its handler alone, `action(async (ctx) => ...)`, and called as `signOut()` ([Actions](actions.md#declaring-an-action)).
- A `transformPage` hook gets the page's `locale` beside its `path` ([Routing](prerendering.md#page-hooks)).
- `page.find()` in `kay/test` gives each element's `html`, the markup inside it, beside its `tag`, `attributes` and `text` ([Testing](testing.md#reading-a-page)).

Releases before 1.46 are in [What's new, older releases](whats-new-archive.md).
