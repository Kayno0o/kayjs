Declare the locales in `kay.config.ts`. Every page is then served in each of them, the default one unprefixed and the others under their prefix: `/about` and `/en/about`.

```ts
export default defineConfig({
  i18n: { locales: ['fr', 'en'], defaultLocale: 'fr' },
})
```

<Callout type="warning">

Do not create `src/routes/en/`: kay already serves every page under each prefix. Give the site an `index.kay`, or a root `[slug].kay` would take `/en` as a slug.

</Callout>

## Messages

One file per locale in `src/messages/`, exporting its messages through `defineMessages`. The default locale's file is the reference: `kay check` holds the others to it, and a key a locale lacks falls back to its text. `src/messages/fr.ts`:

```ts
import { defineMessages } from 'kay/i18n'

export default defineMessages({
  nav: { home: 'Accueil' },
  greeting: 'Bonjour {name}',
  items: { zero: 'Aucun article', one: '{count} article', other: '{count} articles' },
})
```

## Using them

`t()` works anywhere a request is served from: pages, components, islands, actions and guards. Keys and placeholders are typed from the default locale's file, and an object of plural forms is picked by `count`.

```kay
--- server
import { t, formatDate } from 'kay/i18n'
---
h1 {t('greeting', { name: 'Ada' })}
p {t('items', { count: 3 })}
p {formatDate(new Date(), { dateStyle: 'medium' })}
```

`formatNumber(value, options)` and `locale()` work the same way, and `ctx.locale` gives the locale in pages and guards. An island only receives the messages it uses.

## Links and a language switcher

`localize('/about')` is a path in the current locale, and `alternate('en')` is the current page in another locale:

```kay
--- server
import { localize, alternate } from 'kay/i18n'
---
a(href={localize('/about')}) About
a(href={alternate('en')}) English
```

With `site` set, every page also links its copies with `hreflang`, and the sitemap lists them.

## Redirecting to the visitor's locale

With `prefixDefault: true` every locale has a prefix, and a path without one redirects to the visitor's locale: the last one they chose, then their browser's `Accept-Language`, then the default.

```ts
export default defineConfig({
  i18n: { locales: ['fr', 'en'], defaultLocale: 'fr', prefixDefault: true },
})
```

To serve each locale on its own host instead, use `domains: { fr: 'example.fr', en: 'example.com' }`. It does not combine with `prefixDefault`.
