# kayjs-auth: OAuth provider presets

The presets `oauth: { name: true }` and `oauth: { name: { ...options } }` take, their options and what each provider gives back. The flow itself (state, PKCE, linking, failures) is in [OAuth sign-in, two-factor and passkeys](oauth-passkeys-two-factor.md).

## Reference

### Provider presets

- `discordProvider()` (`identify` and `email` by default) and `githubProvider()` are presets; any `OAuthProvider` works. Every preset takes `{ scopes, params }`, `params` added to the authorize URL, and one a server can host takes its base `url`: `githubProvider({ url: 'https://git.example.com' })` for GitHub Enterprise Server (its API at `<url>/api/v3`), `gitlabProvider({ url })`, `discordProvider({ url })` for a proxy of Discord's API. A trailing slash is dropped and a path kept, and production refuses an `http://` one. A provider of your own may set `completeUser(raw, { accessToken, scope })` to add what a second request holds to the user endpoint's answer before `normalizeUser` reads it, as the GitHub preset does for `/user/emails`. A provider's `normalizeUser` reports an `email` only when the provider verified it, as the presets do. The Discord preset gives `avatar` and `banner` as CDN URLs, a gif for an animated one, null without one.
- With `scopes: ['read:user', 'user:email']` the GitHub preset reads the primary verified address off `/user/emails`, so a user hiding their email on their profile signs up with it; an unverified or non-primary address is never taken. Without the scope, or when GitHub fails to answer, the profile's public email is used as before.
- OpenID Connect providers take `{ scopes, params, algorithms }` (Apple `scopes` and `params`), `params` added to the authorize URL, such as Google's `{ access_type: 'offline', prompt: 'consent' }` for a refresh token. Their ID token is checked before anything is read off it: signed by a key of the provider's JWKS, by its issuer, for this `clientId`, unexpired, and carrying the nonce the flow sent. The `alg` of the token has to be an asymmetric one (`RS*`, `PS*`, `ES*`, `EdDSA`), never `none` or an `HS*`; `algorithms: ['RS256']` on an OpenID Connect preset narrows it. In production an `http://` issuer, GitLab `url` or discovered endpoint is refused (`NODE_ENV=production`); development and tests take one.
  - `oidcProvider({ issuer, name })`: any provider by its issuer URL (Keycloak, Authentik, Auth0, Okta, Zitadel...), its endpoints read once off `<issuer>/.well-known/openid-configuration` on first use; a discovery that fails is `unavailable` and tried again on the next sign-in. Its `preferred_username` is the username.
  - `googleProvider()`.
  - `microsoftProvider({ tenant })`: `common` (personal and work accounts, the default), `consumers`, `organizations` or one tenant's id. A work account's email is kept only with the `xms_edov` optional claim on the app registration, saying the domain's owner vouches for it.
  - `gitlabProvider({ url })`: gitlab.com, or a self-hosted instance at `url`.
  - `linkedinProvider()`: "Sign In with LinkedIn using OpenID Connect", the product to add to the LinkedIn app. `email` comes only with the `email` scope and when LinkedIn sends it verified; no usernames.
  - `slackProvider()`: Sign in with Slack (OpenID Connect). `params: { team: 'T0123' }` signs into one workspace. No usernames; `name` is the display name.
  - `twitchProvider()`: OpenID Connect, with the `claims` authorize parameter Twitch needs to put `email`, `email_verified`, `picture` and `preferred_username` in the ID token (set by the preset; the email also needs the `user:read:email` scope, on by default). `preferred_username` is the username; Twitch revokes tokens.
  - `facebookProvider({ version })`: Facebook Login on the Graph API, `v27.0` by default (`version` follows Meta's retirements). Scopes `public_profile` and `email`; no email when the account has no valid address, no usernames, no revocation endpoint, and the avatar is the `large` picture.
  - `xProvider()`: OAuth 2.0 with PKCE, the user read off `users/me`. X gives no email through it (`email` is null, so the user signs up without one, and sign-in is by the X account only), and a confidential client authenticates with an HTTP Basic header, which the preset sets through `clientAuth: 'basic'` on the provider (usable by any provider of your own). Scopes `users.read` and `tweet.read`; add `offline.access` for a refresh token, since access tokens last two hours. Its env name is `X_CLIENT_ID` and `X_CLIENT_SECRET`, its route `/auth/x`.
  - Any other OpenID Connect provider needs no preset: `oauth: { name: { provider: oidcProvider({ issuer, name }), clientId, clientSecret } }`. The five above are presets rather than `oidcProvider` recipes because `oauth: { slack: true }` is the one form `kay env` lists the credentials of, and LinkedIn, Slack and Twitch skip the discovery request (Twitch also needs its `claims` parameter).
  - `appleProvider({ teamId, keyId, privateKey })`: `privateKey` is the `.p8` key's PEM text, the app's `clientId` its Services ID, and it takes no `clientSecret`: the preset signs one. Apple comes back with a POST to the callback, which kayjs-auth turns into a GET so the session cookie rides along. Apple names the user only on their first sign-in, so `profile.displayName` reaches `onSignUp` then and never again.
