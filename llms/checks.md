# Checks and lints

## What `kay check` verifies

- Every expression, prop and server name, as TypeScript does.
- `a(href="/todos/1")` and template literals such as `` `/todos/${id}` `` against the pages, the files in `public/`, the GET routes of the modules under `src/api/` and those of the app's Elysia instance once it is registered (see [Project setup](project.md#project-setup)), as are the paths given to `ctx.redirect` in pages and actions, to a guard's `redirect` and to `navigate()`, and an `img` `src`, a `link` `href` (one with `rel="alternate"` excepted, as feeds are not pages) and a `form` `action` written out as text, unless the form posts with another `method` than GET, which a POST route may serve; paths under `/_kay/`, such as resized images, are not checked; kay's own sitemap, robots.txt, favicons and health route count as served; a segment written out where a param checked by a matcher kay ships goes, `/posts/abc` for `posts/[id=integer]`, must be one the matcher takes; a path may be spelled as written or percent-encoded, `/café` or `/caf%C3%A9`; a catch-all such as `docs/[...path]`, or an app route such as `/files/*`, is reached with a trailing slash, `/docs/`, never as `/docs`; a template literal whose start or end is interpolated may reach any page it fits; a plain `string`, relative paths, `//host` and other schemes are not checked.
- Form field names against the action schema.
- Nothing a `.kay` file declares goes unread (`unread-name`): an import, a declaration in either fence, a destructured prop, or a server value neither the template nor the fence reads, whatever the tsconfig says; `.ts` files are left to its `noUnusedLocals`. A name starting with `_` is unused on purpose, and so is a prop destructured beside `...rest`, which it leaves out. The editor reports them too, greyed out, and offers to remove an unread prop. A file with a compile error is not searched for them until it compiles, as the code the error stopped may read them.
- Literal values the server would refuse when it runs: a `ctx.fail` status outside 400 to 599, a redirect target with a scheme other than http(s), such as `javascript:`, or with a line break, and a `cached()` ttl that is not positive. A computed one is checked when it runs.
- Island props a layout or a page with a `--- server` fence passes can be serialized, those of a `{...spread}` included: no functions, blocks with parameters or class instances. A static component passing one renders as an island in its place (see [Islands](islands.md#islands)), and children pass from anywhere.
- No component reads a browser-only global while it renders, and no island branches on `typeof window` (see [Browser-only components](islands.md#browser-only-components)). Reported by `kay check`, the editor, with quick fixes, and `kay build`, and in `kay dev`'s problems panel.
- No island renders from what the server and the browser compute apart: the clock (`Date.now()`, `new Date()`), `Math.random()`, or `toLocale*String` and `Intl` formats given no locale, or for dates no `timeZone`, while it renders; each would make its markup differ from the server's when it hydrates. Reported by `kay check`, the editor and `kay build`, and in `kay dev`'s problems panel.
- Every string field of an action's schema has a `maxLength` (`unbounded-string`), secrets such as a password excepted, so what a visitor can post into one is bounded by the schema rather than by the request body limit. The quick fix adds `maxLength: 200`. Only a schema written inside the `action(...)` call is read, not one held in a variable.
- Every content collection entry against its schema and the components its collection names, and the props a Markdown entry gives each component against the props it takes, as a template's would be: one missing, misspelt or of another type, reported at the entry's line. `kay check` reads the collections before it type-checks for this, and the editor reports them after a save.
- With `i18n`, every `t()` key and its placeholders against the default locale's messages, and every other locale's messages against them: a key one lacks or has alone, a placeholder it drops or adds, plural forms where the default has text. Links may carry a locale's prefix.
- What a page needs to be usable without seeing it: an `img` has `alt` (`alt=""` for decoration) and so has an `input(type="image")` (`missing-alt`), an `iframe` a `title` (`missing-title`), an element with `onClick` is one a keyboard reaches, such as a `button` or an `a`, or has a `role` (`unreachable-click`), a `button` or a link has text, a value or an `aria-label` to announce, an icon alone not counting (`empty-control`), an `input`, `select` or `textarea` has a `label` around it or pointing at its id, or an `aria-label`, `aria-labelledby`, `title` or `placeholder` (`missing-label`), and a heading follows the one before it by at most a level, each branch of an `if` following the heading before the block (`skipped-heading`). An element with a `{...spread}` is not checked, nor one hidden with `aria-hidden="true"` or `hidden`, such as a honeypot field, and a field among a component's children or with an id written as an expression is left alone, its label maybe elsewhere. These are reported by `kay check`, the editor and `kay build`, and in `kay dev`'s problems panel, the page still running meanwhile.
- ARIA and HTML as their specs define them: an `aria-*` attribute ARIA has, the quick fix writing the closest for a misspelt one (`unknown-aria`), a `role` it defines and no abstract one, a list of fallback roles taken (`unknown-role`), a role with the state it needs, such as `aria-checked` on a `switch`, a native `input` excepted (`missing-state`), nothing the keyboard reaches under `aria-hidden="true"`, `tabindex="-1"` taking a field out of reach (`hidden-focusable`), no `tabindex` above 0 (`positive-tabindex`), no `autofocus` outside a `dialog` or an element with `tabindex="-1"` (`autofocus`), no `a` with `onClick` and no `href`, `href="#"` or a `javascript:` one (`link-as-button`), no control inside a link or a button (`nested-control`), no id two elements of a template share, elements in different branches of an `if` or a `match` or blocks of an `await` excepted, nor one written out inside a `for` (`duplicate-id`), a `label(for="...")` pointing at an id of the template, unless a spread or an expression may set one (`dangling-label`), a captions `track` in a `video` that is not `muted` (`missing-captions`), alt text that is not a filename nor says it is an image (`redundant-alt`), and an `autocomplete` value HTML's autofill defines (`invalid-autocomplete`). Only what the markup says for sure is reported: a value written as an expression, a spread or a component is left alone.

What the markup alone cannot tell, such as text too faint on its background, content outside any landmark or an id two islands both render, is checked on the rendered page: every page the dev server serves, `kay dev`'s or `pages({ dev: true })`'s, runs [axe-core](https://github.com/dequelabs/axe-core) once it settled, and again after each page swap, and lists each rule it breaks in the problems panel as `a11y color-contrast: Elements must meet minimum color contrast ratio thresholds`, then a few of the elements breaking it and the page explaining the fix. Production pages never load it. A test checks a page the same way with `page.a11y()` (see [Testing](testing.md#testing)).

`kay check` keeps TypeScript's incremental state, and what its last clean type check read, in `.kay/cache/check`, and its compiles of `.kay` files in `.kay/cache`. When no file that check read has changed since, packages' own included, and no `.kay` file compiles differently, the type check is skipped: a second `kay check` or `kay build` takes a fraction of the first, and `kay build` little more than `kay build --no-check`. A file written within a second before a check counts as changed, so the next check runs TypeScript again.

## Lints and warnings

`kay check`, `kay build` and `kay dev`'s problems panel print a problem as rustc does, and the editor shows the same message, note and help, type errors and their help included, leaving out the type errors `kay check` leaves out (those of a file that did not compile and of a library component the app never imports): `error[missing-alt]: An \`img\` needs \`alt\``, then ` --> src/routes/index.kay:4:3`, the lines at fault with the span underlined and the other places involved labelled, then `= note:` saying why when the message does not, and `= help:` saying what to write instead. A name in brackets is a lint's, and the project sets its level: `deny` reports it as an error, `warn` as a warning, and `allow` not at all. `kay check` prints warnings beside the errors and counts them apart, failing on them only with `--deny-warnings`, which the `check` script `kay new` writes passes; `kay build` and `kay dev` never fail on one. Lints are found while type checking, so a page with one still runs. Beside each open file's problems, the editor runs what `kay check` finds across the project after a save or a change on disk, never on a keystroke: the config, the collections' entries, the locales' messages, what the server refuses when it boots, the settings libraries take and what guards, API modules and matchers export, each shown at its file, open or not.

- `lints` in `kay.config.ts` sets levels over the defaults: `defineConfig({ lints: { 'positional-key': 'deny', 'unread-name': 'warn' } })`.
- Each lint is in a group, `code`, `a11y`, `forms`, `islands` or `seo`, and `lints` takes a group's level for every lint in it, a lint's own level winning: `lints: { a11y: 'warn', 'missing-alt': 'deny' }`.
- `kay check --only seo` prints one group's lints alone, leaving out the other lints and every problem that is no lint, type errors included: an audit, not a check.
- `// kay-allow constant-signal` allows a lint on the line it ends, or, alone on its line, on the line after it, in a fence or in the template; it takes several names separated by commas, and one that is no lint is reported.
- `kay explain` lists the lints with their group; `kay explain seo` lists a group's; `kay explain positional-key` prints one with an example it reports and the same written right.

| Lint | Default | Group | Reports |
| --- | --- | --- | --- |
| `unread-name` | deny | code | A prop, server value, import or declaration nothing reads (see [What `kay check` verifies](#what-kay-check-verifies)). |
| `missing-alt` | deny | a11y | An `img` or `input(type="image")` with no `alt`. |
| `missing-title` | deny | a11y | An `iframe` with no `title`. |
| `unreachable-click` | deny | a11y | An `onClick` on an element no keyboard reaches and no `role` names. |
| `empty-control` | deny | a11y | A `button`, or an `a` with an `href`, with nothing for a screen reader to announce: no text, no value, no `aria-label`, an icon alone. |
| `unknown-aria` | deny | a11y | An `aria-*` attribute ARIA does not define, such as `aria-labeledby`. The quick fix writes the closest one. |
| `unknown-role` | deny | a11y | A `role` ARIA does not define, or an abstract one such as `widget`. |
| `missing-state` | deny | a11y | A `role` with no state it needs, such as a `switch` with no `aria-checked`. |
| `hidden-focusable` | deny | a11y | An element the keyboard reaches on or inside `aria-hidden="true"`. |
| `positive-tabindex` | deny | a11y | A `tabindex` above 0. |
| `link-as-button` | deny | a11y | An `a` with `onClick` and no `href`, `href="#"` or a `javascript:` one. |
| `nested-control` | deny | a11y | A link, button or field inside a link or a button. |
| `duplicate-id` | deny | a11y | An id two elements of a template share, or one written out inside a `for`. |
| `invalid-autocomplete` | deny | forms | An `autocomplete` value HTML does not define. |
| `unbounded-string` | deny | forms | A string field of an action's schema with no `maxLength`. |
| `positional-key` | warn | islands | `for todo, i of todos key={i}` whose rows read `todo.id`: keyed by position, a row added before others hands their markup and state to the wrong rows. The quick fix drops the key, so they are matched by `todo.id`. |
| `identity-key` | warn | islands | A `for` in an island over objects with no `id` and no `key`, matched by the objects themselves: a list rebuilt with new objects builds every row anew. Found by the type check, so by `kay check` and the editor. |
| `missing-label` | warn | a11y | An `input`, `select` or `textarea` with no `label`, `aria-label`, `aria-labelledby`, `title` or `placeholder`. |
| `skipped-heading` | warn | a11y | A heading skipping a level after the one before it, an `h3` after an `h1`. |
| `autofocus` | warn | a11y | `autofocus` outside a `dialog`, on an element without `tabindex="-1"`. |
| `dangling-label` | warn | a11y | A `label(for="...")` pointing at an id nothing in the template has. |
| `missing-captions` | warn | a11y | A `video` that is not `muted` with no captions `track`. |
| `redundant-alt` | warn | a11y | Alt text that is a filename or says it is an image. |
| `constant-signal` | warn | islands | A signal the component script declares and only ever reads: it never changes, so a plain `const` renders the same without the reactivity. |
| `deprecated-schema-name` | warn | code | `t` imported from `kay` for the schema builder, now `s`; `--fix` renames it, in `.kay` fences and the project's own modules alike. |
| `css-import-without-text` | deny | code | A stylesheet imported for a value without `with { type: 'text' }`, whose value Bun and the compiled executable would give apart; in `.kay` fences and the project's own modules alike. |
| `literal-tag` | warn | code | Template text holding an HTML tag, `p Press <kbd>Ctrl</kbd>`: text is escaped, so readers see the tag as written. Text inside `code`, `pre`, `kbd` and `samp`, an entity such as `&lt;kbd&gt;` and a name that is no element, as in `Array<string>`, are left alone. The quick fix writes a pair around plain text, or a void element, as `#[kbd Ctrl]`. |
| `uncaught-await` | warn | code | An `await` block with no `catch` block: once its value rejects, the pending block goes with nothing in its place and the error only reaches the log. A `try` around it does not catch it, a streamed block settling after the page has rendered. |
| `missing-site` | warn | seo | `seo` set with no `site`, in kay.config.ts or `SITE_URL`: no canonical links, `og:url`, sitemap or robots.txt. |
| `missing-description` | warn | seo | A public site with no `seo.description`. |
| `missing-share-image` | warn | seo | A public site with no `seo.image`, and no `.kay` file of the project setting an `og:image`. |
| `default-favicon` | warn | seo | A public site with no `favicon`, showing kay's mark. |
| `untitled-page` | warn | seo | A prerendered page with no `title`. |
| `undescribed-page` | warn | seo | A prerendered page with no description, its own or `seo.description`. |
| `duplicate-title` | warn | seo | A prerendered page with the title of another of the same locale. |
| `long-description` | warn | seo | A prerendered page whose description runs over 160 characters, which search results cut. |
| `unsized-share-image` | warn | seo | A prerendered page whose `og:image` has no `og:image:width`, kay reading no size off it. |
| `noindex-in-sitemap` | warn | seo | A prerendered page whose head says `noindex` while the sitemap lists it; `noindex: true` in `page` does both. |

## SEO lints

The `seo` group reads what search engines and social networks see of a public site: one with `site` or `seo` set, or exported with `kay build --static`. On any other site they are allowed unless `lints` sets them or `seo`. No `// kay-allow` comment reaches them, as no template reports them.

- `kay check` reads kay.config.ts: `missing-site`, `missing-description`, `missing-share-image`, `default-favicon`. They point at kay.config.ts. `missing-site`, `missing-share-image` and `default-favicon` name what a site lacks until it goes public, as a fresh project from `kay new` does, so only `kay build` and `kay check --only seo` report them, never a plain `kay check`, whose `--deny-warnings` they would fail.
- `kay build` reads the head of every page it prerenders once the check passed: `untitled-page`, `undescribed-page`, `duplicate-title`, `long-description`, `unsized-share-image`, `noindex-in-sitemap`. They point at the page's module and name the path; a page rendered per request is not read. One at `deny` fails the build and leaves the last one in place, as a failing check does; `--no-check` reads none.

## Linting

ESLint lints the script and server fences of `.kay` files through `kay/eslint`, which `@kaynooo/eslint` wires in with `kay: true`: an `eslint.config.ts` of `export default defineConfig({ strict: true, kay: true })`, run with `keslint --cache`, which `kay new` writes along with `lint` and `lint:fix` scripts. The processor lints the TSX `kay check` type-checks a component as and reports only what falls in a fence's own code, at its `.kay` line and column; `--fix` rewrites the `.kay` file, a fix reaching into generated code dropped. The template is left to `kay check`, and the rules the generated code around a fence would trip are off in fences: indentation, blank lines and padding, import order and adjacency.

Type-aware rules, such as `ts/no-floating-promises` under `strict`, read the shadow files `kay check`, `kay dev` and the editor's language server write under `.kay/types`, so lint runs after one of them: a component with none yet fails with `has no type information yet: run kay check, or kay dev, before linting it`, and CI runs `bun run lint` after `bun run check`. `.kay/types/kay-shadow.json` records the routes directory and the components only islands render, which the processor compiles each file with, as it cannot read `kay.config.ts`. ESLint and the editor's ESLint run under Node, so `kay/eslint` ships prebuilt for Node, and from source under Bun. The kay extension does not run ESLint: in VS Code, the ESLint extension lints `.kay` files once `eslint.validate`, which replaces the languages it lints, lists `kay` too, `"eslint.validate": ["javascript", "javascriptreact", "typescript", "typescriptreact", "kay"]` in `.vscode/settings.json`.
