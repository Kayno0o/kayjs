# Deprecated lints

## Common tasks

- Move an app off every old form at once: `kay upgrade`, or `kay check --fix --since 1.74` for one minor alone; see [Apply the quick fixes](lints.md#apply-the-quick-fixes).

## Reference

### Deprecated lints

The lints of the `deprecated` group, each the old form a minor replaced, reported for three minors with a safe fix unless its row says otherwise.

| Lint | Default | Group | Reports |
| --- | --- | --- | --- |
| `promoted-island` | warn | deprecated | A static component passing an island a value its type says is a function, or a block with parameters, since 1.92: the build makes it an island itself when it meets one, and `--- island` says so on every page. The promotion works until 1.95. The fix writes `--- island`, applied where the value is always a function and offered, not applied, where its type is a union holding one. A value the type shows is data, such as an action, reports nothing, and so does a call typed `string`, `any` or `unknown`, which the build still promotes: `kay check` does not list every promotion, so a component that ships more JS than expected is found with `kay build`. A `--- static` pin is never rewritten by `--fix`. |
| `implicit-import` | warn | deprecated | A `kay` value or `t` of `kay/i18n` used with no import, since 1.92: every name is imported where it is used, in a `.kay` file and a `.ts` module alike. The compiler adds the imports until 1.95; the fix writes them into the fence's `kay` import or opens a fence, and `kay check --fix` writes the import of any `kay/*` name a file lacks. `ctx` is left out when the app sets a context module: kay then declares a `ctx` typed from that module in the compiled file, and an `import { ctx }` would collide with it, so `ctx` stays implicit there until the 1.95 removal settles how a typed `ctx` is imported. |
| `island-comment` | warn | deprecated | A `// kay-island` or `// kay-static` comment in a script, since 1.92: `--- island` or `--- static` in place of `---`. The comment works until 1.95; the fix writes the fence line, and a `--- client` component only loses its comment. |
| `deprecated-icon-picker-search` | warn | deprecated | A kayjs-ui IconPicker `search`, since 1.92: `icons` takes a set, a promise or a function handed `{ q, limit, offset }`. The old prop works until 1.95. `kay upgrade` writes `icons={({ q, limit, offset }) => (search)(q, limit, offset)}`; an IconPicker that names `icons` too is reported with no fix |
| `deprecated-menu-danger` | warn | deprecated | A kayjs-ui Menu entry flagged `danger: true`, since 1.92: `tone: 'danger'`, the tone every component names a meaning with. The old flag works until 2.0.0. `kay upgrade` writes the tone in the entries written out in a Menu's `items` (array literals, ternaries, `map` callbacks); an entry that names a `tone` too, or spreads or computes a key that may, is reported with no fix, and items built elsewhere are not found. |
| `deprecated-open-change` | warn | deprecated | A kayjs-ui show and hide callback under its name before 1.90: `onToggle` on a Table or TreeView is `onOpenChange` now, as every show and hide state reports. The old name works until 1.93. `kay upgrade` renames the attribute; one written beside `onOpenChange` is reported with no fix. |
| `deprecated-ui-failures` | warn | deprecated | A kayjs-ui failure prop under its name before 1.90: a message is `failureLabel` (`failure` on a CopyButton, ConfirmDelete, FormDialog, RecordButton, SaveForm or AudioPlayer, `errorLabel` on an IconPicker or ImageCropper, `errorMessage` on a kayjs-ai Chat), and a CopyButton's `onFail` is `onError`, which takes `{ error }`. The old names work until 1.93. The fix renames the attribute, except `onFail`, whose argument changes shape and is reported alone. |
| `deprecated-ui-actions` | warn | deprecated | A kayjs-ui block or prop under its name before 1.90, when the controls a component holds beside its own all became `actions`: a Card's `@head`, a FormField's `@action`, an AppHeader's `@end`, a TreeView's `@trailing` and a MarkdownEditor's `@toolbarExtra`, and a ConfirmDelete's `trigger` string, which is `triggerLook` as `trigger` is a block elsewhere. The old names work until 1.93. The fix renames the block or attribute. |
| `deprecated-chat-icons` | warn | deprecated | A kayjs-ai Chat or ChatLauncher icon block under its form before 1.90: `@sendIcon`, `@stopIcon`, `@newIcon`, `@attachIcon`, `@regenerateIcon`, `@editIcon` and `@recordIcon`, and the launcher's `@icon`, `@closeIcon`, `@expandIcon` and `@collapseIcon`, are one `icons` prop, `icons={{ send: SendIcon }}`, each an icon of the app's set or one imported from `~icons/<prefix>/<name>`. The blocks work until 1.93. Reported with no fix, as a block holds any markup where `icons` takes an icon. |
| `deprecated-auth-error` | warn | deprecated | A kayjs-auth result's `error` compared with a kind, `result.error === 'limited'`, `!==` or a `switch (result.error)` over kinds, since 1.92: `error` is an `ErrorShape` with the kind as `code`, so the old comparison is never true, and TypeScript refuses it too. Found where `kay check` types the result as an auth one; a comparison it cannot type keeps TypeScript's own error. `kay upgrade` reads `error.code`; a subject that is no plain `a.b.error` chain is reported with no fix. |
| `deprecated-stream-types` | warn | deprecated | An import of `EventReader` or `StreamRun` from `kay`, since 1.92: `Connection` and `Stream`, the types of the streams `stream()` and a streaming action give. The old names work until 1.95. `kay upgrade` renames the import and every use of it; an aliased import is renamed without its uses, and a file where the new name is taken is reported with no fix. |
| `deprecated-stream-on` | warn | deprecated | `.on(fn)` of a stream or a socket, since 1.92: `.onData(({ value }) => ...)`, the one hook every source hands its data through. The old name works until 1.95. `kay upgrade` renames the method and gives an arrow of one parameter `{ value: parameter }`, wrapping any other callback, on a name bound once to `stream(` or `socket(` from `kay` in the file; a spread, or a callback naming `value` itself, is reported with no fix. |
| `deprecated-stream-open` | warn | deprecated | `.onOpen(reconnected => ...)` of a stream or a socket, since 1.92: `.onOpen(({ reconnected }) => ...)`, the one object argument every hook takes. The old form still compiles, as an object is truthy, so a callback testing `reconnected` runs on every open. `kay upgrade` gives an arrow of one plain parameter `{ reconnected: parameter }`, on a name bound once to `stream(` or `socket(` from `kay` in the file; a function reference, which may take either form, and any other callback are reported with no fix. |
| `deprecated-local-state` | warn | deprecated | `pending()` and `status()` of a `local()` collection, since 1.92: `unsynced()` and `syncStatus()`, as every other source reads `pending()` as a boolean and `status()` as `idle|loading|ready|failed`. The old names work until 2.0, which gives them that meaning, so this lint stays past the three minors of the others and a template rendering `{todos.pending()}` would read `true` then. `kay upgrade` renames the method, and a `status()` compared with a string reads `'unsynced'` for `'pending'`, on a name bound once to `local(` from `kay` in the file, its template included; a `status()` read in any other way is reported with no fix. |
| `deprecated-hook-dispatch` | warn | deprecated | An import of `notify` or `NotifyOptions` from `kay/library`, since 1.92: `dispatch` and `DispatchOptions`, so `notify` names only the inbox of `kay/server`. The old names work until 1.95. `kay upgrade` renames the import and every use of it; an aliased import is renamed without its uses, and a file where the new name is taken is reported with no fix. |
| `deprecated-library-names` | warn | deprecated | An import of an export under its name before 1.91, since 1.91, when the libraries' constructors became nouns and every Postgres helper took one `PgSource`: kayjs-auth's `createAuth` is `authCore`, `createGate` is `authGate`, `createRoleHierarchy` is `roleHierarchy`, `createWsAuthStore` is `wsAuthStore`, `memoryAuthStore` is `memoryAuth` and `pgStore` is `pgAuth`, kayjs-cms's `createDrafts` and `createEntryForm` are `cmsDrafts` and `cmsEntryForm`, kayjs-mail's `createMailSuppressionTable` and `mailListTables` from `/pg` are `createMailSuppressionTables` and `mailListTableNames`, `PgJobsSource` is `PgSource`, and the `sql` key of a `pgLoader({ ... })` is `source`. The old names work until 1.94. `kay upgrade` renames the import and every use of it, or the key; an aliased import is renamed without its uses, and a file where the new name is taken is reported with no fix. |
| `deprecated-escape-option` | warn | deprecated | The escape of kayjs-auth's `auth()` under its name before 1.91: `plugin: false` is `server: false`, as `mail({ server: false })` is. Works until 1.94. The fix renames the key. |
| `deprecated-size-limits` | warn | deprecated | A size limit under its name before 1.90, when every size limit came to be `maxSize` and a map by path `maxSizeByPath`: the `maxAttachmentBytes` of a kayjs-ai `ask`, the `maxFileSize` of its `Chat` and the `maxSize` map of an extension, now `maxSize`, `maxSize` and `maxSizeByPath`. The old names work until 1.93. `kay upgrade` renames the key; one set beside its new name is reported with no fix. |
| `deprecated-hook-names` | warn | deprecated | A hook under its name before kay and its libraries named their hooks by one rule, since 1.92: kayjs-auth's `onAuthEvent` is `onEvent`, and its `onDelete`, which runs before the account goes and can keep it, is `beforeDelete`; kayjs-ai's `onRequest` is `beforeRequest`, its `onFinish` is `onSuccess`, and its `onError` is told `{ error, context }` where it was told the error; kayjs-ui's `onSaved` is `onSave` on a Form, FormDialog or SaveForm, `onSent` is `onSend` on a ContactForm or SubscribeForm, `onEnded` is `onEnd` on an AudioPlayer, and a SaveForm's own `onSave`, the call that does the save, is `save`. The old names work until 1.95. `kay upgrade` renames the key (not `onDelete`, whose `beforeDelete` is cut off after 10 s and refuses on `false` or a throw: change it by hand) in the kayjs-ui tags of a template (a SaveForm `onSave` only when it has no `action` and no spread, and that one is offered but not applied, as the component may need `--- island`; a no-parameter `onSave` beside an `action` is a warning with no fix), in the options written out at a call of `auth`, `authCore` or `createAuth` and in the `export const hooks` of `src/auth.ts`, and in those of `ai` and `ask`, where it also writes `({ error })` for the parameter of an `onError` written there as a function; a key set beside its new name, or an `onError` that is not written out, is reported with no fix. |
