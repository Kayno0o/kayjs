# kayjs-ui: Icons, buttons, dialogs, cards, popovers and stats

## Common tasks

Each component spreads the other attributes it is given onto its root element, `id`, `aria-*` and `data-*` included. The exceptions: Toggle and Checkbox spread them on their checkbox, Popover on its panel, Menu, AppSwitcher and ConfirmDelete on their trigger, CommandPalette on its dialog and Toaster on its root; FormDialog on its Dialog (its `id` pairs the footer's submit with the form, so it goes on the form), Bell on the BellInbox it draws and TooltipHost on its panel (its `id` is the one tooltips point at, so it stays). `tests/contract-rest.test.ts` fails for a component with no rest spread.

### Icon, Button, IconButton

- `Icon(icon="close")`: an `svg.kui-icon`. It is decorative unless `label` names it for screen readers. `icon` is a slot or an imported `~icons` icon.
- `Button(label="Save" tone="accent" icon="plus")`:
  - `variant` names the form: `solid` (the default, framed), `ghost` (no frame until hovered) or `inline` (reads as a link). `tone` names the meaning: `neutral` (the default), `accent` for the main action, `success` for a confirming one, `danger` for a destructive one, `warning` or `info`. `size` is `xs`, `sm`, `md` or `lg`.
  - `pressed` makes it a toggle button: it writes `aria-pressed` (`true` or `false`) and draws an accent keyline while on, on every variant, so a row of options or an on/off switch needs no CSS. Leave it out for a button that is no toggle.
  - Its label stays on one line; a row of buttons wraps whole buttons, as the dialog and panel footers do.
  - A promise returned by `onClick` holds that button alone busy (spinner in place of the icon, `aria-busy`) and disabled until it settles; a rejection is logged. A `type="submit"` button is busy (spinner, `aria-busy`, clicks ignored) the same way, but not disabled, while its `onClick` or its form's `onSubmit` returns a promise.
  - An explicit `busy` shows a spinner and sets `aria-busy` and has the last word; it does not disable the button.
  - `spinner={false}` keeps the icon and label while the button is busy, and the button still disables itself until its promise settles: for a button that draws its own progress, such as an overlay in its slot.
  - `expanded` sets `aria-expanded`, for a button that opens a panel.
  - `disabled` with a `data-tooltip` renders `aria-disabled="true"` instead, so the keyboard still reaches the button and TooltipHost shows why it is off: its press does nothing and a `submit` or `reset` one turns plain, as SaveForm's buttons already are. A `popovertarget` or `command` on it does nothing either, and a disabled `IconButton` or `BareIconButton` does the same, its label being the tooltip.
  - `type` defaults to `button`, so a button inside a form never submits it by accident: pass `type="submit"` to submit. Children render after `label`.
  - `href` makes it a link looking like a button, `a.kui-btn`, taking a link's attributes such as `target` in place of `type`, `expanded` and `disabled`. A site path in `href` is not checked against the pages the way a literal `a(href)` is. An `onClick` on a link runs before the navigation, which goes on unless the handler calls `event.preventDefault()`.
- `IconButton(icon="delete" label="Delete")`: an icon alone, or a snippet drawing it, `IconButton(label="Send")` with `@icon` and its markup. `BareIconButton` (`bare-icon-button.kay`) is the same button with the drawing nested inside and no icon lookup, for an island drawing only its own `svg`, which then ships none of the default icons. `label` names it for screen readers and shows as its tooltip through TooltipHost. `size` is `xs`, `sm`, `md` or `lg`; `variant` is `solid`, `ghost` or `inline` and `tone` any `Tone`. `href` renders a link with the same look, parts and tooltip, for an action that navigates; IconButton and BareIconButton both take it.

### toast and Toaster

`toast.success|error|info|warning(message)` shows a message from an island, `Toaster` draws them: see [toast and Toaster](toasts.md).

### Dialog, ConfirmDelete

```kay
---
import { editing } from 'kay'
---
Dialog(open={editing()} title="Rename" onOpenChange={() => editing = false})
  @footer
    Button(label="Cancel" onClick={() => editing = false})
    Button(label="Rename" tone="accent" onClick={rename})
  input.kui-field-input(name="name")
```

- `size` is the width: `sm`, `md` (the default) or `lg`, and `full` fills the viewport less its margin in both directions. `bare` drops the body's inset and scroll, for content that runs to the edge, such as a pan and zoom canvas, which then fills the body (`.h-full`); the title and footer keep theirs.
- Dialog, SidePanel, FormDialog and CommandPalette are one overlay family: `size` takes the same names, and Dialog and SidePanel share a head line with a close button (`closeLabel`, `Close`), `@actions` before it, `@header` for the whole line and `@close` for the button, `closeHref` (the close button is a link, `onOpenChange` optional, so a server page shows it) and `modal={false}` (beside the page, open on the server), `dirty` (also locks the close button), FormDialog passing them on.
- Dialog is a modal `dialog`. It closes when its parent sets `open` to false, on Escape, or on a click outside. `onOpenChange(false)` runs however it closed. Closed by Escape or a click outside, its content is still there to read; closed by the parent, it is already gone. Its title names it for screen readers, an `h2` unless `level` says otherwise.
- Once something has been typed inside, Escape, a click outside and the close button ask "Discard changes?" with `confirm()` and close it only once the reader agrees; `discard={{ title, message, confirmLabel, cancelLabel }}` words the question and `discard={false}` locks the close instead. While `dirty` is set (for example while a request is in flight) they leave it open. `autosave` (Dialog, SidePanel, FormDialog) says the fields save as they are typed, so typing asks nothing: a click outside and Escape close it as before anything was typed, and `dirty` still locks it.
- `await confirm({ message, title, tone, confirmLabel })` asks from any handler and resolves a boolean, with no mount: see [confirm and ConfirmHost](toasts.md#confirm-and-confirmhost). ConfirmDelete is its `danger` preset.
- `ConfirmDelete(message="Delete this post?" failureLabel="Could not delete" onConfirm={remove})` renders a trigger that opens a dialog asking before deleting:
  - `onOpenChange(open)` is called with `true` when the trigger is pressed and `false` once the dialog or the armed pair goes, as Dialog's: `onOpenChange={open => open && ask()}` runs `ask` for a `message` read then, such as one that waits on a request; set a signal there and pass it as `message`.
  - While the promise `onConfirm` returns is pending, the dialog's buttons are disabled.
  - `disabled` disables the trigger and the confirm button while the caller is busy, such as a save running: a dialog already open stays open, its confirm button disabled until `disabled` goes false.
  - Once it resolves, the dialog closes. If it throws, the dialog stays open and `failureLabel` is toasted, or a refusal of the whole call such as a limit, as `attempt` does; an `onConfirm` made with `call()` is read the same way, its `ApiError` toasting the route's own words.
  - `refused` reads a refusal of the action's handler, or the `data` of an `ApiError`, as `attempt` does, and its message is toasted in place of `failureLabel`: `ConfirmDelete(... failureLabel="Could not delete" refused={(data: { error: string }) => data.error})`.
  - `open` shows the dialog or the armed pair when the app sets it, `triggerLook="none"` draws no trigger: `ConfirmDelete(triggerLook="none" open={asking()} onOpenChange={open => asking = open} ...)`. `onOpenChange(false)` follows a cancel, Escape and a finished delete.
  - `triggerLook="button"` makes the trigger a labelled danger button rather than an icon, and `triggerLook="link"` a plain underlined text button, for a confirm inside running text. `label` renames the trigger, for "Revoke link" or "Empty trash", and `class` goes on it. `size` and `variant` style the icon trigger only, a `variant` giving it the `tone` too (danger-coloured by default, neutral for `tone="neutral"`; the icon is neutral without one), `size` also sizing the cancel button when asking inline.
  - `success` is toasted once `onConfirm` went through.
  - `title` (`Confirm Deletion`), `confirmLabel` (`Delete`) and `pendingLabel` (`Deleting…`) replace the dialog's words: `ConfirmDelete(message="Rotating breaks every link already shared." failureLabel="Could not rotate" onConfirm={rotate} triggerLook="link" label="Rotate link" title="Rotate link" confirmLabel="Rotate" pendingLabel="Rotating…")`.
  - `tone="neutral"` is for a confirm that is not a deletion, such as a save with a consequence: accent buttons, a check icon, and the title and confirm button worded by `label` (`Confirm`) unless given: `ConfirmDelete(tone="neutral" triggerLook="button" label="Save" message="Save without your own IP?" failureLabel="Could not save" success="Saved" onConfirm={save})`.
  - `ask="inline"` asks in place instead of in a dialog, for a row of a list: a click hides the trigger and shows a danger button saying `confirmLabel` and a cancel button, the focus on the first. `message` names the pair for screen readers and is the danger button's tooltip. Escape or cancel brings the trigger back, focused; a failed delete toasts and stays armed, the focus back on the danger button.

### Card, Badge, EmptyState, Notice, Avatar

- `Card(title="Traffic")`: a `section.kui-card` that frames its children in its `body` part. `@actions` sits at the far end of the title's line, for a count or a link. `bare` drops the body's inset, for content that runs to the edge, such as a table. The title is an `h3`, or the heading `level` given, from 1 to 6: `level={1}` for a card that is the page's content, such as a sign-in panel, whose title is then the page's `h1`. `skipped-heading` reads a template's own headings, so it counts none for a Card's title.
- `RelativeTime(date={post.date})`: a `time` worded relative to now (`3 hours ago`) in the page's locale, ticking in the browser as `relativeTime` does and hydrating the text the server drew, with the full date as a tooltip the keyboard reaches (`tabindex="0"`, shown by TooltipHost). `date` is a `Date`, a timestamp or a string `new Date` reads, a date it cannot read renders nothing. `options` is `Intl.RelativeTimeFormat`'s (`{ style: 'short' }`), `dateOptions` `Intl.DateTimeFormat`'s for the tooltip (`{ dateStyle: 'long', timeStyle: 'short' }` by default, in the server's time zone unless `timeZone` is set). `focusable={false}` leaves out the tab stop, for one inside a link or a focusable row. It is an island.
- `Badge(label="Draft" tone="warning" icon="info")`: `tone` is `neutral`, `accent`, `success`, `warning`, `danger` or `info`. Children render after `label`. `variant` is `outline` (the default), `solid` or `stamp`. `stamp` draws it as a rubber stamp: a hairline in its ink, small spaced mono capitals, its ground turning `stamp-fill-hover` while a `.group` holding it, such as a card link, is hovered. A tone colours a stamp as it does a badge. `solid` fills the badge with its tone, for every tone (neutral included), the text in `--color-accent-foreground`.
- `EmptyState(title="No posts yet" description="Write the first one.")`: what a list shows when it holds nothing. `level` (1 to 6) makes the title a heading, `level={1}` for one standing for the whole page, such as a 404, which then needs no hidden `h1`; without it, the title is a paragraph. An `@actions` block sits below the description, for the button that adds the first item: `EmptyState(title="No posts yet")` then `@actions` holding `Button(href="/new" label="New post")`.
- `Notice(tone="danger" label={failure})`: a form's outcome or a refusal, in place. `tone` is any `Tone` (`neutral` by default); a danger is `role="alert"`, read out at once, the others `role="status"`. Children render after `label`, for a link to follow up. `source={notes}` takes any Source (a `resource`, `stream`, `track()` handle, `local` or `infiniteList`): the notice shows while `notes.error()` is set, says its message unless `label` does, is a `danger` unless `tone` says, and has a retry button (`retryLabel`, `Try again`) calling `notes.retry` and disabled while `notes.pending()`. It is a bordered box, for a page section; `size="sm"` drops the box, for a line under a form (`md` by default).
- `Avatar(src={user.avatar} name={user.name} size="sm")`: the picture, or the name's first letter on a colour seeded by the name when `src` is empty or fails to load; a new `src` is tried again. `size` is `xs`, `sm`, `md` (the default), `lg` or `xl`. It is decorative, the name being written beside it, unless `label` names it for screen readers. `status` (`online`, `away`, `busy`, `offline`) draws a presence dot (offline hollow) and adds the state to the avatar's name (`Ada, online`, from `ui.avatar.<status>`, `statusLabel` words one), so a status avatar is named even with no `label`.
- `AvatarGroup(avatars={people} max={4} size="sm" label="Team")`: overlapping avatars of `{ name, src, label, href, status, key }` entries (a list, a promise or a function answering one, asked in the browser, with `onLoad` and `onError({ error, query })`, a retry on failure), each named by its `label` or name. Past `max` a `+N` chip takes the rest: a button opening a Popover of their names (a person with an `href` is a link; `open`, `onOpenChange` and `placement` as on Popover), or with `moreHref` a link. `moreLabel` (a string with `{count}`, or a function of the count) names the chip, `{count} more` by default. Two people sharing a name need a `key` each. `@avatar(person)` replaces the avatar drawn for a person and `@rest(people)` the popover's list.

### Popover, HoverCard, TooltipHost

```kay
Popover(label="More" placement="bottom-end")
  @trigger(attributes)
    IconButton({...attributes} icon="chevron" label="More")
  Button(label="Duplicate" onClick={duplicate})
```

- Popover is the browser's popover, which needs Chrome and Edge 114, Firefox 125 or Safari 17, and it sits beside its trigger through CSS anchor positioning, Chrome and Edge 129, Firefox 147 or Safari 26, so an older browser opens it away from the trigger. A click on the trigger toggles it, and a click outside or Escape closes it. The panel draws an id unique on the page, pairing it with its trigger; an `id` given instead must be unique too, and made of letters, digits, `-` and `_`, since it also names the CSS anchor.
- `at={{ x, y }}` opens the panel at a point of the window instead (a zero-size fixed anchor stands there, so `placement` and the flip apply) and `@trigger` is then not needed; `open` shows it.
- `@trigger(attributes)` renders the trigger, which spreads `attributes`: `popovertarget`, `aria-expanded`, `aria-haspopup` (from `role`) and its anchor.
- `role` is what the panel is to a screen reader, `dialog` by default, and `label` its name as an `aria-label`, a string having no element for `aria-labelledby` to point at; with a visible heading pass `aria-labelledby="its-id"` instead. `menu`, `listbox`, `tree` and `grid` set the trigger's `aria-haspopup` to the same value, any other role leaves it off, and `none` leaves the panel without a role for content that carries its own (Menu, AppSwitcher and Bell use it). Name every panel that has a role.
- `placement` is `bottom-start`, `bottom-end`, `top-start` or `top-end`, and the browser flips it when there is no room.
- `open` opens or closes it from the page, and `onOpenChange(open)` runs however it changed: a page driving `open` sets its own value back there, or it could not open the panel again after a click outside closed it.
- `HoverCard(anchor={hovered()} placement="bottom")` is a card for an element chosen at run time, with no trigger markup: set `anchor` to the element the pointer or focus is on (`onPointerEnter`, `onFocus`) and back to `undefined` on leave, and one card serves many elements, an SVG shape included, following it as a ZoomPane pans. It shows while there is an anchor, and stays a moment after it is cleared, and while the pointer is on the card, so a visitor can move onto it. `placement` is `top` (default), `bottom`, `left`, `right` or the four Popover values, flipped when there is no room; `id` as for Popover. While it shows, its `id` is added to the anchor's `aria-describedby`, so a screen reader hears it, and Escape closes it. `onOpenChange(open)` hears it shown and hidden, also when it hid itself (Escape, a detached anchor): clear the anchor there, and the same element shows it again.
- TooltipHost shows the `data-tooltip` of whichever element the pointer or a tab lands on. `data-tooltip-placement`, a CSS `position-area`, says where it sits, `top` by default: `button(data-tooltip="Copy link" data-tooltip-placement="bottom")`. IconButton sets `data-tooltip` to its label. While a tooltip shows, its element gets `aria-describedby` pointing at the tooltip, so a screen reader focusing it hears the text too, unless the text is the element's own `aria-label` or content, which it already reads. `TooltipHost(showDelay="200ms" hideDelay="300ms")` sets how long a tooltip waits to show (`80ms`) and to hide (`150ms`), a duration with its unit (`"1s"`; a bare number is a type error). The pointer can cross onto the tooltip without it closing, and Escape closes it until the pointer or the focus moves on. `Tooltip(text="Published on Monday") Published` is a `span` with `data-tooltip` and `tabindex="0"` (`placement` is `data-tooltip-placement`), for text the keyboard must reach, and an `@content` block in place of `text` draws markup in the tooltip, such as a bold name over a line of detail, which TooltipHost copies in as the tooltip shows; other `span` attributes pass through. A hand-written `span(data-tooltip tabindex="0")` is rewritten to it by `kay check --fix` (`hand-tooltip`). `data-hint` is a tooltip for the pointer alone, never shown as focus lands, for a hover explanation of read-only text such as a stat (not reported as `unreachable-tooltip`). On a touch screen a tap shows a `data-hint`, or the `data-tooltip` of an element a tap does not act on (not a link, button, field or a control `role`), and a second tap or a tap elsewhere hides it: it must only add to what the element already says, since neither the keyboard nor a screen reader brings it up.

### Stat, Meter, Progress, Skeleton, BarList, SiteFavicon, CopyButton, Rating

- `Stat(value={12} label="moons" icon="info")`: a figure read with what it counts. `href` makes the whole stat a link. `delta={{ value: "+12%", label: "vs previous", tone: "danger" }}` shows the change beside the figure with an arrow (`trendUp`, `trendDown` or `trendFlat`, following the sign of `value` unless `direction` says); the `tone` is the app's call, since a rise in errors is bad. `layout="tile"` (`inline` by default; `variant` is the deprecated name, rewritten by `deprecated-ui-props`) draws a framed box with the figure above its label, for a grid of them, and `tone` (any `Tone`, `neutral` by default) colours the figure alone: `tone={load > 90 ? "danger" : "neutral"}`.
- `Progress(value max label)`: a `role="progressbar"` for a task, `value` out of `max` (100 as Meter's percentage), so `Progress(value={upload.progress()} max={1} label="Sending")` takes an upload's 0 to 1. Without `value` it is indeterminate, with no `aria-valuenow`; the slide stops under `prefers-reduced-motion`. It takes Meter's `size`, `formatValue`, `thresholds` (in the units of `max`), `showValue` (the percentage by default) and `@reading`, none of which show while indeterminate.
- `Skeleton(shape lines width height label)`: a placeholder for a pending block: `shape` is `text` (`lines` bars, the last shorter, 1 by default), `avatar` or `card`, `width` and `height` CSS lengths. The shapes are `aria-hidden`; `label` adds a visually hidden `role="status"` the pending block announces. The pulse stops under `prefers-reduced-motion`.
- `Meter(value={usage} label="Disk" class={{ fill: 'bg-warning' }})`: a `role="meter"` bar named by the required `label`, holding `value` between 0 and `max` (100 by default), announced as `value` out of `max` (3 of 10 is 3, not 30). `formatValue(value, max)` words it, `(v, m) => v + ' of ' + m + ' GB'`: screen readers hear it as `aria-valuetext`, and `showValue` draws it under the bar (`value / max` without `formatValue`); `@reading(text, value, max)` draws the text in your markup and shows without `showValue`; either wraps the bar in a `field` part. A function or a block with parameters makes it an island, so write `--- island` where a page passes one. `thresholds={[{ upTo: 70, tone: 'success' }, { upTo: 90, tone: 'warning' }, { upTo: Infinity, tone: 'danger' }]}` colours the fill with the first step whose `upTo` is at least the value, any order, the accent past them all (`data-tone` on the fill), `size` is `sm`, `md` or `lg`. `segments={[{ value: 5, tone: 'success', label: 'known' }, { value: 2, tone: 'danger', label: 'missed' }]}` with `max={22}` draws parts of one total end to end in place of `value` (each `{ value, label, tone?, class? }`, held so the sum never passes `max`, each its own `fill` part with `data-tone`), announced as `5 known, 2 missed of 22` unless `formatValue(total, max)` words it (a segment holding 0 is left out; `thresholds` is ignored, `fillClass` and `class={{ fill }}` reach every segment). `class={{ fill: 'bg-warning' }}` styles the fill alone and replaces its colour (`fillClass` still works, deprecated); the `reading` part styles the text.
- `BarList(rows={[{ key: 'fr', label: 'France', value: 120, display: '120 visits' }]})`: a bar per row, each measured against the largest value, reading `display` or else the value. `onSelect(row)` makes each row a button handing back the row pressed (its `key` is on it), from an island; a row with an `href` draws its label as a real link instead (middle-click and a new tab work), its `onSelect` left out; `emptyLabel` is what it reads with no rows. Its rows are typed `BarListRow`, or any type extending it.
- `SiteFavicon(src={site.favicon} name={site.name})`: a site's icon, or the `globe` slot in a colour drawn from `name` when `src` is missing or fails to load.
- `CopyButton(text={url} label="Copy link")`: copies `text`, with `html` alongside for apps that paste rich text, and reads `copiedLabel` for `copiedFor` (a duration with its unit, `2s` by default). The button keeps the width of the wider of `label` and `copiedLabel` (the one not showing is drawn invisibly from `data-other` on its `text` part), and its text and accessible name stay the visible label. It takes Button's `variant`, `tone` and `size`. A copy the browser refuses toasts `failure`.
- `Rating(value={4.6} max={5} label="Rated 4.6 out of 5")`: stars filled to `value`'s share of `max`, part of a star included, kept between none and all. `onChange(value | null)` or `name` makes it a picker over real radios (click, arrows, hover preview, form post and reset, `allowClear`, a refusing promise as Segmented's; `value` then a whole number), and `icon` swaps the star for another glyph. Screen readers read `label`, which is required, as Meter's and Progress's are.
- BarList, SiteFavicon and CopyButton are islands taking data alone, so a static page passes them their props as it would to any element.

## Reference

- An icon is either a slot name such as `'close'`, which the app's settings map to any icon set, or an icon imported from `~icons/<prefix>/<name>`. The default slots use Tabler, so the app installs `@iconify-json/tabler`.
- Dialog, SidePanel and FormDialog leave `open` out to keep their own state: a `@trigger(attributes)` block draws what opens it (`button({...attributes})`), and `onOpenChange` is optional, called with `true` and `false`. Given `open`, they follow it: the parent sets it, then sets it back to false in `onOpenChange(open)`, which every disclosure takes (Dialog, SidePanel, FormDialog, CommandPalette, Popover) and runs however the dialog closed. Their content renders only while they are open. A Popover the page opens through `open` is set back the same way, in `onOpenChange`.
- One vocabulary: `variant` names a form (`solid`, `ghost`, `inline`) and `tone` a meaning (the exported `Tone`: `neutral`, `accent`, `success`, `warning`, `danger`, `info`, taken and drawn by every component with a `tone`), `size` is `xs`, `sm`, `md` or `lg`, and an option is `{ value, label, icon?, disabled? }`. `label` is the visible text of a component that draws it and the accessible name of one that does not (IconButton, Menu, the groups).
