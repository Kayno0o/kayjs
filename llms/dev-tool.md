# The dev tool

A page served by `kay dev` carries the dev tool, a drawer of tabs about the page; the rest of `kay dev` is in [The dev server](dev-server.md).

## Reference

- A problem kay recovers from in the browser, such as an island that did not match its server markup or had no client chunk, or a message no locale has, shows in the console and in the dev tool every dev page carries, a bar at the bottom left of the page counting the problems, red when one is an error and amber for a warning, whose drawer (a click on the bar, or Alt+Shift+K; Escape closes it) lists them under Problems, grouped by kind, with an error nothing caught, one kay caught in an island or an effect, or an unhandled rejection, and its stack, and each source the Content-Security-Policy blocked, a problem logged again counted rather than repeated;
- A `.kay` file a problem names opens in the editor on a click under `kay dev`, and hovering an accessibility problem outlines the elements it names.
- Dismiss, or Dismiss all, hides a problem for the rest of the browser tab, until its text changes, and those the page logged go when it is left.
- Copy puts every listed problem on the clipboard as plain text to paste into an LLM, the page URL first, then a block per problem with its group, level and count, and its message with the file and line it names; dismissed ones are left out, and the button says Copied or Copy failed for a moment.
- Its Request tab shows what served the page: the route it matched, the page and its layouts, the params, the locale, the status with the error a special page shows, the server's time by phase off its `Server-Timing` header (the guards, the import of the page's modules, the loads as a whole and each of them, and the render, which for a streamed page covers what it sends first; the loads alone with `serverTiming: false`), with whether `kay build` prerenders the page, each guard that ran and what it did (passed, redirected, denied, or did not run after a refusal), the redirects the request went through before it and which guard, `redirects` entry or setting made them, the server's time to answer and the response headers, the CSP and cache-control first, all read off what the server did on that request, a page swap showing the next page's;
- Its Network tab lists what the page fetched, read off Resource Timing, by navigation, newest first: the load, then each page swap, the last 5 kept, each request with its kind (document, page for a swap or prefetch, action, server island, fetch, script, stylesheet, image, font), status, size or `from the cache`, time and start after the navigation, an error status counted on the tab for the page shown; the tool's own requests, the live reload's and `/_kay/dev/` are left out, a hover prefetch is listed under its page, and another site's answer shows no status or size without `Timing-Allow-Origin`;
- Its Head tab shows the page's head as it is now: the search result it makes, its title and description with their length and the description's limit of 160 characters, the canonical link, hreflang alternates, the robots tag, whether the sitemap lists the page, the og and twitter tags with a preview of the social card image, and each JSON-LD block parsed or with its parse error; what `kay check` would flag in a built page's head shows as a problem, and with `seo` set but no origin it says there is no canonical link or sitemap; it reads again after each page swap;
- Its Routes tab lists every page, endpoint and API route the server serves, each locale's copy of a page on its own line, filtered by path or file, a path no request fills in linking to itself, fetched again after each restart; a section of what kay serves itself lists the sitemap, robots.txt, feeds, manifest, favicons, service worker, health check and a library's dev pages such as kayjs-mail's `/_kay/mail`, only those the running server serves, so a path an app file took over shows as the app's, and with `seo` set but no origin it says why there is no sitemap or robots.txt; under it a "kay's plumbing" group lists kay's own endpoints the app serves, one line each with its purpose and a `docs` link (the build files, `/_kay/assets/*` and `/_kay/images/*` once the build has some, `/_kay/image`, `/_kay/card`, `/_kay/files/*`, `POST /_kay/action/<file>/<name>` once an action exists, `/_kay/live`, `/_kay/error`, `/_kay/csp` with `security.reports`, `/_kay/preview` and `/_kay/draft` with `preview`, `/_kay/env.js` with `publicEnv`, `/_kay/search.json` and `/_kay/search/*` with a search index, the `analytics()` and `vitals()` routes, `/_kay/THIRD-PARTY-LICENSES.txt`), the filter box matching their path and purpose, a GET path with nothing to fill in linking to itself under `base`;
- Its Env tab lists each variable `publicEnv` sends the browser, read from `/_kay/env.js` with its value, flags one whose value looks like a secret (a URL with a password, a well-known token prefix, a hexadecimal or random string), only noting a name ending in `_KEY`, and says when the app sends no public env; the server's own env is never shown;
- Its Images tab lists each image of the page with the variant it got (a ladder width, a crop, the share card, or not resized by kay), the format and bytes the server answers with (a HEAD request, only for a loaded image of kay's image route or built variants, with a timeout; any other image is not asked), the size served against the size drawn (flagged past 4 times the pixels shown, never for an SVG, whose address ends in `.svg` or whose fetch answered `image/svg+xml`, as Resource Timing keeps it), the largest contentful paint, and an image without `width` and `height` or lazy-loaded while in view; copies of one image drawn alike share a row with their count, and hovering or focusing a row outlines each, and the list follows the page as images change;
- Its Performance tab shows the page load's LCP (with its element), CLS and INP as the browser reports them while the page is used, each rated against its good limit (2.5 s, 0.1, 200 ms) and naming the page they were measured on once a swap moved away from it, and the HTML (the document the browser holds), CSS and JS gzipped, measured again after a swap, with the entry, the islands' chunks and the other chunks apart; the sizes are dev sizes, not minified, larger than `kay build` makes them, and a "Last kay build" block gives the route's scripts and stylesheets from the report `.kay` keeps (its age, `~` for an estimate, nothing before a first build);
- Its Not found tab lists the paths a production run recorded visitors found nothing at (`data/not-found.sqlite`, the file `kay not-found` reads), most hit first, with the hosts they came from and the suggested target, those a `redirects` entry answers left out; a field holds the target (the suggestion, or one typed) and Add redirect writes it into `kay.config.ts` as `kay not-found --redirect` does, then `kay dev` restarts; `kay dev` records nothing itself, so it says so when the file is absent.
- A site with `i18n` and more than one locale has an i18n tab: the page's locale, a link to the same page in each locale (under the base, on its own host when locales go by domain), and the keys the page asked for that no locale has, counted on the tab and cleared as a page swap starts.
- A library adds a tab of its own through `devTool: { module }` in its extension, with no declaration in the app: kayjs-auth shows the session's user with a sign-out, kayjs-mail the mails sent to the outbox each previewed, kayjs-cms whether the visitor is in edit mode with a toggle for the page shown (see [A tab for a library](component-libraries.md#a-tab-for-a-library)).
- Under `kay dev` a file either names opens in the editor on a click.
- Under `kay dev`, an edit that does not compile reloads the open pages into the error page; what each reload, restart or stylesheet swap changed and how long it took is in the terminal, and the bar says nothing of it.
- The dev tool is drawn with kay's mark and the docs site's palette: the drawer's head holds the title, the page's path and icon buttons, each tab has an icon and a count toned by what it counts (red for errors, amber for warnings, plain otherwise), kept from load and each swap, tab closed or not, and the rail folds to icons under 30rem. Problems show a summary of errors and warnings, a severity icon per problem, its position and repeat count under the message; Request puts the method, path, status and server time on one line, the guard, layouts and page as a chain and the load times as bars on the request's scale; Head shows the search result and share card side by side with length meters; Env boxes a secret warning under its variable; Images shows a thumbnail, chips and flags; Performance draws a tile per Web Vital with its limits and the weight as bars beside the last build; Routes marks methods and the current route; i18n lists locales as chips; Islands shows each island's signals in a table with its hydration state.
- Images, Env and Routes draw a row alike: its name, short chips, a line per problem and a muted note. Request, Head, Routes, Env and Images each have a filter box over what they show, a section with nothing to match leaving while it is on and a heading's count following the rows shown, and Head and Images a "Problems only" toggle; image addresses, route URLs, hreflang alternates, URL tag values, header values and env values each have a copy button read out as Copied or Copy failed, and the head's copy button puts the tab as shown on the clipboard as Markdown, its filtered rows left out. A `.kay` file any tab names opens in the editor, and a script or stylesheet (`.ts`, `.tsx`, `.js`, `.mjs`, `.css`, ...) once a folder or a line comes with it; Request counts an error status on its tab.
- The drawer follows the system's light or dark theme, lists its tabs in a rail down its side (Up, Down, Home and End move between them), shows a Content-Security-Policy header one directive to a line, and keeps its open tab for the browser tab across page swaps and reloads; production pages never carry it.
- Floating, the drawer moves by its head (snapping 12 px from an edge let go within 24 px of it), resizes by any edge or corner (at least 280 by 180, arrow keys on the bottom right corner) and fills the window from a header button; three header buttons float it or dock it to the bottom (full width, resized by its top edge) or the right (full height, resized by its left edge, arrow keys on that edge), setting `padding-bottom` or `padding-right` on `<html>` to its size while open (replacing the page's own on that side) so the page stays reachable; dragging the bar's mark lands the bar in the nearest corner (bottom left by default); dock, corner, place and sizes are kept for the browser in `localStorage`, so a new tab opens the tool there (closed, as the open tab is kept per browser tab); a window 480 px wide or narrower ignores the layout, the drawer spanning it.
- The dev tool lists too what `kay check` reports of the project's `.kay` files without type checking, such as an `img` without `alt`, an unread prop or a browser global read while rendering; type errors and unchecked links still wait for `kay check` or the editor.
- It lists as well each accessibility rule the rendered page breaks, such as text too faint on its background, as axe-core finds it once the page settled (see [Checks and lints](checks.md#checks-and-lints)).
- A list icon button in the drawer's head toggles the tab order overlay, which stays on with the drawer closed: a numbered badge on each element Tab reaches (a positive `tabindex` first, then the document's order; disabled, `inert`, not rendered or `tabindex="-1"` elements left out, one radio per group; the contents of open shadow roots are numbered where their host has them, closed ones are out of reach), a line between them, moved on scroll and read again after a resize, a page swap or a change to the page, a class or style change included. A stop drawn entirely above the previous one has a dashed red line and a `!` badge and is logged as `a11y tab-order-jump` (a positive `tabindex` or a visual order unlike the DOM's); a stop whose look and its four nearest ancestors' do not change when focused (outline, shadow, borders, colours, decoration) gets an amber badge and `a11y focus-not-visible`, found by moving focus through the stops and back, again after a class or style change (so `onfocus` handlers run; an element the browser would not show a focus ring on after a script `focus()`, such as a button after a mouse click, is skipped until the keyboard was used, and nothing is checked while focus is inside a closed shadow root, or on a custom element or a block element such as a `div` with a `tabindex`, which may be the host of one: the page reports the host for both); an `inert` part holding focusable elements with no `dialog:modal` open, or a visible `aria-modal="true"` that is not a `dialog` element, is boxed dashed red and logged as `a11y keyboard-trap` (a heuristic: a script trapping Tab is not detectable). These show in Problems like axe-core's, outlining their elements on hover. Dev only, like the rest of the tool ([Performance and the dev tool](/guides/performance#the-tab-order)).
- Its Screen reader tab lists what a screen reader stops at, in reading order (open shadow roots and slots followed, `hidden`, `inert`, `aria-hidden` and not rendered elements left out): landmarks (`header` and `footer` outside a sectioning element, `nav`, `main`, `aside`, `search`, a `section` or `form` with a name, `role`), headings with their level, links, controls (buttons, `summary`, button inputs, `role` button, tab, menuitem) and form fields, each with its role and its accessible name, worked out from `aria-labelledby`, `aria-label`, `label` elements, `alt`, a button input's `value`, the element's text and `title`, `placeholder` last (an approximation of the browser's, `::before` and `::after` text not read), a link with its address and a field with `required` and its description (`aria-describedby`, `aria-description`, `title`). A row is flagged for a heading level skipped or a first heading below h1, no `main` landmark or more than one (the extra ones outlined from the page row), a link, control or field with no name, and links of one name going to different places; the tab counts the flags, and Problems only and a filter narrow the rows. Hovering or focusing a row outlines its element with its tag and `.kay` position, a click scrolls to it, and the position opens in the editor. It reads again after a page swap, an island or any other change to the page, at most about four times a second.
