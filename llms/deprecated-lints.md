# Deprecated lints

## Common tasks

- Move an app off every old form at once: `kay upgrade`, or `kay check --fix --since 1.74` for one minor alone; see [Apply the quick fixes](lints.md#apply-the-quick-fixes).

## Reference

### Deprecated lints

The lints of the `deprecated` group, each the old form a minor replaced, reported for three minors with a safe fix unless its row says otherwise.

| Lint | Default | Group | Reports |
| --- | --- | --- | --- |
| `deprecated-auth-account-methods` | warn | deprecated | A call of a flat kayjs-auth account, provider or audit method on `auth` or `ctx.locals.auth`, the names before 1.87: `auth.deleteAccount(proof)` is `auth.account.delete(proof)`, `auth.linkProvider(...)` is `auth.oauth.link(...)`, `auth.listAuditLog()` is `auth.audit.list()`, `auth.createUser(input)` is `auth.admin.createUser(input)` (found on an imported `auth` too). The flat names work until 1.90. Found in a project depending on `@kaynooo/kayjs-auth`, in its TypeScript files and `.kay` fences; `kay upgrade` renames each call, its arguments unchanged. |
| `deprecated-collection-links` | warn | deprecated | A collection with a literal `route` that also says where its entries' pages are, since 1.87: a `url` function (the route wins over it) and a `path` in its feed's items (the feed links the entry's `url`). Works until 1.90. `kay upgrade` drops the `url` function and a `path` written as the route with the slug, `` `/blog/${post.slug}` `` for `/blog/:slug`; a `path` that differs from the route is reported with no fix. Found in `.ts` files calling `collection` from `kay/content`. |
| `deprecated-hook-names` | warn | deprecated | A hook key under its name before the hook convention, since 1.87: `onFailed` of `queue()`, `workflow()` and `mailer({ queue })` is `onError`. Works until 1.90. `kay upgrade` renames the key, a shorthand `{ onFailed }` becoming `{ onError: onFailed }`; a key beside its new name is reported with no fix. Later releases of the convention add their renames. |
| `deprecated-api-error-answer` | warn | deprecated | A read of `.answer` on an `ApiError` (`data`) or an `ActionError` (`body`), since 1.87. Works until 1.90. Only a read inside the consequent of an `if` or conditional, or the right of an `&&`, testing `x instanceof C` for the same `x` is narrowed: `ActionError` gets `.body` as a safe fix, `ApiError` gets `.data` as a fix `kay upgrade` does not apply (it may be an `ActionError`); a receiver only a `catch` or a cast says is an error is reported with no fix. Found in `.ts` files and `.kay` fences importing either class from `kay`. |
| `deprecated-refusal-message` | warn | deprecated | A call of `refusalMessage(error, fallback)`, since 1.87: an `ApiError`'s `message` is always the text to show. Works until 1.90. The fix, `error instanceof ApiError && error.status !== 0 ? error.message : fallback`, is offered but never applied by `kay upgrade`, as an `ActionError`'s message now also reads its field messages and `data.message`; a first argument that is no plain name is reported with no fix. Found in `.ts` files and `.kay` fences reading it from `kay`. |
| `deprecated-config-groups` | warn | deprecated | A config key 1.88 grouped by concern, written flat, since 1.88: `dirs` (`routesDir`, `apiDir`, `publicDir`), `limits` (`maxSize`, `maxSizeByPath`), `serve` (`apiPath`, `compress`, `compressionDictionary`, `shutdownTimeout`), `observe` (`log`, `serverTiming`, `requestIdHeader`, `tracer`, `onError`) and `client` (`navigation`, `inlineStyles`, `lateStyles`, `typography`, `hydration`, `prefetch`, `saveData`), in `kay.config.ts`, in the options of `pages()` and `testSite()` or in an extension's `config`. The old keys work until 1.91. `kay upgrade` writes the bags; an object with a bag of the same name already, or a spread, is reported with no fix. |
| `deprecated-file-store` | warn | deprecated | The `fileStore` config key, since 1.87: `store: { files }`, in `kay.config.ts`, in the options of `pages()` and `testSite()` or in an extension's `config`. The old key works until 1.90. `kay upgrade` writes `store: { files: <value> }`; a `store` written in the same object is reported with no fix. |
| `deprecated-ui-callbacks` | warn | deprecated | A kayjs-ui callback under its name before 1.87: `onSelect` on a Table, TreeView or Timeline, the components with a `selected` prop, is `onSelectedChange` now, so state a prop can hold reports through `on<Prop>Change` and `onSelect` stays a press of an item. The old name still works until 1.90. `kay upgrade` renames the attribute. Found in `.kay` files importing the component from `@kaynooo/kayjs-ui`. |
| `deprecated-ui-props` | warn | deprecated | A kayjs-ui prop under its name before 1.89: `isDisabled` on a DateInput or DateRangeInput, the per-day predicate, is `disabledDay` now, so `disabled` alone is the boolean, and a Widget's `isEmpty` is `empty` with its `@empty` block `@emptyState`. Works until 1.92. The fix renames the attribute or the block. |
| `deprecated-source-types` | warn | deprecated | An import of `StreamStatus`, `ResourceStatus` or `ResourceFailure` from `kay`, since 1.87: `ConnectionStatus`, `LoadStatus` and `ApiError`, the one vocabulary every source an island reads shares. The fix renames the import and its uses. |
| `deprecated-lifetimes` | warn | deprecated | A lifetime under its name before 1.87: `revalidate` in `export const page`, now `ttl`, `keep` in a `notify` call, now `ttl`, `keepFailed` in a `queue` or `workflow` call, now `failedTtl`, and the `keep` of a kayjs-ai `Chat`, now `history`. The old names work until 1.90. `kay upgrade` writes the new name; one set beside its new name is reported with no fix. |
| `deprecated-room-types` | warn | deprecated | An import of `AsyncRoomStore`, `AsyncRooms` or `StoreRooms` from `kay/server`, since 1.88: `RoomStore` and `Rooms`, as every rooms store answers `state` and `update` with promises. The old names work until 1.91. `kay upgrade` renames the import and every use of it; an aliased import is renamed without its uses, and a file where the new name is taken is reported with no fix. |
| `deprecated-export-names` | warn | deprecated | An import of an export under its name before 1.90, since 1.90: each name came to mean one thing across kay and its libraries (`cssColours` is `cssColors`; `llms/upgrading.md` lists the rest). The old names work until 1.93. `kay upgrade` renames the import and every use of it; an aliased import is renamed without its uses, and a file where the new name is taken is reported with no fix. |
| `deprecated-context-name` | warn | deprecated | An import of `context` from `kay`, since 1.90: `createContext`, which does not read as `ctx` or `defineContext`. The old name works until 1.93. `kay upgrade` renames the import and every use of it; an aliased import is renamed without its uses, and a file where the new name is taken is reported with no fix. |
| `deprecated-duration-seconds` | warn | deprecated | A call of kayjs-auth's `lifetime(seconds, locale)` or kay's `durationWords(seconds, locale)` with a number literal, since 1.88: a duration is written with its unit, `lifetime('86400s', locale)`. The number works until 1.91. `kay upgrade` writes an integer literal as `'<n>s'`; any other number is reported with no fix. A number held in a variable is not found. |
| `deprecated-ui-tone` | warn | deprecated | A kayjs-ui form 1.87 replaced: the `muted` tone of a Sparkline (`tone`, `tones`), a StatusStrip (`cells`) or a Timeline (`entries`), now `neutral`, and a native `size` such as `size={20}` on a TextInput, Select, Combobox, DateInput, TimeInput or DateTimeInput, now `sm`, `md` or `lg`. The old tone draws until 2.0.0. `kay upgrade` writes `neutral` where `muted` is a literal; a native `size` is reported with no fix, its width is a class now. Found in `.kay` files importing the component from `@kaynooo/kayjs-ui`. |
