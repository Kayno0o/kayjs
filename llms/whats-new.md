# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- `call()` types a route's `null` answer as `null`, as it already arrives, rather than `''`; an empty answer (`undefined`, a 204) stays `''` ([API from islands](api-from-islands.md)).
- `src/context.ts`, default-exporting `defineContext(...)`, gives templates `ctx.<key>` with no extension, typed in `kay check`; two sources giving one key stop the page naming both: [Request values](request-values.md).
- `src/context.ts` (picked up by `kay dev` when added or removed, with a new process), default-exporting `defineContext(...)`, gives templates `ctx.<key>` with no extension, typed in `kay check`; two sources giving one key stop the page naming both: [Request values](request-values.md).
- kayjs-ui's `ThemeToggle` switches light, dark and system, keeps the choice in a cookie and puts it on `<html>` as `data-theme`, and `scheme()` writes it from the first render so the page never flashes the other scheme: [ThemeToggle](../packages/ui/llms/setup.md).

## 1.91.0

- kayjs-ui and kayjs-auth depend on `@kaynooo/utils` 3.0.0, so kayjs-ui type-checks in an app that is on utils 3; an app still on utils 2 keeps it, as each package installs its own copy.
- Every error kay and its libraries throw for an app to catch extends `KayError` (from `kay/library`) with `code`, `kind`, `status`, `cause` and `name`, its old class kept for `instanceof`, and `kay explain <code>` documents them in the new `runtime` and `library` groups: [Errors](errors.md). An uncaught `SaveConflictError` now answers 409 and an `UnknownCollectionError` 404, where both answered 500.
- A library's config-time problems (a `cms({ collections })` layout, `roles`, `rules`, a rate limit) throw through `configError`, and each library's `llms/` lists its errors in one `Errors` table.
- `pgData(...).close()` and `pgHandle(...).close()` settle within about 5 seconds whatever a statement in flight or a locked table holds, so an app's shutdown is no longer held by a close that waits on the database: [queues](queues.md).

- A constructor is a noun across the libraries (`authCore`, `authGate`, `memoryAuth`, `pgAuth`, `cmsDrafts`, `cmsEntryForm`), every Postgres store and table helper takes one `PgSource` (a Bun `SQL`, a pg-orm `Database` or a URL; `pgLoader` takes it as `source`), `createXTables` creates, `xTableNames` lists names: see [Component libraries: conventions](component-library-conventions.md#conventions); `deprecated-library-names` renames the old names.
- Each library runs with no argument and takes the same three forms: `mail()` uses a `src/mail.ts` exporting `mail` as `auth()` uses `src/auth.ts` and `src/mail.ts`, `mail({ from })` and `auth({ store })` take their options inline, `module` names a file of the app, and `server: false` is the one escape for an app mounting the plugin by hand (`auth({ plugin: false })` is renamed by `deprecated-escape-option`): [kayjs-mail](../packages/mail/llms/writing-and-sending.md), [kayjs-auth](../packages/auth/llms/setup.md).
- `mail()` with no argument uses the `mail` a `src/mail.ts` exports, as `auth()` already reads that file: an app with `mail()` and a `src/mail.ts` now sends through that file's mailer, where `mail()` built its own from the environment (options given to `mail({ ... })` still win, and a file exporting no mailer stops the boot). `server: false` is the one escape for an app mounting a plugin by hand, on `auth()` and `mail()`; `auth({ plugin: false })` is renamed by `deprecated-escape-option`: [kayjs-mail](../packages/mail/llms/writing-and-sending.md), [kayjs-auth](../packages/auth/llms/setup.md).
- `page.fill` in kay/test waits for the field's island to hydrate, so text typed into a page just loaded or swapped in is no longer written away by hydration: [browser tests](testing-browser.md).
- `add.validate(form, field?)` checks a form in the browser against the action's schema and writes the messages into `add.error(field)` as a refusal does, and kayjs-ui's Form, SaveForm and FormDialog take `validate="submit" | "blur"` to show them on their FormField live: [actions](actions.md#reading-the-outcome), [forms](../packages/ui/llms/forms-and-steps.md).
- `validate` (or `validate="blur"`) on a `form(action={add})` shows the schema's refusals as text in the FormFields of the form instead of the browser's bubble: [actions](actions.md#forms).
- The FormFields (and Checkboxes, Toggles) a static page gives kayjs-ui's Form, SaveForm or FormDialog as children show a refused call's message with JavaScript, with no island of yours holding the fields: [forms](../packages/ui/llms/forms-and-steps.md).
- Environment variable names follow one rule (kay `KAY_`, a prefix per library, vendors' own names kept, [Environment](environment.md)): `KAYJS_AUTH_DATABASE_URL` is `AUTH_DATABASE_URL` and `MAIL_INBOUND_SECRET` is `MAIL_EVENTS_INBOUND`, the old names read until 1.94 with a boot warning, and `kay env` reports one it finds.
- The forms 1.87 deprecated are gone, with their ten `deprecated-*` lints: `fileStore`, kayjs-auth's flat account methods, `revalidate`, `keep` and `keepFailed` for lifetimes, `onFailed`, `onSelect` on a Table, TreeView or Timeline, `.answer`, `refusalMessage`, `StreamStatus`, `ResourceStatus`, `ResourceFailure` and `api({ errorShape })`: [upgrading](upgrading.md#the-forms-187-deprecated-are-gone).

## 1.90.0

- kayjs-ui fields share one `onInput` (live) and `onChange` (committed) convention: MarkdownEditor gains `onChange`, DateInput, TimeInput and ColorInput gain `onInput`, and Select, RadioGroup, Segmented, IconPicker pass the picked option as a second argument, ChipGroup and MultiSelect the picked options: [Forms](../packages/ui/llms/forms.md).
- Every rate limit option is one `RateLimit` (`{ max, window, store?, key? }`, from `kay`, `kay/server` and `kay/library`) alone or in a list: kayjs-ai's `rateLimit` takes a list, kayjs-auth's buckets take a list and a `store` each: [rate limits](rate-limits.md#in-the-libraries).
- kayjs-ui Select, RadioGroup, Slider, ColorInput, Rating, Segmented and ChipGroup take no `value` like the text fields: they keep what is picked, post it under `name` with no JavaScript and a form reset goes back to what they first showed: [forms](../packages/ui/llms/forms.md).
- A FormField (or Checkbox, Toggle) with a `name` inside any `form(action={add})` shows `add.error('name')` with and without JavaScript, so ContactForm and SubscribeForm and your own forms need no `issue` per field; `formErrors()` from `kay` is what a component of yours reads, and kayjs-ui's `Form(action={add})` is the plain page form calling the action as SaveForm does: [forms](../packages/ui/llms/forms-and-steps.md), [actions](actions.md).
- kayjs-ui names the controls a component holds beside its content `@actions` everywhere (Card, FormField, AppHeader, TreeView, MarkdownEditor join the rest; ConfirmDelete's `trigger` string is `triggerLook`), and kayjs-ai's Chat and ChatLauncher take every icon as one `icons` prop; the old names work until 1.93: [blocks and links](../packages/ui/llms/slots-and-links.md#one-name-for-one-role), [Chat blocks](../packages/ai/llms/chat-blocks.md#change-the-icons).
- kayjs-ui entries with an address take `newTab: true | false | 'auto'` (Menu, BellInbox, AudioPlayer chapters, CommandPalette, SiteNav, AppHeader, Breadcrumb, TabNav, Timeline, TreeView, BarList, Carousel, AppSwitcher), an address leaving the site opening in a new tab by default; `isExternal(href)` is exported, and `LineChart` takes `href(mark)`: [links](../packages/ui/llms/slots-and-links.md).
- `format: 'email'` is one strict check, `isEmail` from `kay` (and `normalizeAddress` from `kay/library`), shared by the schema, the browser check, kayjs-auth sign-up and kayjs-mail, so an address that signs up is never refused as a recipient: [actions](actions.md), [upgrading](upgrading.md#the-email-format-is-one-strict-check).
- `kay check` reads a `--- style` fence: `unused-selector` warns of a rule no element of the template can match, `unreachable-selector` is an error for a rule ending on `:root`, `html` or `body` (fixed to `:global(...)`), and a `@keyframes` name is scoped to its component with its `animation` uses, `@keyframes :global(spin)` keeping it global: [components](components.md#file-layout), [upgrading](upgrading.md).
- `sitemap: false` in kay.config.ts serves no `/sitemap.xml` and leaves the `Sitemap:` line out of `robots.txt`, as `robots: false` and `favicon: false` switch theirs off: [sitemap and robots.txt](sitemap-search-fonts.md#sitemap-and-robotstxt)
- kayjs-auth answers `'off'` for every feature the app switched off (`signUp: false` was `'closed'`) and `'not-enabled'` where `twoFactor.regenerateRecoveryCodes` said `'disabled'`; a default-on feature (`password`, `magicLink`, `twoFactor`, `signUp`) is switched off with `false`, `true` working until 1.93 with `deprecated-auth-options` dropping it: [upgrading](upgrading.md)
- A size limit is `maxSize` (bytes or `'5mb'`) and a map by path `maxSizeByPath`: kayjs-ai's `ask` and `Chat` take `maxSize` (was `maxAttachmentBytes`, `maxFileSize`) and an extension's path map is `maxSizeByPath`, the old names working until 1.93 with `deprecated-size-limits` renaming them: [upgrading](upgrading.md)
- kayjs-ui FileDrop is a form control: `name` keeps the files on its input so a plain form posts them, `maxSize` and `maxFiles` refuse the rest with `onReject(files, reason)` (one call per `type`, `size` or `count`), `list` shows the kept files with a remove button, `onChange` hears them, `issue` shows a message under it, and `onFiles` and `@content` are optional (a default button opens the picker); `onReject` is called once per reason and `onChange` is the kept-files callback, see [upgrading](upgrading.md#filedrop-is-a-form-control): [FileDrop](../packages/ui/llms/pickers.md#rangeinput-slider-multiselect-combobox-filedrop-menu-iconpicker).
- kayjs-ui words empty states one way: Table, LineChart, ContributionGraph, Sparkline, StatusStrip, Timeline, DescriptionList, TreeView, Carousel and VirtualList take `emptyLabel` and now draw its default text where they drew nothing (`emptyLabel=""` hides it), every data component (BarChart, BarList, ScatterChart, MediaGallery, Combobox, MultiSelect, IconPicker, CommandPalette too) takes an `@empty` block beside it, and EmptyState takes `icon` and `tone`: [slots and links](../packages/ui/llms/slots-and-links.md).
- kayjs-ui names a failure the same everywhere: `failureLabel` is the message of CopyButton, ConfirmDelete, FormDialog, RecordButton, SaveForm, AudioPlayer, IconPicker and ImageCropper, CopyButton's `onError` replaces `onFail`, and every component's `onError` receives one object (`{ error }`, `{ event }` for the DOM's), as [the components guide](../packages/ui/llms/open-state-and-sources.md) says; the old names work until 1.93 ([upgrading](upgrading.md))
- `kay check` types the HTML attributes limited to keywords (`loading`, `type`, `scope`, `dir`, `target`) and the SVG attributes, with a nearest-name hint for `viewbox` or `strokeWidth`, and the `invalid-aria-value` lint holds a written ARIA state to its values: [upgrading](upgrading.md)
- kayjs-ui reports every show and hide through `onOpenChange`: Table and TreeView take it for `onToggle` (renamed by `deprecated-open-change`), SplitLayout has `onDetailOpenChange` with a back button above the detail below `md`, and CollapsibleSection and Accordion share the defaults `open` and `boxed` false: [open state](../packages/ui/llms/open-state-and-sources.md), [upgrading](upgrading.md).
- `kay check` warns with `once-read-prop` for a destructured prop read into a top-level `const` or `let` that a function or the template reads later in a browser script, which keeps its first value: [lints](lints.md). kayjs-ui Table follows a `countLabel` and a `selectedLabel` the parent changes.
- Each exported name means one thing: kayjs-mail's `cssColours` is `cssColors`, and kay's `schedule()` option type, job table names and data table names are `ScheduleEveryOptions`, `jobTableNames` and `dataTableNames`, and each library prefixes the type or function another package also exports (`MailReply`, `AiReply`, `CmsAction`, `AuthMember`, `authGuard`, `rowEditing`); `kay upgrade` renames the old ones ([upgrading](upgrading.md)).
- A function an `effect` or `onMount` callback returns runs as its cleanup; `effect`, `watch`, `every`, `listen` and `onCleanup` called with no owner warn once in development, and the `unowned-effect` lint flags them in a handler, a timer or after an `await`: [components](components.md), [lints](lints.md).
- A name has one home: kayjs-auth's credential rules are exported by `@kaynooo/kayjs-auth/rules` alone and kayjs-cms's `EntryForm` and `FormScope` by `@kaynooo/kayjs-cms/form` (`deprecated-import-path` moves the imports), `mount` is exported from `kay` as well as `kay/mount`, and `sqliteCache` from `kay/server` as well as `kay/cache`: [project](project.md).
- `createContext(default)` replaces `context(default)` from `kay`, so it does not read as `ctx` or `defineContext`; `TemplateContext` is the public type of `ctx`, and `deprecated-context-name` renames the old import: [components](islands-state-to-ids.md#context), [request values](request-values.md).
- The 404 log and the redirects added while the site runs live in the SQLite file of the app's `store` (`sqliteData`) instead of `data/not-found.sqlite`, an existing `data/not-found.sqlite` still read; workers fill what the `store` leaves out in the database it names (SQLite or Postgres) instead of `data/workers.sqlite`; production warns once at boot when either stays in a local file: [routing](routing-endpoints-and-base.md), [workers](workers.md).
- The 404 log and the redirects added while the site runs live in the SQLite file of the app's `store` (`sqliteData`) instead of `data/not-found.sqlite`, an existing `data/not-found.sqlite` moved into it at the next start; workers fill what the `store` leaves out in the database it names (SQLite or Postgres) instead of `data/workers.sqlite`; production warns once at boot when either stays in a local file: [routing](routing-endpoints-and-base.md), [workers](workers.md).
- kayjs-ui: a Select or Segmented with a `param` and no `value` shows the option the address names, else `paramDefault`, on the server and in the browser, following each navigation and Back or Forward step, so the param is no longer passed as `value` too: [forms](../packages/ui/llms/forms.md).
