# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- kayjs-ui's CollapsibleSection and Accordion tell their state (`onOpenChange`, `value`/`onChange`), Avatar, SiteFavicon, CopyButton and AudioPlayer report their transitions, Pagination takes `@step` and no `url`, TreeView loads branches from a function with `onToggle`, Menu `items` and VirtualList, Masonry, MediaGallery and Carousel `list` take an async source, MultiSelect and Select `options` a function like Combobox's, IconPicker a plain `icons` list, and MultiSelect, RadioGroup, ChipGroup and Segmented an `@option(option)` block: [open state and sources](../packages/ui/llms/open-state-and-sources.md).
- kayjs-ui's MultiSelect, DateInput (and DateRangeInput, with the box in `onOpenChange(open, box)`), Combobox and AppSwitcher take `open` and `onOpenChange`, HoverCard takes `onOpenChange` and tells it when Escape or a detached anchor hid it so the app clears its anchor, and BellInbox takes a `@trigger(attributes, unread)` block: [forms](../packages/ui/llms/forms.md), [basics](../packages/ui/llms/basics.md).
- kayjs-ui's Menu, AppSwitcher and ConfirmDelete spread the attributes they are given on their trigger, CommandPalette on its dialog and Toaster on its root; only TooltipHost, whose `id` its tooltips point at, still takes none: [basics](../packages/ui/llms/basics.md).
- kayjs-ai's `ai({ onRequest, onStep, onToolCall, onFinish, onError })` and the same names per `ask` run around every ask: `onRequest` may change the messages and system prompt or refuse with an `AiError` before anything is sent or counted, the others notify and never fail the reply: [Hooks around an ask](../packages/ai/llms/hooks.md).
- kayjs-ai's Chat takes `onSend`, `onReply`, `onStop`, `onError`, `onToolCall`, `onRegenerate`, `onEdit` and `onSuggestion` and `suggestions` as a function or a promise, ChatLauncher takes `open` and `onOpenChange`, and a `kai-chat-draft` event fills the field from outside: [Chat events and control](../packages/ai/llms/chat-events.md).
- kayjs-ui's SaveForm and FormDialog take `onError(error)` for a refused or failed save, ContactForm and SubscribeForm take `onSent(data)`, `onError(failure)` and a `@sent` block (SubscribeForm also takes extra fields as children), Combobox takes `onInput`, `onLoad` and `onError`, IconPicker `onSearch` and `onError`, RecordButton `onStart`, `onStop('press' | 'limit')`, `onCancel`, `onError` and the `recording` / `onRecordingChange` state pair, and ImageCropper `crop`, `onCropEnd`, `onError` and `fallback`: [forms](../packages/ui/llms/forms-and-steps.md), [Combobox](../packages/ui/llms/forms.md), [ImageCropper](../packages/ui/llms/charts-drag-and-media.md).
- kayjs-ai's ChatLauncher opens on a link to `#chat` (its `hash` prop) and on a window `kai-chat-open` event, and window `kai-chat-send` and `kai-chat-draft` open the panel then reach the chat; kayjs-ui's DateRangeInput takes `open` (`'from'`, `'to'` or `false`): [Chat events and control](../packages/ai/llms/chat-events.md), [forms](../packages/ui/llms/forms.md).
- kayjs-ui's ConfirmDelete takes `open` and `trigger="none"`, so a Menu entry, a context menu or a shortcut can ask for the confirmation, and Menu and AppSwitcher take a `@trigger(attributes)` block in place of the icon button: [basics](../packages/ui/llms/basics.md), [forms](../packages/ui/llms/forms.md).
- kayjs-ui's `Bell` takes `items` (and `unread`) for notifications from the app's own source, drawing for anyone, and `BellInbox` in an island takes a function or promise source, `onRead(id | undefined)`, `onOpenChange` and an `@item(note)` row: [Bell](../packages/ui/llms/page-layout-palette-and-trees.md#bell).
- kayjs-ai's Chat takes `@turn(turn, index)`, `@actions(turn)`, `@call(call)`, `@source(source, n)`, `@empty({ send })` and `@footer` blocks that replace how a turn, the buttons under it, a tool call (a result card), a cited source, the empty chat and the area under the form are drawn, and ChatLauncher forwards them: [Chat blocks](../packages/ai/llms/chat-blocks.md).
- kayjs-ai's Chat takes `images`, the paths of the site a reply may show an image from (`images="/files"`), so a tool's picture shows in the reply instead of as a link; images of other hosts or paths stay dropped: [Chat](../packages/ai/llms/chat.md).
- kayjs-ui's Table takes `expandable` with an `@detail(row)` block: a toggle per row opens a full-width detail under it, or under its card when stacked, and `expanded` and `onToggle(key, open)` control it: [tables](../packages/ui/llms/tables-navigation-and-layout.md).
- kayjs-ui's `attempt`, ConfirmDelete and FormDialog toast a `ctx.fail` refusal that is a string or carries a string `error` or `message` without a `refused` reader, and an `ApiError` answer's `error` is read like its `message`: [basics](../packages/ui/llms/basics.md).
- kayjs-ui's `CommandPalette` takes `search`, a function from the query to a promise of entries (an action works as is) called once typing pauses, whose rows are listed under `searchLabel` after the entries matched, a stale answer dropped and a rejection shown as `searchError`: [Page layout, command palette and trees](../packages/ui/llms/page-layout-palette-and-trees.md#commandpalette).
- kayjs-ui's `toast.error(message, { action: { label, run } })` adds a button to a toast, busy while `run` is pending and dismissing the toast once it settles, and `attempt` takes `refusedAction(data)` for a refusal's: [basics](../packages/ui/llms/basics.md).
- `kay editor install [helix|zed]` sets up Helix and Zed for `.kay` files (the tree-sitter grammar and queries, the language server run from the project's kay when none is on the PATH, a generated Zed extension), and `kay new` offers it as a step or takes `--editor helix,zed`: [editor commands](editor-and-agent-commands.md#set-up-helix-or-zed).
- kayjs-cms has `gitlab({ repo, branch?, token, baseUrl?, timeout?, fetch? })`, a saver committing to GitLab (gitlab.com or self-managed) in one commit per save, and `CMS_HOST=gitlab` picks it for a production server: [Setup and saving files](../packages/cms/llms/setup.md).
- kayjs-ui's RelativeTime takes `focusable={false}` to leave out its tab stop inside a link or a focusable row: [basics](../packages/ui/llms/basics.md).
- kayjs-ui's `infiniteList` has `reload()`, which loads again every row loaded so far and swaps them in at once, keeping the DOM of rows whose key is unchanged: [kayjs-ui infinite lists](../packages/ui/llms/infinite-list.md).
- `kay/test`'s browser page has `drag(from, to, { steps, at, to, hold })`: a mouse drag from one element to another, or a touch drag with `hold`, so a test of a sortable list or a board needs no raw `cdp` mouse events: [browser tests](testing-browser.md).
- kayjs-ui's Menu entries take `href`, drawing the entry as a link with middle-click, Ctrl+click and "copy link", opening in a new tab with `rel="noopener noreferrer"` when the address is of another origin, and `onSelect` is then optional: [forms](../packages/ui/llms/forms.md).
- kayjs-ui's Menu entries take `href`, drawing the entry as a link with middle-click, Ctrl+click and "copy link", opening in a new tab with `rel="noopener noreferrer"` when the address is absolute, and `onSelect` is then optional: [forms](../packages/ui/llms/forms.md).
- `secret-prop` skips a field named like a secret that holds a list of objects, such as a syntax highlighter's `tokens`: [lints](lints.md).
- `kay` runs on `@kaynooo/cli-kit`: `kay --version`, shell completion through `kay __complete`, `--plain` and `--color`, a typo naming the command or option it likely meant, and a usage error (unknown command or option, a missing argument, a `refuse(reason)`) exiting 2 where it exited 1; `kay <command> --help` lists the options with a line each: [project](project.md#commands).
- kayjs-ui's Combobox draws no second line for an option whose `description` is only whitespace: [tables, tabs and navigation](../packages/ui/llms/tables-navigation-and-layout.md).
- `kay dev` warns in the browser console of a keyed live value an island reads only in an effect, which the page's render never noted and so no connection follows: [live values](live-values.md).
- kayjs-ui's Menu and Popover opened `at` a point wait for the release of a pointer button held at that moment, so a context menu opened by Linux's `contextmenu` on the right press stays open: [tabs and navigation](../packages/ui/llms/tables-navigation-and-layout.md).
- kayjs-ui's SiteNav, TabNav and TreeView compare the page's address with each link as the site renders it, so the current link is marked on a page of a prefixed locale, with a trailing slash on the address ignored: [tabs and navigation](../packages/ui/llms/tables-navigation-and-layout.md).
- The Forgejo CI workflow `kay new` and `kay add ci` write runs on an Alpine runner image with bun and git baked in, as on `debian`: its install step adds only the missing `git` and `unzip` (with `apt-get` or `apk`) and Setup Bun is skipped when bun is already there: [project new and add](project-new-and-add.md).
- A bare `---` after a `--- server` or `--- module` fence that was meant as the script fence is reported with the fix, `--- script` on the line closing the first fence, which `kay check --fix` applies: [checks](checks.md).
- An unknown `tooltip` attribute on an element names `data-tooltip` and `data-hint` in `kay check`: [checks](checks.md).
- Kay's tsconfig includes `scripts`, so a script run with `bun scripts/x.ts` is type checked and linted with no `include` in the app: [project](project.md).
- `kay lint --cache` drops ESLint's cache when `tsconfig.json` or a file under `.kay/types` changed, so a parsing error does not outlive the tsconfig that caused it: [checks](checks.md).
- `infiniteList` starts over when what it follows changes, as the props a `persist` island gets from the next page: the props an action source's function `input` reads, or first rows given as a function (`infiniteList(() => rows, ...)`): [kayjs-ui infinite lists](../packages/ui/llms/infinite-list.md).
- kayjs-ui's `SplitLayout` keeps the list's width under `listWidthKey` in a cookie the server reads, not in `localStorage`, so the saved width is drawn from the first paint; a width kept in `localStorage` moves to the cookie once: [Page layout](../packages/ui/llms/page-layout-palette-and-trees.md).
- kayjs-ui's `SidePanel` takes `scrollKey`, whose change brings its body back to the top, so a panel kept in a `persist` island needs no ref into its parts: [Page layout](../packages/ui/llms/page-layout-palette-and-trees.md).
- A form posting to an action keeps its honeypot and time stamp inside an island, so kayjs-ui's ContactForm and SubscribeForm given `onSent` or `onError` no longer drop them from the server HTML: [forms](../packages/ui/llms/forms-and-steps.md).

## 1.85.0

- A string with a `date-time`, `date` or `time` format no longer takes the 10,000 character default, so the OpenAPI document and the tool schemas show a date as its format alone: [API routes](api-routes.md).
- A component call merging a shorthand class, a `class` attribute or a spread with a condition object (`Plain.mt-4(class={{ on: true }})`) passes `kay check` under `exactOptionalPropertyTypes` on a component typing `class?: string`: [styles and assets](styles-and-assets.md).
- kayjs-ui's `LineChart` fed by a signal or a store updates in place on each change instead of redrawing, through chartist 2.2's `chartist/live` (peer `^2.2.0`) loaded on the first change of the data; `pointKey` follows a rolling series' points by label or position, and `animate` moves them from the old data to the new, off under reduced motion: [charts](../packages/ui/llms/charts-drag-and-media.md).
- kayjs-ui's `LineChart` no longer sets a global `Chartist`, which importing `chartist/compat` did.

## 1.84.0

- `page.back()` and `page.forward()` on a page opened with `javaScript: false` no longer fail now and then with `Inspected target navigated or closed` when the browser loads the entry as a new document: [testing in a browser](testing-browser.md).
- A string in an API route's `body` with no `maxLength` takes the same 10,000 character default as an action's: [API routes](api-routes.md).
- Browser tests prefer a `chrome-headless-shell` (on the `PATH` or in Playwright's cache) over full Chrome when no `path` or `BUN_CHROME_PATH` is given: same Blink and V8, far less memory, and a start failure names the executable; the shell also leaves no lock file, which kay's browser cleanup now follows through `/proc`. See [the browser itself](testing-browser.md).
- A relative `mcp: { key: { file } }` is resolved against the working directory in a compiled server, where it was the folder the executable was built in, so `data/mcp-key` lands next to where the executable runs and `KAY_MCP_KEY_FILE` is no longer needed to point it there (a compiled server that ran outside its build folder makes a new key at the new place): [API routes](api-routes.md).
- `site.submit` takes an action declared with no input, with `{}` or no fields, where it failed `kay check` before: [testing](testing.md).
- A parts object passed as `class` takes a part that may be `undefined` (`class={{ fill: tone() }}`), which `kay check` refused under `exactOptionalPropertyTypes`: [styles and assets](styles-and-assets.md).
- A production page handing an island an action the build has no code to revive, one created only in a package outside the app, fails with an error naming the cause instead of reaching the browser as raw props, and `import { action as make }` counts as the app declaring one: [actions from islands](actions-from-islands.md).
- `testSite()` without a `browser` checks the islands once per run instead of once per test file: a file whose sources match the check an earlier file passed builds nothing, which takes about 1.5 s of CPU and 170 MB off each file of an app the size of kay's docs: [Test site](testing.md#test-site).
- kayjs-ui's `LineChart` draws with chartist 2 (peer `^2.0.0`, 1.x is no longer supported): [upgrading](upgrading.md#kayjs-uis-linechart-needs-chartist-2).
- kay parses scripts, fences and templates with oxc-parser in place of `@babel/parser` and `@babel/traverse`: compiling a `.kay` file takes about 40% less CPU and a dev or LSP start compiles its first file faster, an install carries oxc's native binding in place of `@babel/*`, and a syntax error in a script reads in oxc's words. A compiled executable still carries no compiler.
- `links: { schemes: ['webcal', 'geo'] }` lets a bound `href`, `src` or `action` keep a scheme the app trusts instead of going out as `unsafe:`, on the server and in islands (`javascript`, `vbscript` and `data` are refused), and `kay dev` logs once per URL each bound URL it rewrote: [security](proxy-and-security.md).
- An action, an API route and a websocket upgrade refuse a request whose `Origin` is `http:` on the site's own host once the site is served over https (the request itself, `X-Forwarded-Proto`, or an https `site` in production), where only the host was compared; `kay dev` and a server tried on `localhost` over http keep working: [action protection](action-protection.md).
- An island reading the clock, `Math.random()` or a locale-less `Intl` is the `hydration-mismatch` lint of the `islands` group, so `// kay-allow hydration-mismatch`, `kay-allow-file` and `lints` reach it (so `lints: { islands: 'allow' }` now covers it too): [Browser globals on the server](browser-only.md#browser-globals-on-the-server).
- `kay check` points at the attribute and says what to write for a handler written as a call (`onClick={bump()}`), a mistyped `bind:value`, `elif` for `else if`, `className` and `htmlFor`, and reports a bare attribute value (`Card(title=3)`) once, with `title={3}`: [Checks](checks.md#what-kay-check-verifies).
- kayjs-ui: `Tabs` takes `param` (and `paramDefault`) to hold the shown tab in a query param of the page with no island of the app's, drawn from the first paint and written on a pick without a navigation, and a `value` naming no enabled tab shows the first enabled one instead of leaving no tab reachable by keyboard: [Tabs](../packages/ui/llms/tables-navigation-and-layout.md#segmented-chipgroup-tabnav-breadcrumb-sitenav-appheader-tabs-toggle-checkbox).
- kayjs-ai: a conversation kept on the server leaves out a reply stopped before it said anything instead of replaying words the model never wrote, and keeps at most 200,000 characters of tool results, the oldest turns' becoming `(left out)`: [Conversations](../packages/ai/llms/chat-conversations.md).
- kayjs-ai: `kay build --no-cache` keeps the `imageAlt` drafts, `ai({ imageAlt: { reviewed } })` makes `kay check` stop listing reviewed drafts, and a served-page hook that throws is logged once: [Images and PDFs](../packages/ai/llms/attachments.md#draft-the-alt-of-imported-images).
- kayjs-ai: an API root (`AI_BASE_URL`, `AI_AUDIO_URL`, `AI_EMBED_URL`, `baseUrl`) that is not an http(s) URL throws naming the variable (`openai()` and `anthropic()` when called, an environment root at the first ask), a key goes over plain http only to a loopback host unless `AI_INSECURE=true`, and `AI_PROVIDER=openai` without `OPENAI_API_KEY` throws unless `AI_BASE_URL` names a compatible server: [Asking](../packages/ai/llms/asking.md).
- A string field of an action with no `maxLength` takes a default bound of 10,000 characters, refused with the error of a declared one and carried to the form's `maxlength` and the tool's schema. `unbounded-string` is now a warning, and only for a field named like a short value (`name`, `email`, `title`...): [actions](actions.md).
- An island handed an action by a page needs no `Action` import to type the prop, `(input: { name: string }) => Promise<string>` does: the code reviving the action loads in the browser only for a page that passes one, and the `island-action` lint and its render error are gone: [actions from islands](actions-from-islands.md).
- kayjs-auth: `safeRedirect` is kay's `localPath`, which the library's own redirects use; the old name works until 1.87 and `kay upgrade` rewrites it: [Redirects](../packages/auth/llms/oauth-passkeys-two-factor.md).
- `session.settings` holds its lifetimes as durations (`'2592000s'`), like every other duration in the API: [Sessions](server.md#sessions).
- The session stores are `memorySessions()` and `sqliteSessions(path)`, named for what they hold like `memoryJobs` and `sqliteRates`; `memoryStore` and `sqliteStore` work until 1.87, and `kay upgrade` renames them: [Sessions](server.md#sessions).
- Config keys are named by what they hold: `routes`, `api`, `content`, `storage`, `maxSizes` and `settings` are `routesDir`, `apiDir`, `contentConfig`, `fileStore`, `maxSizeByPath` and `librarySettings`, the old names working until 1.87 with `kay upgrade` renaming them: [Project](project.md), [Upgrading](upgrading.md).
- Tailwind needs no line in `kay.config.ts`: a project with `bun-plugin-tailwind` in its `package.json` gets the plugin (once, if the config lists it too), `kay new` stops writing the import and the `plugins` line, and `kay/test` keeps loading its native addon lazily: [Use Tailwind](styles-and-assets.md#use-tailwind).
- `kay start --host <address>` sets `HOST` over the shell's, as `--port` sets `PORT` and `kay dev --host` binds its server: [Build and start](build-and-start.md).
- `base` reads `SITE_BASE` where the config sets none, as `site` reads `SITE_URL`, so a deployment under a path (Pages) needs no line in `kay.config.ts`; `kay new` no longer writes a `process.env.SITE_BASE` line and its import when no base is chosen: [Base path](routing-endpoints-and-base.md).
- A key kay does not know in `kay.config.ts`, `trailingslash` say, is a type error in `defineConfig` and stops `kay check` and the server with the nearest known name, in the config's top level and its `security`, `i18n`, `seo`, `offline`, `health` and `proxy` bags: [Project](project.md).
- kayjs-cms: `github({ repo, token })` commits a file entry to GitHub (or GitHub Enterprise Server with `baseUrl`) through the Git Data API, a rename with the entries that named it as one commit, and `CMS_HOST=github` makes a production server without `files` build it from `CMS_REPO` and `CMS_TOKEN`: [Setup and saving files](../packages/cms/llms/setup.md#commit-saves-to-github).
- kayjs-ai: a conversation a Chat keeps on the server (`keepOnServer`) keeps each reply's tool calls and results too, and the next ask replays them to the model, which no longer invents follow-up answers a tool already gave: [Conversations](../packages/ai/llms/chat-conversations.md).
- kayjs-ai: `mocked(action, run)` makes a tool of an app's action with its own name, description and input schema and a `run` of yours, so a script benches a prompt against the real model with nothing restated: [Actions as tools](../packages/ai/llms/tools.md#benching-a-prompt-against-the-real-model).
- kayjs-ai: `ai({ imageAlt: true })` drafts the `alt` of each imported image a server-rendered page shows with none, once per image content and kept in `.kay/cache`, `kay check` lists the drafts for review and no longer reports `missing-alt` for those images, and `describeImage()` asks the model for one: [Images and PDFs](../packages/ai/llms/attachments.md#draft-the-alt-of-imported-images).
- An extension can carry `transformServedPage`, the page hook for a page rendered per request, and declare `satisfies: ['missing-alt']`, which makes `kay check` skip an `img` of a server-rendered page whose `src` is an imported image, and `kay/library` exports `libraryCacheSlot`, `readCacheEntry` and `writeCacheEntry` for a library's own entries under `.kay/cache`: [Component libraries](component-libraries.md).
