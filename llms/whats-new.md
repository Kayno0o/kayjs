# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- A page's `Table` that renders as plain markup passes `kay check` with its columns typed `Column<Row>[]`, or holding a function `sortValue`, instead of `island-prop`: a use turning no interactive prop on sends nothing, so the type of a variable it is given is no longer read as data ([islands](islands.md#make-a-component-interactive)).

## 1.112.0

- kayjs-ui's `starfield` utility is removed with `@kayjs/ui/starfield.css` and its `--color-star*` tokens, and `kay new` no longer puts stars behind the page: the fixed layer kept the GPU compositing and made pages lag on a machine short of video memory ([upgrading](upgrading.md)).

## 1.111.0

- kay and its libraries need Bun 1.4.5, a security release for HTTP/3, HTTP/1.1, TLS, DNS and Zstandard, and refuse 1.4.4 with the command that updates it ([project](project.md), [upgrading](upgrading.md)).
- A refresh in place no longer jumps the window to the end of the page in Chrome when it drops or moves rows around the one in view (an action posted from a long list of row forms): the swap turns scroll anchoring off while it morphs and keeps the scroll, and a focused field the refresh removed gives the focus to the field of that name now at its place rather than the first of the page, without the text typed into it meanwhile, which goes nowhere (a row is told by its form's `id`, or its action and hidden fields, else its nearest ancestor's `id`), and an island's field a refresh renders afresh gets its typed text back at its own place, not the first field of its name. See [navigation](navigation.md).
- A page that is an island (a closure passed to an interactive component) sends only the `--- server` values its script or template read as props, so a list the fence only reduces no longer weighs the page down ([Props to an island](islands.md#props-to-an-island)).
- The dev tool no longer requests `/_kay/env.js` on an app with no `s.Public` field, which logged a 404 in the browser console on every page: the page's request block says whether the route exists, so the Env tab asks for nothing and still says the app sends no public env ([dev tool](dev-tool.md)).
- A form in a file with a loop over a pattern (`for [key, value] of entries`, `for { id } of rows`) reads its own action again: its `error` and `pending` lines, field values, constraints and messages no longer fall back to the form of the function, where a bare `error` threw `KayFormHere is not defined` and the page answered 500.
- kay's `@kaynooo/pg-orm` peer range takes 9.x beside 7 and 8, and kayjs-ui, kayjs-cms, kayjs-mail, kayjs-ai and kayjs-auth ask for `@kaynooo/utils` `^3.2.0`, which the `kay check` of a lockfile on an older 3.x could not resolve ([component libraries](component-libraries.md)).
- kayjs-mail's confirmation and unsubscribe pages are set in the font and colours of the app's mails with a flat button, in place of a bare `system-ui` column, and the "confirmed" and "unsubscribed" answers state their title alone, so `mail.list.page.confirmed` and `mail.list.page.unsubscribed` are no longer read; a mail's field labels are sentence case and the dev outbox names a real font ([mailing lists](../packages/mail/llms/mailing-list.md)).
- kayjs-ai's Chat is flat (no shadow on the panel or the launcher unless `--kai-chat-shadow` sets one), waits behind a still `Thinking…` line, wraps its suggestions in a squared button, builds its controls from kayjs-ui's `Button` and `ConfirmDelete`, and shows a held tool call by its label and one line of its input, with calls counted `×2` ([chat](../packages/ai/llms/chat.md)).
- kayjs-mail's confirmation and unsubscribe pages follow the `settings` of the app's mails (font stack, colours, radius, so a site that sets them gets its own look) with a flat button, in place of a centred `system-ui` column, and the "confirmed" and "unsubscribed" answers state their title alone, so `mail.list.page.confirmed` and `mail.list.page.unsubscribed` are no longer read; a mail's field labels are sentence case and the dev outbox names a real font ([mailing lists](../packages/mail/llms/mailing-list.md)).
- kayjs-ui's fields draw their text at 16px on a coarse pointer or in a window under 40rem, so iOS no longer zooms the page in on one; a wide window with a mouse keeps the compact sizes ([TextInput](/ui/text-input)).
- kayjs-ui's `TabNav`, `Tabs` and `Segmented` fade out at the edge of a strip that scrolls, so a clipped tab reads as one to scroll to, and `Tabs` opens with its shown tab centred as `TabNav` does ([TabNav](/ui/tab-nav)).
- A kayjs-ui `Table` stacked as cards on a phone names its row of sort buttons with the words `Sort by` (`ui.table.sortBy`) instead of showing bare column names, and draws no per-card label when it has one column ([Table](/ui/table)).
- `kay new .` scaffolds in a fresh clone holding only `.git` and what a new forge repo carries (`README.md`, a licence, `.gitignore`, `.gitattributes`), keeping them and the `origin`, and a folder with anything else is refused naming the entries in the way ([kay new](project-new-and-add.md)).
- `kay build --static` writes the site to a folder beside the output and renames it over `dist` once complete, so a server pointed at `dist` never answers 404 during a rebuild and a failed export leaves the last one untouched (a folder git does not ignore is still removed first, as Tailwind would scan it) ([static export](prerendering.md#static-export)).
- A block drawn per item keeps its nodes and focus across a same-key replacement in kayjs-ui's `TreeView` (`@row`, `@actions`), `Steps` (`@step`), `VirtualList` (`@item`) and `Toaster` (`@toast`), `RelationGraph` (`@middle`) and `MapView` (`@popup`), in a `slot x(item)` inside a form, and in a block whose other arguments, a carousel's index for one, change; an island in an `await` block of a keyed row keeps the row's key as its identity ([slots](templates-elements-slots-snippets.md), [effects](effects.md)).
- On a static export the build reads the `img` and `image()` calls of the islands, so a crop, a quality or a small width only a browser-rendered island draws has its files, and a remote image an island names as a literal URL is downloaded and linked as files; any other remote image keeps its own address in the browser, and `kay build --static` warns of it with `static-remote-image` ([images](images.md)).
- On a static export an island that draws an imported image in the browser links the variant files the build wrote, as the server HTML does, instead of the image route, which a static host answers with a 404 ([images](images.md)).
- `kay check` resolves the imports of a library's own components from where Bun's isolated linker put the library's dependencies, so an app listing `@kayjs/ui` alone no longer lists `@kaynooo/utils` for the check to pass ([component libraries](component-libraries.md)).
- `kay check` reports an `auth()` whose users go through `@kaynooo/pg-orm`, a SQLite file by default, when the app has not installed it, with `bun add @kaynooo/pg-orm`, where the server stopped only at start ([checks](checks.md#peer-packages)).
- `kay check --fix` of `deprecated-schema-builders` keeps an unbounded `s.String()` unbounded, writing `max: Number.MAX_SAFE_INTEGER`, except in an action's input and an API route's `body`, which capped it at 10,000 characters already ([deprecated lints](deprecated-lints.md)).
- A `head` entry in `kay.config.ts` with `children` beside `props` is refused at load and by `kay check`, naming `props.children`, where it used to render an empty tag; the config type refuses it too ([Head](head.md)).
- kayjs-ui's `SiteNav`, `SideNav` and `TabNav` no longer mark every `/#section` link as the current page on that page: a link with a hash is current only when `current` carries the same hash ([TabNav](/ui/tab-nav)).
- The count badge of kayjs-ui's `TabNav`, `Tabs`, `SideNav` and `SiteNav` has the vertical padding of a `Badge`, so its number no longer touches the pill's top and bottom ([TabNav](/ui/tab-nav)).
- A block's item stays the real item when it follows a replacement under the same key: the `row` of a Table's `@cell` and `@detail` is the object in `rows`, so `rows.indexOf(row)` and `row === selected` hold in it and a class instance with private fields works, while its nodes and a field's focus still stay (the 1.110 view of the row, compared by key, is gone). A block or a snippet reads its plain parameters where they are used, `followed(read, draw)` from `kay` draws a call once for the item under its key, and `slot name(item, index)` called with names or paths does it for its first argument, so Tabs, TabNav, Breadcrumb, SiteNav, SideNav and Carousel keep the nodes of the entry blocks across a refresh as the other item blocks do ([templates](templates-elements-slots-snippets.md), [effects](effects.md), [Table](../packages/ui/llms/table.md)).

- An island drawn in a keyed `for` is paired by the loop's key across a refresh, with no `id` or `persist` on it, so deleting the first row leaves each other island its own state; the server writes the key as the island's `data-key`. A `details` of the first load takes the server's value as its baseline, as one a swap brings does ([Navigation](navigation.md#islands-kept-across-pages)).

## 1.110.0

- kayjs-ui's `Checkbox`, `RadioGroup` choices and `Toggle` rows are at least 24px tall, the tap target of WCAG 2.5.8, whatever the label's line height.
- kayjs-ui's `Segmented` keeps each option's label on one line and scrolls sideways inside its container when the options do not fit, and a `Badge` wraps its text between words inside its parent, instead of overflowing it.
- kayjs-ui's `BarChart` draws each shown x-axis label in a box as wide as its text, centred on its column, and no box for a column with no label, so a chart of many columns no longer has labels running past their own box.
- A task list item (`- [ ] a`) inside `.kui-prose`, such as a MarkdownEditor preview, shows no bullet and a drawn box in the accent hanging where the bullet was, not the browser's dimmed checkbox; the space skin draws it too.
- A component listing `island({ interactive })` takes a function or a block with parameters from a use turning none of those props on, so a page's `Table` with an `@cell(row, column)` block is plain markup with the block rendered by the server, and no longer an `island-prop` error ([islands](islands.md#make-a-component-interactive)).
- A Table whose `rows` is replaced by copies under the same `rowKey` keeps the nodes its `@cell` and `@detail` blocks drew, so a field in a cell keeps the focus while it is edited; the block's `row` is a view of the current row, read by its fields where it is used, so compare rows by their key, not by identity (`rows.indexOf(row)` is `-1`); Masonry, AvatarGroup, BellInbox, ChipGroup, Segmented, RadioGroup, MultiSelect, Combobox, DescriptionList, AppSwitcher and AudioPlayer draw their item blocks the same way ([Table](../packages/ui/llms/table.md)).
- A swap keeps what the visitor changed and applies what the server changed: an island stays on a refresh and takes its new props in place, its state kept, as do the islands a layout renders across a visit to a page with the same layout; a static `details` the visitor opened and a field they typed in keep their state through a refresh, in production as in `kay dev`, unless the server changed that value ([Navigation](navigation.md#islands-kept-across-pages), [Actions from islands](actions-from-islands.md)).
- `signal-from-prop` (a warning in the `islands` group) flags a `signal(light)` seeded from a prop and never written, which keeps the first value now that an island stays through a refresh, and `kay check --fix` writes `linked(() => light)` ([lints](island-and-form-lints.md)).
- kayjs-ui's `Dialog` closes with a plain button with a `close` part, so an island holding a Dialog no longer ships `IconButton` and the icon set for it (a plain Dialog island is 7 KB smaller in an app that has no other icon button), and it leaves out `level`, `header`, `handle`, `trigger` and `closeHref` when no call site of the project writes them; the close draws kayjs-ui's `x` icon, and a `close` block replaces it ([restyle](https://git.kaynooo.fr/kaynooo/kayjs/src/branch/main/packages/ui/llms/restyle.md)).
- A kayjs-ui component handing its `...rest` props, or a prop it takes by name, on to a component with optional features (`FormDialog`, `SidePanel` and `ConfirmHost` into `Dialog`) counts by what its own callers write, no longer as every prop, so an island leaves out the features no call site uses.
- A part handed on to a component (`Icon(part="spinner")`) writes its `class` and `parts` as one source, about 45 bytes less in each island per hand-off.
- A `lints` entry in kay.config.ts naming a lint kay has removed (`'deprecated-package-names': 'allow'`) is accepted by the config type and warned about by `kay check`, instead of refused; `kay check --fix` writes `s.Union(Object.keys(R).map(key => s.Literal(key)))` as `s.enum(R)` and leaves any other mapped `s.Union` to the app, see [Upgrading](upgrading.md). The same fix writes `max: Number.MAX_SAFE_INTEGER` on an `s.Array` and `extra: 'strip'` on an `s.Object`, so a rewritten list or object keeps the old behaviour; an app rewritten before has lists capped at 1,000 and objects that refuse extra keys, [how to check](upgrading-archive.md).

Releases before 1.110 are in [What's new, older releases](whats-new-archive.md).
