# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- A link pressed while its hover prefetch was still waiting no longer fetches its page a second time, so a page is requested once per visit on a slow machine too ([navigation](navigation-from-code.md)).
- kayjs-ui's FormField, Checkbox, Toggle and FileDrop keep an empty message line out of the layout, so no row gap is left under a control and a button beside the field lines up with it; the line stays in the page to announce a message ([forms](../packages/ui/llms/forms-and-steps.md)).
- kayjs-ui's CardRow actions show at full opacity on a screen that cannot hover ([layout](../packages/ui/llms/page-layout-palette-and-trees.md)).
- kayjs-ui's MultiSelect trigger is a `combobox` button opening a dialog and takes `aria-invalid` (`invalid` or a FormField message), `aria-required` and `aria-describedby`; its `data-refused` mark is gone ([MultiSelect](../packages/ui/llms/pickers.md)).
- kayjs-ui reads one `--motion-scale` token, `0` under `prefers-reduced-motion`, for every transition it draws, the carousel, SidePanel, Badge, sortable lists and the skins included ([setup](../packages/ui/llms/setup.md)).
- `kay new --with postgres` and `kay add postgres` give each app its own development database port (derived from the app's name, in `.env`, `.env.test` and `compose.dev.yaml`) and keep its data in `data/postgres`, bind-mounted and out of git, instead of port 5433 and a named volume, and the production composes bind-mount `data-prod` (create it before the first start, owned by the container's user) instead of a named volume; the next step reads `bun run db:generate`, as pg-orm's `generate` takes no name ([project new and add](project-new-and-add.md)).
- kayjs-mail's confirmation and footer views get `site` as the site's origin and `host` as its host, and the default confirmation words name the site by its host as the subject does ([upgrading](upgrading.md)).
- The accent picker `kay new` writes sizes its popover to its seven swatches, which no longer overlap.
- Links to the current page inside an island get `aria-current` in the server HTML, as those of a page do, and an island a swap keeps (`persist`) takes the next page's marks ([navigation](navigation.md)).
- After a page swap to `/docs#install` the focus, and a screen reader's position, go to the element the fragment points at, as a page loaded natively does, the title still announced ([navigation](navigation.md)).
- A `session()` made as a module loads reads the app's secret on first use, so `secret` in `kay.config.ts` and its rotation list apply to sessions as well as `KAY_SECRET` ([the app secret](environment.md#the-app-secret)).
- `WebSocket` from `kay/server` is Bun's `WebSocket` client typed with its options, so server code opens a websocket with `headers` or `protocols` with no cast ([server](server.md)).
- An `api()` route with a `params` schema (`params: s.Object({ number: s.Integer() })`) answers over real HTTP again, as it did through `site.api`: kay hands the schema a plain copy of the route's params, which Elysia 1.4.31 could not read from Bun's; kay requires that Elysia.
- `kay check` warns when `i18n.paths` translates the default locale, whose path is the pattern: a link written as the translation would not localize ([locales](locales.md)).
- The sitemap lists a routed entry's translation at its own slug, and points each copy's `xhtml:link` alternates at the others' own slugs, as the page's `<link rel="alternate">` does ([locales](locales.md)).

## 1.93.0

- A `local()` collection signed out stays so until the visitor is back: `retry()` and a retry armed while the server was unreachable no longer send the queue again, nor turn the status to `offline` ([local collections](local-collections.md)).
- kayjs-ui drops the prop names 1.89 deprecated: `isDisabled` on the date inputs and Widget's `isEmpty` and `@empty` are gone with their `deprecated-ui-props` lint ([upgrading](upgrading.md)).
- kayjs-ui's `TooltipHost` shows a `data-hint`, or the `data-tooltip` of an element no tap acts on, when a touch screen taps it, and hides it on a second tap or a tap elsewhere: hints on a phone are readable with nothing to add ([tooltips](../packages/ui/llms/basics.md)).
- kay/test's `page.tap(selector)` taps an element as a finger does, with `touch` pointer events, so a touch-screen behaviour is tested without raw DevTools touch events ([browser tests](testing-browser.md)).

## 1.92.0

- kayjs-ui `AppHeader`, `SiteNav`, `TabNav` and `SideNav` given no links draw nothing to navigate with: no nav landmark, no menu toggle opening an empty popover, no menu button, so the `class={{ nav: links.length === 0 ? 'hidden' : '' }}` workaround goes ([navigation](../packages/ui/llms/tables-navigation-and-layout.md)).

- kayjs-ui's space skin frames every box by a 1px hairline (`--border-width` stays `1px`, `--color-border` at 11%) over a lifted `--color-surface`, and its overlays by `--color-border-strong` with no shadow, so Cards and dialogs stand off the canvas without the dark override orbit-style apps wrote ([skins](../packages/ui/llms/setup.md)).
- An action tool that declares no `tool: { output }` is listed with the `outputSchema` of its handler's return type, read from the types by `kay build` (and in the background by `kay dev`): nothing to declare, and a declared `output` still wins ([action protection](action-protection.md#offering-an-action-to-agents)).
- kayjs-ui's `Select`, and the select of a compact `FormField`, never grows past its container: a long option is cut in the closed select instead of pushing a phone page sideways, so the `[&_select]:max-w-full` workaround on a filter form goes ([forms](../packages/ui/llms/forms-and-steps.md)).
- A `kay.config.ts` setting `images.resolve` or `images.guard` inline no longer makes the config `any` under TypeScript (`error TS7022`, then every `ctx.locals` unresolved in the lint), with nothing to annotate. A callback that returns something read off `ctx.locals` still needs its return type written, as the config's type depends on it ([images from the app's own lookup](images-runtime-and-remote.md)).
- kayjs-ui BarChart fits its figure whatever the number of labels (the gap between columns shrinks as they get narrow, `--bar-gap` sets it) and its first and last x-axis labels stay inside it ([BarChart](../packages/ui/llms/charts.md)).
- A `testSite({ browser })` keeps its build record in `.kay/client`, as the checks of the other sites do in their folder: a later test file, or a later run, whose sources did not change builds the islands and styles no more ([testing](testing-setup.md)).
- `tools/list` carries an `outputSchema`: an action declares it with `tool: { output: t.Object({...}) }`, checked by `kay check` against what the handler returns (an object schema, which the types hold it to), and an API route's object `response` is listed without any declaration; the answer is then always sent as `structuredContent`, and `kay dev` warns once of an action's answer that does not match, a library's tool included ([action protection](action-protection.md#offering-an-action-to-agents)).
- A link to a page streaming `await` blocks shows the page as soon as its first part is in, with the `pending` branches, and each block replaces its branch in place as it arrives, instead of waiting for them all; a slow block no longer ends in a second request after 10 s, and `client: { pageTimeout }` sets that limit. `kay:navigate` fires once, for the first part, and `kay:navigate-stall` when the stream stalls ([navigation from code](navigation-from-code.md#navigation-state-and-hooks)).
- `tool: { text }` on an action (or a route's `detail.tool`) words the MCP answer from what it returned, such as one line per note: the agent gets that text alone, with no JSON twice, while the page still gets the object ([action protection](action-protection.md#offering-an-action-to-agents)).
- An action with `tool: { readOnly: true }` is listed by `/mcp` with `readOnlyHint: true`, so a client can approve it without a prompt; it was always listed as a write ([action protection](action-protection.md)).
- kayjs-cms has hooks before a change: `cms({ beforeSave })` runs before every save, publish, unpublish, duplicate, restore, delete and rename and may change `data` and `body` or refuse (`false` or `refuse()`, shown in the entry form and answered 422 or 403 by the API), `cms({ beforeUpload })` scans, resizes, renames or refuses a file before it is stored and `cms({ onUpload })` is told once it is; `onSave` also gets `data` and `previous`, and the activity log keeps uploads ([Before a save](../packages/cms/llms/loaders.md#before-a-save), [uploads](../packages/cms/llms/uploads.md#hooks), [hooks](hooks.md#kayjs-cms)). `onSave` is now told through kay's `dispatch()`: a throw is reported with source `cms.onSave`.
- A form an island builds in the browser gets the `honeypot` field and the `minTime` stamp of its action: it asks the server (a GET at `/_kay/fields/` answering the same markup the server renders, `no-store`) when it takes focus or is posted, so such a form is no longer refused as expired nor left without a honeypot, with no request on page load and, for a form of an action with neither, one cached request and no field ([action protection](action-protection.md#minimum-time)).
- The MCP tool `not_found` lists the paths visitors found nothing at, as `kay not-found --format json` does (`{ missing, total }`, capped at 200, reading only) ([MCP commands](editor-and-agent-commands.md)).
- kayjs-ui `ui()` imports from the package root like `auth()` and `cms()`: `import { ui } from '@kaynooo/kayjs-ui'` loads in a `kay.config.ts` under plain Bun, `@kaynooo/kayjs-ui/extension` stays as an alias, and `kay add ui` and `kay new` write the root import ([setup](../packages/ui/llms/setup.md)).
- kayjs-mail has [hooks](hooks.md): `mailer({ beforeSend, onSend, onError, onSuppress })` around a send, the queue and a bounce, `onSubscribe`, `onConfirm`, `onUnsubscribe` and `onBroadcast` on a list, and `onSend` and a `to` function on `contactForm` ([details](../packages/mail/llms/writing-and-sending.md#hooks)).
- kayjs-auth's and kayjs-ai's hooks follow the [hook convention](hooks.md#kayjs-auth): `onEvent` (was `onAuthEvent`), `beforeDelete` (was `onDelete`; it can refuse with `false` or `refuse()`, answered as `refused`), `onSignUp` logged rather than failing the sign-up, and an `AuthHookContext` (kay's `HookContext` and the `actor`) in each; in kayjs-ai `beforeRequest` (was `onRequest`; `false` refuses), `onSuccess` (was `onFinish`), `onError({ error, context })`, a `context` in each, and a hook given to `ask()` runs after the one of `ai()` instead of replacing it ([AI hooks](../packages/ai/llms/hooks.md)); kayjs-ui's `onSaved` is `onSave` on Form, FormDialog and SaveForm (whose call that does the save is `save`), `onSent` is `onSend` and AudioPlayer's `onEnded` is `onEnd` ([forms](../packages/ui/llms/forms-and-steps.md)); `deprecated-hook-names` flags the old keys and props ([upgrading](upgrading.md), [auth setup](../packages/auth/llms/setup.md)).
- `session({ onCreate, onDestroy })` and the `onWrite` and `onDelete` of `diskFiles`, `s3Files`, `memoryFiles` and an app's own `FileStore` are [hooks](hooks.md) told `{ id | key, ..., context }`, a throw reported and never failing the request, and they feed `kay_session_events_total` and `kay_file_events_total` in `/metrics` ([sessions](server.md#sessions), [files](files.md#stores)).
- `--- island` and `--- static` in place of `---` pin a component's role: `--- island` makes it an island on every page (where a component passing a function or a block with parameters was promoted only when the build found its chunk reachable), and `--- static` turns anything that would make it an island into the compile error `static-pin`, standing at the `on*` or `kay` value that does it, and is never promoted. What a component passes an island is read from its types: a function, a block with parameters, a symbol or an object holding one is the error `island-prop` (fixed by `--- island`), data and `any` or `unknown` say nothing, and `promoted-island`, now deprecated until 1.95 with the same fix, no longer warns of an action or a call that returns data, so `// kay-allow-file promoted-island` is not needed. `IslandPropsError` names the fix. `// kay-island` and `// kay-static` still work until 1.95: the new `island-comment` lint has `kay upgrade` write them as fence lines, and `island-marker` only reports `--- island` on a page, layout or special page ([Islands](islands.md#islands)). Every name is imported where it is used, in a `.kay` file and a `.ts` module alike: the new `implicit-import` lint warns of a `kay` value or `t` used with no import, which kay adds until 1.95, and `kay upgrade` writes the line (`kay check --fix` writes the import of any `kay/*` name a `.kay` or `.ts` file lacks, and the editor offers it as a quick fix) ([Imports kay adds](components.md#imports-kay-adds)).
