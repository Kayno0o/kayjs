# What's new

What each release of kay and its libraries adds, newest first, each feature with where it is documented. kay and its libraries share one version, so one section covers them all; what a release breaks is in [Upgrading](upgrading.md).

## Unreleased

- `rooms()` gives `response`, a schema for the ws route that types an island `socket()`'s messages as the rooms' `Message` without a schema written for typing, and `memberOf(ws, room)`, the member a connection joined a room as ([Rooms](rooms.md)).
- kay's analytics notice and information line take the site's look: kayjs-ui's tokens when present, else the page's colors, and `--kay-notice-*` properties restyle them ([Privacy](privacy.md)).
- A shorthand class keeps a `.` between two digits, so `div.gap-1.5.p-0.5` reads `gap-1.5` and `p-0.5` where it split each in two, and `kay migrate astro` and `kay fmt` write such classes as shorthand ([Templates](templates.md)).
- A `kay/test` visit has `page.settled`, the page as the visitor ends up seeing it, each streamed `await` block's last part swapped in place ([Testing](testing.md#reading-a-page)).
- `persistedCookie(name, value)` from `kay/test` sets a cookie-kept `persisted` value by name, for `site.as()` ([Testing](testing.md#requests-jobs-sockets-and-sessions)).
- `kay check` keeps what an enclosing `if`, `match` or `for` narrows inside the blocks of an `await` and a `try`, a property path such as `dossier.latest` included ([Rendering](rendering.md#streaming)).
- An action prop typed with the handler's success output, `Action<{ name: string }, string>`, accepts a handler that can also `ctx.fail`, where it failed with an error about `failed()` and `FormFailure`; `FailureData` is `unknown` for an output naming no `Failure` ([Pass an action to a component](actions-from-islands.md#pass-an-action-to-a-component)).
- `sqliteRates`, `sqliteRooms` and `sqliteStore` create their file on first use, not when they are called, so a `kay.config.ts` naming one makes no file in `kay build`, `kay check` or a test run, and an unwritable path now fails on the first use rather than when the config loads ([Privacy](privacy.md)).
- The error reporter loads with the first error and the prefetch code with the first link a visitor points at, presses or focuses (replayed, so that link is still prefetched), not with every page: the entry is about 60 bytes (static page) to 200 bytes (bigger pages) gzip lighter, with no extra request at start; a static export has no reporter ([Navigation](navigation.md#full-loads-and-prefetching)).
- An effect keeps its sources between runs and subscribes only what changed, so a list of 10,000 rows swaps pairs in 6.6 ms instead of 10 and updates in 0.9 ms instead of 1.1; the entry grows by about 160 bytes gzip, so net of the line above it is 103 bytes heavier on the static test page and 50 to 60 lighter on the others measured ([Islands](islands.md)).
- An `if` or `match` naming no value builds one memo, and toggling 2000 blocks takes 22.7 ms instead of 26.5 ([Islands](islands.md)).
- Transitions write all their classes before reading any style, so entering 200 rows forces 7 style recalculations instead of 205, a page swap compares a 1500-row list with 68 `matches` calls instead of 6115, and `followLog` on 5000 lines costs 3.3 ms of script instead of 146 per 60 scroll events.
- A page request skips its promises and round trips on the common paths: a denied guard answers in 12.3 us instead of 16.2, a page under a `base` in 33.4 instead of 39.7, a localized page in 24.7 instead of 27.9 ([Server](server.md)).
- Links on a localized site match their route patterns compiled once per site on the server, about 4 to 90 us per page of 50 links instead of 1.1 ms, and the browser keeps the plain matcher ([Locales](locales.md)).
- `kay dev` saves faster: a types-only write runs no project check and keeps each shadow in memory (68.7 ms to 49.6 per save on the docs), and editing a code file the types process did not load no longer boots a new one (305 ms to 47).
- `kay dev`'s builder keeps the source maps of chunks an edit left alone and no longer holds file text for class tokens: CPU per island edit goes from 1440 ms to 940 and its memory after edits from 293 MB to 265; it exits after 30 seconds without a build, so the first edit after an idle period takes about 0.4 s longer ([The dev server](dev-server.md)).
- `kay add <library>` places the import it writes in `kay.config.ts` where the app's `perfectionist/sort-imports` rule sorts it, so the file passes `kay lint` as written ([Project](project.md)).
- `kay check --fix` declares the raw `process.env.X` reads `kay env` warns of in the app's `defineEnv` schema (or a new `src/env.ts`), keeping a `?? 'default'` as the default and rewriting the reads to `env.X` ([Check](check-and-tools.md)).
- A queue's run writes about its job (`complete`, `retry`, `fail`) only while the hold it was claimed with is still the job's, so one that outlived its hold no longer completes or fails the job another process runs; a `JobStore` gets the hold as a last argument and may return the one it stored in `heldUntil` ([Queues](queues.md)).
- `sqliteCache` creates its file on the first value stored or invalidation published instead of in every process loading the module naming it, and `invalidate` still reaches what it kept after a restart ([Rendering](rendering.md#caching)).
- `pgJobs` takes holds from the database's clock, so replicas' clocks need no longer agree ([Queues](queues.md)).
- `kay/pg-orm` exports `jobTables`, the job queue's `kay_jobs` and `kay_locks` as pg-orm definitions: an app lists them in `new Database({ tables })` and its own migrations create them, instead of `ignoreTables` plus `createJobTables(db)`; pg-orm is an optional peer of kay ([Queues](queues.md)).
- A `pending` block inside `form(action={...})` shows only while that form posts, with no script of an island or of the page: hidden in the render, after the answer, after a refused post and with JavaScript off, and announced to screen readers once shown ([Actions](actions.md#refused-fields-and-their-messages), [Templates](templates.md)).
- A `pending` block inside `form(action={...})` shows only while that form posts, with no script of an island or of the page: hidden in the render, after the answer, after a refused post and with JavaScript off, and announced to screen readers once shown ([Actions](actions.md#show-that-a-form-is-posting), [Templates](templates.md)).
- `add.settled()` on an action, and on a `track()` handle, resolves once no call is in flight, whichever way they went, so an island that fired writes without awaiting them waits for them there, with no list of promises of its own ([Actions](actions-from-islands.md#calling-from-an-island)).
- `refusalMessage(error, fallback)` from `kay` gives the message to show for a caught `call()` error: the route's when it answered, else the fallback, with no `instanceof ApiError` check ([Calling API routes from islands](api-from-islands.md#call-a-route-from-an-event-handler)).
- A streaming action whose own result removes the block its call was made in keeps streaming, handed to the block around it, rather than closing after its first value ([Calling API routes from islands](api-from-islands.md#streaming-actions)).
- The `.class` shorthand takes Tailwind's brackets, variables and star variants whole: `.w-[calc(100%-2rem)]`, `.[&>svg]:size-4`, `.bg-(--brand)/50`, `.*:p-2`, and ends a class ending in a digit before a `2xl:` class, `.col-2.2xl:flex`, so `kay fmt --from-html` and `kay migrate astro` write such classes as shorthand ([Templates](templates.md)).
- `kay fmt` moves the shorthand classes of an element into a `class="..."` inside the parentheses when they make its line longer than 120 characters, the value over several lines when it is long, and a static `class="..."` may run over lines, its words joined by single spaces ([Templates](templates.md)).
- An `_actions.kay` is a `--- server` fence alone, with no closing `---` line, and `kay fmt` leaves a fence running to the end of the file as it is ([Actions](actions.md#declaring-an-action)).
- `s.UnionKeys(record)` is an enum schema over a record's keys, typed as their union where `s.UnionEnum(Object.keys(record) as [...])` needed a cast ([Actions](actions.md#forms)).
- A `kay/test` visit has `stamp(action)`, the stamp its form for `action` rendered with, and `site.submit` takes it back as `{ stamp }`, so a test of a refused form needs no `kay_since` field ([Testing](testing.md#test-site)).

## 1.58.0

- kayjs-auth keeps typed app data on the user: `createAuth({ user: s.Object({ ... }) })` with `onProviderProfile` returning what to store (an avatar, say), `auth.user().data` typed from the schema, and `User.providers` giving each linked provider's id; `pgStore` adds its `data` column on `db.sync()` ([kayjs-auth OAuth](../packages/auth/llms/oauth-passkeys-two-factor.md)).
- kayjs-auth's `secret` is optional: left out, it derives its own key from the session's secret, so an app sets one secret, and `session()` exposes `deriveSecret(purpose)` for the same ([kayjs-auth setup](../packages/auth/llms/setup.md), [Server](server.md)).
- A `cookie` header given to `kay/test`, in a request's headers, `testSite({ headers })` or `site.as()`, is now sent with the cookies the site kept that it does not name, where the kept cookies replaced it ([Testing](testing.md#requests-jobs-sockets-and-sessions)).
- `rooms({ state, snapshot })` keeps a typed state per room, shared through the store and changed with `update`, and sends each joiner a snapshot of it; the rooms reference moved to its own file ([Rooms](rooms.md)).
- `kay/test` has `site.api(module, path, options)`, a call to an API route typed from the module that answers `{ ok, status, headers, body }`, `testSite({ headers })` and `site.as(cookie | headers)` for headers every request sends, and `site.socketRefusal` for a websocket upgrade a route must refuse ([Testing](testing.md#test-an-api-route)).
- `site.open` and `browse` take `cookies` as a `Cookie` header string, as `auth.sessionCookie` returns, beside a list of `{ name, value }`, and the option is documented with a signed-in example; the browser testing reference moved to its own file ([Testing in a browser](testing-browser.md)).
- `safePath(root, name)` from `kay/server` gives the real path of a file inside a folder for a name a visitor typed, or `undefined` for `../`, a symlink out, a NUL byte or a missing file, which `images.resolve` can return ([Server](server.md#files-from-a-folder), [Images](images.md)).
- `checks: [fn]` in kay.config.ts runs an app's own checks inside `kay check`: each reports problems with `report()`, which join kay's in text, JSON and the MCP tool and count toward the exit code, and one that throws is reported while the others run ([Check and tools](check-and-tools.md)).
- `kay env --compose <file> --example <file>`, or `env: { compose, example }` in kay.config.ts, which `kay check` runs too, compares the declared variables with the compose files and `.env.example`, and lists raw `process.env.X` reads nothing declares ([Check](check-and-tools.md)).
- `s.Secret()` declares a secret of at least 32 characters that production must set and `kay dev` and `bun test` derive from the project path and a seed kept in `.kay`, and `requiredInProduction` without a default keeps the type `string` (an empty string outside production); `kay env` marks a secret, and `kay new` uses it ([Check](check-and-tools.md)).
- A queue handler takes the job as a third argument: `job.progress(value)` reports how far the run is, and `queue.job(key)` reads it back while the job runs or after it failed, so a page can show "running, 12/40" ([Queues](queues.md)).
- A queue handler can `throw retryLater('30s')` to run the job again after that wait without spending an attempt, for a full disk or a service asking to slow down ([Queues](queues.md)).
- `enqueue(payload, { key })` keeps one waiting or running job per key and resolves with its id when another holds it, and `queue.job(key)` tells whether a job is waiting, running or failed, so an app no longer tracks that itself ([Queues](queues.md)).
- `pgJobs(db)` from `kay/server` keeps a queue's jobs and schedule locks in Postgres, through a Bun `SQL`, a pg-orm `Database` or a URL; it creates `kay_jobs` and `kay_locks` when missing, so with the app template's `app_rw` the owner runs `createJobTables(db)` once, and pg-orm's `ignoreTables: [...jobTables]` keeps `db.sync()` from dropping them. A `JobStore` may also hold a job's `key`, its `progress` and a `release` with a next run time, which `memoryJobs` and `sqliteJobs` do ([Queues](queues.md)).
- kayjs-ui's keyline token is `--kui-border-width`, a length that sizes the border of buttons, cards and their heads, card rows, widgets, notices, avatars, toasts, dialogs, the palette and popovers (cards and the others drew a fixed 1px); a value that is no length, such as `2px solid red`, leaves it at 1px instead of dropping every keyline, and the old `--kui-border-card` still sets it until 1.61 ([Setup](../packages/ui/llms/setup.md)); see [Upgrading](upgrading.md).
- kayjs-ui's palette derives from eight seeds, `--color-kui-canvas`, `text`, `accent`, `success`, `warning`, `info`, `error` and `field-border`: a skin that sets only those gets the surfaces, greys, hairlines, hover and danger fills mixed from them, in both schemes, and each derived colour stays overridable on its own; the default look holds within 10 steps of a channel (11 for `on-accent`), and the theme's CSS grows by about 600 bytes (110 gzipped) on a page using most colours ([Setup](../packages/ui/llms/setup.md)); see [Upgrading](upgrading.md).
- kayjs-ui ships the French of every `ui.*` text, read on a French page with no setup and after the app's own messages, so a French site no longer words each default itself; any library may ship catalogs the same way with `"kay": { "messages": "./src/messages" }` in its package.json, and a regional locale such as `fr-CA` reads its language's catalog when an extension or library has none for the region ([Texts and languages](../packages/ui/llms/words.md), [Component libraries](component-libraries.md)).
- `kay build --compile --verify-load` loads every module of the executable without starting its server, so a Dockerfile build stage with no database or secrets can prove the binary loads ([Production](production.md#check-the-executable-starts)).
- A message failing a websocket route's `body` is dropped with no reply (nor `onError`), where Elysia sent the sender a validation frame carrying the schema that an island applying every server message misread, and a valid one arrives decoded as an HTTP body is, `at: '1'` as `1` for an integer, and a key the schema does not name is stripped rather than refused ([API from islands](api-from-islands.md#chat-over-a-websocket)).
- `overrideEnv(env, values)` from `kay/test` gives a `defineEnv` value other variables for one test and puts them back, and `defineEnv`'s `source` argument is documented ([Testing](testing.md), [Server](server.md)).
- kayjs-auth's `auth.sessionCookie` mints the `__Host-session` cookie an https site reads, in production when kay.config.ts `site` is https or with `{ secure: true }` ([Hardening and testing](../packages/auth/llms/hardening-and-testing.md)).
- kayjs-ui's `attempt` and ConfirmDelete read the `ApiError` that `call()` throws as they do an action's refusal: the route's own words are toasted for a 4xx when they read as a message (not markup, a status code or a page), `refused` reads its `answer`, and `failure` stands for status 0 or a 5xx ([kayjs-ui](../packages/ui/llms/basics.md)).
- kayjs-ui toasts a short all-caps refusal such as `ACCESS DENIED` as a message (only a code such as `NOT_FOUND` or `404` stays to `failure`), and a `refused` that throws is logged with `console.error` while `failure` is toasted ([kayjs-ui](../packages/ui/llms/basics.md)).
- kayjs-ui's `messageOf(error, fallback)` gives the message of a failed `call()` or action for a page to show where it is, with the words `attempt` would toast and `fallback` otherwise ([kayjs-ui](../packages/ui/llms/basics.md)).
- kayjs-ui `Badge` takes `solid`, filling it with its tone for every tone, its text in `--color-kui-on-accent` or the `--kui-badge-solid-text` a skin sets ([kayjs-ui](../packages/ui/llms/basics.md)); the theme's CSS grows by about 490 bytes (53 gzipped).
- kayjs-ui `Card` takes `level={1}`, for a card that is the page's content: its title is the page's `h1` ([kayjs-ui](../packages/ui/llms/basics.md)).
- kayjs-ui has `AppHeader`: a sticky bar with a `@brand` block, `SiteNav`'s links and menu, and an `@end` block, painted by the theme's tokens; `SiteNav`'s links take an optional `icon` ([kayjs-ui](../packages/ui/llms/tables-navigation-and-layout.md)); the theme's CSS grows by about 1,240 bytes (140 gzipped).
- kayjs-ui `Segmented` takes number option values, and `onChange` hears the option's own type ([Tables, navigation and layout](../packages/ui/llms/tables-navigation-and-layout.md)).
- The metric-matched font fallback also covers Roboto (a sans) and fits Noto Serif (a serif), so on Android and on a Linux machine without Arial-compatible fonts it loads instead of leaving the text to shift as the font swaps in ([Fonts](sitemap-search-fonts.md#fonts)); the page's inline `<style>` grows by about 200 bytes (40 gzipped) per serif family and about 60 bytes (16 gzipped) per sans family, which only lists Roboto beside Arial.
- The link check counts the source of a `redirects` entry, in the config or added while the site runs, as served, so a link, `ctx.redirect`, a guard's `redirect` or `navigate()` to it passes ([Checks](checks.md)).
- `route('/todos/:id', { id })` from `kay` builds the path of a page from its pattern, typed from the file routes (an unknown pattern or a missing param is a type error `kay check` reports), params encoded, with `query` and `hash` options, and the result goes through `base`, locales and translated paths as a literal `href` does ([Routing](routing.md#link-to-a-page-with-params)).
